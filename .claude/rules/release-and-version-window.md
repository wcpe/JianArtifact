# 发布门禁与版本窗口

> 适用于本项目所有正式版本（`vX.Y.Z` tag）的发布与后续版本窗口开启。AI 代理与人类协作者都须遵守。

## 1. 发布门禁（强制）

**任何正式版本发布前必须通过全部验收门**——不满足则不打 tag、不发 release：

1. 质量门通过：`bash scripts/check.sh` 全项绿（前端 + 后端 + govulncheck）。
2. CI 全绿：推 main 触发的 `release.yml` 质量门 5/5 通过。
3. 该版本声明的实机验收门全部通过（定义在 `docs/ROADMAP.md` 对应版本段的"门禁"），且须用户确认。
4. 冒烟验收：已发布产物（GHCR 镜像 / Release 二进制）可运行、前端内嵌渲染正常、e2e 链路绿。

**流程**：先提交非发布改动 → 等 CI 绿 → 实机验收通过 → 提交发布 commit + 打 tag → 推送。

## 2. 版本窗口（强制）

正式版本发布完成后**立即开启下一版本窗口**，具体操作：

1. `VERSION` 文件更新为下一计划 minor（如 `0.5.0` 发布后 → `0.6.0`）。
2. `CHANGELOG.md` "未发布版本"段保持为空模板（已有则确认在）。
3. `apps/server/cmd/jianartifact/main.go` 中 `version` 默认值更新为新版本号。
4. `docs/ROADMAP.md` 标注下一版本为**进行中**（对齐状态行体例）。
5. 以 `chore(release): 开启 X.Y.Z 开发窗口` 提交并推送。

## 3. 禁止

- 禁止在验收未通过时打 tag 或发 release（质量门/实机门任一未过 = 未通过）。
- 禁止发版后遗忘窗口开启（发版提交与窗口开启提交在同一次推送中完成）。
- 禁止 CI 外手动构建产物作为正式发布（正式产物必须源自 CI）。
