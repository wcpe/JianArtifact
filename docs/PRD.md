# 产品需求文档（PRD）：JianArtifact

> 需求的单一真源（WHAT / WHY），也是产品的需求登记册。§4 只登记一行 FR、优先级、目标窗口和状态；详细设计放 `docs/specs/`，当前架构看 `docs/ARCHITECTURE.md`，版本门禁看 `docs/ROADMAP.md`。历史 FR 保留用于追溯，不能把历史交付状态当成当前实现状态。

## 1. 背景与目标

JianArtifact 是一个**自托管、单二进制交付的多格式制品仓库**（artifact repository），用 Go 重写，面向中小团队与私有化 / 离线环境。它托管与代理常见包格式（Raw/Maven/npm 起步，逐步扩展到 Docker/Cargo/PyPI/Go/NuGet 等），并提供从 **Nexus OSS 平滑迁移**的能力，让已有 Nexus 用户零丢失地切换。

一句话价值主张：**一个二进制、开箱即用、可从 Nexus 迁移的轻量私有制品库**——默认无需外部数据库 / 对象存储 / 中间件即可跑起来，同时保留向企业场景（OIDC/LDAP、S3、多节点分发）演进的路径。当前发布版本为 `0.9.0`（真源是根目录 `VERSION`），主题是控制台体验收敛：布局口径、观测页性能、移动端响应式、时区与多语言。

### 非目标

- 不做公共 SaaS 制品托管平台（面向私有化 / 自托管）。
- 不追求首版即覆盖全部包格式；按路线图分期扩展（见 `docs/ROADMAP.md`）。
- 默认形态不依赖外部数据库、消息队列、对象存储；这些为后续期的**可选**增强，需 ADR。
- 不做 CI/CD 流水线、代码托管、制品构建——只做制品的存储、代理、分发与治理。
- MVP 不要求多节点高可用；0.7.0 的对等复制与 0.8.0 的级联只读复制均属历史交付并已整体退役（FR-138），搬迁改为以一致性备份包为传输单位（见 [`adr/0027`](adr/0027-package-based-node-backup-and-relocation.md)），不做自动选主、自动换父或实时复制。

## 2. 角色

- **管理员**：部署与运维实例、管理用户/仓库/ACL、执行 Nexus 迁移、配置代理上游与运行时。
- **节点搬迁执行者**：用一致性备份包完成实例搬迁（生成 → 传输 → 导入 → 重启替换 → 校验），不维护节点拓扑、水位或复制凭据。
- **开发者 / 消费者**：通过原生客户端（curl/mvn/npm 等）或管理端拉取、发布、浏览制品。
- **CI / 自动化系统**：以 API Token 鉴权，自动发布与拉取制品。
- **原生包客户端**：Maven、npm、curl 等按各格式协议与本系统交互，不感知本系统私有细节。
- **上游制品源**：被代理（proxy）的远程仓库（Maven Central、npmjs、Docker Hub 等）。

## 3. 用户故事

- 作为管理员，我希望首次启动即可经网页自举端点创建首个管理员账号（无需环境令牌），并在账号锁死时用 CLI 离线重置，以便零外部依赖地把实例跑起来并可恢复。
- 作为管理员，我希望把现有 Nexus OSS 的仓库与制品迁移进来（在线/离线/自有离线包三种来源），以便平滑切换且不丢数据。
- 作为开发者，我希望用原生 `mvn`/`npm`/`curl` 直接对接仓库发布与拉取，以便无需改变现有工作流。
- 作为开发者，我希望通过 group 仓库聚合多个 hosted/proxy，以便用一个地址取到所有依赖。
- 作为 CI 系统，我希望用 API Token 鉴权自动发布制品，以便无人值守地集成。
- 作为管理员，我希望按仓库设置可见性与读写 ACL，以便隔离不同团队的制品访问。
- 作为运维，我希望用单个二进制或一个容器就能部署、升级、备份与回滚，以便降低运维成本。

## 4. 功能需求（FR）

> 状态取值：计划 / 开发中 / 开发完成，待用户验收 / 开发完成，验收通过，待发版 / 已交付@vX.Y.Z。优先级：P1(MVP=M1) / P2 / P3。
> `开发完成，待用户验收` 表示实现及开发验证已完成，但尚未经过用户验收，不等同于交付或发布。标 `已交付` 是有门的：只有该 FR 的 §6 / spec 验收标准全部满足、对应测试 / 实机验收通过后，才由 `sdd-release-version` 在发版时统一标 `已交付@vX.Y.Z`——开发 / 修复过程中不得自行预标。具体版本落地见 `docs/ROADMAP.md`。
> `开发完成，验收通过，待发版` 表示规格、自动化与已要求的隔离环境验收均已通过，但尚未创建版本提交、tag、远程 CI 或 Release；不得写作已交付。
>
> 当前 `VERSION=0.9.0`（`0.9.0` 已发布，release 提交 + 附注 tag `v0.9.0`）；§4.5 起的后续窗口行只能表示计划或开发目标，里程碑（M3 等）与版本号解耦、待规划时确定。

## 5. 非功能需求（NFR）

- **NFR-01 单二进制 / 零外部依赖**：默认形态无需外部 DB / MQ / 对象存储；一个二进制或一个容器即可运行。
- **NFR-02 大文件与流式**：上传 / 下载 / 回源全程流式，不整体入内存；支持数 GB 级制品，内存占用与文件大小解耦。
- **NFR-03 并发**：同一制品并发拉取经 single-flight 合并，回源至多一次；并发上传 / 下载在设定阈值内稳定。
- **NFR-04 性能**：常规制品拉取 P95 延迟与缓存命中率满足发布基线（数值在 ROADMAP 各版实测冻结）。
- **NFR-05 磁盘 / 内存边界**：blob 存储与缓存有明确上限与清理策略；迁移大规模仓库时磁盘占用可预估。
- **NFR-06 安全**：口令 argon2 哈希；proxy 私有上游 `credentialRef` 仍只从 `JIAN_UPSTREAM_CREDENTIAL_<名称>` 运行时解析。online migration 可持久化已校验来源 URL；页面直填的 Basic/Bearer 凭据只以任务专用密文保存，密钥、明文、密文、Authorization 头、用户名和来源凭据均不得出现在 API 响应、草稿、报告、审计或日志；异步迁移任务仅可额外固化管理端发起人的用户名、稳定用户 ID 和认证来源，用于本地结果审计且不含令牌；出站访问逐跳与连接前重验 URL/DNS 并拒绝内网与云元数据地址；外部输入校验防注入与路径遍历；日志脱敏。
- **NFR-07 可维护性**：分层单向依赖、契约唯一真源、中文分级日志、静态分析警告即失败。
- **NFR-08 可移植性**：`CGO_ENABLED=0` 纯 Go；发布多平台（linux amd64 起，逐步 arm64 / Windows）。
- **NFR-09 兼容性**：与 Nexus OSS 3.70.x 三迁移路径兼容；与原生包客户端协议兼容。

## 6. 验收标准

整体"做完"的可验证判据，对齐测试；已知有实机 / 集成 / 真实环境维度的写成显式验收项并**须由用户确认通过**（测试绿不替代真的能用）。各版本的整期验收门在 `docs/ROADMAP.md` 逐版细化，此处为总纲：

- **AC-01（实机·须用户确认）**：原生 `curl` / `mvn` / `npm` 客户端对 Raw/Maven/npm 的 hosted+proxy+group 发布与拉取互通成功。
- **AC-02（实机·须用户确认）**：从真实 Nexus OSS 3.70.x 经三来源路径（在线 REST / 离线原生目录 / 自有离线包）迁移，制品与元数据零丢失、报告一致、可续传。
- **AC-03**：单二进制 / 单容器零外部依赖启动，`/readyz` `/healthz` 正常；管理员自举可用。
- **AC-04**：并发拉取 single-flight 合并、大文件流式的相关测试穷举通过（见 `testing-and-quality.md` §2）。
- **AC-05**：鉴权 / ACL 越权用例全部拒绝（401/403）；令牌 / 凭据不出现在日志与库中。
- **AC-06**：OpenAPI↔devmock 契约一致性检查通过；前后端据同一契约无漂移。
- **AC-07**：全部质量门（Go + 前端 + 供应链）在 Docker 与 CI 中同脚本通过。
- **AC-08（实机·须用户确认）**：Docker / Compose 部署演练成功，升级与回滚流程可执行。
- **AC-09（0.8.0 实机·须用户确认）**：搬迁以一致性备份包为传输单位完成一次真实演练——热备份生成 → 带签名的无登录下载（含 Range 断点续传）→ 导入（URL / 分片 / CLI 任一通道）→ 重启替换 → 校验（`pre-restore-<ts>/` 备份存在、`restore.pending` 已消费、仓库 / 制品 / blob 规模与基线一致）；写入冻结窗口覆盖「冻结 → 写入被拒 503 `write_frozen` → 读方法放行 → 解冻」；增量差包覆盖「基线缺失拒绝」与「基线齐备导入成功」。原级联树复制验收维度随 FR-138 退役（见 [`ADR-0027`](adr/0027-package-based-node-backup-and-relocation.md)）。

- **第一期（M1，MVP）**：可迁移的核心制品库——认证授权 + Raw/Maven/npm 三格式 + Nexus 迁移 + 单二进制交付与部署骨架。
- **第一点五期（M1.5，插入）**：体验优化与匿名访问——MVP 后的大优化版本（滚动收纳优化需求：匿名访问、登录与列表体验、搜索与浏览增强等）。
- **集群期（插入，0.7.0，历史）**：多节点复制引擎的双向对等能力已交付并由 0.8.0 FR-115 收敛为级联树；该级联模型随后随 FR-138 整体退役，当前不再存在复制通道与节点角色配置。
- **第二期（M2，已发布 0.8.0）**：高频格式扩展（Docker/Cargo/PyPI/Go/NuGet）+ 声明式格式启停 + 制品生命周期与统一原子制品操作 + 控制台（信息架构、审计中心、业务仪表盘、主机监控、页面缓存）+ **搬迁转向一致性备份包**（备份生成 / 写入冻结窗口 / 增量差包 / 导入三通道 / 签名下载）；实时复制通道按 FR-138 退役。

## 8. 术语表

- **hosted 仓库**：本地托管、可发布制品的仓库。
- **proxy 仓库**：代理远程上游、按需回源缓存的仓库。
- **group 仓库**：聚合多个 hosted/proxy 成员、对外呈现单一地址的虚拟仓库。
- **blob**：制品的二进制内容，按内容哈希寻址存储于文件系统。
- **single-flight（单飞合并）**：同一制品的并发回源请求合并为一次上游拉取。
- **Curation**：对制品的准入治理（黑白名单、命名空间隔离、最小发布年龄等）。
- **Hash Pin（完整性校验门）**：制品写入时钉住哈希、读取时校验、不匹配即拒。
- **digest 首见隔离**：代理首次见到的 digest 先隔离待校验，通过后才对外提供。
- **Nexus OSS**：Sonatype Nexus Repository OSS，本项目提供从其迁移的能力。
- **devmock**：前端浏览器 + Node 双端 Mock，据 OpenAPI 契约比对防漂移。
- **节点备份包**：搬迁与备份的传输单位，自包含归档（`manifest.json` + `VACUUM INTO` 快照 + `blobs.index` + 内容寻址 blob），包内只含数据不含密钥（见 [`adr/0027`](adr/0027-package-based-node-backup-and-relocation.md)）。
- **写入冻结窗口**：搬迁切换期临时停写的运行时有界窗口，业务与管理写入返回 503 `write_frozen`。
- **主备 / 级联复制（历史）**：0.7.0–0.8.0 曾交付的实时复制通道（唯一 primary 可写、逐跳拉取、水位与代次），已随 FR-138 整体退役；相关术语（直接父节点、relay standby、watermark、stream generation）仅用于追溯历史 FR 与规格。
