## 2. 历史交付

0.1.0–0.7.1 的交付事实和验收细节保留在 `CHANGELOG.md` 与对应 specs。0.7.0 曾交付全互联双向复制，但该模型已被 0.8.0 开发中的 FR-115/ADR-0023 收敛；新部署不得继续配置双向 peer、共享同步令牌或自动回填。

## 3. 当前 0.8.0 开发窗口

### 3.1 功能范围

- Docker/OCI、Cargo、PyPI、Go modules、NuGet 及其 Nexus 迁移扩展。
- 按格式启停、统一制品操作、可恢复 blob 回收和 v2 原子 operation。
- 发布账号防护、额度、不可变 Release 和完整认证审计。
- 主备安全收敛：唯一 root primary 可写；standby 只读；当前开发代码支持每个非根节点一个直接父节点、每个节点多个直接子节点的级联树。
- 逐跳父子复制凭据、relay 日志、根源连续序列和 stream generation；relay blob 当前保守保留，待子边确认回收门进一步完善。
- 管理控制台信息架构、当前节点审计、业务仪表盘、集群页面、级联邻接监控、当前主机监控、消息中心和页面缓存。
- Linux arm64 构建资产、声明式格式启停和 Windows 原生质量门。

### 3.2 级联树边界

```text
root primary
   ├── relay standby ── child standby
   └── relay standby ── child standby / relay standby
```

- 下级主动向直接上级发送认证 GET；上级不向下级推送。
- relay standby 只提供已经完整接收、校验和原子应用的根源流，不产生本地业务变更。
- 父节点只知道直接子节点；集群页面和监控只展示本节点及直接邻接边。
- 不做自动选主、自动换父、双主写入、全局拓扑控制或跨节点主机监控。

级联树核心与控制台 Mock 已完成开发实现，自动化覆盖四跳、多子边、逐跳凭据和直接邻接读模型；本地四进程初始传播、relay 重启续传和单 relay 双子节点已执行，浏览器和完整发布门仍未执行。详细目标见 [`specs/0.8.0-primary-standby-replication.md`](specs/0.8.0-primary-standby-replication.md)。

### 3.3 当前状态

当前 M2 的协议、迁移、制品生命周期、级联复制和控制台 FR 均已有对应工作区实现或既有交付实现；PRD 以“开发完成，待用户验收”区分尚缺真实证据的功能，以“开发完成，验收通过，待发版”区分已过现有自动化/隔离门的功能。测试通过不等于真实发布通过。

## 4. 0.8.0 整期验收门禁

### 4.1 质量和契约

- Windows 原生 `make check` / `scripts/check.ps1` 通过；包含前端格式、类型、lint、测试、构建、Go vet/lint/race/vuln、契约和静态构建。
- `api/openapi.yaml`、生成 Go 类型、前端 client 和 devmock 一致；生产构建不包含 Mock 数据或 Mock worker。
- 所有 0.8.0 新接口、配置、迁移和安全行为有对应 spec、测试和 CHANGELOG 记录。

### 4.2 制品与协议

- Raw/Maven/npm 及新增格式的原生客户端读写/删除语义经真实服务验收。
- 大文件始终流式；blob 哈希、引用计数、隔离回收和失败恢复一致。
- 统一资产操作和 operation envelope 不出现半批次、错误引用或不可恢复的 blob 删除。

### 4.3 复制和恢复

- root primary 唯一写入、standby 读和复制应用，standby 业务写入统一返回 `503 standby_read_only`；开启 relay 的 standby 可作为复制源。
- 级联实现：自动化已覆盖四层链路、一个 relay 挂两个直接下级；普通 change 与 operation 的根源身份一致，watermark 不跨未完成记录或 stream generation。
- 父子边凭据逐跳创建、导入、验证、撤销和轮换；跨边复用、越权、环路和能力不足均拒绝。
- 父节点、relay、子节点断网或重启后可恢复；人工提升/重新挂接先围栏、核验并生成新流代次，旧节点使用全新数据目录回接。
- 以上至少有后端单测、集成/竞态测试、真实多节点服务和浏览器证据；测试通过不替代真实级联验收。

### 4.4 控制台和运维

- 集群页面和集群监控只展示当前节点、直接父节点、直接子节点和各边健康；一个 relay 的多个子边失败彼此独立。
- 不显示令牌、环境变量、内部地址、原始错误、完整全局拓扑或跨节点主机指标。
- FR-120 仅验证当前实例主机 CPU、内存、磁盘、网络、进程和 `/readyz`，不从邻居采集数据。
- 真实 primary、relay standby、leaf standby、disabled 和未配对/离线场景分别完成浏览器复核。

### 4.5 发布

- 0.8.0 所有目标 FR 完成规格、自动化、必要真实服务/浏览器/真机验收后，才能创建版本提交、tag、远程 CI 和 Release。
- 版本提交之前保持 `VERSION`、PRD 状态、CHANGELOG 未发布段、制品校验和与实际状态一致。

## 5. 后续版本

- **0.9.0 / M3**：OIDC、LDAP、用户组、S3 可选后端、备份恢复、Prometheus、统一调度器、离线镜像 CLI、Helm/Kubernetes 增强和 Windows 发布矩阵。
