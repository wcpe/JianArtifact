# 版本路线图：JianArtifact

> 版本落地的**单一真源**：把 PRD §7 的分期（M1–M5）映射为从 `0.1.0` 到 `1.0.0-rc` 的具体版本。PRD §4 FR 表登记"做什么 + 状态"，本文登记"哪个版本交付什么 + 整期验收门"。每个版本发布均须过整期验收门禁（测试 + 真机证据）后，才由 `sdd-release-version` 把对应 FR 标 `已交付@vX.Y.Z`。

## M1 — 可迁移的核心制品库（MVP），跨 0.1.0–0.5.0

### 0.1.0 工程基座与契约骨架

- monorepo（pnpm workspace + Turborepo + Makefile + Go Task + go.work）；Docker 质量门；`api/openapi.yaml` 全域契约骨架 + `oapi-codegen` 接线；devmock 契约比对；单二进制 embed 打通。
- **部署骨架先落地可演练**：Dockerfile / docker-compose / .env.example / 远程部署脚本。
- 门禁：质量门在 Docker 与 CI 同脚本全绿；契约↔devmock 一致；`/readyz` 可探活。
- 状态：**已交付@v0.1.0**（五项验收门 AC-0.1.0-1~5 全部通过，详见 `docs/specs/0.1.0-foundation.md`）。

### 0.2.0 认证授权 + 管理端骨架

- 管理员自举、登录 / 会话 / 退出、API Token、CLI 鉴权、用户管理、口令修改 / 重置、仓库可见性 / ACL / 仓库管理。
- web 全页面对 devmock 完成、wiki 组件验收。
- 门禁：鉴权 / ACL 越权用例全拒（401/403）；令牌不入库不进日志。
- 状态：**已交付@v0.2.0**（FR-06–12 验收门全绿：鉴权/ACL 越权 401/403、令牌仅存 sha256 摘要不入库不进日志、契约↔devmock 一致；单二进制内嵌 web 真实后端联调冒烟 28/28 通过）。

### 0.3.0 三格式协议真连

- Raw / Maven / npm 的 hosted + proxy + group；通用能力（浏览、使用片段、健康检查 / 就绪自检）；single-flight + 大文件流式；内容寻址 blob + 校验。
- 门禁（实机·须用户确认）：curl / mvn / npm 原生客户端互通验收通过；并发与大文件测试穷举通过。
- 状态：**已交付@v0.3.0**（FR-13–19 验收门全绿：Go/前端测试全绿、e2e smoke 58/0、原生 curl/mvn/npm 互通真机通过）。

### 0.4.0 Nexus 迁移域

- 三来源发现（在线 REST / 离线原生目录 / 自有离线包）、计划预览、异步任务状态机、持久化与幂等续传、冲突策略、凭据安全、迁移报告、切换与最终增量扫描、迁移向导真连。
- Nexus drop-in URL 兼容与公开读入口（FR-24a）：路径同形、public 匿名读、group 聚合、管理端 URL/成员列、运维说明——让迁移后的客户端切换只改 host。
- 仓库页面与权限完善（FR-25a~e，对标旧项目）：ACL 用户下拉框、制品详情多校验和 + 依赖坐标、后端 HTML 目录索引、仓库统计、详情 Tab 布局——MVP 终态体验。
- 门禁（实机·须用户确认）：从真实 Nexus OSS 迁移，制品与元数据零丢失、可续传、报告一致；切换 host 后原生客户端经公开 group 仓匿名解析与拉取成功；管理端浏览/权限/详情体验完整可用。
- 状态：**已交付@v0.4.0**（FR-16a/24a/25a~e 验收门全绿：GHCR 镜像 e2e smoke 54/54、浏览器内嵌渲染登录/列表/详情通过、线上 tmp.wcpe.top 0.4.0 HTTPS 正常；迁移域功能完整但 AC-02 实机门转入 0.5.0 整期验收）。

### 0.5.0 M1 整期验收（首个稳定 MVP）

- PRD §6 全部验收标准通过；NFR 数值（大文件 / 缓冲 / 并发 / 内存 / 磁盘 / 迁移规模）实机达标并冻结基线；真实 Nexus OSS 3.70.x 三路径验收通过。
- 迁移执行：离线目录直读 55,325 资产从 5 hosted 仓零丢失迁入；npm-release（源为空）确认无资产；17 maven proxy + 1 maven group(`maven-public`) 重建并公开匿名读可用。
- 门禁：M1 全部 FR 经 `sdd-accept-phase` 整期验收通过后统一标 `已交付@v0.5.0`。
- NFR 基线（实测冻结 2026-07-25）：
  - NFR-02 大文件流式：cold 2.7ms / warm 2.4ms（3.7MB jar，localhost）
  - NFR-03 并发 single-flight：10 并发 max 17.5ms（同一 3.7MB jar）
  - NFR-04 拉取 P95：P50 0.76ms / P95 0.97ms（4.8KB jar，20 次连续，localhost）
  - NFR-05 资源边界：RSS 19.3MB / 数据目录 6.4GB / 磁盘占用 47%（55k 资产稳态）
- 状态：**已交付@v0.5.0**（AC-01 原生客户端 drop-in HTTPS 全 200、AC-02 逐仓计数精确匹配 + 抽样 sha256 字节一致、AC-08 二进制升级/回滚 ~1s 探活通过、NFR 基线冻结）。

## 集群与高可用 → 0.7.0（插队）

- 内置多节点复制引擎（主从 / 多主制品库）：双向同步（主↔备），主写 + 备临时写；全量数据（制品 blob+元数据 + 仓库 + 用户 + ACL + 令牌 + 配置）；冲突全数据 last-writer-wins；删除双向同步（tombstone）；实时增量（事件驱动）+ 首启全量初始化。
- **复制通道全部走 GET 拉取（pull），禁止 PUT 推送**——规避 Cloudflare Tunnel / CDN 上传体积限制（下载不受限）；备→主直连、主→备经 Tunnel 域名。
- 自动失效切换由部署层实现（DNS 健康检查，复用 `/readyz`），应用内不做自动切换代码。
- 覆盖 FR-83~~100、FR-102~~103；前置：ADR-0013 多节点复制架构决策。
- 复制接收审计记录独立于 `repl_change`：按来源节点与全局序号幂等合并，保留失败证据，管理员可查询应用结果与重试状态。
- 门禁：三节点部署（103/108/124，三个公网域名）实测通过：双向上传/删除同步一致、100 MiB+1 blob 完整校验、blob 只传缺失、首启全量初始化、断网恢复自动补齐；同步全程无 PUT；复制接收审计状态与来源记录可查询且契约一致；CDN/Tunnel 对外 URL 不泄露源站 IP。
- 状态：**已交付@v0.7.0**（Windows `make check` 全绿、GitHub Actions `Release` 质量门/构建资产/镜像/预览发布 5/5 全绿；三节点实机验收结果已纳入 `CHANGELOG.md`）。

## M2 — 高频格式扩展 + 制品生命周期与工程能力 → 0.8.0（顺延）

- Docker/OCI（hosted/proxy/group）、Cargo sparse registry、PyPI、Go modules proxy、NuGet；上述格式的 Nexus 迁移扩展。
- 新增（对标 NORA）：声明式按格式启停（未启用格式零路由零后台任务、缩小攻击面）；arm64 Linux 二进制。
- 制品生命周期与集群：节点全库引用计数线性化、可恢复 Blob 回收、统一原子操作、格式感知删除和携带清单的 operationId 原子复制；对端不暴露半批次，冲突整批解决。
- 发布账号防护：仓库级不可变 Release、可选路径前缀与额度、可禁 Web 登录、协议账号密码兼容、私有上游凭据引用及完整认证身份审计。
- 前置门禁：0.7.0（集群）发布。
- 门禁（实机·须用户确认）：各格式原生客户端互通；三节点目录删除/Raw 移动与格式 metadata 原子复制、断网恢复和共享 blob 回收；所有远程协议凭据仅经有效 HTTPS 与可信反向代理协议使用，Web JWT 不得作为协议发布凭据；发布受限账号不得登录 Web/管理 API 且不能覆盖/越前缀，额度在并发发布下不被绕过；Docker/Cargo/PyPI/NuGet 私有上游凭据、online migration 的 opaque sourceRef 与出站安全策略均不泄露秘密，来源解析可在重启后安全恢复；Linux arm64 同一 Release 资产在原生 runner 与真实设备可启动。

## M3 — 企业认证、存储与运维 → 0.9.0（顺延）

- OIDC、LDAP；用户组与更细粒度权限动作；S3 兼容对象存储后端；审计日志与 Prometheus 指标；备份与恢复；GC / 保留策略 / 配额 / 存储清理；出站代理与受控运行时管理（含热重载）。
- 新增（对标 NORA）：上游断路器；定时任务调度器；离线镜像 CLI（`mirror`）；存储后端迁移 CLI（local↔S3）+ `integrity verify` 离线全量校验；Helm Chart + K8s 清单；Windows 二进制。
- 说明：S3 后端与外部化存储须先立 ADR 再实现；Helm/K8s 采单实例 RWO 卷 + `Recreate`。

## M4 — 安全、供应链与运营可见性 → 0.10.0（顺延）

- 多维限流、连接 / 并发限制、慢请求防护；IP 名单、异常检测、应用层防护；本地漏洞库镜像与坐标匹配；Docker 镜像层扫描；使用分析、容量趋势、缓存命中率与运维告警。
- 新增（NORA 免费、Nexus 付费的核心差异化）：Curation 内容治理链（blocklist/allowlist + namespace 隔离 + 最小发布年龄，enforce/audit 双模式、fail-closed）；完整性校验门（Hash Pin）+ 代理 digest 首见隔离；cosign 签名策略（上游拉取验签，不通过则阻断）。

## M5 — 长尾格式与成熟期能力 → 0.11.0（顺延）

- RubyGems、Conan、Terraform、Ansible Galaxy、Dart/Flutter Pub 等长尾格式；高级虚拟仓库策略与跨成员 metadata 聚合；多节点只读扩展或 HA 可选方案（先独立 ADR）；外部数据库 / 分布式存储可选方案（不破坏默认轻量形态）。
- 新增（对标 Nexus）：deb/rpm（apt/yum）Linux 系统包仓库；Webhooks（制品事件通知）+ 仓库内路径路由规则 / content selector。

## 发布候选 → 1.0.0-rc

- 全格式与迁移兼容矩阵回归；文档 / 运维 / 升级手册完善（含从任意 0.x 升级路径的 migration guide）；semver 契约冻结（API / 配置格式 / 存储布局稳定保证）；`integrity verify` 全量制品校验通过；性能与安全基线冻结；长跑稳定性验收通过后发 `1.0.0-rc`，为正式 `1.0.0` 铺路。

## 产品供应链（贯穿全期）

- release 产物签名（cosign / 校验和）+ 生成 SBOM + 接入 OpenSSF Scorecard（FR-63）。
- 对协议解析 / 路径校验等入口做 Fuzz 模糊测试并纳入 CI 门禁（FR-64）。
- 多架构 / 多平台发布矩阵（arm64 + Windows）产物经校验。

## 与参考项目的架构差异声明

NORA 采「文件系统即真源、无数据库、启动重建内存索引」；JianArtifact 定 **SQLite 元数据真源 + 文件系统 blob**（向前追加迁移，见 ADR-0002）。二者各有取舍，本项目不重开此决策，仅在 ARCHITECTURE 标注对比。

> 版本粒度原则：M1 因体量大跨 5 个 minor（0.1.0–0.5.0）；M1.5 为插入的体验优化期（0.6.0，滚动收纳）；M2–M5 各占 1 个 minor（0.7.0–0.10.0）。后续如某期过大，可在 PATCH / 额外 minor 细分并更新本路线图，整体主线仍收敛到 1.0.0-rc。
>
> 发布门禁与版本窗口：正式发版必须验收通过才打 tag；发版后立即开启下一版本开发窗口。详见 `.claude/rules/release-and-version-window.md`。
