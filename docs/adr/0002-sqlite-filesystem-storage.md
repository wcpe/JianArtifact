# ADR-0002：元数据用纯 Go SQLite、制品内容用文件系统 blob

## 状态

已接受

## 背景

制品仓库需持久化两类数据：结构化元数据（仓库、组件、版本、ACL、迁移任务状态等）与体积可能很大的制品内容（jar / tarball / 镜像层等）。默认部署形态要求零外部依赖、单二进制可跑。对标项目 NORA 采用"文件系统即真源、无数据库、启动重建内存索引"的路线，需就本项目取舍做出决策。

## 决策

- **元数据真源**：`modernc.org/sqlite`（纯 Go 实现，**无 CGO、无系统级 C 依赖**），经 sqlx 访问。
- **制品内容**：落**文件系统 blob**（内容寻址），元数据中仅存引用与校验和。
- 二者以"元数据事务提交 + blob 落盘校验"协同，向前只追加迁移。

## 理由

- `modernc.org/sqlite` 保持 `CGO_ENABLED=0` 静态编译与交叉编译能力（支撑 ADR-0001 / ADR-0005），无需外部数据库进程即获得事务、索引与并发查询能力。
- 元数据用关系型真源，使 ACL、迁移任务状态机、幂等续传、跨仓库检索等以事务与索引表达，比"启动重建内存索引"更省内存、查询更灵活、崩溃恢复更明确。
- 大文件走文件系统流式读写，避免整体入内存（性能不变量）。

## 后果

- 正面：单进程零外部依赖即具备事务与检索；元数据与内容职责清晰；备份可分别处理 DB 与 blob 目录。
- 负面 / 约束：SQLite 单写者模型限制极端写并发，需以合理事务粒度与队列化写入应对；高可用 / 外部数据库为 M5 之后的可选 ADR，不破坏默认轻量形态。与 NORA 的"无 DB"路线是**有意分歧**，仅在 ARCHITECTURE 标注对比，不重开。

## 备选方案

- **NORA 式无数据库 + 启动重建内存索引**：部署更简，但大规模元数据的内存占用、复杂查询与崩溃一致性弱于 SQLite，落选。
- **默认内置外部数据库（PostgreSQL 等）**：并发与规模更强，但违背零外部依赖的默认形态，降级为可选后端。
- **CGO 版 SQLite（mattn/go-sqlite3）**：成熟但引入 C 工具链，破坏纯静态交叉编译，落选。
