# ADR-0005：前端产物经 Go embed 内嵌，单二进制交付

## 状态
已接受

## 背景
产品定位为自托管、易部署的制品仓库。若前后端分离部署（Nginx 托管静态资源 + 反代后端），会增加部署组件与运维复杂度，与"简单优先、零外部依赖"目标相悖。

## 决策
前端 `pnpm build` 产物在后端构建时经 **Go `embed`** 内嵌进 `apps/server`，与后端一起 `CGO_ENABLED=0` 编译为**单个静态二进制**交付。

## 理由
- 单二进制携带前端资源与后端逻辑，部署即"放一个文件 + 一份配置 + 数据目录"，无需额外 Web 服务器。
- 与 ADR-0001 / ADR-0002 的纯 Go 静态编译一致，产出可跨平台分发的自包含制品。
- 容器镜像可基于 `distroless/static` 最小化，攻击面小、体积小。

## 后果
- 正面：部署与升级极简（替换二进制）；开发与生产资源来源一致；容器镜像精简。
- 负面 / 约束：前端产物更新须重新编译后端二进制；构建顺序耦合（先前端 dist 后 Go embed，`task build` 固化此序）；embed 的 dist 目录纳入 `.gitignore`，不入库。

## 备选方案
- **前后端分离部署 + Nginx 静态托管**：灵活但增运维组件，违背简单优先，落选。
- **CDN / 对象存储托管前端**：引入外部依赖，与自托管零依赖定位冲突，落选。
