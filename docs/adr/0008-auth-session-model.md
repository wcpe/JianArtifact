# ADR-0008：认证会话模型（网页自举 + 无状态 JWT + Token 摘要）

## 状态

已接受

## 背景

0.2.0 落地认证授权核心，需就以下取舍定死实现口径：首个管理员如何创建、会话如何表达与撤销、机器凭据（API Token）如何存储、口令如何哈希。约束：单二进制零外部依赖（无 Redis / 外部会话存储），凭据明文不落库不进日志（NFR-06），且需支持账号锁死后的离线恢复。原设计以 `JIAN_BOOTSTRAP_TOKEN` 环境变量引导首个管理员，本 ADR 一并记录改为网页自举的决策。

## 决策

- **管理员自举**：改为网页自举端点 `POST /api/v1/auth/bootstrap`，仅当 `user` 表为空时开放，直接接收用户名 + 口令创建首个管理员并返回会话；已初始化实例恒返回 409。去除 `JIAN_BOOTSTRAP_TOKEN` 环境变量。另提供 CLI `admin reset` 离线直连 SQLite 创建 / 重置管理员，用于锁死恢复。
- **会话**：无状态 JWT HS256（`golang-jwt/jwt/v5`），密钥取 `JIAN_JWT_SECRET`，缺省时从 data 目录 `jwt.secret` 读取 / 生成并持久化并告警一次。登出把当前会话 `jti` 记入 `revoked_token` 表直至其过期，鉴权时按 `jti` 与过期时间拒绝复用。
- **API Token**：随机明文（前缀 `jat_`）仅签发时返回一次；仅存 sha256 摘要于 `api_token` 表，鉴权按摘要查表。
- **口令**：argon2id（`golang.org/x/crypto/argon2`），参数固定并随哈希编码（`$argon2id$...`）存储。
- **鉴权中间件**：`Authorization: Bearer` 统一解析（先试 JWT，再试 Token 摘要），注入 principal；公开端点为 `/auth/{bootstrap,login}` 与健康 / 状态端点，其余需认证。

## 理由

- 网页自举消除"环境变量令牌 + 首启口令"的双通道复杂度与泄漏面，契合未来首启 web 设置页的单一入口；`user` 表为空的门禁天然幂等且可 409 关闭。
- 无状态 JWT 不需外部会话存储，契合零外部依赖；登出的即时撤销用小体量 `revoked_token` 黑名单弥补无状态的固有短板，条目随过期失效，规模可控。
- Token 仅存摘要 + 明文一次性返回，满足 AC-05 / NFR-06；argon2id 为口令哈希当前推荐算法。

## 后果

- 正面：单进程即可完成自举、登录、登出撤销与机器鉴权，无外部依赖；凭据不以明文落库。
- 负面 / 约束：`revoked_token` 需周期清理过期条目（本轮查询时按过期过滤，定时清理留后续）；JWT 密钥自动生成仅便于开发，生产必须显式配置 `JIAN_JWT_SECRET`（见 OPERATIONS）；无状态 JWT 无法在单个令牌过期前逐个吊销之外做更细的会话管理。

## 备选方案

- **服务端有状态会话（DB / Redis session）**：撤销即时且精细，但引入外部存储或膨胀写入，违背零依赖默认形态，落选（仅保留登出黑名单这一最小状态）。
- **保留环境变量引导令牌**：实现简单，但多一条凭据通道与泄漏面，且与未来 web 设置页入口重复，落选。
- **API Token 明文加密存储（可解密）**：可回显明文，但违背"明文仅一次"与最小泄漏面原则，落选（采不可逆摘要）。
- **bcrypt / scrypt 口令哈希**：可用，但 argon2id 抗 GPU / ASIC 更优且已在依赖树，选 argon2id。
