# ADR-0026：级联树逐跳拉取凭据的密封存储与轮换

## 状态

开发完成，待用户验收（v0.8.0 尚未发布；本开发窗口直接修订本 ADR）。本 ADR 约束 ADR-0023 级联树中每条父子边的复制凭据，并取代共享 `JIAN_SYNC_TOKEN` 的配置与存储方式。

## 背景

级联树不再只有 primary 向 standby 提供复制源，任何启用中继能力的 standby 都可能向自己的直接下级提供已经校验的复制数据。共享长效令牌无法表达“只允许访问相邻边”的权限，也无法在不影响其他分支的情况下撤销某一个子节点。

复制仍不是管理 API，也不是业务写入通道。下级只需要读取直接父节点的能力、变更流和缺失 blob；它不需要、也不得获得父节点的管理、协议发布或业务写权限。

## 决策

### 1. 凭据按父子边逐跳创建

每个父节点只为自己的直接下级创建、验证、撤销和轮换凭据：

- 根 primary 为直接 relay/leaf standby 创建凭据；
- 启用中继能力的 standby 为自己的直接下级创建凭据；
- 父节点不需要知道孙节点，凭据不会跨层转发或复用；
- 同一个 node ID 在同一个父节点上最多保留一个当前凭据和一个待验证替换凭据。

凭据绑定直接父节点的稳定 node ID、子节点稳定 node ID 和父节点基址；复制流 generation 由能力协商与 record 校验绑定到该边的 watermark。子节点更换父节点、父节点被提升或复制流 generation 变化时，旧凭据和旧 watermark 均不得继续使用，必须重新配对。

### 2. 最小 GET 权限

凭据只允许访问直接父节点的三类复制 GET：能力协商、v2 records 拉取和按哈希流式拉取 blob。任何管理 API、协议端点、业务读写、非白名单 GET 和所有非 GET 请求都拒绝。

父节点即使是 relay standby，也只提供自己已完整接收、校验并原子应用的连续上游数据；凭据不会解除 standby 的业务只读栅栏。

### 3. primary 摘要、子节点密封

父节点数据库只保存凭据标识、绑定 node ID、随机盐、不可逆验证摘要、创建/撤销/轮换状态和安全审计信息，不保存可恢复明文。子节点通过本地 CLI 从标准输入导入一次性令牌，并使用本数据目录独立的 AES-256-GCM 密钥密封保存。

令牌明文不得进入命令行参数、环境变量、Web/API、日志、审计详情、复制载荷、截图或备份明文。复制凭据密钥不复用 JWT 或迁移凭据密钥，也不得克隆到其他节点。

### 4. 本地 CLI 配对和轮换

每条父子边通过本地 CLI 完成：子节点初始化稳定 node ID，父节点为该 node ID 创建凭据，子节点导入并验证，然后才启动该边的拉取调度。轮换时先创建替换凭据，在子节点验证成功后再撤销旧凭据。撤销或绑定校验失败时，子节点保持只读服务但停止该边拉取，watermark 不推进。

不增加 Web 配对页面、不通过跨节点 POST 交换秘密、不允许运行时管理页面编辑父子拓扑。父节点本地管理员只能管理直接下级的凭据，不能通过该凭据管理下游节点。

## 理由

- 逐跳凭据让每条父子边可独立撤销和轮换，避免一条分支泄露影响整个树；
- 将 relay 能力限制为复制源 GET，不会把只读备用节点变成业务写节点；
- 保持本地 CLI 一次性交付秘密，不引入新的公开配对面或外部密钥服务；
- 与 GET-only、CDN/Tunnel 兼容和单二进制、零外部依赖边界一致。

## 后果

- relay standby 也需要本地凭据摘要仓储，但只能创建直接下级凭据；
- 重新挂接、人工提升和流 generation 变化都要重新配对，不能依赖旧凭据自动续接；
- 每条边都必须记录认证失败、watermark 和轮换状态，集群监控只展示直接邻接边；当前子边上报为有界内存态，持久 relay 日志保护源 record/blob；
- v0.8.0 开发版不再把 `JIAN_SYNC_TOKEN` 作为运行期兼容回退，旧环境迁移必须先完成逐跳凭据配对。

## 备选方案

- 全树共享一个同步令牌：无法按分支撤销，且权限范围过大，否决。
- primary 保存全局所有下级凭据并向下分发：破坏“只知道直接邻接节点”的边界，否决。
- Web 页面跨节点交换凭据：新增公开配对面和跨节点写通道，否决。
- 外部密钥管理或协调器：超出当前单二进制、零外部依赖范围，否决。
