# ADR-0028：仓库别名与重命名的语义

## 状态

已接受（0.9.0，待用户验收）。

## 背景

仓库此前只能按 `repository.name` 单名访问：这个名字既是仓库的身份，也是唯一入口。这带来两个问题：

- **重命名会断链。** 直接 `UPDATE repository SET name = ?` 会让既有客户端坐标（`settings.xml`、`package.json`、CI 脚本里的 URL）与历史链接全部失效，而这些客户端往往分散在运维不可控的下游。
- **一个仓库需要多个入口名。** 迁移切换期（旧 Nexus 名与新名并存）、团队改名、产品别名等场景，都希望同一个仓库能被多个名字等价访问。

关键约束：仓库名在协议路由（Raw/Maven/npm/OCI/Cargo/PyPI/Go/NuGet）与管理端 API 全域都作为路径参数出现，按名取仓库若不在单点收敛，每加一处取仓库的代码都要各自处理别名，迟早分叉。

## 决策

1. **别名是独立表 `repository_alias`**（`alias` 主键 → `repository_id`，随仓库 `ON DELETE CASCADE`），一个仓库可有多个别名。
2. **别名与主名共享命名空间、全局唯一**：别名不得撞任何主名，也不得撞其他别名，也不得等于自身主名；服务层校验，`alias` 主键是最后一道 DB 兜底。
3. **按名解析收敛在单点**：`RepoRepo.GetByName` 先查 `repository.name`，未命中再经 `repository_alias` 解析到所属仓库，**返回的始终是主名仓库**；别名只是访问入口，协议路由与管理端 API 全域因此都能用别名等价访问主名仓库。
4. **重命名 = 改主名 + 旧名转别名（同一事务）**：`POST /api/v1/repositories/{name}/rename` 成功后，旧名登记为该仓库的别名，旧链接与既有客户端坐标仍可解析；不做 404，也不做改名重定向。
5. **历史数据不回填**：`audit_log`（`repo` / `entity_key`）与 `asset_download_minutes.repo` 保留访问当时写入的旧名，不改为新名。
6. **下载统计在查询层按"主名 ∪ 别名"聚合**，而非改写历史行。

## 理由

- **共享命名空间 + 全局唯一**：别名与主名同为路径参数，语义上是同一张名字表。若允许别名撞主名或互相撞，`GetByName` 就会对同一个名字得到两个答案，解析无法确定。让 `alias` 主键承担唯一性是零成本的一致性兜底。
- **别名展开只在单点**：`GetByName` 是唯一按名取仓库的汇聚点，别名只在此处展开，协议与领域服务无需感知别名的存在——改动面最小，语义全局一致。
- **旧名转别名而非 404 / 而非重定向**：旧名仍应是有效入口。相比"改名后保留一张 301 重定向映射 + 额外判定逻辑"，把它建模成"一次额外的别名登记"完整复用了别名机制，不引入新概念，且对非 HTTP 的协议坐标（POM 里的坐标引用、脚本里的仓库名）同样生效。
- **不回填历史**：审计与下载计量记录的是"当时发生了什么"的事实；改写历史会让审计失去证据价值。而旧名已成别名，按旧名仍能解析到仓库，检索与追责都不受影响。
- **查询层聚合**：下载明细按请求路径里的名字落库，经别名访问或重命名前的下载会记在别名/旧名下。若统计只按主名查会漏算这一部分，因此查询侧按"主名 ∪ 别名"全集聚合；选择改查询而不是改数据，与"不回填历史"同源——历史行保持原样。

## 后果

- **正面**：重命名不再断链；一个仓库可被多个名字等价访问；按名解析语义集中在一处，可独立测试。
- **负面 / 后续约束**：
  - 别名与主名共用一个命名空间，创建别名与重命名都必须做**全局占用检查**，冲突返回 `409`。
  - 经别名访问时，凡按"URL 里的名字"落库的位置（审计、下载计量等）会记下别名而非主名；任何按仓库维度做统计或检索的代码，都必须按"主名 ∪ 别名"全集处理，不能只按主名，否则会漏算。
  - 别名不参与身份：解析结果始终是主名仓库，主名才是仓库的唯一身份。
  - 别名随仓库删除级联清理，不留悬空别名。

## 备选方案

1. **只有主名，重命名直接改（现状）**：会导致既有客户端与历史链接断链。落选。
2. **重命名后旧名做 301 重定向**：需要额外的重定向映射表与路径改写逻辑，且对非 HTTP 的协议坐标无意义；把旧名登记为别名可覆盖全部访问链。落选。
3. **回填历史数据**（把 `audit_log.repo` / `entity_key`、`asset_download_minutes.repo` 改为新名）：改写审计与统计的历史事实，且需要一条不可逆的回填迁移。落选。
4. **别名允许跨仓库重复**：同一名字会有歧义，`GetByName` 无法确定返回哪个仓库。落选。
5. **下载统计只按主名查**：会漏掉经别名发生的下载，统计偏低。落选（改为查询层按"主名 ∪ 别名"聚合）。
