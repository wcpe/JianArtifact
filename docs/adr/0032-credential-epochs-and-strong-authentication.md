# ADR-0032：凭据代次、受控管理员认领与强认证

## 状态

已接受（用户已批准正式规格）；待分批实现，不代表凭据撤销和强认证已生效或上线。

## 背景

[当前架构](../ARCHITECTURE.md) 已有本地、OIDC、LDAP、管理和各协议身份；管理中间件仍可接受 Basic、JWT、API Token，改密不会统一撤销旧代身份，初装和旧管理员认领不能继续以口令作为唯一证据。仅改变登录页面或由身份源声明 MFA 无法约束独立服务入口和在途业务。

### 提议的取代范围

- [ADR-0008](0008-auth-session-model.md)：取代无票网页自举、CLI 重设后凭口令取得管理会话、无状态 JWT/仅 `jti` 撤销、管理端兼容 API Token 身份的决策。保留 JWT HS256 传输封装、argon2id、机器秘密不可逆摘要与一次展示、单二进制部署。
- [ADR-0015](0015-protocol-authentication-and-credential-references.md)：部分取代第 1、2、8 项对长期协议口令或原有 Token 资格的承诺，口令仅为过渡，现有原生载体继续支持有用途限制的机凭据；Web JWT 仍不是原生协议凭据，协议 TLS 校验、`web_login_disabled` 的管理限制、发布额/前缀/不可变与上游约束不放松。审计采集语义由 [ADR-0031](0031-trusted-security-events.md) 扩展。
- [ADR-0029](0029-external-identity-providers.md)：更新第 1、5 项的签发前提/自举恢复和后果中的已签发 JWT 失效边界；保留单一签发职责、安全绑定、严格证书校验、环境凭据与本地兜底。外部身份只是一级来源，不新增远端联合撤销保证。

## 决策

1. JWT 作为签名载体，SQLite 会话记录、账号代次及限定用途的机器凭据作为实时授权输入；另取库外安全时代（[ADR-0033](0033-incident-restrictions-and-recovery-gate.md)）。改密、停用、事故封禁、影响授权的资格收窄和因子重置原子提升代次，解禁不复活旧身份。
2. 管理授权基于交互会话；机器 Token 的用途、仓库、路径、动作、期限和实时 ACL 取交集，不能签发同等凭据、登记因子、处置或审批。保留 Basic 携带机器 Token/Bearer/Cargo 通道，不保留 MFA 管理员用口令原生发布的旁路。
3. 本地/LDAP/OIDC 经过共同会话签发门。管理员必须本地 TOTP，普通用户自愿启用。限定用途、短期、限尝试、单效的挑战不是普通会话；恢复码和 TOTP 接受步通过事务原子消耗，不在日志保留秘密。
4. 首装与旧管理员认领必须经具有目标实例 OS 权限的受控本机 CLI（或适用于旧/新管理员、由已有强认证管理员批准）的专用一次性票。第一因素不够；票不签通用会话。因子恢复经受限挑战，旧因子、旧码、会话和相关旧代凭据失效。
5. 敏感操作以近期 MFA 加绑定操作者、目标版本、内容摘要与期限的单次确认。最终事务复核当前身份/授权、代次和目标，所有普通管理写也受事故锁同序约束；异步发布使用不可变原发起来源与信任状态重判当前规则，未知则暂停，禁止代用 system/worker 地址或历史允许结果。成功事件与状态同事务。
6. 新安全时代本身不证明旧口令、启停、角色、绑定或因子有效；按 [FR-168 恢复裁决](../specs/security-incident-controls.md) 核实或受控重建。旧挑战、确认、QQ 映射及待提升授权默认失效，不给旧流程补发新时代授权。

## 理由

- 保留面向客户端的 JWT 封装和协议载体，同时消除仅查签名、仅查一次入口或只按凭据到期无法及时撤销的问题。
- 管理身份与机器发布用途分开，防止把第二因素仅包装为页面限制；真实发布事务可以按当前 ACL 和事故边界拒绝迟到任务。
- 已泄露口令可能是事故起点，不能拿来证明第一个可信管理员。受控本机操作在身份源或因素不可用时保留人工兜底，但不重新开放无因素管理会话。
- 单 SQLite 的状态和审计原子性比外部会话库更匹配单实例约束；代次复核避免每次逐条遍历撤销所有凭据。

## 后果

- 客户端需在批准窗口换发受限机器凭据；原自动登录/发证、管理自动化和原生发布客户端必须逐一验证，不能默认兼容。强制切换后不再回退无代次授权。
- 需要受控本机权限和独立用途密钥，可能需要服务停写与管理员引导。等待任务授权过期会暂停而不是偷偷使用 system，这一可用性代价需要产品显示。
- [FR-166](../specs/security-credential-lifecycle.md)、[FR-167](../specs/security-two-factor-authentication.md) 是状态、范围、挑战和预算的规格真源；恢复隔离和快照详见 FR-168，不在本 ADR 重复建模。
- 接受与实现之后仅更新旧 ADR 状态/取代链接，保留历史正文并同步架构、权限契约和验收边界。

## 备选方案

- **保留无状态 JWT，缩短 TTL**：缩小影响但不实现及时撤销，仍不能裁决在途提交。
- **要求页面输入 TOTP、保持管理 Basic/普通 API Token**：通道特性未改，不能产生无旁路的安全保证。
- **首次或恢复只验证现有口令；接受外部 MFA 声明**：未证明本地认领控制权或当前本地因子，无法满足管理安全边界。
- **依赖 Redis 或外部联合会话/吊销**：额外可用性和部署成本，不解决本地最终提交一致性或旧库回滚，排除。
