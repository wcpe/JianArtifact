# ADR-0033：持久事故隔离、证据保全与恢复安全闸

## 状态

已接受（用户已批准正式规格）；待分批实现，不代表事故隔离、保全和恢复安全闸已生效或上线。

## 背景

[当前架构](../ARCHITECTURE.md) 依靠 `FreezeController` 为搬迁提供短窗口，使用一致性包和重启替换库；内容寻址字节受引用和物理回收协调器管理。事故存在另一种生命周期：隔离不能随时限/重启消失，调查需要保字节，旧包不能复活凭据、开放对象或取消事故处置。

### 提议的取代范围

- [ADR-0027](0027-package-based-node-backup-and-relocation.md)：扩展第 3 项只含公开资产引用的包边界（证据另需保全清单与受控转移），取代第 4、5 项中既有签名下载票/重启替换即可继续服务的前提。票必须受恢复时代约束；替换完成仍须过安全闸。保留包机制、差包、密钥/本地配置不随包、pre-restore 保留与复制退役。
- [ADR-0024](0024-atomic-physical-blob-reclamation.md)：将物理回收的“归零”扩展为业务和安全引用都归零；隔离和访问是不同裁决。无安全引用时仍采用协调回收；提交后不得逆转成功的修正由 [ADR-0031](0031-trusted-security-events.md) 给出。
- 保留 FR-135 及 [当前架构](../ARCHITECTURE.md) 的有界搬迁冻结，有独立持久事故限制及显式安全出口；搬迁窗口不得成为无限事故锁，也不能让安全处置失效。

## 决策

1. 单实例以 SQLite 保存有版本的事故限制、处置动作与证据保全引用。作用于稳定凭据/账号/仓库/路径/版本/实例，或有明确动作范围的 IP/CIDR；默认不由于搬迁、重启、超时自动解封。只有明确设限的 IP 规则可按时间失效。
2. 安全动作须近期 MFA、预览、绑定动作/版本/摘要的确认及审计。写锁下仅允许指定安全动作和必要强认证；事故写锁与所有最终业务写同序，含资产以及 ACL、仓库可见性、别名/group 等普通管理写。这些管理操作不得绕过目标隔离，不要求重扫合法存量。异步发布必须按保存的可信发起 IP 重判当前规则，未知不代入 worker IP。
3. 保全、业务归零、GC、直接删除备用路径、候选清理、启动与快照收尾共享摘要删除预约，从查询引用计数之前持有至实际不可逆完成或核实补偿稳定；预约未决不返回 `present`。保全不是下载授权。本期隔离针对明确目标；候选硬失败不连坐同摘要独立合法引用；同一受限引用不得借别名、group 或摘要旁路。
4. 库外持久恢复闸、节点身份、切换栅栏和单调 `securityEpoch`。源最新性必须核对 `sourceNodeId/securityEpoch/securityStateVersion/cutoverFenceId` 与当前排空的源一致，且源在同一栅栏持久封存；单纯检查点签名不证明最新。源随后新增撤销/保全使旧检查点失效；无法证明当前封存则隔离。一个栅栏只允许一份源端库外持久、不可换目标的转移授权，重签仅重发原授权；目标取消与消费是其库外不可回滚的互斥终态，源只接受与唯一授权全部绑定精确匹配的取消回执后才可重建栅栏。
5. 替库前须关闭当前进程入口、排空或取消在途写/GC 并确认没有迟到提交，再持久关闭库外恢复闸、推进时代并替换。重启并非排空；启动在对外监听/后台发布/回收之前读闸，状态不一致或重入失败仍隔离。
6. 新时代不复用旧 JWT/机凭据/票/确认及待提升授权；按 FR-168 恢复裁决表核实当前账号启停、口令版本、角色、因子及访问状态或受控重建。QQ 映射须重新按当前身份与强认证绑定，不恢复旧意图。没有当前可信记录则保持隔离并重建或拒绝未知范围；仅经当前强认证审核并持久确认，才恢复获准范围的公网、GC 和后台发布。

## 理由

- 持久事故限制和有时限的维护窗口解决不同问题；指定安全出口可在止损时继续撤销与保全，又不让管理写随意绕闸。
- 从最终事务裁决先后才能解释竞态结果；不承诺撤回已经提交或已下发给客户的字节。
- 以证据持有扩展引用比复制全部对象或封死共享摘要更精确；区分保全与读取可以同时阻止证据丢失和下载旁路。
- 恢复包只提供过去一致性；库外时代和可信检查点才可能证明现在的限制，缺证时优先安全而非自动可用。

## 后果

- 恢复可能比旧流程停机更久；失去当前证据的部署需本机重新认领和逐项核对。单实例不承诺两个 DB 同时在线，也不承诺本地资料抵抗主机管理员篡改。
- 应独立演练时代进退、跨机器证明、最新性、崩溃重入、保全数据转移与旧凭据不可复活；自动化不代替真实部署验收或批准生产切换。
- 字段、错误、权限、预算以 [FR-168](../specs/security-incident-controls.md) 为准；和 [ADR-0032](0032-credential-epochs-and-strong-authentication.md) 共用认证与确认界面。
- 接受与实现后，维护者更新被部分取代 ADR 的状态/链接并同步现行架构/运维入口，不改历史决策正文。

## 备选方案

- **用现有冻结过期替代事故锁**：进程重启或时间到期会静默取消止损，或阻断安全操作。
- **仅以备份摘要和恢复旧库检查安全**：只证明过去的数据完整性，会复活旧凭据或丢失限制。
- **缓存审计或复制整份安全库作日常真源**：引入双写真源与冲突；本地检查点仅是恢复输入，不参与日常事务授权。
- **保全即永久禁读整个共享摘要或另开原始文件下载**：前者连坐无关合法引用，后者暴露本应受访问裁决的证据，两者均否决。
