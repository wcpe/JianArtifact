# ADR-0034：私有发布候选与事务准入

## 状态

已接受（用户已批准正式规格）；待分批实现。分支：`feat/security-incident-controls`。仅按下述明确范围登记旧决策的部分取代，不代表内容检测、事务准入已实现或完成环境验收。

## 背景

hosted 制品必须先接受有界静态检测，再进入授权可见的仓库。HTTP 前置拦截无法覆盖内部批量发布、格式导入、移动改名和事务回放；共享文件摘要也不天然携带目标仓库、路径和发布策略的授权。

现有 `AssetMutationRepo.complete` 把资产变更、索引、操作记录及 hook 收敛到最终 SQLite 提交；`AssetMutationCoordinator.applyLockedWithEnvelopeAndHook` 在提交前能以隔离快照补偿，但提交后删除回滚快照失败，仅登记待清理，不撤销资产或事务内事实。与规范的文件系统 blob、SQLite 元数据双真源相容，不宣称跨介质原子事务。

本 ADR 取代 [ADR-0024](0024-atomic-physical-blob-reclamation.md) 中「回滚快照删除失败（含启动收尾失败）会撤销已经提交的业务；物理临时副本必须清除后才能返回成功」及衍生的成功/审计语义。保留其归零 blob 退出活动存储、同卷隔离、流式回滚快照与提交前失败补偿约束，且服从 [ADR-0033](0033-incident-restrictions-and-recovery-gate.md) 的保全与恢复闸。FR-104 历史交付不重标。

## 决策

**候选和扫描事实保持私有，以事务内复核本地批准、写入准入回执的 SQLite `COMMIT` 作为 hosted 新引用的唯一公开线性化点。**

### 私有字节与静态检测

- 接收时先写同卷私有暂存、持久化封存清单和队列状态。不让候选进入公开 `asset`、格式索引、FTS、可下载引用或公开摘要解析域。
- 主进程只做有限协议封装和流式字节传输；同一二进制的独立 `scan-worker` 处理所有未信任的制品内容，包括为发布取得坐标、索引或依赖所必需的预解析。不运行制品、不外联、不持业务秘密；Linux/Windows 必须具备可验的 OS 硬隔离，缺能力先阻塞，不能在任何入口回退到主进程旧解析器。
- 检测事实与授权分开。有合格最小事实但命中风险或专项覆盖不足时可强认证人工例外；无合格事实时首版只允许恢复安全环境后重新检测，不提供外部复核导入接口或开关。未来受控复核须另审签发者、验证根、必检版本、内容绑定与撤销；自由文本和附件不算事实。硬完整性失败只拒绝候选，不得例外或触发发布摘要封禁。
- 内容事实可按摘要和引擎/规则/解析配置版本缓存，批准和发布授权不能缓存为跨目标凭据。批准绑定仓库、操作、版本化封存清单、摘要、覆盖、检测配置、适用策略、审批者和有效期。

### 写边界与读取边界

- 对每个新挂的 hosted 可见引用和改变可见对象的操作，在最终短事务内对照实际差量验证批准、主体/凭据代次、实时范围与 ACL、锁/闸、不可变规则、配额与引用闭包；handler 成功准备不替代终审。事务内原子写公开资产、索引、可信成功事件、准入回执及相应状态。
- 物理字节必须在提交前按意图就位，受租约保护；事务前失败可恢复明确前镜像并清理，不发布成功事实。提交成功后不因快照清理、通知或响应丢失撤销发布；公开成功事实只出现一次。提交不确定先查持久回执，不能猜测后回滚或再写。
- 所有读取按已提交仓库/格式引用及实时 ACL、事故限制解析，不以裸摘要、相同字节、候选 ID 或回执换读取权限。D 只允许人工隔离具体目标；同一受限引用不可经主名/别名、group、HEAD/Range/条件响应、索引或 OCI digest 绕过，无关合法共享引用不受牵连；不新增全摘要跨仓隔离。
- 主提交路径以及直接 Upsert、内部批量/信封、Raw 改名/移动、协议索引、格式 importer 与通用 Put 都要检查能否新挂引用；纯 FTS 投影和没有新增引用的维护无需签发新回执。异步重放按原发起身份及 A 的不可变来源快照 `{originRequestId,clientIp,proxyTrust,sourceTrustVersion}`；终提交查当前信任版本和发布 IP 规则，未知或信任版本变化时暂停，不借 worker/IP 或新请求改写来源。复制通道已退役，不恢复。
- 私有引用、提升意图、已发布引用和证据保全共同参与回收裁决。灾备恢复不得以旧库里的批准或回执解除隔离；D 的可信检查点及安全时代闸通过前，不开服务、GC 或后台发布。

### 协议与重试

- 原生步骤只有其应公开的对象已提交、可合法读取才返回该步骤成功。Maven 是逐 PUT，表单才有完整批次；OCI 上传会话/分块 `202` 只确认传输，blob 封口成功前先可读，后续 manifest/tag 另验依赖闭包。历史复制、未支持 OCI mount 和 Go hosted/导入不顺带开放。
- 管理网页可明确 `202` 受理，待审与超时原生请求保持非成功且可追踪。同一仓库/动作/真实主体/意图和封存内容查原回执；不同内容不得复用，历史回执不授权当前可见性或重复发布。合法删除后，只有当前授权主体显式确认才可开新操作并重新准入；没有显式关联的原生网络重试不吸附新操作。

## 理由

- 把「收到字节」「检测事实」「公开提交」分开，网络重试和异步检测才不会改变真实业务结果。
- SQLite 提交可与授权变更排序；防止并发冻结、规则更新、相同摘要、多入口和后台执行出现时间差绕过。初始化失效时拒绝新 hosted 提交而不是降级到旧写路径。
- 短事务不持锁解析归档、等待队列或发网络；流式同卷存储、有界队列与本地 SQLite 避免引入外部 DB、MQ 或新的运行服务。
- 回滚快照删除与事务提交是两种持久化事件。清理失败若补偿已提交结果，会造成观察者见过公开资产但记录被改写，重试又可能制造第二条成功事实。

## 后果

- 增加候选、结果、批准、回执、启动对账和清理水位；运营须监测资源耗尽和隔离阻塞，保留明确待审及健康状态。不把存量或 proxy 自动标为已扫描。
- 等待预算不足时原生发布返回按协议封套的可追踪失败；CI 可能需要适配流程，不牺牲真实成功边界。同一原子发布单元不能为减小资源占用而拆成半可见结果。
- 发布协议矩阵和准入模型以 [FR-169](../specs/security-content-admission.md)、[FR-170](../specs/security-protocol-admission.md) 为准，具体契约以批准后的 OpenAPI 为准。可信业务事件参照 [ADR-0031](0031-trusted-security-events.md)，代次和强认证参照 [ADR-0032](0032-credential-epochs-and-strong-authentication.md)。
- 正式审核接受后，由主代理更新 ADR 索引、ADR-0024 状态行及取代链接（保留历史正文）、ARCHITECTURE、受影响规则与契约；本提案不先行改动旧决策。
- 本地故障和客户端隔离验收、真实部署环境的 OS 隔离/客户端兼容、生产恢复与切换须分别取证。实机和生产未经独立授权，不得标为已通过或可上线。

## 备选方案

- **先公开再扫描/撤回**：暴露窗口不可追回，已开始传输、索引和外部使用无法靠撤回抹除，否决。
- **仅 HTTP 中间件拦截**：内部批次、迁移、路径重绑与其他非 HTTP writer 无最终保障，否决。
- **共享摘要自动放行或长事务内扫描**：前者绕过跨目标授权，后者把昂贵且不可信解析放进写锁，均否决。
- **所有请求统一异步 202**：把原生协议成功和私有接收混淆，尤其破坏 Maven 客户端顺序与 OCI blob 闭包，否决。
- **快照清理失败回滚已经提交的业务**：破坏真实线性化、审计和幂等回执；采用提交后独立清理重试。
