# 功能规格：0.1.0 工程基座与契约骨架

> 状态：开发中　·　关联 PRD：FR-01/02/03/04/05/24（M1，P1）　·　分支：main（批0 基座串行，非并行 worktree）

## 1. 背景与目标

M1 的第一版本 0.1.0 不实现业务能力，而是把**从骨架到可构建、可测试、可探活、可部署演练**的工程地基一次打通，作为后续 0.2.0（认证）、0.3.0（协议）、0.4.0（迁移）所有并行开发的底座。参见 ADR-0001/0004/0005/0006/0007 与 ROADMAP「0.1.0 工程基座与契约骨架」。

## 2. 需求（要什么）

- **FR-01 monorepo 工程基座**：pnpm workspace + Turborepo + Makefile + Go Task + go.work 真实可跑（`pnpm install`、`pnpm build`、`task build` 全部成功）。
- **FR-03 契约→Go**：`api/openapi.yaml` 为唯一真源，`oapi-codegen` 生成 Go 类型 + Gin server 接口；生成产物不手改。
- **FR-04 契约→前端 + devmock**：据 OpenAPI 生成前端 TS 类型 / client；devmock 依同一契约做 schema 级比对，漂移即测试失败（对齐 AC-06）。
- **FR-05 单二进制 embed**：前端 `dist/` 经 Go `embed` 内嵌，`CGO_ENABLED=0` 静态编译出单二进制；二进制启动即提供 `/healthz`、`/readyz` 与内嵌前端。
- **FR-02 质量门**：一组脚本覆盖格式 / 构建 / 静态分析 / 测试 / 契约一致 / 依赖漏洞，本地与 CI 复用同一入口（`scripts/check.sh`），任一失败非零退出。
- **FR-24 部署骨架**：多阶段 `Dockerfile` 可 `docker build` 成功产出可运行镜像；`docker-compose` 配置合法。
- 范围内：健康 / 就绪端点的真实实现 + 测试；契约生成管线；embed 管线；质量门接线；Docker 构建演练。
- 不做（范围外）：任何管理 API、协议端点、鉴权、SQLite/blob 存储、Mantine 全页面（属 0.2.0+）；真机 curl/mvn/npm 与 Nexus 迁移（属 0.3.0/0.4.0）。

## 3. 设计（怎么做）

**后端（apps/server）**

- `internal/api/`：oapi-codegen 生成 `types.gen.go` + `server.gen.go`（`gin-server` + `types`，package `api`），由 `internal/api/cfg.yaml` 驱动，`task gen` 调 `go tool oapi-codegen`。
- `internal/httpserver/`：实现生成的 `ServerInterface`（`GetHealthz`/`GetReadyz`），装配 `gin.Engine`，挂载生成路由 + 内嵌前端静态资源；`readyz` 预留依赖自检钩子（0.1.0 恒 ready）。
- `web/`：`//go:embed all:dist` 内嵌前端产物；提交占位 `dist/index.html` 保证独立 `go build` 可用（前端构建覆盖之）。
- `cmd/jianartifact/main.go`：读环境（`JIAN_HTTP_ADDR`，默认 `:8080`），构建 server，`http.Server` + 优雅关停（SIGINT/SIGTERM）。
- 分层依赖方向遵循 `internal/doc.go`。

**前端（apps/web / packages/devmock）**

- `packages/devmock`：`openapi-typescript` 据 `api/openapi.yaml` 生成 `src/schema.gen.ts`；mock 处理器产出契约响应；`ajv` + 解析 OpenAPI schema 做运行时比对，`vitest` 断言无漂移。
- `apps/web`：React + Vite + TS 最小可构建应用（Mantine 全页面留 0.2.0），`vite build` 产出 `dist/`。

**质量门（scripts/check.sh）**

- 前端：`prettier --check`、`eslint --max-warnings 0`、`tsc --noEmit`、`vitest`、`build`；后端：`gofmt -l`、`go vet`、`golangci-lint`、`go test -race`、`govulncheck`、`build`；契约：devmock 比对。任一失败即非零退出。

## 4. 任务拆分

- [ ] 后端：oapi-codegen 配置 + 生成 + httpserver 实现 + embed + main 优雅关停 + 单测（httptest）
- [ ] 前端：devmock 契约比对（openapi-typescript + ajv + vitest）+ apps/web 可构建 React 应用
- [ ] 工程：pnpm/turbo/task/Makefile 接线为真实命令；`scripts/check.sh` 接入实际步骤
- [ ] 部署：`docker build` 演练成功
- [ ] 文档同步：PRD 状态（FR-01–05,24 计划→开发中）、ARCHITECTURE、API、CHANGELOG

## 5. 验收标准

- **AC-0.1.0-1**：`task build`（含 `pnpm build` 产 dist）产出单二进制；`CGO_ENABLED=0`。
- **AC-0.1.0-2**：运行二进制，`GET /healthz`、`GET /readyz` 返回 200 且体符合 `HealthStatus` 契约；根路径返回内嵌前端。
- **AC-0.1.0-3（对齐 AC-06）**：devmock↔OpenAPI 契约一致性 `vitest` 通过；故意改坏 mock 能被测出。
- **AC-0.1.0-4（对齐 AC-07）**：`scripts/check.sh` 全绿（前端 + 后端 + 契约 + 漏洞）。
- **AC-0.1.0-5（对齐 AC-08 的构建维度）**：`docker build` 成功产出镜像；容器 `/readyz` 探活 200。
- 说明：AC-01/02（真机 curl/mvn/npm、Nexus 迁移）不在 0.1.0，属 0.3.0/0.4.0。

## 6. 风险 / 待定

- oapi-codegen v2 gin-server 生成的接口签名需与手写实现严格对齐（以生成产物为准）。
- distroless 运行镜像无 shell，容器内探活用 `wget`/外部探测；compose healthcheck 采 Go 二进制自探或外部 curl。
- 前端 0.1.0 仅需可构建可 embed，Mantine 全量栈在 0.2.0 引入以控制本版体积与风险。
