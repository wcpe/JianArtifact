# 功能规格：外部身份源接入（OIDC / LDAP）

> 状态：OIDC 段与 LDAP 段开发完成，待用户审批与验收　·　关联 PRD：FR-34（OIDC）、FR-35（LDAP）　·　分支：feat/ldap-auth（OIDC 段已合入 main）　·　依赖：[ADR-0008](../adr/0008-auth-session-model.md)（会话模型，由 [ADR-0029](../adr/0029-external-identity-providers.md) 扩展）

## 1. 背景与目标

- **问题**：当前身份只来自本地 `user` 表（argon2id 口令 + JWT 会话，见 ADR-0008）。企业环境下账号由 IdP / 目录服务统一管理，要求：员工用企业身份登录、离职在目录侧停用后**无法再次登录**（已签发会话在其过期前仍有效，与本地账号语义一致）、账号不再两处维护。

**目标（对用户）**：

- **OIDC（FR-34）**：配好 issuer 与客户端凭据后，网页端可经授权码流程用 IdP 登录；
- **LDAP（FR-35）**：配好目录地址与检索条件后，网页端可用目录账号登录；
- 两者都**签发本地 JWT 会话**——下游 ACL、审计、冻结窗口、API 契约对客户端不变；
- 身份可审计：登录事件记录来源（`oidc` / `ldap` / 本地）；
- **永不锁死**：本地管理员始终可用本地口令登录（即使 IdP / 目录不可达）。

## 2. 需求（要什么）

- **OIDC**：授权码 + PKCE；`state` / `nonce` 校验；ID Token 按 `issuer` / `audience` / `exp` / 签名（JWKS，含缓存与 kid 轮换）校验；用户标识取稳定 `sub`；用户名与邮箱取可配置 claim（缺省 `preferred_username` / `email`）。
- **LDAP**：支持 `ldaps://` 与 StartTLS；检索 + 绑定两种模式（服务账号检索用户 DN 后以其凭据 bind；或按 DN 模板直接 bind）；属性映射可配置（用户名 / 邮箱）。
- **用户供给与绑定**：
  - 首次外部登录：按 `external_subject` 绑定既有用户；未绑定则按用户名匹配未绑定用户并绑定；仍无则**建号**（角色固定 `user`，权限仍完全由 ACL 决定）；
  - 可选白名单（允许的域名 / 用户名），作为收紧手段；
  - `status=disabled` 与 `web_login_disabled` 对两种来源同样生效。
- **凭据存放**：OIDC client secret 与 LDAP bind 密码**只从环境变量解析**，不落库、不进日志（对齐 `JIAN_UPSTREAM_CREDENTIAL_<名称>` 与 NFR-06 的既有范式）。
- **可追溯**：外部来源记录在 `user.auth_source`（OIDC `sub` / LDAP DN 存 `external_subject`），登录失败原因进服务端中文日志、对外只回笼统错误码（不泄露账号是否存在）；登录事件本身沿用既有口径**不写管理审计**（与本地登录一致），后续请求在审计中的 `authSource` 仍为会话来源。
- **范围外（不做）**：用户组与更细粒度权限动作（FR-36）；目录组 → 角色 / ACL 映射；多 IdP 与 SCIM；单点登出（SLO）与 IdP 会话联动；MFA；协议侧（git / npm / mvn）经外部身份源鉴权。

## 3. 设计（怎么做）

### 3.1 模块与依赖

```
api/auth_handlers（新增 OIDC 起跳与回调端点；登录端点扩展 LDAP 分支）
  ↓
auth 包（新增 oidc.go / ldap.go：协议交互与凭据校验）
  ↓
domain.AuthService（单一签发点：绑定 / 供给 / 状态校验 → JWT）
  ↓
repository.UserRepo（新增 auth_source / external_subject 列）
```

- 新依赖（均纯 Go、无 CGO，符合架构不变量）：`github.com/coreos/go-oidc/v3`、`golang.org/x/oauth2`（OIDC）、`github.com/go-ldap/ldap/v3`（LDAP）。
- 装配与配置沿用既有范式：**存在即启用**（对齐 `JIAN_SYNC_PEER_URL` 先例），未配置则相关端点 404 / 登录分支不启用。

### 3.2 数据模型（迁移 `0044`，向前追加）

- `user` 表新增：
  - `auth_source TEXT NOT NULL DEFAULT 'local'`（`local` / `oidc` / `ldap`）；
  - `external_subject TEXT NOT NULL DEFAULT ''` + `UNIQUE` 部分索引（`WHERE external_subject <> ''`）；
- 既有列沿用：`username`（唯一）、`email`、`role`、`status`、`web_login_disabled`、`password_hash`（外部来源用户不设口令，为空串）。

### 3.3 流程

- **OIDC**：`GET /api/v1/auth/oidc/start` 生成 `state` + PKCE 并 302 到 IdP；`GET /api/v1/auth/oidc/callback` 校验后经 `AuthService` 绑定 / 供给，签发 JWT 并 302 回前端（令牌经 **URL 片段**携带，避免进入服务端访问日志）；失败重定向回登录页并带错误码。
- **LDAP**：`POST /api/v1/auth/login` 在本地校验失败或用户 `auth_source='ldap'` 时走目录 bind；目录不可达返回与原登录失败一致的外部表现（不泄露账号是否存在），日志区分原因。
- **绑定 / 供给**（两者共用）：`external_subject` 命中 → 校验状态 → 签发；未命中 → 按用户名尝试绑定未绑定用户；仍无 → 建号（`role='user'`、`auth_source` 记来源、不设口令）。

### 3.4 契约与文档

- `api/openapi.yaml` 新增 OIDC 两个端点并 `task gen`；devmock 同步；`docs/API.md` 与 `OPERATIONS.md`（配置与排障）同步。
- **新增 ADR-0029「外部身份源（OIDC/LDAP）接入与会话签发」**（ADR-0008 不动，作为其扩展与补充引用）；`docs/ARCHITECTURE.md` 身份与权限段更新。

### LDAP 段（FR-35）验收记录

- **协议级（已执行）**：对进程内**真 LDAP 服务端**完成「服务账号 bind → 检索用户 → 用户本人 bind」往返，证据：`检索已发生=true，Subject=uid=alice,ou=people,dc=example,dc=com`；负例（错误口令、空口令）均被拒。该用例默认跳过、`JIAN_LDAP_PROTOCOL_TEST=1` 显式运行——原因是所用服务端库在关停阶段会从自身 goroutine 触发空指针 panic、且多实例并存时相互干扰，不适合作为常驻回归测试（详见 [ldap_protocol_test.go](../../apps/server/internal/auth/ldap_protocol_test.go) 顶部说明）。
- **接口级（已执行）**：登录回退端点测试覆盖「目录建号口径（`auth_source=ldap`、`role=user`、无本地口令）」「本地口令通过时**不触碰目录**」「两侧皆失败返回 401 且表现一致」。
- **配置级（已执行）**：未配置即不启用；非 ldap(s) 协议、缺基准 DN、过滤器缺占位、服务账号缺口令、StartTLS 与 ldaps 冲突、CA 不可读——六类均在启动期报错。
- **仍待（用户自有目录复验）**：对真实企业目录完成一次登录（含 `sAMAccountName` 等 AD 口径与自定义 CA 场景）；该复验为可选加强项，不作本段交付前置。

## 5. 验收标准

- **OIDC（集成）**：对本地假 IdP（含 JWKS 与 kid 轮换、非法 `state` / `nonce` / `aud` 负例）完成授权码登录；令牌只经片段下发、服务端日志无令牌。
- **LDAP（集成）**：对本地假目录完成检索 + bind 登录；错误口令、不存在用户、目录不可达三条路径均与本地登录失败表现一致。
- **绑定与供给（单元）**：`external_subject` 命中 / 用户名绑定 / 新建三路径；`disabled` 与 `web_login_disabled` 一律拒绝；建号角色恒为 `user` 且无口令。
- **防锁死（单元 + 真实运行）**：IdP 与目录均不可达时，本地管理员仍可登录；bootstrap 与 `admin reset` 不受影响。
- **安全**：client secret 与 bind 密码仅来自环境变量；令牌 / 口令 / ID Token 不出现于日志、审计与库；白名单命中与拒绝两条路径均被测试覆盖。
- **质量门**：`scripts/check.ps1` 全绿。
- **实机（已执行）**：以**本地真 IdP**（Keycloak 26.7.4，Maven 中央仓发行包，Java 21）+ **真实浏览器**（Chrome，自动化驱动）完成一次完整登录：
  - 授权请求携带 **PKCE S256 / nonce / state**，`redirect_uri` 与 IdP 注册逐字符一致；discovery 的 issuer 与本方配置 **MATCH**；
  - 回调后建号：`auth_source=oidc`、`role=user`、**无本地口令**、`external_subject` 为 IdP 的 `sub`；界面显示登录身份且会话可实际使用（非仅界面状态）；服务端**零失败日志**；
  - 同时验证**防锁死**：本地管理员口令通道在该实例上照常可用。
  - **本次验收发现并修复一处缺陷**：回调原回跳 `/login`，而该路由在前端是一次客户端跳转、会丢弃承载令牌的 URL 片段（服务端已建号签发、前端却始终未登录）；改为直达业务页 `/repositories` 并用端点测试锁定该不变量。

## 6. 风险 / 待定（评审已拍板项）

- **JIT 供给默认值（已定）**：默认**建号**（`role=user`、无本地口令），权限完全由 ACL 决定；可选白名单（域名 / 用户名）作为收紧手段。备选"默认拒绝未预建账号"未被采用——它把上手成本推给管理员，而建号本身不授予任何可见性。
- **回调令牌传递（本稿决定）**：令牌经 **URL 片段**回前端（简单、无服务端一次性状态）；备选是一次性交换码换 JWT（更严格但引入短时服务端状态），如后续要求更严可替换，不影响下游。
- **LDAP 证书校验**：默认严格校验，仅允许配置自定义 CA（对齐 FR-131 "防静默降级"口径），**不提供跳过校验开关**。
- **实机验收环境（已定）**：经用户确认改为**本地真 IdP** 路线（Keycloak 26.7.4 + 真实浏览器），已执行并通过（见 §5）；用户自有 IdP 的复验为可选，不作为本段交付前置。
- **会话撤销语义（如实登记）**：禁用（本地或目录侧）只对新登录即刻生效，已签发 JWT 在过期前仍有效——与本地账号既有语义一致；"即时踢出"不在本期范围（如需另立增量：缩短 TTL 或会话版本号）。
- **范围风险**：目录组 → 权限映射最容易被顺手做进来，属 FR-36 / 后续增量，本稿明确不做。
