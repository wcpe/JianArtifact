# 功能规格：上游断路器补强（FR-43）

> 状态：开发完成，待用户验收　·　关联 PRD：FR-43（补强 FR-112）　·　分支：feat/fr43-upstream-circuit-breaker　·　依赖：[ADR-0010](../adr/0010-proxy-cache-singleflight-group-routing.md)（proxy 回源与上游健康）

## 1. 背景与目标

- **问题**：上游断路器的基础能力已随 FR-112（v0.7.1）交付——失败进入 `AUTO_BLOCKED`、退避窗口起始 40s 每档翻倍、窗口内读请求零连接快速失败、后台 HEAD 探测成功自动恢复、状态可展示且可手动重测。本条只补三个缺口：

**目标（对用户）**：

- **退避起始可配置**：现固定 40s，仅测试钩子可调；运维需按上游特性调整（对着慢恢复的上游要更长，对着本地上游要更短）。
- **断路器可观测**：打开次数与当前状态目前只能靠肉眼看仓库列表；需进 Prometheus 指标，供告警与趋势分析。
- **半开语义显式化**：现「窗口到期 → 探测返回」之间存在**无节流的流量窗口**，真实业务流量会不受限制地打向上游；且状态对外仍显示 `AUTO_BLOCKED`，与实际行为不符。

## 2. 需求（要什么）

### 2.1 退避起始可配置

- 新增环境变量 `JIAN_AUTO_BLOCK_BASE_SECONDS`，默认 40（秒），语义为「首次失败的阻止窗口时长」；后续档位仍按既有规则翻倍。
- 非法值（非数字 / 负数 / 0）**回落默认且不报错**，与既有数值类配置一致（见 `config.go` 的 `upstreamTimeout()` 范式）。
- 既有 `SetAutoBlockBase` 保留：既作为测试钩子（7 处测试依赖），也作为配置注入入口。
- **范围外（不做）**：退避上限（cap）与抖动（jitter）。当前实现无上限、无抖动，本批不引入——避免改变既有退避曲线形状。

### 2.2 断路器运行指标

- 新增 counter `jianartifact_upstream_block_events_total`，标签 `reason`（**闭集枚举**）。
- **标签基数约束**（`ARCHITECTURE.md` §指标导出）：仓库名/路径**不得**作为标签。故不按仓库维度打标签。
- 新增 gauge `jianartifact_upstream_blocked_repositories`，报告当前处于阻止态的仓库数（无标签）。
- 指标经既有 `/metrics` 暴露，沿用 `RejectionRecorder` 那种「领域定义接口 + 装配层注入 `*metrics.Registry`、nil 表示不记录」的范式（见 `storage_quota.go`）。
- 现有指标族「无样本也输出 HELP/TYPE」的约定必须保持。

### 2.3 半开试探语义显式化

- **新增状态 `HALF_OPEN`**：探测窗口到期后进入该状态，表示「正在试探上游」。
- **流量闸门（核心修复）**：每轮半开**只放行一个试探请求**，其余请求在试探结果返回前等效于封锁（快速失败）。当前实现是窗口一到就无条件放开全部流量，这是必须修掉的行为缺口。
- 试探成功 → `AVAILABLE` 并重置退避；失败 → 回到 `AUTO_BLOCKED` 并推进一档。
- **对外语义**：`HALF_OPEN` 进契约枚举，管理界面与告警按新状态展示（不再把半开期误报为 `AUTO_BLOCKED`）。
- **措辞纠正**：PRD 与 CHANGELOG 现写「斐波那契退避」，但实现是**每档翻倍**（40s→80s→160s，几何增长），并非斐波那契数列（40→40→80→120）。本条一并改正措辞为「每档翻倍」；代码注释本就写作「每档翻倍」，无需改。

## 3. 设计（怎么做）

### 3.1 模块与依赖

```
config（新增 JIAN_AUTO_BLOCK_BASE_SECONDS）
  ↓
cmd/jianartifact/wiring.go（把配置注入 AssetService.SetAutoBlockBase）
domain（proxy_health.go 状态机改造 + 指标接口定义）
  ↓
metrics（新增 counter / gauge，经既有 /metrics 暴露）
  ↓
api（契约枚举扩展 → 重新生成 → 前端穷举映射同步）
```

### 3.2 状态机改造（`domain/proxy_health.go`）

现有三态 `READY` / `AVAILABLE` / `AUTO_BLOCKED` 改为四态，新增 `HALF_OPEN`：

```
READY ──失败──> AUTO_BLOCKED(第 N 档窗口)
                     │ 窗口到期
                     ▼
                  HALF_OPEN（只放行一个试探请求，其余快速失败）
                     │
        ┌────────────┴────────────┐
     试探成功                   试探失败
        │                          │
        ▼                          ▼
   AVAILABLE                 AUTO_BLOCKED(第 N+1 档)
   （重置退避）               （窗口重新计时）
```

- **`shouldBlock` 语义扩展**：`AUTO_BLOCKED` 且窗口未到 → 封锁；`HALF_OPEN` → 除首个试探外的请求封锁。
- **闸门实现**：`remoteState` 增加「半开试探是否已被占用」的标记（布尔或计数），在 `shouldBlock` 的同一把锁内判定与置位，避免竞态。探测结果返回时清除。
- **探测线程不变**：仍由 `checkStatus` 负责等待与探测；到点后先把状态切到 `HALF_OPEN` 再探测，探测结果决定落回哪一态。不变量「`AUTO_BLOCKED` ⇒ 必有探测线程在跑」保持，`HALF_OPEN` 同理。
- **手动重测（`recheck`）**：语义不变（同步探测，不等窗口），但失败时同样推进退避档。

### 3.3 指标接入

- 领域侧定义 recorder 接口（对齐 `RejectionRecorder` 范式），`nil` 表示不记录。
- 装配层在 `wiring.go` 注入 `*metrics.Registry`。
- `reason` 闭集取值：至少含 `probe_failed`（探测失败延长封锁）与 `upstream_error`（回源失败触发封锁）；未知值忽略，与既有 `PublishRejection` 一致。

### 3.4 契约与前端

- `ConnectionStatus.status` 枚举加 `HALF_OPEN`（契约真源 `api/openapi.yaml`），description 说明其含义。
- 重新生成 Go 与 TS 两侧产物（`task gen` + `pnpm --filter @jianartifact/devmock gen`）。
- 前端 `apps/web/src/lib/connectionStatus.ts` 的 `CONN_COLOR` / `CONN_LABEL_KEY` 是**穷举映射，加枚举值会直接编译失败**，必须同步补 `HALF_OPEN` 的颜色与 i18n 标签键（中英都要）。
- devmock 契约测试补正向 + 反向断言。

## 5. 验收

### 5.1 单元与集成（须全绿）

- 配置解析：5 例表驱动。
- 状态机：闸门并发唯一放行、`AUTO_BLOCKED → HALF_OPEN → AVAILABLE`、`→ AUTO_BLOCKED` 推进、手动重测语义。
- 指标：新族无样本输出、闭集标签、未知标签忽略。
- 既有断路器测试（`asset_service_resolve_test.go` 的 5 个 auto-block 用例 + 4 个 recheck 用例）**必须继续通过**——它们钉住了既有行为，是回归保险。
- 全量质量门 `bash scripts/check.sh` 全绿。

### 5.2 实机验收（需用户确认）

- 在测试站独立隔离实例上：
  1. 配 `JIAN_AUTO_BLOCK_BASE_SECONDS=5` 起一个实例，指向不可达上游，确认首次封锁窗口为 5s 且逐档翻倍；
  2. 上游恢复后确认自动回到 `AVAILABLE`；
  3. 半开期并发发起多个请求，确认**只有一个**真正打到上游（其余快速失败）；
  4. `curl /metrics` 确认新指标出现且计数随封锁增长；
  5. 管理界面仓库列表/详情能看到 `HALF_OPEN` 状态（不再误报 `AUTO_BLOCKED`）。

## 6. 风险与范围外

- **风险**：闸门改动触及既有并发路径，需 `-race` 验证；契约加枚举会波及前端所有穷举映射与 devmock，遗漏即编译失败（已列入任务）。
- **范围外**：退避上限与抖动、跨仓库聚合的断路器指标、断路器的手动"强制打开/关闭"、管理界面新增断路器详情页。
