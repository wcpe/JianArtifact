# 功能规格：0.2.0 认证授权核心

> 状态：已交付@v0.2.0　·　关联 PRD：FR-06/07/08（M1，P1）　·　分支：feature/auth-core（脊柱 S1+S2 串行）

## 1. 背景与目标

在 0.1.0 工程基座之上落地认证授权核心：SQLite 持久化底座、口令哈希、无状态会话、API Token 与鉴权中间件，作为用户管理（FR-09）与仓库 ACL（FR-10）并行开发的前置脊柱。参见 ADR-0002（SQLite/文件系统存储）、ADR-0008（认证会话模型）。

## 2. 需求（要什么）

- **FR-06 管理员自举**：改为网页自举端点 `POST /api/v1/auth/bootstrap`，仅在 `user` 表为空时开放，接收用户名 + 口令直接创建首个管理员并返回会话；实例已初始化后恒返回 409。去除 `JIAN_BOOTSTRAP_TOKEN` 环境变量。另提供 CLI `admin reset` 用于账号锁死恢复。
- **FR-07 登录 / 会话 / 退出**：`POST /auth/login` 校验口令签发 JWT(HS256)；`POST /auth/logout` 将当前会话 `jti` 记入 `revoked_token` 短期黑名单直至过期。
- **FR-08 API Token**：`POST /tokens` 随机生成，仅存 sha256 摘要，明文仅签发时返回一次；鉴权按摘要查表。
- 范围内：`internal/config`、`internal/persistence`（连接 + 迁移器 + `0001_init.sql`）、`internal/auth`（argon2id / JWT / token 摘要 / 中间件）、三个 auth 端点、`/api/v1/status`、CLI 子命令分发器（`admin reset` / `status` / 保留 `healthcheck`）、`/readyz` 依赖自检。
- 不做：首启 web 设置页（前端 UI）留下一轮；组 / 角色细粒度授权（本轮仅 admin / user 两级 + 仓库 ACL）。

## 3. 设计（怎么做）

- **持久化**：`modernc.org/sqlite`（无 CGO）+ `jmoiron/sqlx`；DB 路径取 `JIAN_DATA_DIR`（默认 `./data`）下 `jianartifact.db`；开启 WAL、`foreign_keys=ON`、`busy_timeout`。迁移经 `migrations/*.sql` 前向追加，`schema_migrations` 记录已应用版本，内置迁移器按文件名字典序执行。
- **口令**：argon2id（`golang.org/x/crypto/argon2`），参数固定并随哈希编码存储（`$argon2id$...`）；明文不落库不进日志（NFR-06）。
- **会话**：无状态 JWT HS256（`golang-jwt/jwt/v5`），密钥取 `JIAN_JWT_SECRET`，缺省时从 data 目录 `jwt.secret` 读取 / 生成并持久化（0600）并告警一次。登出把 `jti` 记入 `revoked_token`。
- **API Token**：随机明文（前缀 `jat_`）+ sha256 摘要入 `api_token` 表，明文仅返回一次。
- **鉴权中间件**：`Authorization: Bearer` 统一解析（先 JWT，再 Token 摘要），注入 principal；中间件为 Optional（解析不拒绝），各 handler 自行 `requirePrincipal` / `requireAdmin`。`/auth/{bootstrap,login}` 与健康 / 状态端点公开，其余需认证。
- **CLI**：`cmd/jianartifact` 扩为子命令分发器；`admin reset` 离线直连 SQLite 重置 / 创建管理员（缺省口令交互式不回显录入）；`status` 在线探 `/api/v1/status` 或离线输出配置。
- **分层**：`api → domain → repository/auth → persistence`，`config` 横切（见 `internal/doc.go`）。

## 5. 验收标准

- **AC-04（对齐 FR-07）**：登录返回 JWT，带 `Bearer` 可访问受保护端点；登出后旧令牌被拒（401）。
- **AC-05（对齐 FR-08 / NFR-06）**：API Token 明文仅签发时返回一次；DB 中仅存摘要，日志不含明文。
- **AC-06（对齐契约门）**：devmock↔OpenAPI 契约一致性通过（新增 auth / status schema 覆盖）。
- 空库自举 201、已初始化再自举 409、未认证受保护端点 401，均有集成测试佐证。

## 6. 风险 / 待定

- 无状态 JWT 的登出依赖 `revoked_token` 黑名单，需周期清理过期条目（本轮不做定时清理，查询时按过期过滤）。
- JWT 密钥自动生成仅便于开发；生产必须显式配置 `JIAN_JWT_SECRET`（OPERATIONS 已注明）。
