# 功能规格：0.2.0 仓库与 ACL 管理

> 状态：开发中　·　关联 PRD：FR-10（M1，P1）　·　分支：feature/repos（从 S3 契约冻结切出）

## 1. 背景与目标

在认证核心之上提供仓库元数据管理与基于 ACL 的访问控制，为后续协议端点（Raw/Maven/npm）提供可见性与读写授权判定的统一基础。

## 2. 需求（要什么）

- **FR-10 仓库管理 + ACL**：`GET/POST/PATCH/DELETE /api/v1/repositories`（列表分页、创建、更新可见性、删除）+ `GET/PUT /api/v1/repositories/{name}/acl`（读 / 覆盖写 ACL）。
- 可见性：`public` / `private`；ACL 动作：`read` / `write` / `admin`，admin 蕴含 read/write，write 蕴含 read。
- 授权：仓库 CRUD 仅全局管理员；ACL 读写需全局管理员或该仓库 `admin` ACL；列表按可见性 / ACL 过滤（非管理员仅见 public 或自己有 read 权的仓库）。
- 范围内：`internal/domain` 仓库服务 + `internal/repository` repoRepo / aclRepo + `api` handler + ACL 判定。
- 不做：group 成员解析、proxy 上游拉取（属协议版本）；仅落地元数据字段。

## 3. 设计（怎么做）

- **repository**：`RepoRepo`（显式列名）读写 `repository` 表；`AclRepo` 以事务覆盖写（`DELETE` + `INSERT OR IGNORE`），`HasPermission` 按动作展开蕴含集合（read→{read,write,admin} 等）用 `sqlx.In` 计数判定。
- **domain**：`RepositoryService` 提供 CRUD、`GetAcl`/`SetAcl`、`CanAccess`；`CanAccess` 对 `public` 仓库的 `read` 直接放行，其余走 ACL；仓库不存在返回 `ErrNotFound`。
- **api**：CRUD 用 `requireAdmin`；ACL 读写用 `requireRepoAdmin`（全局 admin 直接放行，否则查该仓库 `admin` ACL）；`ListRepositories` 对非管理员逐个 `CanAccess(read)` 过滤且 `total` 取过滤后计数。
- **分层**：`api → domain → repository → persistence`；ACL 判定供未来协议端点中间件复用。

## 4. 任务拆分

- [x] repoRepo / aclRepo（显式列名、事务覆盖写、蕴含判定）+ RepositoryService + repository handlers
- [x] ACL 判定接入：CRUD/ACL 授权、列表按可见性 / ACL 过滤
- [x] 单元：`CanAccess` 蕴含矩阵（read/write/admin）+ public read + not found
- [x] 集成：私有仓库对无 ACL 用户不可见、授 read 后可见、无 admin 读 ACL 403
- [x] 文档同步：PRD 状态、API、ARCHITECTURE §3、CHANGELOG

## 5. 验收标准

- 管理员可创建 / 更新 / 删除仓库并读写 ACL；非管理员越权得 403、未认证得 401。
- private 仓库对无 ACL 主体不可见、不可读；授 `read` 后可见可读；ACL 蕴含矩阵符合预期。
- 契约一致性测试覆盖 `Repository` / `RepositoryList` / `AclList`。

## 6. 风险 / 待定

- ACL 主体当前仅用户（无组）；组授权与继承留后续版本。
- 列表过滤对非管理员逐个判定，仓库量大时需优化为单查询联表（本轮规模可接受）。
