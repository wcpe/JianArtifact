# 功能规格：0.2.0 用户管理

> 状态：已交付@v0.2.0　·　关联 PRD：FR-09（M1，P1）　·　分支：feature/users（从 S3 契约冻结切出）

## 1. 背景与目标

在认证核心（0.2.0-auth-core）之上提供用户账号管理与口令维护，供管理员运营实例、普通用户自助改密。

## 2. 需求（要什么）

- **FR-09 用户管理**：`GET/POST/PATCH/DELETE /api/v1/users`（列表分页、创建、更新角色 / 状态、删除）+ `POST /api/v1/users/{id}/password`（口令修改 / 重置）。
- 授权：用户 CRUD 仅管理员；改密允许管理员改任意用户，普通用户仅能改自己（否则 403）。
- 范围内：`internal/domain` 用户服务 + `internal/repository` userRepo + `api` handler。
- 不做：组 / 组织、邮箱 / SSO、口令策略强校验（本轮仅 OpenAPI `minLength` 约束）。

## 3. 设计（怎么做）

- **repository**：`UserRepo` 读写 `user` 表（显式列名，避免 `SELECT *` 拉出未映射列导致 sqlx 报错）；唯一约束冲突转 `ErrConflict`，未命中转 `ErrNotFound`。
- **domain**：`UserService.Create` 默认角色 `user`，口令经 `auth.HashPassword`（argon2id）；`Update` 空串不改；`ChangePassword` 重算哈希。
- **api**：`requireAdmin` 守 CRUD；`ChangePassword` 先 `requirePrincipal`，再判 `p.IsAdmin() || p.UserID == id`；响应经 `toAPIUser` 转换（不含口令哈希）。
- **分层**：`api → domain → repository → persistence`。

## 4. 任务拆分

- [x] userRepo（显式列名）+ UserService + user handlers（CRUD + 改密）
- [x] 授权判定：CRUD 仅 admin，改密 admin 或本人
- [x] 集成测试：管理员建用户、非管理员列用户 403、错误口令 401
- [x] 文档同步：PRD 状态、API、CHANGELOG

## 5. 验收标准

- 管理员可创建 / 列表 / 更新 / 删除用户；非管理员访问用户管理端点得 403。
- 普通用户可改自己口令、不可改他人（403）；改密后旧口令失效、新口令可登录。
- 响应体不含口令哈希；契约一致性测试覆盖 `User` / `UserList`。

## 6. 风险 / 待定

- 删除用户经 `ON DELETE CASCADE` 连带清理其 `api_token` 与 `acl`；删除自身管理员账号的防呆留后续（本轮不限制）。
