# 功能规格：0.2.0 组件 / 业务模式验收站（wiki）

> 状态：已交付　·　关联 PRD：FR-12（M1，P1）　·　依赖：FR-11 管理端 web 已交付、`packages/ui` 共享组件已迁入 Mantine 7

## 1. 背景与目标

在 `packages/ui` 迁入 Mantine 7（AppProvider / PageHeader / 四类状态态组件 / 设计令牌）之后，需要一个独立、脱离后端的**验收站**，把共享 UI 组件与管理端高频业务交互模式集中展示，供评审在开发期核对组件呈现、状态态一致性与关键交互行为，避免只能在管理端真实页面里零散验证。参见 ADR-0003（Mantine 7）、ADR-0006（monorepo 工作区）。

## 2. 需求（要什么）

- **FR-12 wiki UI 组件 / 业务模式验收站**：React 18 + Mantine 7 的独立静态站点，以 AppShell 导航切换展台，覆盖四类展台：
  - 设计令牌：品牌色 / 圆角 / 间距令牌的可视化核对（与 `packages/ui` 令牌同源）。
  - 页头 PageHeader：标题 / 描述 / 右侧动作三态布局，与管理端页面顶部一致。
  - 状态态：并列展示 `LoadingState` / `EmptyState` / `ErrorState` / `ForbiddenState` 四类业务状态态。
  - 关键交互：表单校验（Mantine `useForm`）+ 全局通知（`notifications`）的“提交—反馈”业务模式。
- 范围内：`apps/wiki`（入口/画廊/展台/展台注册表/测试）；复用 `packages/ui` 的 `AppProvider` 与组件、`api/openapi.yaml` 无关（不消费后端契约）。
- 不做：真实数据 / 后端联调（验收站脱离后端）；把验收站产物内嵌进后端二进制（仅供开发/评审预览）；英文资源。

## 3. 设计（怎么做）

- **复用共享 UI**：根用 `packages/ui` 的 `AppProvider`（MantineProvider + 主题），验证共享主题在验收站与管理端表现一致；展台直接消费 `packages/ui` 导出的组件与 `tokens`。
- **画廊与导航**：`Gallery` 用 Mantine `AppShell`（Header + Navbar + Main），以受控 `useState` 切换展台，**不引入路由依赖**，保持验收站轻量；空注册表时抛错兜底（`noUncheckedIndexedAccess` 下的安全取值）。
- **展台注册表**：`src/sections/index.ts` 集中登记 `{ id, label, description, component }`，新增展台仅需登记一处，画廊据此渲染导航与内容。
- **工程接线**：与 `apps/web` 同构（Vite + `@vitejs/plugin-react` + PostCSS Mantine 预设 + 严格 TS/ESLint 继承共享配置）；`apps/wiki` 随本轮重新纳入 pnpm 工作区（0.1.0 曾暂移出）。
- **测试**：Vitest + jsdom（matchMedia/ResizeObserver 垫片）+ testing-library；画廊默认展台 / 导航齐全 / 分区切换，状态态四类渲染，关键交互的校验失败与提交成功路径。

## 5. 验收标准

- **AC-10（对齐 FR-11/12）**：验收站复用 `packages/ui` 的 `AppProvider` 与四类状态态组件，与管理端同源渲染，无重复实现。
- **AC-11（对齐 FR-12）**：验收站默认渲染首个展台、导航含全部注册展台、点击导航可切换分区；均有组件测试佐证。
- **AC-12（对齐 FR-12）**：关键交互展台的表单校验失败与提交成功（弹出通知）两条路径经集成测试走通（wiki 6 测试全绿）。

## 6. 风险 / 待定

- 验收站为独立静态站点，**不**内嵌进后端二进制；如需对外托管评审预览，由 Vite `build` 产物单独部署。
- 当前仅覆盖 `packages/ui` 现有组件与两类关键交互；后续 UI 组件增补时同步在此登记新展台（`sections/index.ts` 单点扩展）。
- 未接入路由与深链接；若展台数量显著增长，可评估引入 hash 路由以支持可分享的展台链接。
