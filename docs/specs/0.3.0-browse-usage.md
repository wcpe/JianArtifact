# 功能规格：0.3.0 制品浏览 + 使用说明片段

> 状态：已交付@v0.3.0　·　关联 PRD：FR-16（浏览与使用引导）　·　分支：feature/browse-usage

## 1. 背景与目标

在 Raw/Maven/npm 三格式协议真连之上，为管理端补齐**只读浏览面**：分页列出仓库内已存 asset（路径/大小/hash/更新时间），并据仓库 `format`/`type` 生成 curl/mvn/npm 客户端接入片段，降低使用者上手成本。属 M2（P1）。健康/就绪自检已在 0.2.0 具备，本增量不重复。

管理面端点前缀沿用 `/api/v1`，与协议层 `/repository`、`/npm` 互不冲突。

## 2. 需求（要什么）

- **浏览端点**：`GET /api/v1/repositories/{name}/assets`
  - query：`page`（默认 1）、`page_size`（默认 20）、`prefix`（可选路径前缀过滤）。
  - 响应 `AssetList{items:[AssetSummary], total}`；`AssetSummary{path, size, hash, contentType?, updatedAt}`；`items` 按 `path` 升序。
  - 权限：复用仓库读授权（admin 放行 / `CanAccess(read)`；public 仓库匿名可读）；未认证 401、越权 403、仓库不存在 404。
- **使用片段端点**：`GET /api/v1/repositories/{name}/usage`
  - 响应 `UsageInfo{format, type, snippets:[UsageSnippet]}`；`UsageSnippet{title, description?, code}`。
  - 片段据 `format`/`type` 生成：maven（settings.xml 认证 + pom 解析 +（hosted）distributionManagement 发布）、npm（registry 配置 + install +（hosted）publish）、raw（curl 下载 +（hosted）上传）。仅 hosted 含写入片段。
  - 对外基址由请求推断（`X-Forwarded-Proto` + `Host`），maven/raw 指向 `<base>/repository/<name>`、npm 指向 `<base>/npm/<name>/`。
  - 权限同浏览端点。
- 不做（留待后续）：asset 排序/过滤维度扩展、下载计数与统计、usage 多语言样例、按具体版本生成坐标。

## 3. 设计（怎么做）

- **契约**：`api/openapi.yaml` 增两端点与 `AssetSummary`/`AssetList`/`UsageInfo`/`UsageSnippet` schema 及 `prefix` 参数；`oapi-codegen` 重生 Go 接口、`openapi-typescript` 重生 `schema.gen.ts`。
- **repository/persistence**：`AssetRepo` 增 `ListByRepo(repoID, prefix, limit, offset)` 与 `CountByRepo(repoID, prefix)`；前缀过滤用 SQLite `LIKE ... ESCAPE '\'`（转义 `%`/`_`/`\`）。
- **domain**：`RepositoryService` 增 `ListAssets(name, prefix, page, pageSize)`（仓库不存在→`ErrNotFound`）与 `Usage(name, baseURL)`；`buildUsage(repo, base)` 据 format/type 组装片段（writable = `type=="hosted"`）。
- **api**：`repository_handlers.go` 的 `ListRepositoryAssets`/`GetRepositoryUsage` 经 `requireRepoRead` 授权后调用 domain，`toAPIAsset`/`toAPIUsageSnippet` 转契约类型；`apiBaseURL(c)` 据转发头推断对外基址。
- **web**：`RepositoryDetailPage` 经 `listRepositoryAssets`/`getRepositoryUsage` 渲染制品表（路径/大小/哈希/更新时间 + 前缀过滤）与使用片段卡片（`CopyButton` 可复制）；路由 `/repositories/:name`，列表页增「浏览」入口；i18n 补 `repoDetail`。
- **devmock**：store 增 `assets` 种子与 `listAssets`/`usage`（`buildUsage` 与后端逻辑一致），msw 增两 handler；契约一致性测试覆盖新 schema。
- **分层**：`api → domain → repository → persistence`（api 不直连 repository/persistence）。

## 5. 验收标准

- 浏览：GET assets 返回按 path 升序的分页结果，`total` 为过滤后总数；`prefix` 命中子集；仓库不存在→404。
- 使用：GET usage 据 format/type 返回正确片段，maven/raw 含 `<base>/repository/<name>`、npm 含 `<base>/npm/<name>/`；仅 hosted 含写入片段。
- 权限：未认证 401、越权 403、public 仓库匿名可读。
- 契约↔devmock 一致；web 详情页渲染种子制品与片段、可复制、未鉴权入错误态。
- `gofmt`/`go vet`/`go test ./...`/`CGO_ENABLED=0 go build ./...` 全绿；前端 typecheck/lint/test 全绿。

## 6. 风险 / 待定

- **usage 基址依赖请求头**：反代部署须透传 `X-Forwarded-Proto`/`Host`，否则片段中的 scheme/host 可能不符对外地址（与 ADR-0011 tarball 重写同源）。
- **浏览为扁平列表**：不做目录树聚合与多维排序；大仓库分页够用，深度浏览留待后续。
- **buildUsage 前后端双份**：后端 domain 与 devmock 各维护一份逻辑，需保持同步（已在契约/集成测试间接约束）。
