# 功能规格：0.3.0 Maven 全类型（hosted/proxy/group + metadata）

> 状态：已交付@v0.3.0　·　关联 PRD：FR-14（Maven hosted/proxy/group）　·　分支：feature/maven

## 1. 背景与目标

Raw proxy/group 回源与聚合读（见 `0.3.0-raw-proxy-group.md`）已把 `AssetService.Resolve` 抽象为格式无关的读路径（hosted 本地读 / proxy 回源缓存 / group 有序聚合）。本增量在其上补齐 Maven 格式：制品字节的发布/拉取完全复用既有内容寻址存储与 `Resolve`，仅补两点 Maven 专属语义——**校验和文件缺失时据底层制品现算**、**group 的 `maven-metadata.xml` 跨成员合并**。属 M2（P1）。

关键结构决策：`/repository/:repo/*artifactPath` 端点由**单一路由 + Dispatcher 按仓库 `format` 分派**承载，Maven 与 Raw 复用同一 URL 形态而各有独立 handler；`MavenHandler` 通过 Go 嵌入复用 `RawHandler` 的发布/删除/鉴权，仅覆盖 `Get`。不引入 Maven 格式专用表，元数据由 asset 组装/合并。

## 2. 需求（要什么）

- **格式分派**：`GET|HEAD|PUT|DELETE /repository/:repo/*artifactPath` 依仓库 `format` 分派——`maven`→`MavenHandler`，其余（含 raw、未知、不存在仓库）→`RawHandler`。
- **hosted 发布/拉取**：制品字节（jar/pom/`maven-metadata.xml`/`.md5`/`.sha1`/`.sha256` 等）经 `AssetService.Put` 原样内容寻址存储；`Put` 校验放宽为 **hosted-only**（格式语义由协议层分派后处理，不再限 raw）。GET 经 `Resolve` 回写 `Content-Type`/`Content-Length`/`ETag`(=blob sha256)。
- **校验和现算**：GET `.md5/.sha1/.sha256` 若该校验和文件本身未被部署（`Resolve`→`ErrNotFound`），则据去后缀的底层制品字节现算对应摘要、以 `text/plain` 十六进制返回；底层制品也不存在→404。已部署的校验和文件按原样存取（优先命中）。
- **proxy 回源**：制品与 metadata、校验和均经 `Resolve` 的 proxy 分支回源缓存（含 single-flight），上游 404→404、超时→504、其余失败→502。
- **group 聚合**：`maven-metadata.xml` 按 `members` 有序解析、合并各成员 `versions`（去重）、重算 `latest`/`release`/`lastUpdated` 后返回；全成员皆无该文件→404。其余制品（含校验和）按成员有序命中（复用 `Resolve` 的 group 分支）。
- **写仍仅 hosted**：proxy/group 的 PUT/DELETE→409（沿用 `AssetService.Put`/`Delete` 的 hosted 校验）。
- 不做（留待后续）：SNAPSHOT 唯一时间戳版本的语义解析与 `snapshotVersioning` 元数据、语义化版本排序、metadata 校验和的服务端再生成、proxy metadata 的 TTL 失效。

## 3. 设计（怎么做）

- **protocol/router.go**：`RegisterRoutes` 签名由 `*RawHandler` 泛化为 `artifactHandler` 接口（`Get`/`Put`/`Delete`），路由本身不变；`*RawHandler` 与 `*Dispatcher` 均满足该接口。
- **protocol/maven.go**：
  - `Dispatcher{repoSvc, raw, maven}` + `route(repoName)`：`repoSvc.Get` 取 `Format` 选处理器，仓库不存在回退 `raw`（其 `authorize` 产出 404）；`Get`/`Put`/`Delete` 委派。
  - `MavenHandler{*RawHandler}`：`Get` 覆盖——先 `authorize(read)`→取 repo；`group`+`isMavenMetadataFile`→`serveGroupMetadata`；否则 `Resolve`，`ErrNotFound` 且命中 `checksumExt` 则 `serveComputedChecksum`；成功走 `writeArtifact`。
  - `serveComputedChecksum`：`Resolve` 去后缀底层制品→按 ext 选 `md5/sha1/sha256`→`io.Copy` 摘要→hex→`text/plain`；HEAD 不写 body。
  - `serveGroupMetadata`：遍历 `cfg.Members` 逐一 `Resolve`+`ReadAll`+`merge`，`encode` 后以 `application/xml` 返回。
  - `mavenMetadata`（`metadata/versioning/{latest,release,versions/version[],lastUpdated}`）+ `merge`（groupId/artifactId 取首个非空、versions 按序去重）+ `encode`（latest=末项、release=最后非 SNAPSHOT、lastUpdated=当前 UTC、`xml.MarshalIndent`+`xml.Header`）。
- **domain/asset_service.go**：`Put` guard 由 `repo.Format != "raw" || repo.Type != "hosted"` 放宽为 `repo.Type != "hosted"`（格式路由上移至协议层），其余不变。
- **wiring**：`main.go` 与集成测试装配 `rawHandler → mavenHandler → dispatcher`，`RegisterRoutes(r, dispatcher, ...)`。
- **分层**：`protocol → domain → repository/blobstore/upstream → persistence`，无新增表、无新增迁移。

## 5. 验收标准

- maven hosted：PUT jar/pom→201；GET 字节一致、`Content-Type`/`ETag` 正确；GET 未部署的 `.sha1`→据 jar 现算 hex 与 `sha1.Sum(jar)` 一致；缺失制品→404。
- maven proxy：首次 GET 未命中→回源 200 并缓存；上游缺失→404。
- maven group：`maven-metadata.xml` 合并两成员 versions（并集去重）、`release`=最后非 SNAPSHOT、`latest`=末项；缺失 metadata→404。
- proxy/group PUT→409；hosted 与既有 raw 行为不回归。
- `gofmt`/`go vet`/`go test ./...`/`CGO_ENABLED=0 go build ./...` 全绿。

## 6. 风险 / 待定

- **SNAPSHOT/版本排序边界**：SNAPSHOT 唯一时间戳版本按路径原样存取，不解析 `snapshotVersioning`；group metadata 的 `latest`/版本顺序采**成员出现顺序**而非语义化版本比较，跨成员版本序可能非单调，复杂场景留待后续增量。
- group 合并仅覆盖 `maven-metadata.xml` 主体；其校验和（`maven-metadata.xml.sha1` 等）按普通制品有序命中，不据合并结果再生成，客户端若强校验合并 metadata 的摘要可能不匹配。
- proxy 缓存无 TTL：上游 metadata 更新后本地返回旧副本，直至 asset 被删；沿用增量 B 权衡。
