# 功能规格：0.3.0 npm registry 全类型（packument/tarball/publish）

> 状态：已交付@v0.3.0　·　关联 PRD：FR-15（npm hosted/proxy/group）　·　分支：feature/npm

## 1. 背景与目标

在 Raw/Maven（见 `0.3.0-raw-proxy-group.md`、`0.3.0-maven.md`）与 `AssetService.Resolve` 读路径分派之上补齐 npm registry 格式：支持 `npm publish` 发布、`npm install` 拉取（packument + tarball），并覆盖 hosted/proxy/group 三类型。属 M2（P1）。端点布局与 tarball 重写决策见 `docs/adr/0011-npm-registry-layout-and-tarball-rewrite.md`。

registry 基址为 `<server>/npm/<repo>/`，客户端经 `npm config set registry <server>/npm/<repo>/` 接入。

## 2. 需求（要什么）

- **端点**（独立 `/npm` 前缀，不与 `/api/v1`、`/repository`、SPA 撞车）：
  - packument：`GET|HEAD /npm/:repo/<pkg>`（`<pkg>` 支持 scoped `@scope/name`）；
  - tarball：`GET|HEAD /npm/:repo/<pkg>/-/<file>`；
  - publish：`PUT /npm/:repo/<pkg>`。
- **hosted publish**：请求体为含 `_attachments`（base64 tarball map）的 packument 片段；解码各 tarball 落 blob（路径 `<pkg>/-/<file>`），与已存 packument 合并（versions/dist-tags/time 逐键 last-writer-wins）后覆盖写文档（路径 `<pkg>`）。返回 201 `{"ok":true,"id":"<pkg>"}`。
- **install 拉取**：packument 经 `Resolve` 取文档、把各版本 `dist.tarball` 重写为 `<基址>/npm/<repo>/<pkg>/-/<原文件名>` 后以 `application/json` 返回；tarball 经 `Resolve` 流式回写字节（`Content-Type`/`Content-Length`/`ETag`）。缺失→404。
- **proxy**：packument 经 `Resolve` 回源上游 `<pkg>` 并缓存，服务端重写 `dist.tarball` 指向本仓；tarball 经 `Resolve` 回源上游 `<pkg>/-/<file>` 缓存。上游 404→404、超时→504、其余→502。
- **group**：packument 按 `members` 有序合并（versions 并集、dist-tags 首成员优先），tarball 经 `Resolve` group 分支有序命中回落各成员；全成员皆无该包→404。
- **写仍仅 hosted**：proxy/group 的 PUT（publish）经 `AssetService.Put` 返回 409。
- 不做（留待后续）：packument 由 asset 逐版本动态组装、semver 语义排序、shasum/integrity 校验、`npm unpublish`/`deprecate`/audit、proxy metadata TTL 失效。

## 3. 设计（怎么做）

- **protocol/npm.go**：
  - `NpmHandler{*RawHandler}` 复用 `assets`/`repoSvc`/`authorize`；`RegisterNpmRoutes(r, h, mw...)` 挂 `/npm/:repo/*rest`（GET/HEAD/PUT）。
  - `Get`：`authorize(read)`→`splitTarball(rest)`（含 `/-/`→tarball，否则 packument）。`serveTarball` 经 `Resolve(<pkg>/-/<file>)`+`writeArtifact`；`servePackument` group 走 `serveGroupPackument`，否则 `Resolve(<pkg>)`+`rewritePackumentBytes`+`writePackument`。
  - `Put`：`authorize(write)`→`publish`：`ReadAll` 体→`_attachments` base64 解码逐件 `Put(<pkg>/-/<name>)`→与 `Get(<pkg>)` 已存文档 `mergePackumentLastWins`→`Put(<pkg>, application/json)`。
  - `serveGroupPackument`：遍历 `cfg.Members` 逐一 `Resolve(<pkg>)`+`mergePackumentFirstWins`→`rewritePackument`→序列化返回。
  - 辅助：`splitTarball`、`requestBaseURL`（`X-Forwarded-Proto`+`Host`）、`rewritePackument`（逐版本 `dist.tarball`←`<base>/npm/<repo>/<pkg>/-/<path.Base(原)>`）、`mergePackumentLastWins`/`mergePackumentFirstWins`/`overlayMap`/`ensureMap`/`subMap`/`writePackument`。
- **存储**：复用 `asset` 表 + 内容寻址 blob，无新增表/迁移。packument 存于 `<pkg>`、tarball 存于 `<pkg>/-/<file>`（两者路径串不冲突）。
- **wiring**：`main.go` 与 `protocol_test.go` 装配 `npmHandler := NewNpmHandler(rawHandler)`，`RegisterNpmRoutes(r, npmHandler, authenticator.Optional())` 与既有 `RegisterRoutes` 并列注册。
- **分层**：`protocol → domain → repository/blobstore/upstream → persistence`。

## 5. 验收标准

- hosted：publish→201；GET packument `dist-tags.latest` 正确、`dist.tarball` 重写为 `http.../npm/<repo>/<pkg>/-/<file>`；GET 该 tarball 字节一致；缺失包→404。
- scoped：`@scope/name` publish 与 packument/tarball 往返正常。
- proxy：GET packument 回源并重写 tarball 为本仓地址（不含上游主机）；GET tarball 经本仓回源字节一致。
- group：packument 合并两成员 versions（并集）、`dist-tags.latest` 取首成员；group tarball 有序命中成员字节一致。
- proxy/group publish→409；hosted 与既有 raw/maven 行为不回归。
- `gofmt`/`go vet`/`go test ./...`/`CGO_ENABLED=0 go build ./...` 全绿。

## 6. 风险 / 待定

- **packument 整份存取**：不做 semver 排序与 integrity/shasum 校验；服务端不理解版本语义，`latest` 由发布方 `dist-tags` 决定。
- **proxy packument 无 TTL**：上游新版本在缓存 asset 被删前不可见（tarball 内容寻址不受影响）；沿用 ADR-0010 权衡。
- **group dist-tags 首成员优先**：跨成员同名版本以首个出现者为准，非语义化择新。
- **重写依赖请求基址**：反代部署须透传 `X-Forwarded-Proto`/`Host`，否则 `dist.tarball` 的 scheme/host 可能不符对外地址。
