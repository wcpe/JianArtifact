# 功能规格：0.3.0 Raw hosted 纵切贯通

> 状态：开发中　·　关联 PRD：FR-13（部分）/ FR-18 / FR-16（部分）　·　分支：feature/raw-hosted

## 1. 背景与目标

在 0.2.0 的认证、仓库与 ACL 之上，打通 **Raw hosted** 的最小闭环：「PUT 发布 → 内容寻址落盘 → GET 拉取 → sha256 校验」。同时落地后续 Maven/npm 与 proxy/group 复用的三块地基——**blob 存储**、**asset 元数据**、**protocol 协议层**。属 M1 收尾 / M2 起步（P1）。

## 2. 需求（要什么）

- **FR-13（部分）Raw hosted 协议端点**：`GET|HEAD|PUT|DELETE /repository/{repo}/{path...}`，原生客户端（curl）直连。
- **FR-18 内容寻址存储**：制品内容按 sha256 分片落盘，相同内容去重；元数据（路径→blob）落 SQLite。
- **鉴权**：原生客户端经 **API Token**（HTTP Basic 或 Bearer）鉴权，复用 `CanAccess`（public read 匿名放行）。见 ADR-0009。
- 范围内：`internal/blobstore`、`asset` 迁移 + `AssetRepo`、`domain.AssetService`、`internal/protocol` Raw handler + router、auth 中间件补 Basic、httpserver 协议路由装配。
- 不做（留待后续 0.3.0 增量）：proxy 回源缓存、group 路由合并、single-flight（FR-17）、Maven 元数据 / npm registry 语义、协议层浏览页面（FR-16 browse）、blob 即时 GC、`If-None-Match` 条件请求。

## 3. 设计（怎么做）

- **blobstore**（平级 persistence）：`Store{root}`，内容寻址 `root/<h[0:2]>/<h[2:4]>/<h>`；`Put` 经 `root/tmp/*` 临时文件 + 边写边算 sha256 + 原子 rename 落盘，命中已存在即去重；`Open`/`Exists` + 哈希合法性校验。分片布局见 ADR-0009。
- **元数据**：迁移 `0002_asset.sql` 建 `asset(id, repository_id FK CASCADE, path, blob_hash, size, content_type, created_at, updated_at, UNIQUE(repository_id, path))`；`AssetRepo` 提供 `Upsert`（`ON CONFLICT` 覆盖写）/`GetByPath`/`DeleteByPath`。
- **domain**：`AssetService.Put` 校验仓库存在且 `raw && hosted`（否则 `ErrConflict`/`ErrNotFound`），流式入 blob 再 upsert asset；`Get` 返回元数据 + `io.ReadCloser`；`Delete` 仅删元数据（blob 保留）。
- **auth**：中间件补 `Authorization: Basic` 解析，取 password（空则 username）作候选凭据；仅接受 `jat_` 前缀的 API Token（不启用口令登录），Bearer 行为不变。
- **protocol**（`protocol → domain, auth`）：`RawHandler` 把 HTTP 语义翻译为 `AssetService` 调用；GET/HEAD 走 `read`、PUT/DELETE 走 `write`；错误映射：无主体且非 public→401、有主体无权限→403、仓库/路径不存在→404、非 raw-hosted PUT→409；GET 设置 `Content-Type`/`Content-Length`/`ETag`(=blob sha256)。
- **httpserver**：新增 `WithProtocolRoutes` Option，在契约路由之后、静态 SPA 回退之前注册协议路由（不与 `/api/v1`、`/healthz` 冲突）；协议组挂 `authenticator.Optional()`（已支持 Basic + Bearer）。
- **分层**：`protocol → domain → repository/blobstore → persistence`，元数据落 SQLite、内容落文件系统。

## 5. 验收标准

- 经 Bearer 与 Basic 各 PUT 一件制品到 raw hosted 仓库均得 201；GET 字节级一致，响应含正确 `Content-Type` 与 `ETag`（blob sha256）；HEAD 得 200 且无 body。
- 私有仓匿名读得 401；已认证但无 write 权 PUT 得 403；未知路径得 404；非 raw-hosted 仓库 PUT 得 409；public 仓匿名可读。
- 相同内容重复 PUT 在 blob 层去重（不重复落盘），并发写同内容不损坏。
- **真实后端联调**（需用户确认通过）：`scripts/e2e-smoke.mjs` 覆盖 Raw hosted roundtrip 全部 Check 通过；单元 / 集成全绿不替代该项。

## 6. 风险 / 待定

- ETag 采用强校验（blob sha256），暂不实现 `If-None-Match` 条件请求；DELETE 仅删元数据，blob 即时 GC 留待后续增量。
- Raw 路径前缀采用 Nexus 风格 `/repository/{repo}/{path...}`；协议端点不进 OpenAPI 契约（面向原生客户端）。
- 管理端对 asset 的浏览页面（FR-16 browse）留待后续增量；本轮不改前端。
