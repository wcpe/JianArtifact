# 功能规格：0.3.0 Raw proxy/group 回源与聚合读

> 状态：开发中　·　关联 PRD：FR-13（Raw proxy/group 全）/ FR-17（并发回源收敛）/ FR-18（流式落盘复验）　·　分支：feature/raw-proxy-group

## 1. 背景与目标

仓库配置基座（见 `0.3.0-repository-config.md`）已落地 proxy 的 `remoteUrl` 与 group 的 `members` 配置但尚未消费。本增量补齐 Raw 格式 proxy/group 的**读路径**：proxy 未命中回源上游并缓存、group 按成员有序聚合读，并以 single-flight 收敛并发首次回源。写路径（PUT/DELETE）仍仅限 hosted。属 M2（P1）。设计与权衡见 `docs/adr/0010-proxy-cache-singleflight-group-routing.md`。

## 2. 需求（要什么）

- **upstream 回源客户端**：新增 `internal/upstream`，`Client.Fetch(ctx, baseURL, path)` 返回内容流 + 响应头；超时可配（`JIAN_UPSTREAM_TIMEOUT`，默认 30s）。上游 404 → `ErrNotFound`，非 2xx → `StatusError`，支持超时判定 `IsTimeout`。
- **proxy 读**：本地缓存命中即返回；未命中经 upstream 回源，**流式**落 blob（不整体入内存，复验 FR-18）并 upsert asset（缓存）后返回。上游 404→404、超时→504、其余失败→502。不做 TTL/负缓存。
- **single-flight（FR-17）**：以 `repoID\x00path` 为键收敛并发首次回源，N 个并发请求对同一未命中路径只回源一次。
- **group 读**：按 `members` 顺序逐一解析（成员可为 hosted/proxy/group），首个命中即返回；成员未命中或回源失败跳过，全未命中→404；深度上限遏制环引用。
- **写仍仅 hosted**：proxy/group 的 PUT/DELETE 返回 409（沿用既有 `Put`/`Delete` 的 raw-hosted 校验）。
- 不做（留待增量 C~）：Maven/npm 格式回源与元数据合并、proxy 缓存失效/GC、group 元数据合并。

## 3. 设计（怎么做）

- **upstream**：`Client{http *http.Client}`，`NewClient(timeout)`（≤0 取默认 30s）；`Fetch` 经 `joinURL` 拼接绝对 http/https URL、`GET` 带 ctx，404→`ErrNotFound`、非 2xx→`*StatusError{Code}`、2xx→`(body, header, nil)`；`IsTimeout` 识别 `context.DeadlineExceeded` 与 `net.Error.Timeout()`。
- **config**：新增 `EnvUpstreamTimeout`（秒）与 `Config.UpstreamTimeout`，非法/缺省取 `defaultUpstreamTimeout=30s`；wiring 装配 `upstream.NewClient(cfg.UpstreamTimeout)` 注入 `AssetService`。
- **domain**：`AssetService` 增 `upstream *upstream.Client` 与 `sf singleflight.Group`；新增 `Resolve(ctx, repoName, path)` → `resolve(ctx, repo, path, depth)` 按 `repo.Type` 分派：proxy→`proxyGet`、group→`groupGet`、其余→`localGet`。`proxyGet` 命中即返回，未命中经 `sf.Do(repoID\x00path)`（临界区先复查缓存→`Fetch`→`blobs.Put`→`Upsert`）后 `localGet`。`groupGet` 遍历 `members` 递归 `resolve`，首个 `err==nil` 返回。`mapUpstreamErr` 映射 `ErrNotFound`/`ErrUpstreamTimeout`/`ErrUpstream`。新增 domain 错误 `ErrUpstream`（502）、`ErrUpstreamTimeout`（504）。
- **protocol**：`raw.go` 的 `Get` 改用 `Resolve(c.Request.Context(), repo, artPath)`（支持 hosted/proxy/group 读）；`writeAssetErr` 补 `ErrUpstreamTimeout`→504（`upstream_timeout`）、`ErrUpstream`→502（`upstream_error`）。`Put`/`Delete` 不变（proxy/group 写→409）。
- **分层**：`protocol → domain → repository/blobstore/upstream → persistence`，无新增表、无新增迁移。

## 5. 验收标准

- proxy 首次 GET 未命中→回源 200 并落缓存；二次 GET 命中本地、内容一致、上游只被请求一次；Content-Type 由上游响应头透传。
- proxy 上游 404→协议层 404；上游 500→502；上游超时→504。
- group 读命中近端 hosted 成员优先；hosted 未命中回退命中 proxy 成员（经回源）；全成员皆无→404。
- 同一 proxy 未命中路径 N 并发请求，上游实际只被回源一次（single-flight 计数断言）。
- proxy/group 仓库 PUT/DELETE→409；hosted 行为不回归。
- `gofmt`/`go vet`/`go test ./...`/`CGO_ENABLED=0 go build ./...` 全绿。

## 6. 风险 / 待定

- proxy 无缓存失效：上游更新后本地返回旧副本，直至 asset 被删或后续增量引入 TTL；GC 仍不即时。
- group 成员回源错误被静默跳过（不阻断聚合），故 group 读不暴露 502/504；此类状态仅见于直接读 proxy 仓库。
- 本增量仅 Raw 格式；Maven/npm 的回源与元数据合并复用 `Resolve` 但需格式专属 handler，留待增量 C/D。
