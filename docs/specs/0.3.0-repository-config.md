# 功能规格：0.3.0 仓库配置基座（proxy/group 契约扩展）

> 状态：开发中　·　关联 PRD：FR-13（proxy/group 配置前置）　·　分支：feature/repository-config

## 1. 背景与目标

在 Raw hosted 纵切之上，为后续 proxy 回源与 group 聚合奠定**仓库配置能力**：proxy 需记录上游地址（remoteUrl），group 需记录有序成员仓库（members）。本增量只做配置的**契约扩展、校验、持久化与前端表单**，不做回源/聚合逻辑（留待增量 B 起）。属 M2 起步（P1）。

## 2. 需求（要什么）

- **配置存储**：proxy/group 配置复用 `repository` 表既有 `config TEXT NOT NULL DEFAULT '{}'` 列（`{"remoteUrl":...,"members":[...]}`），**不新增迁移**。
- **契约扩展**：`Repository`/`CreateRepositoryRequest`/`UpdateRepositoryRequest` 增可选 `remoteUrl`（string）与 `members`（string[]），重生成 Go + TS，同步 devmock 与前端表单。
- **校验规则**（domain，违规返回 `ErrValidation`→400）：
  - `hosted`：`remoteUrl`、`members` 均须为空；
  - `proxy`：`remoteUrl` 必填且为合法 http/https 绝对地址，`members` 须为空；
  - `group`：`members` 必填（≥1），每个成员须存在、与本仓 `format` 一致、非自引用，`remoteUrl` 须为空。
- 范围内：`repository` 模型/仓库层 config 读写、`RepositoryService` 校验与结构化 Create/Update、api handler 映射、OpenAPI 扩展与代码重生成、devmock store/handlers、web 创建表单条件字段与 i18n。
- 不做（留待增量 B~）：proxy 回源缓存、group 有序路由/合并、single-flight、config 的运行时消费（AssetService 尚未读 config）。

## 3. 设计（怎么做）

- **repository**：`Repository` 增 `Config string`（映射既有 `config` 列）；新增 `RepositoryConfig{RemoteURL, Members}` 与 `DecodeConfig`/`EncodeRepositoryConfig` 编解码（空串视为空配置）。`RepoRepo.Create` 增 `config` 入参（空则落 `{}`），`GetByName`/`List` SELECT 补 `config` 列，新增 `UpdateConfig(name, configJSON)`。
- **domain**：`RepositoryService.Create` 接收 `cfg RepositoryConfig`、`Update` 接收 `cfg *RepositoryConfig`（nil 表示不改配置）；新增 `validateConfig` 按 `type` 施加上述规则，group 成员存在性/格式经 `RepoRepo.GetByName` 核验。
- **api**：`CreateRepository`/`UpdateRepository` 从契约 `RemoteUrl`/`Members` 指针字段装配 `RepositoryConfig`；`toAPIRepository` 解码 config 回写 `remoteUrl`/`members`。`ErrValidation` 经 `writeDomainErr` 映射 400（`validation_error`）。
- **契约**：`api/openapi.yaml` 三 schema 增可选字段；`oapi-codegen` 重生 `api.gen.go`（`RemoteUrl *string`、`Members *[]string`），`openapi-typescript` 重生 `schema.gen.ts`。
- **devmock/web**：store 种子与 `createRepository`/`updateRepository` 支持 remoteUrl/members；msw handler 透传；web 创建表单据 `type` 条件渲染 remoteUrl（proxy）输入与 members（group）多选，前端做同格式候选过滤与基本校验；i18n 文案补齐。
- **分层**：`api → domain → repository → persistence`，不新增表、不新增运行时消费路径。

## 4. 任务拆分

- [x] `repository`：`Config` 字段 + `RepositoryConfig` + 编解码；`Create` 加 config、SELECT 补 config、`UpdateConfig`
- [x] `domain`：`Create`/`Update` 结构化签名 + `validateConfig`（hosted/proxy/group 规则）
- [x] `api`：handler 映射 remoteUrl/members + `toAPIRepository` 回写
- [x] OpenAPI 扩展 + `oapi-codegen`/`openapi-typescript` 重生成
- [x] devmock store/handlers 支持字段；web 创建表单条件字段 + i18n
- [x] 测试：repo config 往返/默认/UpdateConfig；service 校验（proxy 缺/非法 url、group 成员不存在/跨 format/自引用）；web 表单集成（选 proxy 填 url 新建）；契约一致性
- [x] 文档同步：本 spec、CHANGELOG

## 5. 验收标准

- proxy 仓库缺 `remoteUrl` 或 `remoteUrl` 非法（非 http/https 绝对地址）→ 校验失败（400）；合法则通过。
- group 仓库成员为空、成员不存在、成员与本仓 `format` 不一致、或自引用 → 校验失败（400）；成员合法则通过。
- 配置经 Create 落库、GetByName 读回后 remoteUrl/members 无损往返；空 config 落库为 `{}` 且解码为空配置。
- `Repository` 响应对 proxy 回显 `remoteUrl`、对 group 回显 `members`；devmock↔OpenAPI 契约一致性测试绿。
- web 创建仓库选 proxy 时出现上游地址输入、选 group 时出现成员多选，新建 proxy 仓库后列表出现该仓库。

## 6. 风险 / 待定

- 本增量仅落配置与校验，回源/聚合尚未消费 config；proxy/group 仓库此时对协议读写的行为仍等同占位（增量 B 起接入）。
- 前端 members 候选来自当前已加载仓库列表（分页上限内），跨页成员选择留待浏览增量细化；后端校验为准。
