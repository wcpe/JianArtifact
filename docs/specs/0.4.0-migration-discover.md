# 功能规格：0.4.0 三来源发现与计划预览

> 状态：已实现（待发版验收）　·　关联 PRD：FR-20 / FR-21（计划预览）

## 1. 背景与目标

在迁移地基之上，实现 **Nexus 三来源发现** 与 **计划预览**，让管理员在真正搬数据前看到：将迁哪些仓库、格式映射、规模估算、不支持项。属 M1（P1）。接口形状对齐 `docs/API.md` 与 ADR-0012。

## 2. 需求（要什么）

- **`POST /api/v1/migrations/discover`**（admin）：
  - 入参：`sourceType`（`online_rest` | `offline_dir` | `offline_bundle`）+ 来源配置 + 可选 `credentialRef` + `conflictPolicy`（默认 skip）。
  - 行为：**同步发现**；成功后 **落库一条 `planned` 任务**（plan_json / source / credentialRef / conflictPolicy）。
  - 出参：`{ taskId, plan }`——`MigrationPlan` 含 `repositories[]`（建议名、format、type、资产数估算）、`warnings[]`、`stats`。
  - 发现失败：**不落库**，返回错误（无半截 planned 行）。
- **三来源**：
  1. **online_rest**：访问 Nexus REST（基线 3.70.x）；列出 raw/maven/npm 相关仓库与资产分页游标探测。
  2. **offline_dir**：扫描 Nexus 原生存储目录（路径由配置给出；只读）。
  3. **offline_bundle**：扫描「自有离线包」约定布局（见 §3；文档固化最小清单格式）。
- **格式范围**：仅识别并纳入 plan 的 **raw / maven / npm**；其它 format 进 `warnings`，不进入可执行条目。
- **不自动执行**：落库状态固定为 **`planned`**；搬运须后续 `POST .../start`（见 execute spec）。
- 不做：执行搬运、resume、报告、web 向导完整交互（可先 API only）。

## 3. 设计（怎么做）

- **包**：`internal/migration/discover/`：
  - `Source` 接口：`Discover(ctx, cfg) (Plan, error)`
  - 实现：`OnlineREST`、`OfflineDir`、`OfflineBundle`
- **online_rest**（草案）：
  - 仓库列表：Nexus `GET /service/rest/v1/repositories`（或 3.70 等价）
  - 资产枚举：按仓库 `GET /service/rest/v1/assets?repository=` 分页；超时与分页上限可配，避免 discover 挂死。
  - 认证：Basic 或 Bearer，值来自 `credentialRef` → env。
- **offline_dir**（草案）：
  - 接受 Nexus data 目录或 blob store 路径；按已知布局推仓库/路径（实现时对照 3.70 文档/样例固化；规格验收用夹具目录）。
- **offline_bundle**（草案最小约定）：
  ```
  bundle/
    manifest.json   # { "repositories": [ { "name", "format", "type" } ] }
    content/
      <repo>/<path...>   # 原始文件
  ```
  - 无 manifest 时可仅扫描 `content/*` 一级目录为仓库名，format 默认 raw 并 warning。
- **domain**：`MigrationService.Discover` 调用 Source → 组装 Plan → **Repo.Create(status=planned)** → 返回 taskId+plan；不写 blob、不 start。
- **错误**：来源不可达 → 502/`upstream_error`；路径不存在 → 400；认证失败 → 统一 `validation_error`（401 语义的源认证失败不暴露为登录页 401，避免与会话混淆）并测。

## 5. 验收标准

- 对 **httptest 模拟的 Nexus REST**：discover 返回含 raw/maven/npm 仓库条目；docker 等进 warnings；响应含 **taskId**；`GET /migrations/{id}` 状态为 **`planned`** 且 plan 与响应一致。
- 对 **离线目录夹具** 与 **bundle 夹具**：discover 条目与夹具一致且已落库。
- 发现失败（坏路径/坏凭据）：HTTP 错误且 **无新 planned 任务**。
- 错误响应与日志无密钥；非 admin → 403。
- discover 后任务仍为 planned，**未**出现 running/copied 副作用。

## 6. 风险 / 待定

- Nexus REST 在不同小版本字段差异：以 3.70.x 为准，字段用容错解析。
- 在线 discover 全量资产列表可能很慢：计划预览允许「只列仓库 + 抽样计数」；精确计数可标 `estimated=true`。
- 原生目录布局需在实现前用真实/录制样例冻结；若与预想不符，更新本 spec 与夹具，不静默猜。
