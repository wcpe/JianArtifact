# 功能规格：0.4.0 异步执行、幂等续传与冲突策略

> 状态：已实现（待发版验收）　·　关联 PRD：FR-21（状态机）/ FR-22

## 1. 背景与目标

在 discover + 地基之上，实现 **按计划异步搬运**、**断点续传** 与 **冲突策略**，把 Nexus（或离线源）中的制品写入本系统 hosted 仓库与 blob。属 M1（P1）。状态机见 ADR-0012。

## 2. 需求（要什么）

- **`POST /api/v1/migrations/{id}/start`**（定稿）：仅当状态为 **`planned`** 时合法 → 置 `running` + 异步执行；其它状态 → 409。
- **`POST /api/v1/migrations`**：只创建 **planned**（不执行）；可带 plan 或 source（无 plan 时服务端可内嵌一次 discover 再落 planned，仍不 start）。
- **执行**：
  - 若目标仓库不存在：按 plan 创建 hosted 仓库（format/type/visibility 默认 private）。
  - 逐资产：拉取源字节（REST 下载 / 读本地文件）→ `AssetService.Put` 流式写入。
  - 进度：更新 `checkpoint_json` + 计数（copied/skipped/failed）。
- **冲突策略**：`skip` | `overwrite` | `fail`（任务级，创建/discover 时固定，之后不可改）。
- **`POST /api/v1/migrations/{id}/resume`**：`failed`/`cancelled` → `running`，从 checkpoint 继续。
- **`POST /api/v1/migrations/{id}/cancel`**：
  - `planned`：直接 `cancelled`；
  - `running`：协作式取消（执行循环检查 ctx/flag）→ `cancelled`。
- **进程崩溃恢复（定稿）**：服务启动时扫描 **`running` → 一律 `failed`**（中文 error_message 提示 resume）；**禁止自动 resume**。
- 不做：多任务并行调度器优先级、跨节点、格式转换、proxy/group 目标仓写入；创建即 running。

## 3. 设计（怎么做）

- **包**：`internal/migration/runner`：
  - `Runner.Start(taskID)`：仅由 domain 在状态已改为 `running` 后调用；goroutine + mutex per taskID。
  - 循环：读 checkpoint → 取下一批源资产 → 应用冲突策略 → Put → 持久化 checkpoint。
- **冲突**：
  - `skip`：`GetByPath` 存在则 skip。
  - `overwrite`：直接 Put。
  - `fail`：存在则任务 failed + error_message。
- **源读取**：
  - online：HTTP GET 资产 downloadUrl（流式，复用 upstream 超时配置或独立 `JIAN_MIGRATION_TIMEOUT`）。
  - offline：`os.Open` 流式。
- **domain**：`Start` / `Cancel` / `Resume`；**禁止** api 层直接开 goroutine。
- **启动回收**：`main`/wiring 在迁移子系统 init 时 `FailInterruptedRunning()`：`UPDATE migration_task SET status='failed', ... WHERE status='running'`。
- **可观测**：中文日志（任务 id、仓库、进度百分比粗算）；密钥脱敏。

## 4. 任务拆分

- [x] Runner + 任务互斥 + 执行失败标 failed
- [x] 冲突三策略单测（offline bundle）
- [ ] 在线源拉包（httptest）+ 写入 blob/asset 集成测（MVP 暂返回明确错误，后续增强）
- [x] 离线源夹具：discover 落库 planned → start → completed
- [x] resume / 崩溃回收单测
- [x] 启动时 running → failed（不自动 resume）单测
- [x] api start/resume/cancel（foundation 已有）+ wiring 接 Runner
- [x] 文档：本 spec、CHANGELOG

## 5. 验收标准

- discover 后未 start：目标仓无新资产。
- planned → start → 夹具源（offline bundle）迁移：目标 hosted 中路径字节与源一致；任务 `completed`。
- 预先放入冲突路径：`skip` 不覆盖、`overwrite` 覆盖、`fail` 失败；resume 后行为符合策略（改策略须新任务）。
- 执行中 cancel → `cancelled`；resume 后剩余项继续。
- 模拟崩溃：将任务标为 running 后调启动回收 → `failed`；**无**自动继续写入；resume 后从断点继续且已成功项不重复失败。
- 大文件流式：执行路径不 `ReadAll` 整文件进内存（测试可用中等文件 + 代码审查/单测断言）。

## 6. 风险 / 待定

- 在线迁移速率与 Nexus 限流：需重试退避；MVP 简单重试 3 次。
- 仓库命名冲突（本地已有同名不同 format）：创建前校验，冲突则 fail 该仓并记 report（推荐，实现时写死一种并测）。
