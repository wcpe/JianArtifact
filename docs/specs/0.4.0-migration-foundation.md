# 功能规格：0.4.0 迁移域地基（任务模型 / 契约 / 凭据）

> 状态：已实现（待发版验收）　·　关联 PRD：FR-21（部分）/ FR-22（部分）/ FR-23（凭据）

## 1. 背景与目标

在 0.3.0 协议真连之上，为 Nexus 迁移建立**可持久化的任务骨架**与**管理面契约**，不实现具体发现/拉包。后续 discover / execute / report 增量均挂在本地基上。属 M1（P1）。决策见 `docs/adr/0012-nexus-migration-state-machine.md`。

## 2. 需求（要什么）

- **数据模型**：`migration_task` 表 + `MigrationTaskRepo`（Create / Get / List / UpdateStatus / SaveCheckpoint / SaveReportMeta）。
- **领域**：`domain.MigrationService` 骨架——创建 **planned** 任务、查询、未启动取消、`start`/`resume` 入口（具体执行留 execute 增量）；状态转换校验。
- **契约**：OpenAPI 增补 migrations 相关 path 与 schema（含 `POST .../start`）；`oapi-codegen` + `openapi-typescript` 重生；devmock 占位 handler（内存任务，创建后为 planned）。
- **鉴权**：全部 migrations 端点 **admin only**（401/403）。
- **凭据**：请求体仅接受 `credentialRef` 字符串；服务端解析环境变量；缺失引用 → 400 `validation_error`。
- **定稿约定**（ADR-0012）：任务一律落库；`POST /migrations` 只建 **planned**，不自动 running；`start` 才进入执行（本增量 start 可仅改状态 + 钩子空实现）。
- 范围内：`0003_migration.sql`、repository/domain/api、devmock、OPERATIONS 环境变量说明。
- 不做：真实 Nexus 调用、异步拉包、报告正文、web 向导页（后续增量）。

## 3. 设计（怎么做）

- **迁移脚本 `0003_migration.sql`**（草案字段，实现时可微调但需迁移兼容）：

```sql
-- migration_task：Nexus 迁移任务主表
CREATE TABLE migration_task (
  id              INTEGER PRIMARY KEY AUTOINCREMENT,
  status          TEXT NOT NULL,           -- planned/running/completed/failed/cancelled（MVP 不用 pending/discovering 持久态）
  source_type     TEXT NOT NULL,           -- online_rest / offline_dir / offline_bundle
  source_config   TEXT NOT NULL DEFAULT '{}', -- JSON：url/path 等，无密钥
  credential_ref  TEXT,                    -- 环境变量引用名，可空（离线无认证）
  conflict_policy TEXT NOT NULL DEFAULT 'skip', -- skip|overwrite|fail
  plan_json       TEXT NOT NULL DEFAULT '{}',
  checkpoint_json TEXT NOT NULL DEFAULT '{}',
  report_json     TEXT NOT NULL DEFAULT '{}',
  error_message   TEXT,
  created_at      TEXT NOT NULL DEFAULT (datetime('now')),
  updated_at      TEXT NOT NULL DEFAULT (datetime('now')),
  started_at      TEXT,
  finished_at     TEXT
);
```

- **domain 状态守卫**：非法迁移返回 `ErrConflict`；不存在 `ErrNotFound`。
- **api**：handlers 映射 OpenAPI；`writeDomainErr` 复用。
- **分层**：`api → domain → repository → persistence`；**不**在 foundation 引入 `internal/migration` 执行器（execute 增量再建）。

## 5. 验收标准

- 管理员可 `POST /api/v1/migrations` 创建任务并 `GET` 查到状态 **`planned`**（非 running）；非 admin → 403；未认证 → 401。
- `POST .../start` 仅允许 `planned → running`；对 `completed` 调 start → 409。
- 带未知 `credentialRef` 创建 → 400；库中无明文密钥字段。
- 非法状态迁移（如 `completed → running` via resume）→ 409。
- 契约↔devmock 一致；`go test` / 前端契约测试绿。

## 6. 风险 / 待定

- `plan_json` / `report_json` 体积：大仓计划可能很大，后续可改为附件表或截断摘要 + 详情文件；0.4 MVP 先 JSON 列，设合理上限（如 16MB）并在验收注明。
- discover 落库行为由 `0.4.0-migration-discover.md` 实现；本增量只保证任务模型与 start 契约形状。
