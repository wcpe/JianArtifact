# 功能规格：0.4.0 迁移报告、切换与最终增量扫描

> 状态：已实现（待发版验收）　·　关联 PRD：FR-23

## 1. 背景与目标

迁移执行完成后，管理员需要 **可核对的报告**、**切换指引**，以及在切换窗口对源做一次 **最终增量扫描** 补齐窗口期内新增制品，满足「制品与元数据零丢失、报告一致」。属 M1（P1）。

## 2. 需求（要什么）

- **`GET /api/v1/migrations/{id}/report`**：返回结构化报告（JSON）：
  - 任务摘要（id、来源、策略、起止时间、终态）
  - 按仓库统计：copied / skipped / failed / bytes
  - 失败条目列表（上限 N 条，其余 only count）
  - 警告列表
- **报告持久化**：任务 `completed`/`failed`/`cancelled` 时写入 `report_json`（或完成后只读聚合）；重复 GET 幂等。
- **切换（cutover）**：
  - 文档 + 使用片段级：报告中附「切换检查清单」（DNS/客户端 registry 地址、只读源、最终增量建议）。
  - API：`POST /api/v1/migrations/{id}/finalize`——对同一来源再 discover 差量并 **仅复制新增路径**（增量执行须显式调用，不自动跑）；完成后更新报告 `delta` 段。仅当任务已为 `completed`（或约定终态）时允许。
- **凭据安全复验**：报告与日志不含口令/Token 明文；错误信息脱敏 URL userinfo。
- 不做：自动改客户端配置、自动停 Nexus、多任务报告导出 PDF；崩溃自动 resume（见 ADR-0012，标 failed 等人操作）。

## 3. 设计（怎么做）

- **Report 结构**（草案）：

```json
{
  "taskId": 1,
  "status": "completed",
  "sourceType": "online_rest",
  "conflictPolicy": "skip",
  "startedAt": "...",
  "finishedAt": "...",
  "totals": { "copied": 0, "skipped": 0, "failed": 0, "bytes": 0 },
  "repositories": [
    { "name": "maven-releases", "format": "maven", "copied": 0, "skipped": 0, "failed": 0 }
  ],
  "failures": [{ "repo": "...", "path": "...", "error": "..." }],
  "warnings": ["..."],
  "cutover": {
    "checklist": ["将 CI registry 指向本实例", "Nexus 置只读", "执行 finalize 增量"],
    "delta": null
  }
}
```

- **finalize 增量**：复用 Runner，checkpoint 独立或 `deltaCheckpoint`；只处理 plan 中「目标不存在」的路径（与 skip 类似但对源做一次新发现）。
- **web（可本增量或并入 wizard）**：任务详情页展示报告表格与复制清单。

## 4. 任务拆分

- [x] 执行结束时组装 report_json + GET report API
- [x] 失败条目截断策略（runner 上限 50）
- [x] finalize 增量（夹具：迁完后再往源加文件 → finalize 补上）
- [x] 报告无密钥字段（仅 credentialRef）
- [x] 文档：切换手册段落进 OPERATIONS + 本 spec、CHANGELOG

## 5. 验收标准

- 完成任务后 GET report：totals 与真实写入一致（与 DB asset 计数可对账）。
- 夹具：迁移后源新增 1 文件 → finalize → 目标可见且 report.delta.copied ≥ 1。
- 报告 JSON 与日志 grep 不到测试用的假密码/Token。
- **真机（须用户确认）**：对真实 Nexus 3.70.x 在线路径跑通一次完整迁移 + report 对账 + finalize；对齐 PRD AC-02 的一部分。

## 6. 风险 / 待定

- 增量发现成本：大仓 finalize 可能再次全量 enumerate——可接受为 MVP；后续优化为时间窗过滤。
- finalize 与主迁移共用 Runner/互斥：同一 task 上 start 与 finalize 不得并行。
