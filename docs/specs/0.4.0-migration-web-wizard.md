# 功能规格：0.4.0 管理端迁移向导真连

> 状态：已实现（待发版验收）　·　关联 PRD：FR-20–23（管理端体验）/ FR-11 延伸

## 1. 背景与目标

为管理员提供 **内嵌 web 迁移向导**，对接 0.4 后端 migrations API：选来源 → 填配置/凭据引用 → 预览计划 → 启动 → 看进度/报告 → 切换清单。属 M1（P1），依赖 foundation/discover/execute/report 的 API 可用（可与后端增量并行，先接 devmock）。

## 2. 需求（要什么）

- **导航**：管理端侧栏「迁移」入口（admin 可见）。
- **列表页**：任务表（状态、来源、进度摘要、创建时间）+ 「新建迁移」。
- **向导步骤**（可 Stepper；对齐 ADR-0012）：
  1. 选择来源类型（在线 REST / 离线目录 / 离线包）
  2. 填写配置（URL 或路径）+ `credentialRef`（在线）+ 冲突策略
  3. 调用 **discover** → 展示 plan 与 warnings；此时已落库 **`planned`**（拿到 taskId）
  4. 用户确认后点「开始迁移」→ **`POST .../start`**（显式 start，禁止自动跑）
  5. 执行中：轮询任务状态/进度；支持取消
  6. 完成或失败：展示 report；失败提供「续传 resume」；展示 cutover checklist；链到仓库浏览
- **权限**：非 admin 不可见入口；API 403 时错误态。
- **i18n**：中文文案（与现网一致）。
- 不做：实时 WebSocket（轮询即可）；复杂图表；多任务并行编排 UI；discover 后自动 start。

## 3. 设计（怎么做）

- **路由**：`/migrations`、`/migrations/new`、`/migrations/:id`。
- **api client**：`endpoints.ts` 增 discover / create / start / resume / cancel / report；类型来自 openapi schema。
- **devmock**：内存状态机 `planned →（start）running → completed`；可模拟 failed + resume。
- **组件**：复用 Mantine Stepper、Table、Alert、CopyButton；危险操作（取消）用 modals 确认（与 wiki/管理端同源）。
- **轮询**：仅在 `running` 时 2s interval；终态停止；页面卸载清理。

## 5. 验收标准

- admin 可走完「discover（planned）→ 确认 start → completed 报告」全流程（devmock 与真后端各至少一条路径）。
- discover 成功后列表出现 **planned** 任务；未点开始前无进度写入。
- 失败任务可点续传（resume）；文案说明进程中断后须手动续传。
- 非 admin 无入口或进页 403 错误态。
- 轮询不在终态后空转；取消有确认。
- typecheck/lint/test 绿。

## 6. 风险 / 待定

- 后端 API 字段未完全冻结时前端用宽松类型 + mock 先行；契约变更跟着重 gen。
