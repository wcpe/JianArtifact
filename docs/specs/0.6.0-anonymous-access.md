# 功能规格：内置匿名主体 + 可配置权限 + 全局匿名开关

> 状态：已实现（待整期验收）　·　关联 PRD：FR-66　·　分支：main

## 1. 背景与目标

现状匿名 = 未认证请求，仅能读 `public` 仓库，能力硬编码、不可配置。目标（M2/P2）：

- 把匿名变成**一等 ACL 主体**：管理员可在任意仓库 ACL 中给匿名授 `read`（含 private 仓库）；
- 提供**实例级全局开关**「启用匿名访问」（默认开），关闭后一切匿名请求 401（public 仓库也不例外）；
- 仓库列表 API 支持匿名调用，返回"匿名可读"仓库集合（FR-67 前端依赖）。

## 2. 需求（要什么）

- 内置 `anonymous` 用户（迁移脚本创建，不可登录、不可删除、不可改密/停用/改角色）；ACL 页把它当普通主体选择授权。
- 匿名授权语义：仅 `read` 生效预期场景；`write/admin` 不在 UI 引导（但数据模型不强禁，见 §6 风险）。
- 全局设置 `anonymous_access_enabled`（存库，默认 `true`）：
  - 关 → 所有匿名入口 401：协议层（raw/maven/npm/browse）、API 层（tree/assets/usage/search）、公开仓库列表；
  - 开 → 匿名可读 = `public` 仓库 ∪ anonymous 主体被授 read 的仓库。
- `GET /api/v1/repositories`（契约端点）改可选鉴权：匿名请求返回匿名可读集合；已登录行为不变。
- 设置端点（非契约，随 tree/search 先例）：`GET/PUT /api/v1/settings/anonymous-access`，仅管理员。
- 管理端 UI：用户管理页顶部放「允许匿名访问」开关（仅管理员可见）。
- **不做（范围外）**：细粒度权限动作扩展（FR-36）、匿名限流、settings 通用框架（只做单键）。

## 3. 设计（怎么做）

**鉴权单点**：API 层 `requireRepoRead` 与协议层 `authorize` 均走 `RepositoryService.CanAccess(name, subjectID, action)`，`subjectID==0` 即匿名。匿名逻辑全部收敛于此，协议层/大部分 API 层零改动。

- **迁移 `0007_anonymous_setting.sql`**：
  - `setting(key TEXT PRIMARY KEY, value TEXT NOT NULL, updated_at TEXT)`；
  - 内置用户：`INSERT INTO user (username, password_hash, role, status) VALUES ('anonymous', '!', 'user', 'active')`（`!` 非法 argon2 哈希，永不通过口令验证）。
- **repository 层**：新增 `SettingRepo`（Get/Set）；`UserRepo` 复用 `GetByUsername` 解析 anonymous ID。
- **domain 层**：
  - `SettingService`：`AnonymousAccessEnabled()` / `SetAnonymousAccessEnabled(bool)`（无缓存，SQLite 直查）；
  - `RepositoryService.CanAccess` 改造（注入 SettingService + UserRepo）：
    - `subjectID==0` 时：开关关 → false；开 → public read 放行，否则按 anonymous 用户 ID 查 ACL；
    - `subjectID>0` 行为不变；
  - `SearchAssets` 匿名分支：可搜范围 = public ∪ anonymous ACL 仓库；开关关由 handler 拦 401；
  - `UserService`：`Update/Delete/ChangePassword` 对 anonymous 用户返回 `ErrValidation`；`PrincipalByPassword` 拒绝 `anonymous` 登录。
- **api 层**：
  - `ListRepositories`：`requirePrincipal` → 可选鉴权；匿名时开关关 401，开则按 `CanAccess(name, 0, read)` 过滤；
  - `ListPublicRepositories`：改为"匿名可读列表"（public ∪ anonymous ACL），开关关 401；
  - 新增 `GetAnonymousAccessSetting` / `PutAnonymousAccessSetting` handler（admin），经 `WithProtocolRoutes` 注册。
- **web 前端**：
  - UsersPage 顶部开关卡片（Switch，管理员）调设置端点；
  - AclPage 用户下拉自然包含 anonymous（来自用户列表），无需特殊逻辑；显示时加「匿名」标注。

## 5. 验收标准

- anonymous 在 ACL 授 read 后：private 仓库匿名可经协议层（GET /repository/...）与 API 层（tree/assets/usage）读取；未授权 private 仍 401。
- 开关关闭：public 仓库匿名读 401、公开列表 401、匿名搜索 401；开启后恢复。
- 匿名 `GET /api/v1/repositories` 200，仅含匿名可读仓库；已登录用户行为与现状一致。
- anonymous 用户：口令登录 401；删除/改密/停用/改角色均 4xx 拒绝。
- 越权用例全部拒绝（对齐 AC-05）；既有测试全绿。
- **实机（须用户确认）**：tmp.wcpe.top 部署后匿名 curl 验证 ACL 授权的 private 仓库可读、开关关后 401。

## 6. 风险 / 待定

- 数据模型不强禁给 anonymous 授 write/admin（CHECK 不区分主体）；UI 不引导、文档注明不建议。协议层 write 会因此对匿名生效——视为管理员显式决定。
- `ListPublicRepositories` 语义从"public 仓库"扩为"匿名可读仓库"，未登录侧边栏展示范围随之扩大——正是需求预期。
- 设置端点走非契约路由（与 tree/search/cleanup 同先例），后续统一收编进 OpenAPI 契约（记入技术债）。
