# Spec：Maven 网页上传（FR-73）

> 状态：已实现 ｜ 版本：0.6.0 ｜ 分类：feat ｜ 优先级：P2
> 关联：PRD §4.2 FR-73；依赖 `mavenMetadata`（maven.go）、`AssetService.Put`（asset_service.go）

## 1. 目标与范围

为 **Maven hosted** 仓库补齐管理端网页上传：用户填 GAV + packaging + 选文件，
服务端自动生成 pom.xml、各文件 .md5/.sha1、更新 artifact 级 maven-metadata.xml
及其校验和，使 `mvn` 客户端能以该 GAV 直接解析拉取。

**不做**（YAGNI）：

- **不支持 SNAPSHOT 版本**：网页上传仅限 release 版（SNAPSHOT 需 timestamp/buildNumber
  版本级 metadata 语义，属客户端 deploy 职责）——version 含 `-SNAPSHOT` 返回 400，
  提示改用 `mvn deploy`
- 不支持 classifier（sources/javadoc 附件）与自带 pom 覆盖——pom 一律服务端生成最小骨架
- 不支持 npm 网页上传（已在拆解阶段砍掉）
- 不生成 .sha256/.sha512 文件（GET 侧已有缺失现算兜底 `serveComputedChecksum`）

## 2. 后端设计

### 2.1 新端点（非契约，循 main.go `WithProtocolRoutes` 先例）

```
POST /api/v1/repositories/:name/maven-upload
Content-Type: multipart/form-data
字段：groupId, artifactId, version, packaging(默认 jar), file
```

- 注册：`main.go` 闭包内 `r.POST(..., authMW, ...)`，authMW 用 `authenticator.Optional()`，
  权限在 handler 内校验（同 anonymous-access 先例）；不进 openapi.yaml
- Handler 落 `protocol` 包新文件 `maven_upload.go`：`MavenHandler.UploadForm(c *gin.Context)`
  （内嵌 RawHandler 已有 `authorize` 可复用）

### 2.2 校验（全部失败即 400/403/404/409，不产生任何写入）

1. GAV 三段必填，各段匹配 `^[A-Za-z0-9._-]+$`（拒绝路径穿越字符）；packaging 同规则，缺省 `jar`
2. version 含 `-SNAPSHOT`（不区分大小写）→ 400 `snapshot_not_supported`
3. 仓库存在且 `format == "maven"`、`type == "hosted"`，否则 409（复用 ErrConflict 语义）
4. `authorize(c, repo, "write")`：无主体 401 / 有主体无权限 403 / 仓库不存在 404

### 2.3 写入流程（路径 = `g/r/o/u/p/artifactId/version/`）

| #   | 文件                                   | 内容来源                                                                                                           |
| --- | -------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| 1   | `artifactId-version.packaging`         | 上传文件字节，`assets.Put` 流式入库                                                                                |
| 2   | 同名 `.md5` / `.sha1`                  | 直接取 #1 返回 `Asset.Md5` / `Asset.Sha1`（hex 文本），无需重算                                                    |
| 3   | `artifactId-version.pom`               | 服务端生成最小 pom（modelVersion 4.0.0 + GAV + packaging）                                                         |
| 4   | pom 的 `.md5` / `.sha1`                | 取 #3 返回值同上                                                                                                   |
| 5   | `../maven-metadata.xml`（artifact 级） | 读现存（Resolve 404 视为空）→ `mavenMetadata.merge` 并入本版本 → `encode()`（自动重算 latest/release/lastUpdated） |
| 6   | metadata 的 `.md5` / `.sha1`           | 取 #5 返回值同上                                                                                                   |

- 校验和小文件 Content-Type `text/plain`；pom/metadata 为 `application/xml`；
  主文件按 packaging 猜（jar/war → `application/java-archive`，其余 `application/octet-stream`）
- 重复上传同 GAV：`assets.Upsert` 语义覆盖旧文件；metadata merge 按 version 去重，幂等
- 非原子性说明：多文件顺序写入，中途失败返回 500 且可能留下部分文件——重传即自愈
  （Upsert 覆盖），不引入事务回滚（与 mvn deploy 客户端多次 PUT 的行为一致）
- 成功返回 201：`{ repository, groupId, artifactId, version, files: [路径...] }`

### 2.4 生成的 pom.xml 骨架

```xml
<?xml version="1.0" encoding="UTF-8"?>
<project xmlns="http://maven.apache.org/POM/4.0.0">
  <modelVersion>4.0.0</modelVersion>
  <groupId>{groupId}</groupId>
  <artifactId>{artifactId}</artifactId>
  <version>{version}</version>
  <packaging>{packaging}</packaging>
</project>
```

（packaging=jar 时省略 `<packaging>`，与 Maven 默认一致）

## 3. 前端设计

- `endpoints.ts` 新增 `uploadMavenArtifact(repo, form: {groupId, artifactId, version, packaging, file})`：
  fetch POST multipart + Bearer（仿 `putProtocolAsset` 的鉴权头处理）
- `RepoBrowser.tsx`：上传区按 format 分叉——
  - `format === "raw"`：现有 Raw 上传卡不变
  - `format === "maven" && repoType === "hosted" && allowUpload && !publicMode`：
    新组件 `MavenUploadCard`（`components/repo/` 下）：GroupId / ArtifactId / Version 三个
    TextInput + Packaging Select（jar/war/pom，默认 jar）+ FileButton；上传中按钮 loading；
    成功后 notify + `setReloadNonce` 刷树、清空 version 字段（GAV 常连传多版本，保留 group/artifact）
  - 其余（npm、proxy、group）：保持"请用客户端发布"提示（紧凑化属 FR-74，不在本 FR 动）
- version 含 `-SNAPSHOT` 前端即时校验提示（后端仍兜底）

## 4. 测试计划（先行）

**Go（`protocol` 包 httptest）**：

1. 成功上传 jar：断言 201 且仓库内出现 9 个 asset（jar/pom/metadata 各 + .md5/.sha1），
   metadata XML 含该 version 且 latest/release 正确，checksum 文件内容与 asset 表 md5/sha1 列一致
2. 二次上传新版本：metadata versions 含两版、latest 为后者；重传同版本不重复 version
3. 拒绝：SNAPSHOT version 400、非 maven 仓 409、proxy 仓 409、非法 groupId（含 `../`）400、
   匿名无权限 401、有主体无 write 403
4. packaging=pom 时不重复生成 pom（主文件即 pom，只写主文件 + checksums + metadata）

**前端（vitest）**：

5. maven hosted + 登录：渲染 MavenUploadCard（GAV 字段在）；raw 仓不渲染该卡
6. 填表提交调用 `uploadMavenArtifact`，成功后触发刷新

## 5. 验收标准（PRD FR-73）

- 管理端 Maven hosted 仓库页可见 GAV 表单，上传后文件树出现完整 GAV 目录结构
- `mvn dependency:get -Dartifact=g:a:v`（或项目 dependency）从该仓库解析拉取成功且校验和通过
- **实机验收：tmp.wcpe.top** 上传真实 jar 后用 mvn 客户端拉取验证

## 6. 风险与边界

- packaging=pom 的特判（#4 测试覆盖）避免生成两份冲突 pom
- metadata 读-改-写无锁：并发网页上传同 artifact 可能丢版本——管理端低频操作可接受，
  客户端 deploy 同样无此保护；不引入锁（与现状一致）
- group 仓 GET metadata 合并逻辑（serveGroupMetadata）对 hosted 成员新增版本自动生效，无需改动
