# 功能规格：制品创建/更新时间与源 Nexus 对齐

> 状态：已交付@v0.7.0　·　关联 PRD：FR-91　·　分支：main　·　依赖：FR-83（复制变更日志）、FR-84（复制协议）

## 1. 背景与目标

迁移自源 Nexus 的制品，其 `asset.created_at/updated_at` 在写入时取的是**本地写入时刻**（`datetime('now')`），与源 Nexus 的 `blobCreated/lastModified` 不一致；且复制应用（`applyAsset`）此前用本地时间覆盖，导致复制两侧时间也漂移。本 FR 让**制品的创建/更新时间与源完全对齐，并在复制时自动同步到对端**。

目标（对用户/运维）：

- `admin backfill-times`：从源 Nexus 拉取 `blobCreated/lastModified`，回填本地 `created_at/updated_at`，与源秒级一致（幂等可重复）。
- 复制变更携带创建/更新时间：写路径（Put）与回填（backfill）记录时间，对端 `applyAsset` 用源时间落库，复制两侧时间一致。
- `admin emit-asset-times`：为存量资产重新登记带时间的变更，对端复制应用后自动同步时间，**无需在对端单独回填**。

## 2. 需求（要什么）

- **时间回填命令** `jianartifact admin backfill-times --url <源基址> [--repos <a,b>] [--cred user:pass] [--batch N]`：
  - 从源 Nexus assets API 分页拉取每个资产 `blobCreated`/`lastModified`（RFC3339Nano，转 UTC `YYYY-MM-DD HH:MM:SS`）；
  - 按 仓库名+路径 更新本地 `asset.created_at/updated_at`；本地无此资产/时间非法则跳过；
  - 多仓库并行拉取，避免源清单分页（10 条/页）串行过慢。
- **复制变更携带时间**：
  - `AssetChangeData` 增加 `CreatedAt`（`UpdatedAt` 已有）；`AssetService.Put` 的变更数据携带资产实际时间；
  - `ReplicationService.applyAsset` 用 `AssetRepo.UpsertWithTime` 回填 `created_at/updated_at`；
  - `backfillAssets`（对端全量初始化）同样携带时间。
- **存量时间同步命令** `jianartifact admin emit-asset-times`：
  - 遍历全部 hosted 仓库资产，为每条记录带时间的 put 变更（内容幂等，对端已存在则更新时间）。
- **Sync 水位推进修复**：`ReplicationClient.Sync` 的水位推进到**本批最后一条 seq**（而非对端最新 seq），避免对端一次性积压大量变更时跳过未拉取部分。
- **范围内**：`asset.created_at/updated_at` 的字段语义（created_at=首次创建、updated_at=最后修改），与源 `blobCreated/lastModified` 对应。
- **不做（范围外）**：repl:* 集群配置键不参与复制（已有约束）；变更日志 GC；对端时间不一致的自动对账（由 emit + 复制保证）。

## 3. 设计（怎么做）

- `repository/asset_repo.go`：
  - `UpsertWithTime(repoID, path, blobHash, size, ct, sha1, md5, createdAt, updatedAt)`：INSERT 用提供的 created/updated（非空时），UPDATE 分支在 created 非空时更新、updated 非空时更新，否则回退 `datetime('now')`；
  - `UpdateTimes(repoID, path, createdAt, updatedAt) (int64, error)`：按 仓库+路径 回填时间，路径不存在影响 0 行。
- `domain/asset_service.go`：
  - `Put` 的 `recordChange` 携带资产 `CreatedAt/UpdatedAt`；
  - `BackfillTimes(entries []AssetTimeEntry, batch)`：批量更新（repoID 缓存 + 分片），幂等；
  - `EmitTimeChanges()`：遍历 hosted 仓库资产，记录带时间的 put 变更。
- `domain/replication.go`：`AssetChangeData` 加 `CreatedAt`；`applyAsset`/`backfillAssets` 用 `UpsertWithTime`。
- `domain/replication_client.go`：`Sync` 水位推进改为本批最后一条 `changes[len-1].Seq`。
- `migration/runner/online.go`：`OnlineAsset` 增加 `BlobCreated`/`LastModified`；导出 `ListAllAssets(ctx, base, repo, cred)` 供 CLI 复用。
- `cmd/jianartifact/commands.go`：`admin backfill-times`（多仓库并行拉取）、`admin emit-asset-times`、`parseNexusTime`（RFC3339Nano→UTC `YYYY-MM-DD HH:MM:SS`）。

## 6. 风险 / 待定

- 源清单分页（assets API 10 条/页）经 CDN 拉取较慢：多仓库并行缓解；单仓库大（maven-releases 3 万+）仍需分钟级。
- `UpsertWithTime` 的 UPDATE 分支会更新 `created_at`（非空时）：对端已有资产时以源创建时间覆盖（同源数据一致；不同源由 LWW 保护）。
- emit 一次性产生数万条变更：依赖 Sync 水位修复后逐批拉取，避免跳过。
