# 功能规格：审计日志（谁在何时做了什么）

> 状态：开发中　·　关联 PRD：FR-38　·　分支：feature/audit-log

## 1. 背景与目标

制品仓库的管理写操作（上传/删除/修改制品、仓库/ACL/用户/令牌/设置变更）此前无审计留痕，无法回答"谁在何时上传/删除了什么"。本 FR 提供**独立的审计日志**（`audit_log` 表），记录全部管理写操作，并在管理端提供「审计日志」页按 时间/操作者/操作类型/仓库 筛选查看。

目标（对用户/运维）：

- 每次管理写操作生成一条审计记录（操作者 / 时间 / 操作类型 / 对象 / 仓库 / 结果 / 来源 IP）。
- 管理端「审计日志」页列表 + 筛选 + 分页。
- 与复制变更日志（`repl_change`）**相互独立**：`repl_change` 服务复制同步，`audit_log` 服务审计（不随复制传播，仅本节点本地写操作记录）。

## 2. 需求（要什么）

- **审计记录覆盖**：
  - 制品：上传（`asset.put`）/ 删除（`asset.delete`）；
  - 仓库：创建（`repo.create`）/ 删除（`repo.delete`）/ 配置更新（含 group members、proxy remoteUrl）；
  - ACL：`acl.set`；
  - 用户：创建 / 更新 / 删除 / 口令修改（`user.create/update/delete/password`）；
  - 令牌：签发 / 吊销（`token.create/revoke`）；
  - 设置：`setting.set`。
- **审计字段**：`ts`（操作时间 RFC3339Nano）、`actor`（操作者用户名）、`action`、`entity_type`、`entity_key`、`repo`（关联仓库）、`detail`（补充说明）、`result`（ok/error）、`ip`（来源 IP，取 X-Forwarded-For 或 RemoteAddr）。
- **查询 API**：`GET /api/v1/audit-logs`（仅管理员），分页 + 筛选（`actor`/`action`/`repo`/`from`/`to`）。
- **管理页**：侧边栏「审计日志」入口（仅管理员），列表 + 筛选栏 + 分页 + 操作中文标签。
- **范围内**：仅记录**本节点**本地写操作（审计不复制，对端不共享）。
- **不做（范围外）**：记录读操作 / 登录登出会话审计；审计日志的导出/归档/清理策略（后续）；变更日志 GC。

## 3. 设计（怎么做）

- **迁移 `0012_audit_log.sql`**：`audit_log` 表（字段见上）+ `ts/actor/action/repo` 索引。
- `repository/audit_log_repo.go`：`AuditLogRepo`（`Insert` 尽力而为、`List`/`Count` 按 `AuditFilter` 筛选）。
- `internal/api/audit_handlers.go`：`GetAuditLogs`（查询端点）+ `Handlers.AuditLog`（写路径记录辅助，actor 取 Principal、ip 取 ClientIP）。
- **写路径接入**：管理写 handler（仓库/ACL/用户/令牌/设置）成功后调 `h.AuditLog(...)`；制品上传/删除在 `protocol/raw.go`（`RawHandler` 增加 `AuditFunc` 回调，main 注入 `Handlers.AuditLog`，避免 protocol 依赖 api 包）。
- **注入**：`wiring.go` 创建 `AuditLogRepo`，经 `Deps.AuditLogs` 注入 `Handlers`；`main.go` 注册 `GET /api/v1/audit-logs` 并 `rawHandler.SetAudit(apiHandlers.AuditLog)`。
- **前端**：`AuditLogPage.tsx`（列表 + 筛选 + 分页）、`endpoints.ts`（`getAuditLogs`）、`AppLayout.tsx`（侧边栏入口）、`router.tsx`（`/audit-logs` 路由）。

## 5. 验收标准

- [x] 每次管理写操作（上传/删除/仓库/ACL/用户/令牌/设置）生成一条审计记录，含操作者/时间/对象/结果。
- [x] 审计页可按 操作者/操作类型/仓库 筛选 + 分页（后端 `List`/`Count` 支持对应过滤）。
- [x] 审计记录与真实操作一致（实机上传后 `GET /audit-logs` 可见 `asset.put`）。
- [x] 审计不参与复制（`audit_log` 非复制实体），对端不受影响。

## 6. 风险 / 待定

- `Insert` 尽力而为（失败不阻断业务写）：审计记录可能因 DB 故障丢失（可接受，审计是增强非门禁）。
- IP 取自 `ClientIP`（gin 的 `X-Forwarded-For` 处理），经多层代理时以最近一跳为准。
