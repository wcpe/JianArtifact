# 功能规格：制品批量删除（文件树多选 + 批量删除 API）

> 状态：开发中（实现完成，待实机验收）　·　关联 PRD：FR-103　·　分支：feature/batch-delete-assets

## 1. 背景与目标

仓库浏览页目前只能逐个删除制品（FR-102 文件详情面板单删按钮，调协议 `DELETE /repository/{repo}/{path}`）。当某个目录下积累多个版本（如 Maven `com/example/app/` 下的 `1.0.0/`、`1.1.0/`、`2.0.0/`）需批量清理时，逐条删除效率低且容易遗漏。本 FR 提供**文件树复选框多选 + 工具栏「删除所选」**的批量删除能力，并新增**管理端批量删除 API**（协议层只有单条 DELETE）。

目标：

- 管理端在文件树（限当前浏览的目录）勾选多个**文件行**（单个制品文件），点「删除所选」一次删除。
- 删除语义与单删一致：仅删元数据（blob 保留）、逐条写 `asset.delete` 审计、逐条产生复制变更（对端同步删除）。
- 部分失败时给出明确提示。

## 2. 需求（要什么）

- **前端多选**：文件树（`RepoAssetTree`）每行增加复选框，仅管理员可见；多选**限定当前目录树内已加载的文件行**（勾选文件，不含目录递归）。
- **工具栏**：文件树顶部/底部在勾选数 >0 时出现「删除所选（N）」按钮（仅管理员），点击弹确认框（危险操作，列出将删除的文件数）。
- **批量删除 API**：新增管理端端点 `POST /api/v1/repositories/{name}/assets/batch-delete`，body `{ paths: string[] }`，仅管理员；对每个 path 复用现有 `AssetService.Delete`（元数据删 + 复制 tombstone），并逐条写 `asset.delete` 审计；返回 `{ deleted: number, failed: [{path, error}] }`。
- **部分失败**：前端展示失败明细（路径 + 原因），成功部分照常生效。
- **成功后**：刷新文件树，清空勾选。
- **范围内**：仅管理员；限文件行（不含目录递归删除）；blob 保留；审计/复制逐条联动。
- **不做（范围外）**：目录级递归删除；blob 回收（需新 ADR）；跨目录多选；非管理员批量删除；批量删除的 OpenAPI 之外的 CLI 形态。

## 3. 设计（怎么做）

### 后端

- **契约**：`api/openapi.yaml` 新增 `POST /api/v1/repositories/{name}/assets/batch-delete`（仅管理员；401/403/404；请求 `BatchDeleteAssetsRequest{paths: string[]}`，响应 `BatchDeleteAssetsResponse{deleted, failed:[{path,error}]}`）。经 `task gen` 生成 Go 类型 + `ServerInterface` 方法；经 devmock `gen` 生成 schema 与 mock 路由。
- **Handler**：`internal/api/` 新增 `batch_delete_assets_handlers.go`：`requireAdmin` → 校验 body（paths 非空、单条 ≤ 某上限如 500、路径非空）→ 逐条调 `assets.Delete(repoName, path)`，成功写 `h.AuditLog(c, "asset.delete", "asset", repo+"/"+path, repo, "", "ok")`，失败收集进 failed（不整体回滚，逐条尽力）。
- **复用**：`AssetService.Delete`（已含元数据删 + 复制 tombstone，见 `asset_service.go:376`），无需改 domain。
- **接入**：`wiring.go` 注入 assets 到 `api.Handlers.Deps`；`main.go` 经生成路由注册（生成链自动挂到 `RegisterHandlers`）。

### 前端

- `api/endpoints.ts`：新增 `batchDeleteAssets(repo, paths)` → POST 契约端点。
- `components/repo/RepoAssetTree.tsx`：增加复选框渲染与选中态（`selectedPaths: Set<string>` + 回调）；父组件维护 `Set<string>`。
- `components/repo/RepoBrowser.tsx`：工具栏「删除所选」按钮（勾选数 >0 且管理员时显示）→ 确认框 → 调 `batchDeleteAssets` → 失败明细提示 → 刷新树（复用 `reloadNonce`）→ 清空勾选；切换目录或搜索上下文时也清空勾选，保证请求只包含当前上下文的文件。
- `i18n/zh.ts`：新增批量删除相关文案（按钮、确认、成功、失败明细）。
- 仅管理员：用 `useAuth().user?.role === "admin"` 门控（与 FR-102 一致）。

### 测试

- 后端：handler 单测（管理员可删 / 非管理员 403 / 未认证 401 / 空 paths 400 / 部分失败返回 failed）+ 复制 tombstone 与审计逐条写入断言。
- 前端：勾选多行 → 点删除所选 → 断言 POST 请求体含全部 paths；确认后刷新树并清空勾选；切换目录或搜索上下文后不保留勾选；非管理员不显示复选框/按钮；部分失败提示。

## 5. 验收标准

- [ ] 管理员在文件树勾选多个文件，点「删除所选」一次删除成功；树刷新、勾选清空。
- [ ] 批量删除逐条写 `asset.delete` 审计（审计页可见多条）并产生复制变更（对端同步删除）。
- [ ] 部分失败（如混入已不存在路径）返回 `failed` 明细，前端提示，成功部分照常生效。
- [ ] 非管理员不显示复选框与「删除所选」；未认证/无权限访问批量删除 API 返回 401/403。
- [ ] 空 paths / 超上限返回 400。
- [ ] 实机（须用户确认）：在真实仓库目录勾选多个版本批量删除，审计页与对端同步生效。

## 6. 风险 / 待定

- 逐条删除（非事务）：批量中部分失败会留下"部分已删"，属预期（尽力而为 + 失败明细），不做整体回滚。
- paths 上限：默认 500，超限 400；勾选数量超过时前端应提示分批。
- 与 FR-102 共用删除语义（元数据 + blob 保留 + 审计 + 复制），避免两处删除行为漂移。
