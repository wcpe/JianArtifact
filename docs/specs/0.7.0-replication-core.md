# 功能规格：复制变更日志与冲突解决（复制引擎核心）

> 状态：已交付@v0.7.0　·　关联 PRD：FR-83　·　分支：main　·　依赖：ADR-0013

## 1. 背景与目标

为多节点制品库（0.7.0 集群功能，见 ADR-0013）提供复制引擎的核心：**变更日志 + last-writer-wins 冲突解决 + 删除 tombstone + seq 断点续传**。FR-83 是本批 FR 的基础（FR-84 复制协议 / FR-85 调度 / FR-86 管理面均依赖它），但**不实现网络传输**（协议属 FR-84）。

目标（对用户）：

- 每个节点本地记录全部写操作（制品 / 仓库 / 用户 / ACL / 令牌 / 配置），带全局递增序号、写入节点、时间戳；
- 对端应用变更时按 `(ts, node_id)` 后写覆盖（last-writer-wins）；
- 删除以 tombstone 落日志，对端可识别并删除本地对应实体；
- 支持按 seq 断点续传（本地水位 = 已应用到的最远变更序号）。

## 2. 需求（要什么）

- **变更日志表 `repl_change`**（迁移 0010）：`seq`（自增主键）、`node_id`、`op`（put/delete）、`entity_type`、`entity_key`、`data`（变更后 JSON）、`ts`（RFC3339Nano）。
- **全部写路径接入**：domain 层以下写操作在业务写成功后各记一条变更日志：
  - 制品：`AssetService.Put` / `AssetService.Delete`（含 Maven 上传、npm publish、Raw 上传等一切最终落到 asset 的写）
  - 仓库：`RepositoryService.Create` / `Update` / `Delete`（配置 / 可见性 / 描述变化都记）
  - ACL：`RepositoryService.SetAcl`
  - 用户：`UserService` 创建 / 更新 / 删除 / 口令修改
  - 令牌：`TokenService` 创建 / 吊销
  - 配置：`SettingService` 写入
- **节点标识 `node_id`**：每节点唯一、持久化（首次启动生成随机 ID 存 `setting`，或用环境变量 `JIAN_NODE_ID` 显式指定——显式优先）。
- **变更应用器（Applier）**：本地实现"把一条远端变更应用到本地业务表"的逻辑（LWW 裁决 + tombstone 识别 + 自然键映射）。FR-83 提供纯本地可测的 `Apply(change)`，FR-84 负责把远端拉到的变更喂给它。
- **LWW 裁决**：应用变更前，查本地该 `entity_key` 最近一条变更的 `(ts, node_id)`；若本地更晚则跳过（该变更已被更新的本地写入覆盖）。
- **seq 水位**：可查询本地最新 `seq`（供 FR-84 作为 `since`）；可查询指定 `entity_key` 的最近变更（供 LWW）。
- **删除 tombstone**：`op=delete` 的变更 `data` 为 `{"deleted":true,...}`；应用时删本地实体；tombstone 也参与 LWW（比 tombstone 更晚的 put 可"复活"实体）。
- **跨节点自然键一致性**：同步不依赖数值主键（SQLite 自增 ID 两节点不一致），全部实体用**自然键**编址；关联（ACL→user、token→user）在 data 中带 `username` 而非 `userID`，应用时解析本地 ID。
- **不做（范围外）**：网络传输协议（FR-84）、同步调度 / 对账 / 首启全量（FR-85）、管理面（FR-86）、变更日志 GC（本 FR 先保留全量，GC 策略随 FR-85 对账窗口定）、自动失效切换（部署层）。

## 3. 设计（怎么做）

### 3.1 数据模型（迁移 0010）

```sql
CREATE TABLE repl_change (
  seq         INTEGER PRIMARY KEY AUTOINCREMENT,
  node_id     TEXT    NOT NULL,             -- 写入节点（本节点 node_id）
  op          TEXT    NOT NULL,             -- 'put' | 'delete'
  entity_type TEXT    NOT NULL,             -- 'asset'|'repository'|'acl'|'user'|'token'|'setting'
  entity_key  TEXT    NOT NULL,             -- 自然键，见 3.2
  data        TEXT    NOT NULL,             -- 变更后数据 JSON（delete 为 tombstone）
  ts          TEXT    NOT NULL              -- RFC3339Nano，写入节点本地时钟
);
CREATE INDEX idx_repl_change_entity ON repl_change(entity_type, entity_key, ts);
```

### 3.2 自然键约定（跨节点一致，不依赖数值 ID）

| entity_type  | entity_key 格式                      | data 关键字段                                             |
| ------------ | ------------------------------------ | --------------------------------------------------------- |
| `asset`      | `repo:<name>/<path>`                 | path, blobHash, size, contentType, sha1, md5, updatedAt   |
| `repository` | `repo:<name>`                        | name, format, type, visibility, description, config(JSON) |
| `acl`        | `acl:<repoName>:<username>:<action>` | repoName, username, action                                |
| `user`       | `user:<username>`                    | username, role, status, passwordHash, createdAt           |
| `token`      | `token:<hash>`                       | hash(sha256 摘要), username, name, createdAt, revokedAt   |
| `setting`    | `setting:<key>`                      | key, value                                                |

> 令牌 / 凭据：仅同步 sha256 摘要与引用，**明文密钥永不入库、不同步**（延续 ADR-0002 / SECURITY 约定）。口令同步 argon2id 哈希（非明文，可登录验证），用户选"全量同步用户"故含口令哈希。

### 3.3 模块与依赖（遵循分层，不反向穿透）

```
repository（新增 repl_change_repo.go）   repl_change 表读写：Append / LatestSeq / LastChangeOf(entity) / ListSince(seq, limit)
  ↓
domain（新增 replication_service.go）    ReplicationService：
                                           - Record(entityType, entityKey, op, data)  // 写路径调用
                                           - LatestSeq()
                                           - Apply(change)                            // LWW 裁决 + 落本地业务表
                                           - NodeID()
  ↓
写路径接入（domain 各 Service）          Put/Delete/Create/Update/SetAcl/... 成功后调用 Record
```

- `persistence` 不动（repl_change 经 repository 层访问，单连接串行化已保证 seq 自增安全）。
- `Apply` 内复用现有各 Repo 的写方法（`AssetRepo.Upsert/DeleteByPath`、`RepoRepo.Create/Update*`、`UserRepo.*`、`TokenRepo.*`、`SettingRepo.Set`、`AclRepo.Set`），避免重复实现业务写。

### 3.4 LWW 与 tombstone 语义

- 比较键：`(ts, node_id)` 字典序。应用前 `LastChangeOf(entityKey)`：本地存在且 `(ts,node_id) > (远端)` → 跳过；否则应用。
- `op=put`：upsert（repository 按 name 存在则 update，asset 按 repo+path upsert）。
- `op=delete`：删除本地实体；tombstone 本身也写入本地 `repl_change`（作为一次本地变更），保证后续更晚 put 能覆盖它。
- ACL / token 的 user 关联：data 带 `username`，Apply 时经 `UserRepo.GetByUsername` 解析本地 ID；对端先同步 user 变更（依赖 FR-85 排序保证 user 先于其 acl/token 到达——FR-83 的 Apply 对缺失关联**不报错**，落到对账兜底）。

### 3.5 node_id 来源

- 优先环境变量 `JIAN_NODE_ID`（部署两节点时显式指定，便于辨识）；
- 未设则首次启动生成随机 16 hex 并持久化到 `setting`（key `node_id`）。

## 5. 验收标准

- **每类写操作产生变更日志**：对 asset/repository/acl/user/token/setting 各执行 put/delete，`repl_change` 均出现对应 `op`、`entity_key`、`data` 正确的记录。
- **LWW 后写覆盖**：同一 `entity_key` 两条变更（ts 早 / ts 晚），Apply 晚者覆盖早者；本地已有更晚变更时，Apply 早者跳过。
- **删除 tombstone**：`op=delete` 变更 Apply 后本地实体删除；比 tombstone 更晚的 put Apply 后实体恢复（复活语义正确）。
- **seq 断点续传**：`LatestSeq` 正确；`ListSince(seq)` 返回 seq 之后的有序变更。
- **自然键一致性**：Apply 的 ACL/token 变更不依赖数值 ID；`username` 解析正确。
- **安全**：令牌仅同步摘要、明文不出现；凭据引用不同步明文。
- **测试**：domain 单元测试（Record/LWW/tombstone/Apply 各路径）+ repository 集成测试全绿；既有测试全绿。
- **实机（FR-84/85 落地后整体验收，用户确认）**：两台机器 / 两个域名组主备，双向上传/删除经复制协议同步一致。

## 6. 风险 / 待定

- **日志与业务写非同一事务**（ADR-0013 决策 1）：崩溃窗口可能丢日志，靠 FR-85 对账兜底；本 FR 不做事务化改造（避免大规模重构写路径）。
- **变更日志无 GC**：本 FR 保留全量，GC 策略随 FR-85 对账窗口确定后补（待定）。
- **ACL/token 关联 user 的到达顺序**：FR-83 的 Apply 对缺失关联不报错（幂等），靠对账兜底；是否要求 FR-85 按序同步待定。
- **时钟漂移**：LWW 用 node_id 打破同 ts 平局；漂移造成误判由对账修复（ADR-0013 决策 5）。
