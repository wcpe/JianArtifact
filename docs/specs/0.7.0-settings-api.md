# 功能规格：设置 API 与基础配置动态生效

> 状态：已交付@v0.7.0　·　关联 PRD：FR-89　·　分支：main

## 1. 背景与目标

设置页统一化（FR-89/FR-90）的后端支撑。当前实例级基础配置来源不一：

- 匿名访问开关已入库（`anonymous_access_enabled`，web 可改，藏在用户页）；
- 对外基础 URL（`JIAN_PUBLIC_URL`）、回源超时（`JIAN_UPSTREAM_TIMEOUT`）、同步间隔（`JIAN_SYNC_INTERVAL`）**只读环境变量**，web 无法修改，改动需重启进程。

目标：这三项基础配置与匿名开关一并入库 `setting`，提供仅管理员的设置读写端点，且**写后运行时生效（不重启）**，为 FR-90 设置页（web UI + 配置迁移）提供后端契约。属 P2，集群期（0.7.0）延展。

## 2. 需求（要什么）

- 对外 URL / 回源超时 / 同步间隔三个配置项入库 `setting`，web 可读可改；改动不重启即生效。`public_url` 是节点本地配置，不参与复制。
- 新增设置读写端点（仅管理员）：GET 读全部可配置项、PUT 部分字段写入，非法输入拒绝。
- env 值作为首启默认兜底写入（与对端 URL/令牌 FR-88 一致的模式），web 可覆盖。
- 范围内：仅基础设置四项（匿名开关、对外 URL、回源超时、同步间隔）。
- 范围外：集群配置（对端 URL/令牌/自动开关）沿用现有 `GET/PUT /api/v1/cluster`（FR-88），本 FR 不动；设置页 UI 属 FR-90。

## 3. 设计（怎么做）

### 3.1 Setting key（复用 `setting` 表，无新表）

| key                        | 含义                                               | 缺省               |
| -------------------------- | -------------------------------------------------- | ------------------ |
| `anonymous_access_enabled` | 匿名访问开关（已有）                               | true               |
| `public_url`               | 对外基础 URL（FR-87 增强为可 web 配置）；空=未配置 | 空（回退请求推断） |
| `upstream_timeout`         | 回源整体超时（秒）                                 | 30                 |
| `repl:sync_interval`       | 同步轮询间隔（秒）                                 | 5（env 默认）      |

### 3.2 env 兜底写 setting（wiring 启动时）

与 FR-88 对端 URL/令牌兜底同一模式：setting 缺 key 或值为空时写入 env 值，web 后续可覆盖。

- `JIAN_PUBLIC_URL` → `public_url`（仅当前节点）
- `JIAN_UPSTREAM_TIMEOUT`（缺省 30）→ `upstream_timeout`
- `JIAN_SYNC_INTERVAL`（缺省 5）→ `repl:sync_interval`

匿名开关维持现有"缺省 true"读取逻辑，不兜底。

### 3.3 动态生效机制（三项各自落地）

1. **同步间隔**：`ReplicationScheduler.run` 每轮 `ticker.C` 触发后读 `repl:sync_interval`（秒），与当前 interval 不同则 `ticker.Reset`；缺省（setting 无值）回退构造时 interval（env/默认 5s）。仅调度器单 goroutine 读写 ticker，无并发竞争。
2. **对外 URL**：`Handlers.apiBaseURL` 改读 `SettingService.PublicURL()`（读 `public_url`）；空值回退现有请求推断逻辑（`X-Forwarded-Proto` + Host）。
3. **回源超时**：`upstream.Client` 新增 `SetTimeout(d)`（RWMutex 保护替换内部 `http.Client`，`Fetch` 读锁取引用，并发安全）；`Handlers` 新增可选回调字段 `OnUpstreamTimeoutChange func(time.Duration)`，写成功触发；wiring 注入 `func(d) { upstreamClient.SetTimeout(d) }`。api 层不依赖 upstream 实现，仅函数回调，维持分层。

### 3.4 设置端点 GET/PUT /api/v1/settings（仅管理员，非契约）

经 `WithProtocolRoutes` 注册，风格对齐 cluster 端点（`requireAdmin` + 可选指针字段 + `writeDomainErr`）。

- `GET /api/v1/settings` → `{ anonymousAccess: bool, publicUrl: string, upstreamTimeout: int(秒), syncInterval: int(秒) }`
- `PUT /api/v1/settings`：可选字段，传哪个改哪个
  - `anonymousAccess *bool`
  - `publicUrl *string`（http/https 绝对 URL 或空串；非法拒绝 400）
  - `upstreamTimeout *int`（1–3600 秒；非法拒绝 400）
  - `syncInterval *int`（1–3600 秒；非法拒绝 400）
  - 写成功返回更新后全量配置
- 匿名开关旧端点 `GET/PUT /api/v1/settings/anonymous-access` **保留不动**（兼容既有调用；FR-90 前端切到新端点后仍可用）。

### 3.5 SettingService 扩展

- `PublicURL() string`：读 `public_url`，缺省空
- `SetPublicURL(v string) error`（记变更日志）
- `SyncIntervalSecs() int`：读 `repl:sync_interval`，缺省/非法 0
- `SetSyncInterval(secs int) error`（记变更日志）
- `UpstreamTimeoutSecs() int`：读 `upstream_timeout`，缺省/非法 0
- `SetUpstreamTimeout(secs int) error`（记变更日志）
- 复用 `AnonymousAccessEnabled` / `SetAnonymousAccessEnabled`

- `apps/server/internal/upstream/client.go`：`SetTimeout`
- `apps/server/internal/domain/setting_service.go`：新方法

## 5. 验收标准

- 写 `repl:sync_interval=10` → 下一轮调度生效（ticker 周期变 10s；scheduler 测试断言读取变化）。
- 写 `public_url` → `apiBaseURL` 立即用新值（handler 测试）；空值回退请求推断；该键不产生复制变更，也不应用对端变更。
- 写 `upstream_timeout` → 回调触发 `upstreamClient.SetTimeout`（测试断言 client 超时更新、并发 Fetch 无数据竞争）。
- PUT 非法值（非数字、越界 1–3600、非法 URL）→ 400；仅管理员可访问，非 admin 403。
- 缺省回退：setting 空时 `publicUrl` 空、`syncInterval` 用 env/默认 5、`upstreamTimeout` 用默认 30。
- 服务端 `go test ./...` 全绿（含 `-race` 的 httpserver/domain 并发相关包）。
- 实机（真机）：部署后在设置端点写配置，**不重启**确认生效（同步日志周期 / usage URL / 回源超时行为）。

## 6. 风险 / 待定

- 回源超时动态化经回调注入，仅 web 写路径触发；直改数据库不触发（可接受，与 peer_url 同待遇）。
- `repl:sync_interval` 键前缀沿用复制命名空间；对外 URL / 回源超时用无前缀键（实例级配置），与 `anonymous_access_enabled` 一致。
- 设置端点暂不入 OpenAPI 契约（与 cluster / sync-logs 同先例，后续统一收编）。
