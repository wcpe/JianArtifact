# 功能规格：集群同步历史详情模态框（查看某次同步的具体变更）

> 状态：已交付@v0.7.0　·　关联 PRD：FR-98　·　分支：main　·　依赖：FR-83（复制变更日志）、FR-88/95（同步历史可视化）

## 1. 背景与目标

集群页的「同步历史」此前只展示汇总（变更/应用/失败条数、实体构成），无法查看**某次同步具体拉取/应用了哪些变更**（哪些资产/仓库/用户，put 还是 delete）。本 FR 提供**同步历史详情模态框**：点击一条同步记录的「详情」在当前页弹出明细，按该次同步的 `fromSeq→toSeq` 区间从 `repl_change` 反推具体变更列表（实体类型 / 操作 / 对象 / 时间），分页展示；关闭后保持同步历史列表上下文。

目标（对用户/运维）：

- 集群页同步历史每条可点击「详情」，在模态框查看该次同步的具体变更明细并可关闭返回。
- 变更明细从 `repl_change` 反推（按该次同步的 seq 区间），不额外记录副本。
- 支持按实体类型分类和正向分页（大同步可能数万条变更）。

## 2. 需求（要什么）

- **后端**：`GET /api/v1/cluster/sync-logs/:id/changes`（仅管理员），按 `repl_sync_log:id` 的 `fromSeq→toSeq` 从 `repl_change` 分页返回变更（`limit`/`offset`，上限 500）。
  - `SyncLogRepo.Get(id)`：取单条同步记录（含 fromSeq/toSeq）。
  - `ReplChangeRepo.ListRange(from, to, limit, offset)` / `CountRange(from, to)`：分页查询 seq 区间 (from, to] 的变更。
- **前端**：集群页同步历史表新增「详情」列，点击后在当前页打开模态框；`SyncLogChangesView` 展示该次同步的变更列表（seq / 操作徽章 / 实体类型 / 对象路径 / 时间）+ 同步摘要（状态/变更/应用/失败/Blob）+ 分类与分页，关闭模态框后回到原同步历史列表。
- **范围内**：变更来自 `repl_change`（seq 区间反推）；失败数与错误摘要分别由同步记录的 `failed`、`errorText` 展示。由于 `repl_change` 不记录单次应用结果，详情列表不把失败状态逐条归因到具体变更项。
- **不做（范围外）**：变更的原始 data 详情展开（仅列 entityKey）；跨同步的对账/重放；审计日志（FR-38 独立）。

## 3. 设计（怎么做）

- `repository/sync_log_repo.go`：新增 `Get(id)`（单条查询，不存在 ErrNotFound）。
- `repository/repl_change_repo.go`：新增 `ListRange(from, to, limit, offset)` 与 `CountRange(from, to)`（`WHERE seq > ? AND seq <= ?`）。
- `domain/replication.go`：`ReplicationService` 暴露 `ListChangeRange` / `CountChangeRange`（转发 ReplChangeRepo）。
- `internal/api/replication_handlers.go`：`GetClusterSyncLogChanges`（校验 admin + 取 sync-log + 查区间变更 + 分页）。
- `main.go`：注册 `GET /api/v1/cluster/sync-logs/:id/changes`。
- 前端：`ClusterPage.tsx`（同步历史行加「详情」链接并管理模态框开关）；`SyncLogChangesView.tsx`（同步摘要 + 变更表格 + 分类/分页，可被模态框复用）；`endpoints.ts`（`getClusterSyncLogChanges` + `ReplChangeEntry` 类型）。

## 5. 验收标准

- [x] 点击任意同步历史记录的「详情」打开模态框，列出该次同步的变更（与 fromSeq/toSeq 区间对应），关闭后返回原列表。
- [x] 变更多时正向分页（`total` 正确、页码 2 对应 `offset=pageSize`），切换实体分类后回到第一页。
- [x] 空同步（changes=0）显示"该次同步无变更记录"。
- [x] 失败数与错误摘要在同步摘要/历史行展示，不对详情变更逐条标失败。
- [x] 非管理员访问 401/403。

## 6. 风险 / 待定

- 变更从 `repl_change` 反推：若变更日志被 GC 清理，历史同步明细会缺失（当前 repl_change 保留全量，GC 策略未定）。
- 大同步（数万变更）明细查询依赖 `ListRange` 分页 + 索引（seq 主键），性能可接受。
