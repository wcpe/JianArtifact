# 功能规格：proxy/group 404 负缓存

> 状态：已交付@v0.7.1　·　关联 PRD：FR-111　·　分支：feature/404-negative-cache

## 1. 背景与目标

FR-110 后 group 缺失制品返回 404 仍需 6-9s（并行探测所有未熔断 proxy 成员）。对**同一个缺失路径的反复请求**（如 Gradle 反复尝试缺失子模块），每次都重新探测一轮，浪费且延迟高。借鉴 Nexus `NegativeCacheHandler`：对明确 404 做短窗缓存，后续同路径请求秒级返回 404。

目标：同缺失路径连续请求，首次 6-9s，后续 <1s（负缓存命中）。

## 2. 需求（要什么）

- **404 负缓存**：proxy/group 读路径对**明确 404**（所有成员确认不存在，非上游故障）做短窗缓存（TTL 60s），同路径后续请求直接返回缓存 404，不再回源/探测。
- **上游故障不缓存**：上游连接失败/超时/5xx（非 404）导致的错误**不写负缓存**，避免把上游故障误缓存成"永久不存在"。
- **复制请求跳过**：复制同步（ReplicationClient）请求跳过负缓存，避免对端同步被缓存 404 误导。
- **成功失效**：同路径后来成功（上传/同步进来）时失效负缓存。
- **键粒度**：按 `(repoID, path)`；仅 GET/HEAD；内存态。
- **范围内**：读路径负缓存；不涉及 blob/元数据缓存。
- **不做（范围外）**：分布式负缓存、持久化、LRU 上限之外的复杂策略。

## 3. 设计（怎么做）

- `domain/asset_service.go` 新增 `negativeCache`（`sync.Mutex` + `map[string]time.Time`，键 = `repoID\0path`）：
  - `Resolve`/`groupGet`/`proxyGet` 入口先查负缓存：命中 → 直接 `ErrNotFound`（不再回源）。
  - 明确 404 时写负缓存（TTL 60s）；错误（非 404）不写。
  - 写路径（`Put`/`Delete`/复制应用）失效对应负缓存键。
- **不可判定 404 不写负缓存（M-1，关键）**：group 层写负缓存前须判定本次 404 是否「确认不存在」。若存在成员被熔断（FR-110 fuse）、auto-blocked（FR-112）或 offline（FR-113）**跳过**，则该 404 是「不可判定」（可能只是全部成员暂时不可用），**不写负缓存**，避免把上游故障误缓存为永久不存在。
  - 实现：`groupGet` 返回带原因的 404（附「是否有成员不可判定」标志，如 `ErrNotFoundUncertain` 或附带 context 标记）；`proxyGet` 的 auto-block 阻止窗口快速失败同样不写负缓存。
- 与 `proxyFuse`（FR-110）/ `proxyHealth`（FR-112）区分：fuse/health 跳过不可达成员，负缓存跳过整个 path 的探测。
- **负缓存失效联动（M-1）**：auto-block 恢复（FR-112 后台探测成功 → AVAILABLE）时，若之前因「不可判定」未写负缓存则无残留；对已写的「确认不存在」负缓存，不因 auto-block 恢复而失效（其 TTL 自会过期），但复制/上传成功仍须失效。

## 4. 任务拆分

- [ ] domain 负缓存结构 + 读路径接入（Resolve/groupGet/proxyGet）
- [ ] groupGet 返回「不可判定 404」标志；有跳过成员时不写负缓存
- [ ] 写路径失效（Put/Delete/复制应用）
- [ ] 复制请求跳过负缓存
- [ ] 测试：命中/未命中/上游故障不缓存/**有成员被熔断或 offline 跳过时不缓存**/成功后失效/复制跳过
- [ ] 文档同步：ARCHITECTURE、CHANGELOG

## 5. 验收标准

- 同缺失路径连续请求：首次 6-9s，后续（TTL 内）<1s 返回 404。
- 上游 5xx/超时导致的错误不写负缓存（下次仍尝试回源，不误判不存在）。
- **有成员被熔断/auto-blocked/offline 跳过时，group 404 不写负缓存**；上游恢复后同路径立即重试成功，不返回缓存的过期 404。
- 同路径成功上传/同步后负缓存失效，可立即读到新制品。
- 复制同步请求不受负缓存影响。
- 测试全绿（含 -race）。

## 6. 风险 / 待定

- TTL 内新制品可能延迟可见（最长 60s）——可通过"成功失效"缓解，属可接受权衡。
- 键粒度 `(repoID, path)` 简单直接；group 的 404 在 `groupGet` 层缓存（整个 group 探测结果），proxy 的 404 在 `proxyGet` 层缓存。
