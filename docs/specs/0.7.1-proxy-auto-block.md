# 功能规格：proxy 上游 auto-block 主动探测恢复

> 状态：草拟　·　关联 PRD：FR-112　·　分支：feature/proxy-auto-block

## 1. 背景与目标

FR-110 用固定 30s TTL 的 `proxyFuse` 熔断不可达上游——窗口内跳过，30s 后被动重试。借鉴 Nexus `BlockingHttpClient` 的 auto-block 状态机，改为**仓库级连接状态 + Fibonacci 退避 + 后台 HEAD 主动探测恢复**，更成熟：阻止窗口递增、恢复无需等到窗口结束（探测成功即恢复）。

目标：上游不可达时 group 请求秒级 404（阻止窗口零连接）；上游恢复后自动快速可用。

## 2. 需求（要什么）

- **仓库级连接状态机**：每个 proxy 仓库维护 `RemoteConnectionStatus`（READY / AVAILABLE / UNAVAILABLE / AUTO_BLOCKED / OFFLINE / BLOCKED）。
- **auto-block 触发**：上游失败（IO 异常、连接失败/超时、应阻止的状态码如 5xx/401/403）→ 进入 `AUTO_BLOCKED_UNAVAILABLE`，`blockedUntil = now + Fibonacci(40s)`（40s→80s→160s… 递增）。
- **阻止窗口零连接**：blocked 窗口内，proxy 读直接快速失败（抛 `RemoteBlockedIOException`），**不发起上游连接**——这是"group 读不拖慢"的关键。
- **后台主动探测恢复**：到 `blockedUntil` 后，后台线程发 HEAD 探测上游；成功 → 恢复 `AVAILABLE` 并 reset 退避；失败 → 继续延长。
- **手动 BLOCKED**（可选保留）：管理员可手动阻止/解阻。
- **状态可查**：连接状态经接口暴露（供 FR-114 状态展示）。
- **范围内**：proxy 上游连接状态管理；不涉及 blob/元数据缓存。
- **不做（范围外）**：持久化状态（内存态，重启重置）、分布式状态同步。

## 3. 设计（怎么做）

- `domain/` 新增 `RemoteStatus` 类型 + `proxyHealth`（仓库级状态机）：
  - 字段：`state`（枚举）、`blockedUntil`、`autoBlockSequence`（Fibonacci，起始 40s）、`checkStatusThread`。
  - `shouldBlock()`：blocked 窗口内返回 true → proxyGet 直接快速失败。
  - `recordFailure()`：进入 AUTO_BLOCKED，blockedUntil = now + next Fibonacci，启动后台探测线程。
  - `recordSuccess()`：恢复 AVAILABLE，reset 退避，中断探测线程。
  - 后台 `CheckStatus`：sleep 到 blockedUntil → HEAD 探测上游 → 成功恢复/失败延长。
- `AssetService` 持有 `proxyHealth`（替换/增强 FR-110 的 `proxyFuse`）。
- `proxyGet` 失败 → `recordFailure`；成功 → `recordSuccess`。
- 上游 HEAD 探测用 `upstream.Client`（IPv4 优先）。

## 4. 任务拆分

- [ ] 文档同步：ARCHITECTURE、CHANGELOG

## 5. 验收标准

- 上游不可达：首次失败后进入 AUTO_BLOCKED，阻止窗口内 group 请求**零连接快速 404**（<1s）。
- 上游恢复：后台 HEAD 探测成功后自动恢复 AVAILABLE，后续请求正常回源。
- 退避递增：持续失败 blockedUntil 按 Fibonacci 递增（40s→80s→…）。
- 状态经接口可查（FR-114 用）。
- 测试全绿（含 -race、并发安全）。

## 6. 风险 / 待定

- 内存态状态机重启重置——可接受（补丁版；持久化留后续）。
- 后台探测线程需防泄漏（stop 时中断、自引用检查，借鉴 Nexus `CheckStatus` 的 `currentThread` 防自中断）。
- 与 FR-110 `proxyFuse` 的关系：FR-112 取代/增强它（fuse 逻辑并入 proxyHealth）。
