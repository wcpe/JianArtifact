# 功能规格：仓库级 online/offline 开关

> 状态：已交付@v0.7.1　·　关联 PRD：FR-113　·　分支：feature/repository-online-offline

## 1. 背景与目标

借鉴 Nexus 的仓库 online/offline 状态：管理员可手动把 proxy/group 仓库置为 offline，group 读**跳过 offline 成员**（不再尝试回源），从而把"已知不可达/维护中"的上游排除出聚合读，减少无效探测。offline 状态持久化，重启保留。

## 2. 需求（要什么）

- **仓库级 online/offline 属性**：repository 增加持久化字段 `online`（默认 true）。
- **group 读跳过 offline 成员**：`groupGet` 遍历成员时跳过 `online=false` 的成员（本地快查与并行回源都跳过）。
- **offline 时行为**：offline proxy 的读请求直接返回 404/错误（不发起回源）；offline 状态在管理端可见。
- **持久化**：`online` 随 repository 配置持久化（SQLite），重启保留。
- **范围内**：proxy/group 仓库可 offline；hosted 是否可 offline 由实现决定（默认也可，但影响小）。
- **不做（范围外）**：自动 offline（由 FR-112 auto-block 处理，是独立的 AUTO_BLOCKED 状态）；offline 触发下游事件的复杂逻辑。

## 3. 设计（怎么做）

- `repository` 表新增列 `online`（优先独立列，查询友好），迁移 `0015` 加列默认 1。
- `repository.Repository` 模型加 `Online` 字段；`RepoRepo` 读写该字段。
- `RepositoryService` 加 `SetOnline(name, online)` 方法（仅 admin）。
- `groupGet`（`asset_service.go`）遍历成员时跳过 `!member.Online`。
- `proxyGet`/`resolve`：offline 时直接 `ErrNotFound` 或专用错误（不发起回源）。
- **端点（MD-3 拍板）**：独立端点 `PUT /api/v1/repositories/{name}/online`（body `{online:bool}`，仅 admin）——与 FR-114 统一，不并入 update 端点。
- 前端：仓库列表/详情展示 online 状态 + 开关（FR-114 一并做状态展示，本 FR 后端 + 最小前端开关）。

### online 不参与复制（M-2 硬约束）

repository 实体整表参与复制（`recordChange(EntityRepository)` → `RepoChangeData{Name,Format,Type,Visibility,Description,Config}` → `applyRepository`），online 作为 repository 列**无集中拦截机制**（不同于 `repl:*` 的 setting 键名前缀拦截）。因此须以三条硬约束保证 online 不随复制传播（否则对端会覆盖节点本地运维状态，违反 FR-96 隔离初衷）：

1. **`SetOnline` 不得写 repl_change**：`RepositoryService.SetOnline` 直接落库，不调用 `recordChange`。
2. **`RepoChangeData` 禁止新增 `online` 字段**：复制变更数据结构不含 online，应用路径 `applyRepository` 的 `Create/UpdateVisibility/UpdateDescription/UpdateConfig` 均不触碰 online。
3. **加守护测试**：仿照 `TestSettingsClusterKeyNotReplicated`（settings_test.go）新增 `TestRepoOnlineNotReplicated`——复制应用 `RepoChangeData` 后本地 online 保持不变；`SetOnline` 不产生 repl_change。

- **边界情形**：对端删除再重建同名仓库时，本地 online 会被重置为默认 online=1（因应用路径 Create 建默认 online）——属可接受（对端重建是显式运维动作，本地可重新置 offline）。

## 5. 验收标准

- offline 的 proxy 成员被 group 读跳过（不再回源），缺失制品不因 offline 成员拖慢。
- offline 的 proxy 单独读返回 404/错误（不回源）。
- `online` 持久化：重启后仍 offline。
- **online 不随复制传播**：`SetOnline` 不产生 repl_change；复制应用 `RepoChangeData` 后本地 online 不变（守护测试通过）。
- 设置 online 开关仅 admin 可操作（401/403）。
- 测试全绿（含迁移幂等）。

## 6. 风险 / 待定

- offline 不参与复制：节点本地运维状态，避免对端覆盖（M-2 三约束 + 守护测试保证）。
- hosted offline 的语义：hosted 无上游，offline 主要影响 group 跳过它；单独读 hosted 若 offline 可返回 404（可选，默认允许读）。
- 对端删除重建同名仓库会重置本地 online 为默认（可接受，见 M-2 边界）。
