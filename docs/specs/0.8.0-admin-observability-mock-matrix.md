# 功能规格：账户、服务与可观测性 Mock 验收矩阵

> 状态：开发完成，待用户验收　·　关联 PRD：FR-122（原 FR-124 并入）、FR-53、FR-117–120　·　依赖：FR-122、FR-119　·　目标版本：v0.8.0（尚未发布）

## 1. 背景与目标

账户、服务设置和可观测性页面承担管理控制台的日常运营工作。目前部分页面已有开发预览或局部 MSW 测试，但状态与操作反馈不完整，且观测预览必须严格避免被生产环境误当成真实事实。本功能补齐可视化验收矩阵，不增加生产观测采集或管理权限。

## 2. 需求

- 覆盖 `/setup`、`/users`、`/tokens`、`/settings`、`/dashboard`、`/audit-logs`、`/cluster`、`/cluster/sync-logs/:id` 与 `/host-monitoring`。
- 自举覆盖空库正常、加载、状态失败、已初始化跳转、表单校验、成功及失败；失败不泄露或回显口令。
- 用户覆盖列表正常/空态/加载/失败/无权限、新建、角色和状态修改、重置口令、删除的成功与失败；令牌覆盖列表状态、新建一次性明文展示、撤销确认的成功与失败。
- 设置覆盖读取状态、无权限、字段校验、保存成功、保存失败并保留待保存值；不得恢复集群角色、来源或令牌编辑。
- 仪表盘、审计、集群、同步详情和主机监控覆盖开发态正常、空态、加载、失败及其业务状态：审计的待处理关注队列、批次详情、共享确认、聚合/完整记录，集群的 primary/standby/relay standby/leaf standby/disabled/未配对/父节点离线/子节点离线/分支落后/能力拒绝/子边应用失败，主机指标未知/告警。集群页面和监控只展示本节点及直接邻接边，不伪造全局拓扑；集群的 Tab 保持在内容区顶部。
- 观测页面的预览同步、筛选、展开详情等局部操作均有本地成功和失败反馈，且不会发起节点访问。立即同步仅在 standby 场景可执行；primary、disabled 与未配对场景不显示可执行控制。生产态不显示固定 KPI、审计、同步或主机样例，继续使用真实读模型。
- 不做：新增指标采集、审计写入、跨节点读取、运行时主备配置、令牌明文持久化或新的授权模型。

本规格只验证 Mock 的角色、导航、加载/失败和交互反馈；级联 relay 的真实复制、逐跳凭据和邻接 API 由 FR-105/115/119/121/126 的实现与真实验收负责。

## 3. 设计

- 用户、令牌、设置和自举沿用真实 API 形状的 MSW handler；错误、空态和加载由 FR-122 统一场景驱动。
- 仪表盘、审计、集群和主机监控维持明确的开发态本地预览数据，扩展到完整状态矩阵；审计预览以失败优先、仅高风险次之、同级最新优先的待处理关注队列突出关键记录，并将普通成功项独立按时间展示。每个关注批次均使用服务端契约同形的 `attentionId`；页眉通知跳转 `/audit-logs?attentionId=…`，审计页以该标识打开批次详情，确认请求也只提交该标识，客户端不拼接成员。
- 审计 Mock 以单个共享 MSW 状态模拟当前节点：夹具包含两个全局管理员会话、失败、高风险成功、普通成功、同组跨桶、无关联项和脱敏错误摘要。管理员 A 成功确认后，管理员 B 刷新读取到同一确认人和时间；对同一 `attentionId` 的并发或重复确认返回首个成功确认结果而不产生第二个确认；一次性确认失败注入只令该写入失败、保留队列和通知计数，不得改变共享状态；批次新增未确认风险后自动重新进入关注队列。可单次注入 `409 attention_stale`：页面明确提示批次已变化，保留安全筛选条件并提供刷新审计操作；刷新后以新快照重新定位批次，旧标识不得再次确认。
- 审计 Mock 对每次读取先冻结同一事件快照，先应用范围与筛选条件，再由该结果派生关注队列、普通成功时间流、聚合计数、KPI、趋势、完整记录和批次详情；禁止使用固定趋势或与列表不同的数据源。页眉通知从同一快照中以服务端当前时间计算最近 24 小时未确认批次，返回总数、失败优先且同级最新的至多 20 条预览及是否有更多；「查看全部审计」进入审计页而不截断或伪造完整记录。生产代码不导入这些夹具，也不由前端伪造真实状态。
- 操作反馈使用项目既有确认框、通知和 `AsyncBoundary`，不引入新的状态管理或图表依赖。筛选、Tab、抽屉和详情均用可访问的标准控件。

## 5. 验收标准

- 九条路由均可在开发态复现其适用的正常、空态、加载和失败；读写页的关键操作均具备成功与失败反馈。
- 自举、用户、令牌、设置失败时不丢失可安全保留的输入或选择；令牌明文只在创建成功后的单次反馈中出现，后续视图不包含它。适用业务写操作的 `503 standby_read_only` 必须保留输入/选择且不改变业务 Mock 状态。
- 普通用户、未登录用户和无权限管理员不会因 Mock 场景而获得原本不可见或不可执行的管理操作。
- 审计聚合只按稳定操作关联组和时间桶展示；同一操作标识跨时间桶必须拆为不同聚合项，不得并入最新桶。Mock 默认先显示失败、再显示仅高风险、同级按最新时间排序的关注队列，普通成功项不重复；切换完整记录后全部原始记录仍按稳定时间顺序可见。通知和队列中的每个 `attentionId` 都能跳转并打开同一批次详情；确认只以该标识完成整批操作。管理员 A 确认成功后，管理员 B 刷新可见相同确认人和时间；同一标识的并发或重复确认保持首个确认结果；一次性确认失败不改变队列、详情或通知数；`409 attention_stale` 明确提示批次已变化，刷新后按新快照重新定位并只允许确认新标识；同一批次出现新风险事件后必须重新出现。范围和筛选变化后，以同一冻结快照重算关注队列、普通成功时间流、聚合计数、KPI、趋势、完整记录计数和详情成员，不能保留范围外的固定趋势。页眉只展示最近 24 小时未确认项的总数与至多 20 条预览，按失败优先、同级最新排序；超出部分只能通过「查看全部审计」进入审计页查看。重点项第一层展示文字结果、操作与目标，详情仅保留错误分类、脱敏摘要和必要追溯字段，不包含堆栈、原始响应、令牌、环境变量、内部地址或凭据。集群时间线清楚显示当前节点、方向、触发方式、发起人和脱敏错误，不显示令牌、环境变量、内部地址或凭据。同步详情预览仅接受已登记的夹具标识，未知标识显示可重试的 404。primary、disabled 和未配对场景不显示立即同步；失败/过期场景不尝试匿名拉取。
- 所有固定观测样例仅在开发态可见；生产构建/预览不渲染它们且不会向不存在的 Mock API 请求数据。
- FR-122 的 Mock 验收只证明前端状态、导航、可访问性和交互反馈；不得替代 FR-117/FR-118 的真实契约、SQLite 持久化、授权、并发、standby 拒绝和真实浏览器验收。真实验收以 `0.8.0-audit-observability.md` 的独立证据为准。
- 相关 web/devmock 测试、类型检查、lint、格式检查和构建通过；浏览器分别复核账户管理、审计聚合、集群时间线与主机监控。

## 6. 风险 / 待定与验收边界

- 生产态只调用当前节点的真实读模型；读取失败必须显示错误状态，不得以预览夹具填充数据。固定观测样例仍仅在开发态可见。
- 本地开发服务器的 DevMock 验证已覆盖本矩阵所列审计、集群和主机监控关键状态。该验证仅证明本地开发态的状态与交互，不构成线上验收或用户验收。
- 用户验收仍以第 5 节为准，不能以 Mock 通过替代真实服务、权限和节点行为验证。
