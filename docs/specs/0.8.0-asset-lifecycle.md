# 功能规格：原子制品生命周期与 Blob 回收

> 状态：计划　·　关联 PRD：FR-104　·　分支：main　·　决策：ADR-0019

## 1. 背景与目标

制品删除和覆盖后，已无引用的内容 blob 必须回收，但相同 hash 可被同一节点多个仓库或路径共享。本功能提供可恢复的原子操作基础，避免删除失败、进程崩溃或共享引用导致数据损坏。

## 2. 需求

- 以节点全库活动 `asset` 的 `blob_hash` 引用数判断是否可回收；协议发布/覆盖、proxy cache、格式派生 metadata 关联 asset、管理操作、仓库删除、迁移和复制的所有本地引用变更必须经 `AssetMutationCoordinator` 串行化，并在短写事务中重新计算引用数与操作计划。
- 500 条上限仅适用于 FR-107 的交互管理单批：目录展开、协议派生资产和删除资产均计入。仓库删除同样最多 500 条，超限整批拒绝；迁移按单个逻辑对象的独立协调器批次执行，不受交互式 500 条上限约束，也不得把无界迁移包成一个操作。
- 活动 blob 移入持久隔离区失败时，资产、审计、复制记录和操作状态均不得对外可见；已暂存 blob 必须恢复。完成后的隔离区永久删除失败只记录可重试 GC，不回滚已完成操作。
- 覆盖发布、proxy cache、格式派生 metadata、统一删除引擎、仓库删除、迁移和复制等会移除或替换资产引用的写路径必须复用该回收语义。
- 不做：异步保留策略、跨节点共享文件系统、无界目录操作。

## 3. 设计

按 ADR-0019 使用持久化 intent、同盘隔离区和操作 outbox。协调器为节点级注入服务：短事务持久化前镜像与 intent，锁外原子移动或恢复文件，短事务同时切换业务视图、审计与 outbox 的完成状态；不得以包级全局锁替代，也不得持 SQLite 写锁执行文件 IO。读路径在 `staged` 时从隔离区读取旧视图，在 `committing`/`rolling_back` 时经读门等待终态；审计查询和复制拉取仅返回已完成操作。启动恢复按 intent 和前镜像完成提交或回滚，隔离区永久删除由可重试 GC 处理。

## 4. 任务拆分

- [ ] 新增资产操作与 blob 暂存恢复的数据模型、迁移和存储接口。
- [ ] 增加全库引用统计、操作预检、事务提交与崩溃恢复。
- [ ] 让协议发布/覆盖、proxy cache、格式派生 metadata、管理操作、仓库删除、迁移和复制等所有变更 `asset.blob_hash` 的写路径委托协调器和统一引擎。
- [ ] 文档同步：PRD、ARCHITECTURE、API、CHANGELOG。

## 5. 验收标准

- 相同 hash 尚有任一活动引用时，删除其中一个资产不删除 blob；最后一个引用删除后 blob 物理不存在。
- 并发上传/覆盖、proxy cache、迁移、复制与删除同一 hash 时，结果线性化：完成操作对应的活动引用始终可读，不会因陈旧引用计数被暂存或删除。
- 隔离移动失败、数据库失败和进程在暂存/提交边界中断后，恢复结果均为完整成功或完整回滚；完成后隔离 GC 永久删除失败不重新暴露 blob、不回滚业务，仅留下可重试记录。
- 交互管理操作和仓库删除超过 500 条、非法路径、非 hosted 仓库均拒绝且不产生副作用；迁移超过 500 个逻辑对象时以单对象批次持续执行。
- 相关 Go 测试覆盖共享引用、覆盖发布、失败注入和重启恢复。

## 6. 风险

SQLite 与文件系统没有共同事务，必须以恢复状态机保证可观察原子性；不得以尽力删除替代。
