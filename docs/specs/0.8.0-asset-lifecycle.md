# 功能规格：原子制品生命周期与 Blob 回收

> 状态：开发完成，验收通过，待发版　·　关联 PRD：FR-104　·　分支：main　·　决策：ADR-0019、ADR-0024

## 1. 背景与目标

制品删除和覆盖后，已无引用的内容 blob 必须回收，但相同 hash 可被同一节点多个仓库或路径共享。本功能提供可恢复的原子操作基础，避免删除失败、进程崩溃或共享引用导致数据损坏。

## 2. 需求

- 以节点全库活动 `asset` 的 `blob_hash` 引用数判断是否可回收；协议发布/覆盖、proxy cache、格式派生 metadata 关联 asset、管理操作、仓库删除、迁移和复制的所有本地引用变更必须经 `AssetMutationCoordinator` 串行化，并在短写事务中重新计算引用数与操作计划。
- 500 条上限仅适用于 FR-105 的交互管理单批：目录展开、协议派生资产和删除资产均计入。仓库删除同样最多 500 条，超限整批拒绝；迁移按单个逻辑对象的独立协调器批次执行，不受交互式 500 条上限约束，也不得把无界迁移包成一个操作。
- 活动 blob 移入持久隔离区、隔离原件永久删除、提交事务或最终临时快照删除任一步失败时，资产、格式元数据、审计、复制记录和操作状态均不得对外可见；已暂存 blob 必须恢复。成功返回前不得保留归零 blob 二进制内容。
- 覆盖发布、proxy cache、格式派生 metadata、统一删除引擎、仓库删除、迁移和复制等会移除或替换资产引用的写路径必须复用该回收语义。
- 进程启动只恢复未完成的资产 intent 并清理 OCI 上传临时文件，不得扫描或删除活动 blob 目录中的孤立文件。写入和格式元数据重建在 blob 最终 rename 前登记内存暂存保护；运行期 GC 只能删除既无活动引用、也无暂存保护的 blob，并以按 hash 删除预约与同 hash 新写入线性化，不能删除尚待资产提交的内容。仅 `primary` 在 `JIAN_BLOB_GC_INTERVAL` 指定的间隔（缺省 24 小时）后执行孤立 blob 清理；显式设为 `0` 禁用，`standby` 与 `disabled` 均不得运行该任务，进程 context 取消后停止。该任务只处理失败写入等遗留孤立 blob，不改变归零引用的同步物理回收语义。
- 不做：异步保留策略、跨节点共享文件系统、无界目录操作。

## 3. 设计

按 ADR-0019 与 ADR-0024 使用持久化 intent、同盘隔离区、单操作流式回滚快照和 operation outbox。协调器为节点级注入服务：短事务持久化前镜像与 intent，锁外原子移动、快照、物理回收或恢复文件，短事务同时切换业务视图、格式元数据、审计与 outbox 的完成状态；不得以包级全局锁替代，也不得持 SQLite 写锁执行文件 IO。读路径在 `staged`、`committing`/`rolling_back` 时经读门等待终态；审计查询和复制拉取仅返回物理回收与事务均完成的操作。启动恢复按 intent 和快照回滚未完成操作；`run` 仅在 primary 启动一个无立即首扫的轻量 ticker，用于后续清理失败写入留下的孤立 blob。

## 5. 验收标准

- 相同 hash 尚有任一活动引用时，删除其中一个资产不删除 blob；最后一个引用删除后 blob 物理不存在。
- 并发上传/覆盖、proxy cache、迁移、复制与删除同一 hash 时，结果线性化：完成操作对应的活动引用始终可读，不会因陈旧引用计数被暂存或删除；GC 与尚未提交引用的 staged blob 交错时，提交成功的资产仍可读。
- 隔离移动、任一 blob 物理回收、数据库提交、最终快照删除失败和进程在这些边界中断后，恢复结果均为完整回滚；成功返回时最后引用的 blob 已物理不存在。
- 交互管理操作和仓库删除超过 500 条、非法路径、非 hosted 仓库均拒绝且不产生副作用；迁移超过 500 个逻辑对象时以单对象批次持续执行。
- 相关 Go 测试覆盖共享引用、覆盖发布、失败注入和重启恢复。
- 覆盖启动不扫描、primary 首个间隔后触发、显式禁用、standby 不运行以及 context 取消后停止；OCI 上传临时文件清理和 intent 恢复保持启动行为。

## 6. 风险

SQLite 与文件系统没有共同事务，必须以恢复状态机保证可观察原子性；不得以尽力删除替代。
