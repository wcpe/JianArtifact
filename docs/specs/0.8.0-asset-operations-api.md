# 功能规格：统一制品操作 API

> 状态：计划　·　关联 PRD：FR-107　·　分支：main　·　依赖：FR-104～106

## 1. 背景与目标

现有批删接口允许部分成功，单删与批删入口的语义不一致。统一 API 将删除、Raw 路径移动和单项重命名收敛为同一个原子操作模型。

## 2. 需求

- 新增管理员专用统一操作契约：删除、Raw 移动/改路径、Raw 单项重命名。
- 删除可接受 typed logical target、文件或目录目标，后端递归展开、去重并原子执行；移动保留多选项名称与相对层级；重命名只允许单项。所有目标和递归展开后的实际制品总数不得超过 500；该上限不适用于逐逻辑对象运行的迁移。
- 目标冲突、路径非法、操作超限或活动 blob 隔离移动失败均整批拒绝，不覆盖、不合并；完成后隔离区 GC 的永久删除失败不改变操作结果。
- 旧 `batch-delete` 标记弃用并委托新引擎，成功返回兼容结果但不再产生部分成功；旧协议 DELETE 同样委托新引擎。任一失败统一返回整批错误与 operationId，不返回逐项成功列表。
- Maven/npm 的移动和重命名明确返回不支持。

## 3. 设计

以 OpenAPI 为契约真源，生成服务端、Web 类型与 devmock。删除 target 为区分 `raw_path`、`maven_version`、`maven_artifact`、`npm_package`、`npm_version`、`asset_path` 的判别联合；`asset_path` 只允许文件树提供并须唯一解析。响应携带 `operationId`，供审计和集群同步追踪；后端强制全局管理员、hosted 类型和仓库级不可变 Release 校验。不可变 Release 的管理员例外只允许统一管理 API 携带非空 `overrideReason`，原生协议不得覆盖；迁移入口按单逻辑对象复用同一事务引擎，但已有逻辑对象只能 skip/fail，不能由通用 overwrite 绕过。

## 4. 任务拆分

- [ ] 设计 OpenAPI 操作请求、响应、错误码与弃用说明。
- [ ] 实现 handler、协议入口委托和兼容映射。
- [ ] 更新 devmock、契约测试与旧接口回归。
- [ ] 文档同步：PRD、ARCHITECTURE、API、CHANGELOG。

## 5. 验收标准

- 401/403、404、409、400 与 500 回收失败均不产生部分变更。
- Raw 多项移动、目录删除、单项重命名成功后返回 operationId，并可关联逐制品审计。
- npm 文件树选择 tarball/packument 能以 typed `asset_path` 映射到唯一逻辑删除目标；裸路径删除返回 `409 logical_delete_required`。旧批删调用不再部分成功；Maven/npm 移动或重命名被明确拒绝。

## 6. 风险

这是已发布批删接口的失败语义迁移，必须在 API 文档、弃用说明和 v0.8.0 CHANGELOG 中明确。
