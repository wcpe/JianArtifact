# 功能规格：集群原子制品操作复制

> 状态：计划　·　关联 PRD：FR-105　·　分支：main　·　依赖：FR-104　·　决策：ADR-0019、ADR-0020、ADR-0021

## 1. 背景与目标

本地目录删除或 Raw 路径迁移必须整批原子，对端也不能在同步中读取到只删除了一半或只移动了一半的目录。

## 2. 需求

- 每个受影响资产或格式元数据保留独立复制变更和接收审计，并携带 UUIDv7 `operationId`、来源节点、统一版本元组、排序实体键、项目数和清单 SHA-256；逐项变更只属于 operation envelope，不独立占用复制流的 `seq`。
- 复制流只读取与本地 completed 状态同事务提交且已分配既有全局 `seq` 的操作 outbox；`protocol=v2` 将其作为联合 records 流中的不可分割 envelope 返回，响应为 `{records,latestSeq,hasMore}`。对端仅在收齐、校验清单、依赖关系与缺失 blob 后应用，watermark 只能在完整 envelope 成功后推进，`hasMore` 是唯一翻页依据；v1 保持普通 `repl_change[]` 兼容而不承载 operation，若范围包含 operation 必须 409 拒绝而不能越过其 seq。
- 发起原子资产操作前，所有已配置活动对端必须协商支持 v2；任一对端不足时返回 `409 cluster_peer_upgrade_required` 且不产生本地操作或 outbox。
- 对端应用使用 FR-104 的同一回收与恢复语义；重试和重复拉取幂等。
- 任一清单实体存在更高本地版本时，对端拒绝原批次且不部分应用；接收节点逐 item 比较 put/tombstone 的版本元组，选择较高版本的完整状态，以严格更高统一版本生成、持久化并发布含全部赢家状态的 successor 操作，确保最终收敛。
- 不做：PUT 推送、跨操作强一致或跨节点共享事务。

## 3. 设计

在既有 GET pull 变更流上扩展 ADR-0020 的 `protocol=v2` 联合 records、操作 outbox、完成边界和可扩展 `operation_item(type,key,data,blob_hashes,depends_on)`。协调器在 completed outbox 同一事务中分配既有全局 `seq`；pull 将 outbox 作为单条至多 500 项的 operation envelope 与普通 change 同序返回，普通页大小不得把它拆分，持久 watermark 仅在 envelope 完整成功后推进。接收节点将未完成项持久化为暂存状态，先取齐 blob 与格式元数据依赖，再通过 FR-104 协调器在单个本地事务中应用；完成前不进入正常资产读视图，完成后不会缺失可拉取清单。发现冲突时不应用原批次：将每个 item 的本地较高状态或暂存远端较高状态组成排序后的 successor 清单，分配严格高于两侧最大值的新版本元组和 `operationId`，持久化、记录冲突接收审计并按正常 GET pull 发布。相等版本而内容不同视为损坏并停止该批次。接收审计保留本地复制服务身份、来源节点和原始操作者快照，不复制任何凭据。

## 4. 任务拆分

- [ ] 扩展复制变更、实体版本和接收状态的数据模型。
- [ ] 实现批次接收、完整性校验、原子应用与失败重试。
- [ ] 扩展同步历史与接收审计的 operationId 关联。
- [ ] 文档同步：PRD、ARCHITECTURE、API、CHANGELOG。

## 5. 验收标准

- 两节点间的目录删除和 Raw 多项移动在对端一次性可见，不出现半批次状态。
- 断网、重复拉取、重启恢复和任一实体 LWW 冲突后，两个节点的资产、格式元数据、blob 引用和操作结果最终一致；冲突时没有半批次。
- 覆盖重叠目录移动、put-vs-delete、delete-vs-put、相等版本内容不一致和 successor 重试：每个可恢复冲突只发布一个包含全部赢家状态的 successor，损坏批次不修改正常读视图。
- 覆盖完成状态与 outbox 同事务提交、完成前崩溃回滚、完成后重启仍可拉取完整清单；不得以定期对账补偿缺失的原子批次。
- 覆盖普通变更与多项 operation 交错、普通分页边界、断网重试和重复拉取：watermark 不得越过未完整交付的 operation envelope。
- 覆盖 v1 普通变更兼容、v2 协商、旧对端拒绝原子操作和 v2 普通 change/operation envelope 联合排序。
- 覆盖 operation envelope 恰好填满普通页、空 records、并发新增、断网重试，以及先有 operation 后新增/恢复 v1 对端时的 `409 cluster_peer_upgrade_required`；watermark 不得跨越未成功 record。
- 每项变更均可由 operationId 关联到本地审计、复制日志和接收审计；Docker/Cargo/PyPI/NuGet 的派生 metadata 在依赖 blob 到齐前不可读。

## 6. 风险

必须保留既有 GET-only 复制约束；批次暂存不可让未完成状态泄漏至读路径。
