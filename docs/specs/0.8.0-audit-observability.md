# 功能规格：当前节点可视化审计中心与操作关联

> 状态：已交付@v0.8.0　·　关联 PRD：FR-117、FR-118、FR-38、FR-100　·　目标版本：v0.8.0

## 1. 背景与目标

当前页面以「管理操作」和「复制应用」两个技术标签分表展示，并在列表行中堆叠 IP、请求标识、客户端等诊断字段，导致用户难以看清谁做了什么、失败在哪里和同步是否完成。

本功能建设当前节点的统一审计读模型。`audit_log` 是管理写入的不可变审计真源；`replication_apply_log` 保持复制接收的**当前状态**真源；新增仅本节点的追加式 `replication_apply_event` 记录每次复制接收尝试或状态转换，作为统一审计的复制事件真源。三者不能为了页面合并而相互替代，也都不能被复制到其他节点。

## 2. 需求

- 默认显示近 24 小时，提供 7 天、30 天快捷范围、筛选条件标签和高级筛选抽屉。
- 审计页面同时提供「聚合视图」和「完整记录」：完整记录始终逐条保留；聚合视图按稳定操作关联组（`operationId` 或等价关联标识）和所选时间范围的时间桶共同归组。没有稳定关联标识的记录必须单条保留，禁止依据相近时间、操作者、动作或目标猜测归组；同一组跨时间桶时必须拆为不同聚合项，不得并入最新桶，并分别显示该桶内起止时间与记录数。服务端为每个可关注聚合项签发不透明 `attentionId`，它绑定当前节点、关联键、时间桶和读快照；前端只消费它，禁止自行构造。类别、结果、操作者和仓库筛选只决定该批次是否可见，不能将同一关注批次拆成部分确认；确认始终覆盖该关联键和时间桶中的完整风险来源。
- 默认打开聚合视图时，先显示「需要关注」队列：筛选和时间范围生效后，任一原始记录为失败的聚合项优先，其次是仅含高风险操作的聚合项；同一优先级按组内最新记录时间倒序，再以稳定事件排序打破平局。普通成功项只在其后的「按时间查看」中出现，不得与关注队列重复；没有关注项时显示明确的无待处理事件状态。
- 全局管理员可以将当前节点的风险批次标记为「已确认处理」。确认不删除、修改或隐藏完整审计记录，只会将已确认的风险来源从待处理队列和通知中心移除，并在聚合时间流与详情显示确认人和确认时间。同一节点的所有全局管理员共享该状态；审计和确认状态均不参与复制，因此不得声称其他节点已经确认。
- 确认以构成关注项的不可变原始风险事件为最小持久化单位：客户端只提交服务端签发的 `attentionId`，不得枚举事件 ID。服务端在一个事务内按该 ID 所绑定的快照解析并确认该批次**全部**未确认风险来源；批次只有全部来源已确认时才退出待处理队列。重复或并发确认必须返回首个确认人和时间，不能因事件已确认而失败。快照签发后新产生的失败或高风险事件不属于该次确认，必须立即作为新的待处理项出现；它处于另一时间桶时按该桶独立展示。客户端不得按当前视图时间桶持久化确认状态，也不得以浏览器本地存储代替服务端状态。
- 事件按固定分类展示，不再使用技术来源作为一级标签：仓库/用户/ACL/令牌/设置/迁移写入归为「管理变更」；协议发布、制品删除和资产操作归为「制品变更」；管理写入或协议写入的认证、授权、standby 只读、不可变发布、前缀或额度拒绝归为「安全事件」；`replication_apply_event` 归为「同步复制」。所有管理和协议**写入**拒绝都必须经统一、脱敏的安全审计边界记录；登录成功/失败、普通下载、匿名协议读取的 `401/403/404` 与其他协议读取只进入 FR-53 分钟指标或正常请求处理，不写入审计。
- 顶部展示事件总量、失败次数/失败率、涉及账号数和高风险操作数；趋势图展示总量、失败量和类别构成。失败率分母固定为最终结果为成功或失败的事件数，进行中和未知结果不计入分母；涉及账号数以稳定 user ID 去重，缺失 user ID 时以非空操作者快照去重，系统/匿名/复制来源不计入。
- 高风险操作固定为仓库删除、管理员制品删除、用户删除、令牌撤销、ACL 写入、运行时设置写入和迁移切换/完成；未映射的新 action 归为「其他管理变更」且不计入高风险，直到后端映射与测试补齐。
- 关注队列将有文字的失败/高风险结果、操作和目标仓库或制品作为第一层；时间、操作者与认证来源作为第二层。可显示安全的结果摘要、错误分类和关联标识，但不得把堆栈、原始响应体、内部地址或原始诊断内容带入主列表。完整记录保持真源的稳定时间顺序逐条呈现，不因置顶而重排，仍以结果、操作和目标为阅读重点。IP、User-Agent、请求标识、令牌标识和精确来源节点不得返回给管理端；详情抽屉也只显示服务端脱敏后的必要追溯字段。
- 新产生的原子制品操作在各自节点的详情中保留同一操作标识，供管理员跨节点人工对照。页面不得把来源节点记录拼成远端已经应用的完成时间线；历史记录缺少关联标识时必须明确标记为不可关联。
- 不得展示口令、令牌明文/密文/摘要、同步密钥、上游凭据或 Authorization 信息。
- 页眉风险通知中心只对全局管理员展示：服务端固定使用当前时刻向前 24 小时，返回未确认风险批次总数，以及按失败优先、最新时间倒序的最多 20 条预览和 `hasMore`。通知项只包含不透明关注标识、严重性、时间、结果、操作、对象、脱敏摘要、成功/失败/影响计数与可选操作标识；不得包含 IP、User-Agent、请求标识、来源节点、内部地址或任何凭据。读取失败必须以不可用状态呈现，不能显示为零风险；不引入轮询、WebSocket 或外部通知渠道。

范围内：当前节点审计汇总、统一事件读模型、详情、本地操作标识、共享风险确认与页眉最近 24 小时风险通知。

不做：更改审计写入权限、让审计记录参与复制、跨节点读取或回执、删除历史记录、确认撤销、浏览器本地忽略、轮询/推送通道或新增外部 SIEM。

## 3. 设计

SQLite 迁移 `0026_audit_observability.sql` 为 `audit_log` 增加可选 `correlation_id`，并建立当前节点的 `replication_apply_event` 与 `audit_attention_ack`。后端在读侧只统一当前节点的两类不可变审计事件源（`audit_log` 与 `replication_apply_event`）的分页、筛选和归类，并以服务端常量完成 action、结果和高风险映射；`replication_apply_log` 仅供集群当前状态和同步诊断使用。操作写入时把可选 `correlation_id` 单列保存，作为管理员跨节点人工对照的稳定标识，不从 `detail` 反向解析；历史无关联记录保留原样。汇总查询以时间桶完成，详情按最小必要字段受管理员授权保护。前端在同一快照内按稳定关联标识和时间桶构造仅用于展示的聚合卡；筛选后再派生关注队列，不能改变逐条审计的分页真源、聚合键或完整记录时序。管理和协议写入拒绝统一经脱敏安全审计边界写入；该审计写入失败不改变原请求响应，但必须用正式日志记录可观测内部错误。

`replication_apply_event` 每次仅追加，不更新或删除既有事件；至少保存本地自增 ID、来源节点/序号、可选操作标识、实体摘要、结果、脱敏错误分类、时间与来源操作者快照，不保存 peer URL、凭据或原始错误。`audit_attention_ack` 以 `(source, source_event_id)` 唯一约束保存确认状态，并固化 `acknowledged_by_user_id`、用户名、认证来源和确认时间；它不对 `user` 建外键，用户删除后仍以快照显示确认人。`audit_log`、`replication_apply_event` 和确认表均不生成复制 change。批次安全摘要以成员的 `categoryCounts` 表示完整分类构成，不能把跨类别的关联批次伪装为单一类别；分类计数按固定分类枚举顺序返回。`action` 和对象摘要取批次中优先级最高的成员：失败优先，其次按严重性、发生时间和稳定事件标识倒序；`affectedCount` 表示实际影响数量。

summary 捕获两个不可变源的最高 ID 边界和 `snapshotAt`，并签发不透明 `snapshot`；它把当前节点、时间范围、类别、结果、操作者和仓库筛选一并绑定。后续 events 分页必须携带完全匹配的快照和筛选条件，期间产生的新事件只在下一次刷新出现。完整事件流直接在 SQLite 分页，`limit` 为 1–100（默认 50），返回权威 `totalCount` 与 `nextCursor`；汇总、关注批次和通知聚合最多读取 5,000 条源事件，超过即返回 `409 audit_query_too_large`，调用方须缩小范围或筛选条件。单事件详情按不可变 `eventId` 获取，并返回当前确认快照。`attentionId` 由服务端签发并完整绑定节点、关联键、时间桶和该快照；篡改或无法在快照中重建的 ID 返回 `409 attention_stale`，客户端刷新后重试。确认端点先原子校验该 ID 的来源均在当前节点、均是风险来源且与该快照相符；已确认来源不是错误。随后在同一 SQLite 事务内对全部成员执行幂等插入、读取最早确认信息，并写入普通管理审计 `audit.attention_acknowledge`；任一写入失败整批回滚。任一来源失效、非风险或不匹配时整批拒绝且不写入。该确认审计不属于高风险，也不会递归产生通知。新风险事件的 ID 超出旧快照，天然不会被旧确认覆盖。

| 接口                                                         | 权限       | 关键参数                                                                                | 返回                                                                     |
| ------------------------------------------------------------ | ---------- | --------------------------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| `GET /api/v1/observability/audit/summary`                    | 全局管理员 | `from`、`to`（UTC `[from,to)`，最大 30 天）、筛选条件                                   | KPI、按服务端有效粒度的趋势、类别构成、`snapshot` 与 `snapshotAt`        |
| `GET /api/v1/observability/audit/events`                     | 全局管理员 | `from`、`to`、类别、结果、操作者、仓库、`snapshot`、`cursor`、`limit`（1–100，默认 50） | 当前节点统一事件分页；风险项带 `attentionId`；主列表不含诊断敏感字段     |
| `GET /api/v1/observability/audit/events/{eventId}`           | 全局管理员 | 来源带前缀的不透明事件标识                                                              | 当前节点脱敏详情、可选操作标识与当前确认快照                             |
| `GET /api/v1/observability/audit/attention/{attentionId}`    | 全局管理员 | 服务端签发的 `attentionId`、`cursor`、`limit`（1–100，默认 50）                         | 批次安全摘要、确认状态和成员分页；无效或不可重建为 `409 attention_stale` |
| `PUT /api/v1/observability/audit/attention-acknowledgements` | 全局管理员 | 请求体仅含服务端签发的 `attentionId`                                                    | 按完整批次原子、幂等确认的确认人快照、时间、总成员数与本次新增确认数     |
| `GET /api/v1/observability/audit/notifications`              | 全局管理员 | 无；服务端固定最近 24 小时                                                              | `totalUnacknowledged`、最多 20 项预览、`hasMore` 与安全摘要              |

事件按 `(timestamp DESC, source, sourceEventID DESC)` 稳定排序；`eventId`、`cursor`、`snapshot` 与 `attentionId` 都由服务端编码，调用方不得解析。服务端固定趋势粒度：范围不超过 24 小时为分钟桶，超过 24 小时且不超过 7 天为小时桶，超过 7 天为天桶。

## 5. 验收标准

- 当前节点存在的管理写审计和追加式复制接收事件都能在统一事件流中出现，来源与分类正确；`audit_log` 与 `replication_apply_event` 仅追加，`replication_apply_log` 继续仅表达当前接收状态。
- 新产生的原子操作保留稳定操作标识；历史无关联项明确标记为“无关联记录”。页面不声称另一节点已应用，也不发起跨节点读取。
- 聚合视图仅合并同一稳定操作关联组且同一时间桶中的本节点记录，并按所选范围的时间桶清晰排列；每个聚合项展示桶内起止时间、记录数、操作者、目标、类别与结果概览，可展开恢复该项的全部逐条记录。筛选后，默认关注队列先显示含失败的聚合项，再显示仅高风险的聚合项，同级按最新时间倒序并以稳定事件排序打破平局；普通成功项不与关注项重复。无关联项不与任何其他记录合并，聚合计数与完整记录计数一致。
- 全局管理员确认一个风险批次时，当前节点内所有管理员随即看到相同确认人和时间；已确认批次退出关注队列与通知中心但完整记录永远保留。确认只提交服务端 `attentionId`，并原子覆盖其快照内完整批次，无客户端成员上限；任一成员失效、非风险或不匹配时整批失败且无确认行写入。重复或并发确认幂等，最先成功的确认信息稳定保留；用户删除后确认人仍由身份快照显示；新出现的失败或高风险来源必以新待处理项出现。standby 仍按既有只读规则拒绝确认写入，任何节点都不复制确认状态。
- 近 24 小时、7 天、30 天、筛选、分页和空结果的 KPI、趋势、关注队列、时间流和列表计数一致；每次筛选、时间范围或快照变更后都基于当前结果重新聚合和排序。summary 后插入事件或追加新的复制尝试时，携带其 `snapshot` 的首轮和后续分页仍与 summary 一致，新事件仅在下一次刷新出现。类别映射、高风险集合、涉及账号去重、失败率分母、事件 ID、`attentionId`、并发插入和复制重试下的游标边界均由夹具穷举验证。
- 主列表不返回或渲染诊断敏感字段；重点项的结果摘要仅能包含可行动的脱敏摘要、错误分类和关联标识，详情仅对管理员显示必要追溯字段，且不泄露堆栈、原始响应体、秘密或内部地址。
- 完整记录始终恢复全部逐条记录的稳定时间顺序，不因默认关注队列置顶而漏项或重排。行项目、筛选、详情抽屉均可键盘操作；结果状态不只依赖颜色表达。
- 页眉通知中心只向全局管理员显示最近 24 小时未确认风险批次总数和最多 20 条预览，数量和文字无障碍名称一致；正常、空态、加载和失败均有清晰状态，失败不伪装为零风险。条目可键盘打开并跳转对应本节点 `attentionId` 详情；确认成功后通知数与关注队列同步刷新，`hasMore` 时可进入完整审计，不泄露诊断敏感字段。
- 管理和协议写入的 401、403、503 与策略拒绝均产生脱敏安全审计；普通读取与登录仍不因本功能额外写审计。确认写入、确认审计与安全拒绝审计均不记录请求体、口令、令牌、凭据或内部地址。
- 后端读模型/脱敏/并发/快照/拒绝审计测试、前端交互测试、契约/devmock 校验、类型检查、lint 与构建通过；浏览器分别验证 primary 的本地变更、standby 的本地复制事件和 standby 确认拒绝。

## 6. 风险 / 待定与验收边界

- 旧审计记录没有关联标识，只能按来源独立展示；禁止用时间接近等启发式错误关联。
- 确认只在当前节点生效；这是审计不复制和 standby 管理写保护的直接后果，不能把“所有管理员共享”解释为跨节点共享。
- `make check` 已通过；本地开发服务器的 DevMock 浏览器验证已覆盖审计的正常、空态、加载、失败、关注批次、确认与过期刷新交互。该验证仅证明本地开发态的 UI 行为，不构成线上验收或用户验收。
- 用户验收仍以第 5 节为准，尤其需要核对 primary 的本地管理变更、standby 的本地复制事件以及 standby 对确认写入的拒绝。
