# 功能规格：级联树集群页面与邻接同步监控

> 状态：开发完成，待用户验收　·　关联 PRD：FR-119、FR-115、FR-121、FR-122　·　目标版本：v0.8.0（尚未发布）　·　决策：ADR-0023、ADR-0026

## 1. 背景与目标

现有集群页面按“当前节点 + 唯一 primary/standby”展示，无法表达中继备用节点和多个直接下级；集群监控也容易把单节点同步状态、父节点状态和下级状态混在一起。级联树下，任何节点都只掌握直接邻接事实，页面必须明确区分本地状态、父边和子边，不能伪造全局拓扑健康。

本功能重做集群页面和集群监控：

- 集群页面回答“我是谁、我的直接上级是谁、我的直接下级有哪些、我是否允许写入”；
- 集群监控回答“每一条相邻复制边最近是否成功、落后多少、失败在哪一步、下一步如何恢复”；
- primary、relay standby、leaf standby 和 disabled 的展示与操作边界一致；
- 不读取或汇总孙节点、祖先节点之外的远程节点，也不把 FR-120 的主机指标扩展为跨节点监控。

## 2. 需求

### 2.1 集群页面（ClusterPage）

- 页面顶部显示当前节点角色、业务读写能力、中继能力、复制代次和本节点数据状态。
- 以关系卡显示直接父节点：根 primary 显示“无上级”；standby 显示已配对/未配对、父边在线状态、最近成功 watermark 和最近错误；不显示内部 URL、环境变量或令牌。
- 以关系卡列表显示直接下级：显示下级稳定展示名或脱敏标识、是否完成配对、中继边状态、最近请求时间、最近确认 watermark、积压和错误摘要；父节点只展示直接子节点，不展示孙节点。
- relay standby 必须同时展示父边和所有子边；leaf standby 只展示父边；disabled 显示不参与复制；primary 显示根节点和直接子节点。
- 页面明确区分“本地同步事实”和“下级最近上报事实”。没有上报、上报过期、下级离线、未配对和父节点不可用都必须降级展示，不得推断“全树健康”。
- 仅保留既有受控操作：有父边且角色为 standby 时可手动触发向父节点同步；不得在 Web 页面编辑角色、父节点、子节点、凭据、自动选主或自动换父。

### 2.2 集群监控（ClusterMonitorPage）

- 以邻接边为主维度展示监控，而不是使用 primary/standby 固定两列。每条边至少显示方向、边角色（父边/子边）、复制状态、最近请求/成功时间、起止 watermark、积压、记录/operation/blob 计数和阶段化错误。
- 父边重点展示本节点向上拉取：能力协商、认证、拉取、blob 补齐、原子应用、watermark 推进和恢复提示。
- 子边重点展示本节点向下提供：子节点最近请求的 cursor/watermark、可转发连续前缀、待确认记录/blob、凭据状态和服务错误。未启用中继能力的 standby 不显示可提供复制源的假状态。
- 一个节点挂多个下级时，各子边独立显示、独立筛选和独立降级；一个子节点离线不能把其他子节点标记为失败。
- 监控提供“本节点概览 / 父边 / 子边 / 同步事件”层次；同步事件详情仍只显示服务端脱敏后的阶段、稳定错误码、原因和恢复建议。
- 状态必须使用文字、图标和结构共同表达，不只依赖颜色；移动端和窄屏不使用无法阅读的横向宽表。

### 2.3 观测与安全边界

- 父节点通过已经认证的复制 GET 请求接收直接子节点的有界脱敏观测快照；relay standby 对上向父节点上报自身拉取事实，对下接收子节点上报事实。
- 观测只表示直接邻接边，不能跨级查询、代理查询或持久化全局拓扑；中继节点重启后丢失的内存快照只能在下一次邻接请求后恢复。
- 页面、响应、Mock 和日志不得出现令牌、凭据、环境变量、内部地址、原始网络错误、命令参数或文件路径。
- FR-120 的“当前主机监控”继续只采集本实例所在主机，不从父节点或子节点读取 CPU、内存、磁盘、网络或进程数据。

## 3. 设计

### 3.1 读模型

继续使用 `GET /api/v1/observability/cluster` 作为集群概览入口，扩展响应为本节点邻接读模型：

- `self`：角色、读写能力、中继能力、stream generation、本地同步状态；
- `parent`：直接父边状态、watermark、最近拉取事件和上报新鲜度；根 primary 无该字段；
- `children[]`：直接子边状态、子节点上报的新鲜度、请求 cursor、可转发前缀和脱敏错误；无子节点时为空数组；
- `scope`：固定为 `local_neighbors`，前端不得把响应解释为全局集群状态。

现有同步事件列表、详情和变更明细接口继续只查询当前节点本地事实；父节点收到的子节点快照在集群概览中作为直接子边窗口展示，不提供跨节点历史代理端点。API 契约以 `api/openapi.yaml` 为唯一真源，实施时必须先改契约再生成代码和 devmock。

### 3.2 观测上报

沿用 FR-119 的认证 GET 捎带方式：子节点在向父节点拉取时携带自己的父边同步快照；子节点向 relay 父节点发起请求时，relay 以同一认证边界接收并按 node ID 归属。relay 为下级提供 records/blob 时，子节点请求中附带的观测信息只写入 relay 的直接子边状态，不向上游转发整棵树的观测数据。

快照必须有界、可丢弃、失败不影响复制。每条邻接边至少能判定 `healthy`、`syncing`、`stale`、`failed`、`unpaired`、`paused`、`disabled` 或 `unknown`，判定依据由服务端提供，前端不得自行推断代次或积压。

### 3.3 页面信息架构（方案 B：双 Tab 工作台，集群页与集群监控合并）

- 侧栏单入口「集群」（/cluster）；旧 /cluster-monitor 保留 301 重定向，独立「集群监控」导航项、独立监控视图与布局选型组件已移除。
- 页头：角色/状态徽章 + 水位、积压、最近同步健康摘要；「立即同步」仅 standby 可用，刷新作用于整页数据。
- Tab「总览」：拓扑管线（父 → 本节点 → 直接子边，节点卡可点击）→ 点击节点卡打开边详情抽屉（吸收原「边与节点明细」区块）→ 需要关注列表（边问题锚点打开对应边抽屉，同步失败锚点跳同步记录 Tab 并打开详情）→ 本节点参数卡（状态原因 / 写开关 / 来源配置 / 同步间隔 / 流代次）→ 旧版备用节点上报兼容卡（仅 legacy primary 展示，含拉取记录下钻）。
- Tab「同步记录」：原集群监控诊断流整体迁入——结果/触发筛选、成功失败统计、可展开时间线与详情抽屉；支持 `?tab=sync&eventId=…` 深链（页眉通知/告警可直达具体记录），Tab 状态经 URL 保留、刷新可复现。
- primary 不再显示“自己向 standby 拉取”的错误状态；relay standby 不再只显示一个 primary；多个子节点不使用固定单 standby 文案。
- devmock 必须覆盖根节点、单父叶子、单父多子 relay、未配对、父边失败、子节点离线、子边应用失败、分支落后、能力拒绝和 disabled（与 FR-122 验收矩阵对齐）；离线场景不得伪造最近请求/最近成功时间。

## 5. 验收标准

- root primary、relay standby、leaf standby、disabled 四类角色页面显示正确；relay 同时显示一个父边和至少两个子边，leaf 不显示虚假的子边。
- 集群页面和集群监控只展示直接邻接节点；任何页面文案、API 字段和 Mock 都不声称掌握孙节点或完整集群健康。
- 一个 relay 挂两个下级时，两个子边的成功、落后、离线、凭据失败和恢复状态相互独立；一条边失败不覆盖另一条边的成功事实。
- 父边拉取与子边服务的方向、watermark、积压、请求/成功时间、记录/operation/blob 计数和阶段化错误与后端本地事实一致；无数据时显示未知/未上报，不填零或伪造健康。
- 页面不允许运行时编辑角色、父子关系、凭据、自动换父或自动选主；仅允许既有 standby 手动同步入口，且不会在 primary/disabled/无父节点上出现。
- 页面与响应不出现令牌、凭据、环境变量、内部地址、原始网络错误、系统路径或跨节点主机指标；开发 Mock 也只使用固定脱敏标识。
- 覆盖 876px、1316px 和移动宽度；关系卡、子边列表、事件详情、长错误和 Tab 可读，键盘/读屏语义完整。
- devmock、前端组件测试、OpenAPI 生成校验、后端读模型/脱敏/边界测试、类型检查、lint 和项目整期 build 已通过；真实级联树浏览器复核仍是发布前门禁。

## 6. 风险 / 待定

- 子节点上报窗口是最近事实，不是全局历史；页面必须始终标明“直接邻接”和新鲜度。
- 多子边会增加 primary/relay 的内存状态和 UI 信息量；实现应使用分页或有限窗口，不能恢复宽表堆叠。
- 集群监控不得借名读取 FR-120 主机指标；如未来需要跨节点主机监控，应在其他需求中单独定义。
