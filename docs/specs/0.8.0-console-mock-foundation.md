# 功能规格：管理控制台 DevMock 场景基座

> 状态：已交付@v0.8.0　·　关联 PRD：FR-122　·　目标版本：v0.8.0

## 1. 背景与目标

管理端已能在开发态通过 MSW 脱离后端运行，但不同页面的 Mock 覆盖不一致：部分缺少空态、加载态和失败态，未处理请求会落入 Vite 的 HTML 回退并导致 JSON 解析报错。需要一套只在开发/测试态生效的统一场景基座，使每条控制台路由可被稳定预览和自动验证，而不改变任何生产 API 或线上数据。

## 2. 需求

- 为下游页面提供固定四类读取场景：正常数据、空态、加载态和失败态；页面可额外声明业务必要的细分场景，但不得把它们当作生产事实。路由专属夹具与 handler 由 FR-122 负责，本 FR 只提供通用场景机制。
- 为可写页面提供成功与失败两类操作场景；失败时保留用户已填写的表单和已选项目，并显示可读反馈。
- 开发态通过页面范围的预览控制选择场景；场景选择只影响浏览器内的 Mock，不写入服务端、不访问外部地址。只有需要局部切换的页面显示控制，其他页面使用固定 URL 场景入口，避免在 18 页重复堆叠开发工具。
- 测试可直接设置同一场景，不依赖计时或随机数据；加载场景必须由测试显式挂起和释放，请求缺少 handler 时必须得到可诊断的 API 错误，不得把 HTML 当 JSON 解析。
- 生产构建不得包含 `mockServiceWorker.js`、MSW chunk 或通用场景控制；worker 必须迁至仅开发态可服务的位置，生产页面继续走既有真实 API 路径。仪表盘、审计、集群和主机的固定预览夹具剔除由 FR-122 负责。
- 所有适用的业务写操作均必须覆盖 `standby_read_only`：模拟 `503` 后保留本地输入/选择、不改变业务 Mock 状态；内部复制应用不属于业务写成功。
- 不做：新增管理 API、数据库表、生产调试开关、全局模拟数据总览页或新的第三方依赖。

## 3. 设计

- `packages/devmock` 继续是浏览器和 Node 测试共用的 handler/内存态真源；本 FR 不新增任何远端接口。已列入 OpenAPI 的响应保持契约一致；既有但尚未纳入 OpenAPI 的生产路由只镜像当前实现，不在本 FR 静默扩大为契约治理工作。
- `apps/web` 提供仅开发态加载的场景上下文和轻量页面内预览控制。场景以路由为边界，固定场景标识可由 URL 查询参数恢复，便于刷新、截图和自动化复现；生产态忽略该参数。
- `api/client.ts` 对 2xx 非 JSON 响应返回受控 `ApiError`，保留现有 204 和 JSON 响应语义，避免 SPA 回退页泄露为原始 `SyntaxError`。
- 不发明观察数据接口。仪表盘、审计、集群和主机监控的固定数据仅在 `import.meta.env.DEV` 分支使用；生产态继续显示既有真实数据或明确的未接入状态。固定预览数据的生产构建隔离由 FR-122 实现。
- 场景标识固定为页面支持的 `normal`、`empty`、`loading`、`error` 及本页声明的业务场景；未知 URL 场景回落该页 `normal`，不改变 store。`error` 仅模拟本页真实可发生的 401/403/404/5xx、网络或 `503 standby_read_only`，不能把所有错误伪装为同一种失败。

## 4. 任务拆分

- [x] 定义路由范围的读取/写入场景类型、显式可释放加载请求和测试设置工具。
- [x] 建立通用 `error` 与 `standby_read_only` 守卫，并将未处理或非 JSON 响应转换为可读错误；路由专属 handler 留给 FR-122。
- [x] 实现仅开发态可见的页面预览控制和 URL 场景恢复；将 worker 与通用场景代码从生产构建完全剔除。
- [x] 补齐场景隔离、MSW 契约、非 JSON 响应和生产构建不含 Mock 的测试。
- [x] 文档同步：PRD、ROADMAP、ARCHITECTURE（如模块边界发生变化）、CHANGELOG。

## 5. 验收标准

- 路由验收矩阵中的 18 条页面路由均能在开发态稳定呈现正常、空态、加载和失败，不依赖网络、随机时间或前一条测试留下的内存状态。
- 任一可写操作均可单独验证成功与失败；失败反馈可读、输入和选择保留，成功后页面状态按操作语义刷新。
- 同一路由的场景在刷新后可重现，不会影响其他路由或下一个测试；测试运行之间的 store 被明确重置。
- 缺少 handler、网关回退或其他 2xx 非 JSON 响应不会触发原始 JSON 解析异常，页面显示统一错误态并可重试。
- 生产构建产物中不存在 `mockServiceWorker.js`、MSW chunk 或通用场景控制；真实 API、鉴权与写操作路径不变。固定业务/审计/同步/主机预览夹具的产物检查由 FR-122 验收。
- devmock 与 web 的相关单元/集成测试、类型检查、lint、格式检查和生产构建通过；浏览器以 fresh reload 逐条复核 18 条页面路由的正常态，并在每个功能组各复核一条空态、加载态、失败态与写失败。生产构建预览复核一条公开路由、一条受保护路由和一条迁移写路径，确认均未被 Mock 接管。

## 6. 风险 / 待定

- 页面预览控制是开发工具，不是产品功能；如需要对外演示环境，应另行定义受控演示数据，不得复用该机制。
