# 功能规格：声明式按格式启停

> 状态：计划　·　关联 PRD：FR-32　·　分支：main　·　被依赖：FR-25～29

## 1. 背景与目标

实例当前无论实际使用哪些格式，都会装配 Raw、Maven 和 npm 的全部协议入口。0.8.0 新增多种格式后，这会扩大不需要的网络暴露面，也会让未来格式专属任务在未使用时仍被启动。

本功能提供启动期、声明式的格式允许列表：运维可只启用实例实际使用的格式；未启用格式不得暴露协议能力，也不得创建格式专属后台任务。它不改变 SQLite 元数据和 blob 文件系统的真源边界，不引入插件框架或运行时热切换。

## 2. 需求

- 新增启动环境变量 `JIAN_ENABLED_FORMATS`，使用逗号分隔的格式标识：`raw`、`maven`、`npm`、`docker`、`cargo`、`pypi`、`gomod`、`nuget`。
- 变量未设置时，为兼容既有部署，默认启用 `raw,maven,npm`；变量显式设置为空字符串时不启用任何格式。名称大小写和首尾空白归一化；未知名称或归一化后无效项使启动失败，错误消息不得包含凭据。
- 格式启停只在进程启动时读取。修改环境变量后必须重启；不得写入 setting、复制到对端或通过管理 API 在运行中切换。
- 已启用格式才装配其协议 handler、专属路由和专属后台任务。未启用格式的原生协议请求必须为 404，不能被 SPA 回退为 200，也不得触发上游访问、blob 读取或格式专属 goroutine。
- Raw 与 Maven 复用 `/repository/:repo/*artifactPath` 前缀时，只有至少一个已启用时才安装共享传输路由；Dispatcher 仅持有已启用格式的 handler。请求指向已禁用格式仓库时返回 404。该共享传输路由不构成被禁用格式的路由。
- npm 及后续每个拥有独立 URL 前缀的格式，只有启用时才注册该前缀。协议前缀没有任何已启用 handler 时，静态资源回退必须显式返回 404。
- 仓库创建、迁移导入和管理端格式选择器都只能使用当前启用格式；请求创建已知但未启用的格式返回稳定的 `409 format_disabled`。管理端以 OpenAPI 契约提供当前启用格式清单，并隐藏不可创建的格式。
- 禁用不删除已有仓库、资产、ACL、复制变更或 blob。管理员仍可查看其管理元数据以便恢复配置；原生协议读写、格式专属 usage 与专属后台工作均不可用，直到该格式重新启用并重启。
- 复制、审计、SQLite 迁移和全局健康检查属于格式无关基础能力，不因某一格式禁用而停止；但它们不得构造或调用被禁用格式的 handler。
- 范围外：按仓库启停、用户级格式权限、动态热切换、第三方插件发现、删除禁用格式的数据、为未实现格式预留空壳协议。

## 3. 设计

- `config.Load` 解析并校验允许列表，向启动装配传递一个不可变的格式能力集合；格式 ID 的唯一注册表位于 domain-neutral 的配置/能力包，由 `RepositoryService` 以依赖注入使用，避免 domain 反向依赖 protocol。
- 协议层定义轻量格式模块描述（格式名、路由注册函数、可选启动函数），由 main 只为允许列表中的模块构造依赖并注册。协议 handler 仍遵守 `protocol → domain → repository/blobstore → persistence`，不得因开关直接访问 SQLite。
- `RepositoryService` 在创建和迁移入口校验注入的格式能力集合；group 成员继续要求同格式，且其格式必须已启用。复制接收保留对端已有元数据以维持最终一致，但不因此打开本节点协议面。
- OpenAPI 新增管理员只读的启用格式查询；前端仓库创建表单据此渲染选项。服务端校验是唯一权威，前端隐藏不作为安全边界。
- HTTP 服务的静态回退维护协议保留前缀拒绝表，保证未注册的 `/repository/*`、`/npm/*` 及后续格式前缀不会落入 `index.html`。错误不透露仓库是否存在。
- 配置、启动日志和健康信息只记录启用格式名称，不记录环境原值中可能混入的无关内容；格式集合不进入复制 setting。

## 5. 验收标准

- 未设置 `JIAN_ENABLED_FORMATS` 的升级实例继续启用 Raw、Maven、npm；显式 `raw` 实例仅能访问 Raw hosted/proxy/group，Maven 与 npm 原生请求均为 404。
- 空列表实例不注册任何格式协议路由；`/repository/...` 与 `/npm/...` 返回 404 而非 SPA HTML，且测试证明未创建格式 handler、未访问 blob 或上游、未启动格式后台任务。
- 已知未启用格式的仓库创建和迁移导入均返回 `409 format_disabled`；未知格式和非法配置在启动或请求校验阶段明确失败，已有禁用格式仓库及其 blob 不被删除。
- Raw/Maven 组合的共享前缀只向启用格式分派；已禁用格式仓库的请求不泄露其存在且不执行协议读写。
- 管理端仅展示当前启用格式；直接伪造管理请求仍由服务端拒绝。OpenAPI、生成代码和 devmock 一致。
- **真实部署验收（需用户确认）**：使用两个独立实例分别配置 `raw` 与 `raw,maven,npm`，以 curl/mvn/npm 验证启用格式可用、禁用格式为 404；重启改变配置后行为随之切换，且无格式专属后台任务残留。

## 6. 风险 / 待定

- 同一集群节点允许配置不同格式集合时，复制可以保存对端元数据但本节点不会提供对应协议服务；运维必须避免把该节点作为该格式的对外入口。
- Raw/Maven 共用 URL 前缀，无法在 Gin 层为每个格式各自注册不同的路径模板；本规格以“未构造/未分派该格式 handler + 对外 404”定义零路由语义。
- 未来新增格式必须同时登记到注册表、协议保留前缀和此配置文档；遗漏任一处会破坏攻击面收缩，需由装配测试阻断。
