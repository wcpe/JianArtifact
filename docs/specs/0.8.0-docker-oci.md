# 功能规格：Docker / OCI Distribution Registry

> 状态：已交付@v0.8.0（客户端维度豁免）　·　关联 PRD：FR-25　·　分支：当前工作区　·　依赖：FR-32、FR-104、FR-105、FR-109；决策：ADR-0010、ADR-0015、ADR-0016

## 1. 背景与目标

JianArtifact 已支持 Raw、Maven、npm 的 hosted/proxy/group 制品读写，但容器镜像不能以普通文件 PUT 模拟：Docker 与 OCI 客户端需要 Distribution API 的上传会话、manifest/tag 引用、digest 校验与仓库级 blob 查询。本功能让 `docker pull`、`docker push`、OCI 兼容客户端可以在一个 JianArtifact 仓库中使用 hosted、proxy 与 group，同时保持现有 SQLite 元数据、文件系统内容寻址 blob、ACL、审计和多节点复制边界。

仓库名是镜像引用的首段。例如 Docker hosted 仓库为 `containers` 时，镜像 `team/api:1.2.0` 的客户端引用为 `<host>/containers/team/api:1.2.0`；服务端协议路径为 `/v2/containers/team/api/manifests/1.2.0`。不新增端口分仓或独立 registry 进程。

## 2. 需求（要什么）

- **原生端点与兼容性**：实现 OCI Distribution Specification 规定的 `/v2/` 探测、manifest、blob、blob 上传会话与 tag 列表端点；响应携带 `Docker-Distribution-API-Version: registry/2.0`。支持 Docker schema 2 与 OCI image/index manifest 媒体类型；仅接受 `sha256` digest。
- **hosted push/pull**：
  - `GET|HEAD /v2/<repo>/<image>/manifests/<tag-or-digest>`、`GET|HEAD /v2/<repo>/<image>/blobs/<digest>`、`GET /v2/<repo>/<image>/tags/list` 可拉取；manifest 的 `Docker-Content-Digest` 必须是正文的 sha256。
  - `POST /v2/<repo>/<image>/blobs/uploads/` 创建持久上传会话；`PATCH` 流式追加；`PUT .../uploads/<uuid>?digest=sha256:...` 完成并校验；支持带 `digest` 的单请求完成上传。上传会话 UUID 及其 layer/config 暂存仅属于会话，不产生可见 asset、审计或复制变更；只有最终 manifest PUT 才生成发布 operationId。不得把 layer、config 或 manifest 整体读入内存。
  - `PUT /v2/<repo>/<image>/manifests/<reference>` 仅在正文 digest、路径 digest（若 reference 为 digest）和所引用 config/layer/blob 均存在且介质类型允许时创建 manifest；tag 指向该 manifest。相同 tag 指向不同 digest 视为覆盖。
  - hosted 写请求必须走 ACL `write`，并接入 FR-109 的发布策略：不可变 Release 仓库的原生协议一律拒绝已有 tag 或 digest 的覆盖，即使请求主体是全局管理员；仅未来的统一管理 API 可在显式 `overrideReason`、管理员身份和审计齐全时执行格式感知覆盖。发布账号的前缀与额度按逻辑镜像名、blob 大小和新 manifest 计量。
- **proxy pull**：本地 manifest/blob/tag 未命中时从 `config.remoteUrl` 指向的远端 Registry v2 根地址拉取、校验 digest 并缓存。必须支持公开 Registry 返回的 Bearer challenge 换取只读上游令牌；私有上游仅允许以 ADR-0022 定义的逻辑 `credentialRef` 关联到 `JIAN_UPSTREAM_CREDENTIAL_<credentialRef>`，禁止在 repository.config、日志或审计中保存明文、任意环境变量名或解析值。上游地址、DNS 解析和重定向必须通过统一出站安全策略，拒绝环回、链路本地、私网与云元数据地址。上游 404→404、超时→504、其他上游失败→502。
- **group pull**：按 `members` 顺序解析 manifest 与 blob，首个命中胜出；`tags/list` 合并成员 tag 并按字典序去重。group 永远不可写。
- **认证与授权**：读写均复用 ADR-0015 的协议认证器和 `RepositoryService.CanAccess`：Basic 只接受账号口令或 API Token，Bearer 仅接受 `jat_` API Token，任何 Web JWT Bearer 在协议端点均为 401。未认证私有请求返回 Basic challenge，不能实现或暴露 Docker Token Service。全局管理员仍绕过 ACL，但发布策略和不可变规则不得被普通 `write` ACL 绕过。
- **元数据、审计与集群**：上传会话完成只把 blob 放入待引用存储；最终 manifest PUT 以一个 operationId 原子发布 manifest、tag 和所引用 blob。复制节点补齐 blob 后再公开 manifest/tag。审计不得记录 Authorization、上游令牌、layer 内容或密码；会话超时清理属于暂存 GC，不是已发布制品删除。
- **范围外**：Docker Registry HTTP API v1、Notary/Cosign、镜像扫描、垃圾回收策略、跨仓库 blob mount、删除 manifest/blob、跨仓库复制、匿名 Docker Token 服务和 UI 镜像层浏览不在本 FR。格式感知管理端删除仅覆盖 FR-105 已列格式，Docker 的管理员删除另立 FR。

## 3. 设计（怎么做）

### 3.1 路由与格式分派

- 新增 `protocol/oci.go` 与 `RegisterOCIRoutes`，在静态 SPA 回退之前注册：`/v2/` 只作能力探测；其余 `/v2/:repo/*rest` 从首个路径段解析 JianArtifact 仓库名和镜像名。路由注册由 FR-32 的格式注册表控制；`docker` 未启用时该组完全不挂载。
- 仓库 `format` 增加 `docker`，OpenAPI 仓库枚举、前端/devmock、Nexus 迁移识别与使用片段同步扩展。`RepositoryConfig.RemoteURL` 对 Docker proxy 表示 Registry 根地址，禁止包含凭据、查询参数和 `/v2/<image>` 资源路径。
- `OCIHandler` 只做 HTTP、头与错误码映射；`domain.OCIService` 负责引用校验、缓存、事务、授权策略调用与复制记录；repository/blobstore 负责表与字节。私有上游统一通过 `RepositoryConfig.CredentialRef` 的 ADR-0022 受限运行时 resolver 取得凭据，所有请求及重定向均经 ADR-0015 的出站地址、DNS 重解析与重定向校验。保持 `protocol → domain → repository/blobstore/upstream` 单向依赖。

### 3.2 持久化与存储

- 新增迁移及仓储接口：
  - `oci_manifest`：`repository_id`、`image_name`、manifest digest、asset 路径、媒体类型、大小、创建时间；同仓同镜像同 digest 唯一。
  - `oci_tag`：`repository_id`、`image_name`、tag、manifest digest、更新时间；tag 是可变引用，唯一约束为同仓/镜像/tag。
  - `oci_upload`：上传 UUID、仓库、镜像、同盘暂存文件、已接收字节、创建/更新时间和状态；重启后可继续或按 TTL 清理未完成暂存文件，清理不影响已完成 blob。
- manifest 与 blob 正文仍写入现有 blobstore，并各建 `asset` 引用：blob 使用仓库内保留路径 `oci/blobs/sha256/<hex>`，manifest 使用 `oci/manifests/<image>/<hex>`。同仓重复 layer 只留一个 asset 引用；OCI 表只保存协议索引，不复制字节。FR-104 的全节点引用计算必须将 OCI asset 一并纳入，不能因 tag 改写删除仍被 digest 引用的内容。
- 上传完成先校验请求 digest 与 blobstore sha256 一致，再原子登记 blob asset；manifest 创建在单个 SQLite 事务中登记 manifest asset、manifest 行和 tag 行。失败时不得发布 tag 或留下可拉取的半条引用。

### 3.3 解析、代理与复制

- hosted manifest 写入前解析 JSON 的 `config.digest`、`layers[].digest` 和 index 的 child manifest digest，逐一确认本仓可见；缺失返回 Distribution API 的 `BLOB_UNKNOWN` 或 `MANIFEST_BLOB_UNKNOWN`。读取按 `Accept` 协商 manifest 媒体类型，不接受的媒体类型返回 `MANIFEST_UNKNOWN`。
- proxy 使用专用 `OCIUpstreamClient`：只允许经统一出站安全策略验证的 `http/https`，流式转发并验证 `Docker-Content-Digest`/请求 digest；遇 401 challenge 时仅向同样通过安全策略的 token endpoint 请求最小 pull scope 的短期令牌。缓存 manifest、blob 与 tag 映射时使用 single-flight 键 `(repo,image,digest-or-tag)`，避免并发冷拉重复下载。
- group 的 manifest/tag 解析由 `OCIService` 完成，不能直接调用 generic `AssetService.Resolve` 绕过 OCI tag 元数据；成员失败按 ADR-0010 的读路径语义跳过，全部未命中才返回 404。
- `oci_manifest`、`oci_tag` 和已完成 blob 引用定义为复制实体；同一 push 带 `operationId` 与完成边界。接收节点先拉齐缺失 blob，再在单事务写 OCI 元数据，最后公布批次。按 `(ts,node_id)` 的 LWW 只能裁决同一 tag，digest manifest 与 blob 不可被覆盖为不同内容。

## 5. 验收标准

### 自动化

- hosted 集成测试覆盖 schema2 与 OCI manifest：分块上传、单请求上传、`HEAD`、digest 不匹配、缺 layer、重复 tag 覆盖和不可变仓库拒绝；断言所有大 body 经 reader 流式处理且内存不随 layer 大小线性增长。
- manifest/tag/blob 的成功和失败路径均检查 SQLite 行、asset 引用、blob 文件与审计/复制记录一致；中断上传、暂存文件丢失、事务失败和重启恢复不产生可见半 manifest。
- proxy 的 httptest Registry 覆盖 public Bearer challenge、404/超时/5xx、digest 校验、二次缓存命中与 single-flight；group 覆盖成员优先、失败回退与 tag 去重。
- 权限测试覆盖 anonymous/public、私有 Basic challenge、ACL read/write、管理员、禁止 Web 的发布账号、前缀/额度/不可变拒绝，以及 JWT Bearer 在协议端点为 401；任何响应、日志、审计样本不得含密码或上游令牌。
- 覆盖私有上游的 `credentialRef` 运行时解析、环回/私网/DNS 重绑定/危险重定向拒绝，以及 resolver、响应、日志和审计均不泄露凭据值。
- 两节点集成测试在节点 A push 多 layer/image manifest，节点 B 只能在完整批次到达后成功 pull；断网重连后 digest、tag、审计和引用计数一致。

### 真机验收（须用户确认）

- 使用真实 Docker Engine 或 Docker-compatible CLI，对 hosted 执行 `docker login`、`docker push`、删除本地镜像后 `docker pull`，再 `docker run` 一个无副作用镜像验证 config/layer 完整；同时用 OCI 工具拉取 OCI index，确认多媒体类型 manifest 可解析。
- 使用一个公开上游和一个具凭据引用的私有上游 Docker proxy，真实 `docker pull` 验证首次回源与断开上游后的本地缓存；group 对两个成员的同名 tag 按配置顺序返回。
- 在两台真实节点经现有 CDN/Tunnel 拓扑发布并从对端 pull，监看同步历史和审计按同一 operationId 完整归组；断网中不应拉到半 manifest，恢复后可拉取。

## 6. 风险 / 待定

- Docker 客户端对 `Location`、Range、错误 JSON 与 media type 极敏感；必须以真实 Docker CLI 和录制协议夹具作为兼容性权威，不能仅以 handler 单测判定完成。
- 上游 Registry 的 Bearer challenge、scope 与重定向实现存在差异；首版仅承诺标准公开 challenge 与显式凭据引用，不把 token 缓存或其值写入 SQLite/审计。
- OCI metadata 引入 asset 以外的可复制索引。FR-104/105 未扩展其引用与复制白名单前不得启用写路由，否则会出现 blob 回收或同步遗漏。
- tag 是天然可变引用，与 Release 不可变策略冲突时以 FR-109 为准：Release 禁止 tag 覆盖；开发仓的 tag 覆盖仍必须原子、可审计、可复制。
