# 功能规格：Go modules proxy

> 状态：已交付@v0.8.0（客户端维度豁免）　·　关联 PRD：FR-28　·　分支：当前工作区　·　依赖：FR-32（格式启停）；决策：ADR-0010、ADR-0015

## 1. 背景与目标

Go 工程通过 `GOPROXY` 使用模块代理拉取版本列表、模块描述和 zip 内容。现有 Raw/Maven/npm 的通用资产、代理缓存、ACL 和流式 blob 能力可复用，但 Go proxy 的路径转义、`@latest`、`@v/list` 与 404/410 回退语义必须按 Go 模块协议实现。

本 FR 为**只读代理格式**：让 Go 原生客户端经 JianArtifact 拉取上游模块并复用本地缓存，而不是把 Go 模块伪装成可任意上传的普通文件仓库。

## 2. 需求

- 新增仓库 format `gomod`，仅允许 `proxy` 类型；创建 hosted/group 或把非 `gomod` 仓库接入 Go 路由均拒绝。
- Go proxy 基址为 `<public-base>/go/<repository>`，支持 `GET`/`HEAD`：
  - `/<escaped-module>/@v/list`
  - `/<escaped-module>/@v/latest`
  - `/<escaped-module>/@v/<version>.info`
  - `/<escaped-module>/@v/<version>.mod`
  - `/<escaped-module>/@v/<version>.zip`
- `<escaped-module>` 必须遵循 Go 模块代理转义规则（大写字母以 `!` 加小写字母表示）。服务端只接受规范转义、相对路径和上述固定端点；`..`、重复分隔符、未知后缀、非规范版本或试图解码为绝对路径的请求一律拒绝，且不回源。
- 代理上游为仓库 `remoteUrl` 指向的兼容 `GOPROXY` 基址；私有上游仅通过 `RepositoryConfig.CredentialRef` 的 ADR-0022 受限运行时 resolver 从 `JIAN_UPSTREAM_CREDENTIAL_<credentialRef>` 取得凭据。首次未命中时按完整规范化路径流式回源并缓存为该 `gomod` proxy 仓的 asset；命中后不重复回源。
- 上游 404 与 410 均须保持 Go proxy 的“该模块/版本不可用”语义，使客户端可按自身 `GOPROXY` 逗号链路继续回退；上游超时与非预期失败按既有 504/502 语义返回。
- 协议读请求复用 ADR-0015 协议认证、public read 与 ACL 规则：Basic 只接受账号口令或 API Token，Bearer 仅接受 `jat_` API Token，Web JWT Bearer 在 Go 协议端点统一为 401；未认证私有仓库仍带 Basic 质询。该格式没有 publish、delete、管理端移动或重命名协议入口。
- 所有返回和缓存 key 使用请求的规范化转义路径；不重写 `.info`、`.mod`、`.zip` 或 `@latest` 的内容，不提供 checksum database、`sum.golang.org` 镜像、私有模块直连或 VCS 拉取能力。
- 未启用 `gomod` 格式时，FR-32 保证不注册 `/go` 路由、不创建该格式后台任务，也不接受该 format 仓库。

范围内：只读 GOPROXY 兼容代理、缓存与管理端 usage 片段。
不做：Go modules hosted/group、checksum database、VCS/direct fallback、模块版本重写、依赖漏洞扫描。

## 3. 设计

- **路由与分层**：新增 `protocol/go_proxy.go`，由 `main` 在 format 已启用时注册 `/go/:repo/*rest`；handler 只做鉴权、请求语义解析和 HTTP 映射，经 domain 的格式代理读服务访问 repository/blobstore/upstream，禁止直连 SQLite。
- **路径模型**：解析器将 `rest` 拆为 `escapedModule` 与固定 `@v` 操作，使用 Go 兼容的转义/反转义校验确认其为唯一规范表示，再以规范化 `rest` 作为 asset 路径与回源相对路径。版本端点仅允许 Go 代理协议接受的版本字面量；不会把 URL 解码后的 module path 用于文件系统路径。
- **缓存与回源**：复用 `AssetService` 的 proxy single-flight、内容寻址 blob 和流式传输；single-flight key 必须含仓库与规范化完整端点路径。`remoteUrl`、私有上游 credentialRef 的 resolver 和每一次重定向均经 ADR-0015 的出站地址、DNS 重解析和重定向校验，拒绝环回、链路本地、私网与云元数据地址。上游状态映射需能区分 404、410、超时和其它失败，不能把 410 降级成 502。
- **仓库校验与使用片段**：`RepositoryService` 扩展 `gomod` format/type 组合校验，`Usage` 为 Go modules 仓库生成 `GOPROXY=<public-base>/go/<repo>` 示例；`direct` 只能作为用户明确选择的回退，不在“全部请求经本仓”的默认示例中。对外 URL 按 FR-87/89 的节点本地 public URL 规则生成，不能泄露上游地址。
- **可观测性**：沿用协议访问日志和审计边界；只读缓存命中/回源不写管理审计。错误、日志、响应和缓存元数据不得写入上游凭据或请求 Authorization。

## 5. 验收标准

### 自动化

- 单元测试覆盖 module 转义规范性、大小写转义、`@v` 端点、非法路径/未知端点拒绝，以及 404/410/502/504 映射；非法请求不得访问上游。
- `httptest` 上游验证 list、latest、info、mod、zip 首次流式缓存、二次命中不回源，以及同一路径并发只回源一次。
- 覆盖 public/private ACL、Basic/Bearer、JWT Bearer 协议 401、未认证 Basic 质询、非 `gomod` 或非 proxy 仓库拒绝、未启用格式零路由，以及 credentialRef、环回/私网/DNS 重绑定/危险重定向拒绝；所有响应、持久化、日志与审计不得泄露凭据值。
- 运行一个临时 Go module，设置 `GOPROXY=<JianArtifact>/go/<repo>` 与 `GONOSUMDB=*`，`go mod download` 能通过本仓完成下载并校验 zip；该测试不依赖外网。
- 受影响 Go/前端契约与格式化、静态检查、构建测试全绿。

### 真机验收（须用户确认）

- 以真实 Go 工程执行 `go mod download`、`go list -m` 和构建，确认所有模块请求经指定 JianArtifact proxy；冷缓存与热缓存均成功，公网/私有部署不泄露上游 URL。
- 上游返回 404/410 时，将该仓置于 `GOPROXY=<JianArtifact>,direct` 链路前位，确认 Go 客户端能按标准行为回退；私有仓库的未授权请求保持 401/403。

## 6. 风险 / 待定

- Go proxy 的路径转义和 404/410 回退是兼容性关键点；不得用通用 `path.Clean` 悄悄改写合法的 `!` 转义路径。
- 上游缓存沿用当前无 TTL 策略，新的模块版本在本地缓存的 `@latest` 或 list 被显式失效前不可见；失效策略不在本 FR。
- checksum database 与私有 VCS 直连不在范围内。使用私有模块的部署须由使用方配置 `GONOSUMDB`/`GOPRIVATE`，本系统不代管该安全策略。
