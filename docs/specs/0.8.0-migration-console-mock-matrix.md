# 功能规格：迁移控制台 Mock 验收矩阵

> 状态：已交付@v0.8.0　·　关联 PRD：FR-122（原 FR-125 并入）、FR-20–23、FR-31、FR-116　·　依赖：FR-122　·　目标版本：v0.8.0

## 1. 背景与目标

迁移控制台已经连接真实迁移 API，但开发态 store 只能演示 `planned → running` 的最短路径，详情请求失败还可能停留在加载界面。管理员无法预览失败、取消、完成报告和切换清单。本功能补齐开发态完整生命周期，同时保持生产迁移的真实写入、权限和安全边界。

## 2. 需求

- 覆盖 `/migrations`、`/migrations/new` 与 `/migrations/:id` 的正常、空态、加载、失败及无权限。
- 列表提供空库、混合生命周期、加载/分页/刷新失败、运行中任务跳转等场景。
- 向导提供 online/offline 来源、匿名/Basic（密码或 User Token pair）/Bearer 的安全表单、发现成功后 `planned` 预览、显式启动、发现/索引/启动失败、取消与草稿边界。不得自动从 discover 进入 running。
- 详情提供 planned/running/failed/cancelled/completed，以及报告失败、任务 404、轮询停止、失败明细和切换清单；启动、恢复、取消和完成操作均有确认、成功与失败反馈。
- 开发态成功操作可在当前浏览器内按合法状态机推进，失败操作不得改变任务状态或丢失表单/确认上下文。生产态继续调用真实迁移 API，绝不由前端生成迁移结果。
- 所有错误信息必须脱敏：不得展示在线来源的凭据、主机名/IP、Authorization、密文或服务器本地路径；在线认证材料继续只写不读。
- 不做：改变迁移后端状态机、添加 WebSocket、替代真实执行器、真实连接外部 Nexus 或自动启动迁移。

## 3. 设计

- 在 `packages/devmock` 增加只限开发/测试的固定迁移生命周期夹具和合法迁移函数；数据只保存在测试/浏览器内存，不进入 API 契约和生产包。
- 三个页面继续通过既有 typed endpoints 触发实际 UI 路径。详情读取错误必须进入显式错误态并提供重试，不得保持无限加载。
- 向导的 discover、start、resume、cancel、finalize 的成功/失败由场景驱动；同一任务的状态转换和报告/切换清单保持一致，便于端到端组件测试。

## 5. 验收标准

- 三条迁移路由均可在开发态展示正常、空态、加载、失败及适用的生命周期终态；详情请求失败显示可重试错误而非永久加载。
- discover 成功仅生成 `planned`；只有明确确认 start 才进入 `running`。取消、恢复和完成遵守合法状态机，失败操作不会推进状态。
- 向导与详情的成功/失败反馈均通过真实表单、确认框和请求路径验证；失败后保留安全的本地输入/选择，不回显密码、User Token pair、Bearer token 或来源敏感信息。`503 standby_read_only` 不改变任务状态。
- production build 中迁移页面未导入固定任务、报告或失败样例，仍调用真实 API；开发态 Mock 不会访问外部 Nexus。
- 相关 web/devmock 测试、类型检查、lint、格式检查和构建通过；浏览器在开发态完整复核 discover → planned → start → 终态，以及一条失败恢复路径。

## 6. 风险 / 待定

- Mock 生命周期是视觉和交互验收工具，不能证明真实迁移执行器、外部网络或大库迁移已经通过验收；这些仍按既有迁移实机门执行。
