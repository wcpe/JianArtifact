# 功能规格：Nexus 格式扩展迁移

> 状态：开发完成，待用户验收　·　关联 PRD：FR-31　·　分支：当前工作区　·　依赖：FR-25～29、FR-32、ADR-0012

## 1. 背景与目标

现有 Nexus 迁移只识别 Raw/Maven/npm，且执行器按普通 asset 写入 hosted 仓库。v0.8.0 新增 Docker/OCI、Cargo、PyPI、Go modules proxy 和 NuGet 后，发现、计划、迁移、断点续传、报告和最终增量扫描必须能理解这些格式及其仓库类型，不能把格式专属元数据迁坏成普通文件。

本 FR 扩展既有三来源迁移框架，不新建第二套迁移状态机；管理员在开始前仍能看到可执行的格式、仓库类型、配置缺口和不支持项。

## 2. 需求

- `online_rest`、`offline_dir`、`offline_bundle` 的发现计划支持 `docker`、`cargo`、`pypi`、`gomod`、`nuget`，并保留既有 raw/maven/npm 行为。
- 计划仓库条目必须包含 name、format、type、可迁移配置摘要、资产估算、迁移模式和 warning；秘密、Nexus API Token、Basic 口令、cookie、完整上游认证头不得进入 plan、任务表、报告或日志。
- 映射规则：
  - Nexus hosted → 目标同 format hosted；格式资产经对应 domain import 路径写入。
  - Nexus proxy → 目标同 format proxy；只迁移已知安全的上游基址配置，**默认不搬运 Nexus 缓存内容**，由目标按需回源。缺少可用上游 URL 或需要私有上游凭据时标为不可执行 warning，等待管理员补充配置。
  - Nexus group → 目标同 format group；仅在所有成员可映射、同 format 且无循环时创建，并在其成员都创建后写入成员顺序。存在不支持/缺失成员时整个 group 不执行，计划明确原因。
  - Go format 仅允许 proxy：发现到 hosted/group Go 仓库时跳过并 warning，不能降级成 Raw。
- **格式导入边界**：Docker/OCI 保留 manifest、blob 与 media type 布局；Cargo 保留 sparse index 与 crate 版本关联；PyPI 根据 wheel/sdist 建立 simple index 所需元数据；NuGet 从 nupkg 建立 package metadata；Go proxy 不导入资产。格式专属派生数据必须由目标格式的 domain importer 生成，不能由迁移 runner 直接写 SQLite。
- 在线迁移继续按 Nexus REST 分页枚举和 downloadUrl 流式下载，但计划、来源配置、checkpoint、报告和日志只持久化 ADR-0022 定义的逻辑 `sourceRef`；online `sourceConfig` 仅保存该字段并只从 `JIAN_MIGRATION_SOURCE_<sourceRef>` 解析来源基址，独立的 `credentialRef` 只从 `JIAN_UPSTREAM_CREDENTIAL_<credentialRef>` 解析认证值。离线 `sourceConfig` 仅保存 `path`。两者及其解析结果均不得回写到持久化诊断数据。`sourceRef` 不得是 URL、主机名、IP、来源用户信息、Token、任意环境变量名或用户可见标签；未知或失效引用必须安全失败且不输出解析值。Nexus assets API 返回的 `downloadUrl` 必须与受信来源基址同 origin（协议、主机和有效端口均相同），否则在发起请求和附加凭据前拒绝。离线包 manifest 可声明 format/type/remoteUrl/members 等非敏感目标配置；离线原生 blob store 若没有可信仓库 format/type 映射则拒绝或 warning 跳过，禁止再默认为 Maven。
- 状态机、冲突策略、取消、崩溃后标 failed、resume、report 与 finalize 沿用 ADR-0012。每个实际写入仍经目标格式的正常资产写路径和 `AssetMutationCoordinator`：大迁移按单个逻辑对象或不超过 500 项实际资产变更的受控小批提交，任务总量不受管理端目录操作上限限制，且不得绕过内容寻址、校验、审计、复制或可见性语义。
- 不做：从 Nexus 导入用户、ACL、LDAP/OIDC、私钥、仓库 secret、任务调度配置；格式转换；把 proxy 缓存转成 hosted；自动修复损坏源 metadata。

范围内：五种新格式的仓库发现、计划、类型/配置映射、流式格式导入和报告。
不做：不受目标格式支持的 Nexus 特性、保密配置迁移、跨格式转换。

## 3. 设计

- **计划模型**：扩展 `discover.PlanRepository` 的持久化 JSON，增加无敏感 `config` 摘要、`migrationMode`（`assets`、`proxy_config`、`group_config`、`unsupported`）与结构化 warnings；在线来源以 ADR-0022 的逻辑 `sourceRef` 关联到任务，来源基址、凭据、Token、来源用户信息和任意环境变量名永不写入计划或来源字段。OpenAPI 的 MigrationPlan 同步更新并重新生成产物。计划一经落库不可被静默改变，需修正配置时新建任务。
- **来源适配器**：
  - Online REST 在开始发现与每次 resume 时通过安全来源解析器按 `sourceRef` 从 `JIAN_MIGRATION_SOURCE_<sourceRef>` 取得仅驻留内存的来源基址，并由独立 `credentialRef` 从 `JIAN_UPSTREAM_CREDENTIAL_<credentialRef>` 在运行时取得认证值，再读取 Nexus repository format/type/config 与 assets 分页；所有请求、重定向和连接前 DNS 复核均复用 ADR-0015 的出站策略。assets API 的 `downloadUrl` 还须与该基址同 origin 才能请求并附加认证，不能将“跨 origin 重定向剥离认证头”当作下载地址的放行条件。`POST /api/v1/migrations/remote-repositories` 和迁移向导只提交逻辑 `sourceRef`（可选独立 `credentialRef`），拒绝原始 URL 作为来源。格式名映射集中在 `migration/discover`，不散落在 handler。解析器失效时任务失败并保留可重试 checkpoint，但错误仅记录 `sourceRef` 与脱敏原因。
  - Offline bundle manifest 新增可选 `remoteUrl`、`members` 与 format/type；字段仅是非敏感目标配置。
  - Offline dir 增加“仓库元数据映射”输入或可验证的配置导出解析；只凭 blob `.properties` 无法可靠得知 format/type 时不生成可执行条目。
- **执行器**：拆分为仓库拓扑准备与格式资产导入两步。先拓扑排序创建 hosted/proxy，校验并最后创建 group；`assets` 模式按 checkpoint 逐项从 source 打开 `io.ReadCloser`，交给 `FormatImporter.Import`。importer 位于 domain/migration 边界并复用每个格式的校验、派生元数据、asset/blob 与复制记录，不允许 runner 直接 `asset.Upsert`。
- **冲突与幂等**：延续任务级 `skip`/`overwrite`/`fail`，但格式 importer 定义逻辑身份（如 NuGet ID+版本、OCI manifest tag、PyPI 文件名）。不可变 Release 仓库一律不允许 `overwrite`：既有逻辑对象只能 `skip` 或 `fail`，迁移管理员不能静默绕过；checkpoint 记录逻辑对象及源路径，resume 不重复发布已经确认的对象；proxy/group 配置创建同样幂等。
- **报告与安全**：报告按仓库和 format/type 统计 copied/skipped/failed/bytes，并分别列出“未执行的 proxy/group”和 warning。在线来源只保存逻辑 `sourceRef`，不保存 URL、主机名、IP、用户信息或 Token；凭据只保存逻辑 `credentialRef`，不保存任意环境变量名或值。最终增量仅处理 `assets` 模式的新逻辑对象，proxy/group 重新校验配置而不复制缓存。
- **异步结果审计**：创建或发现任务时固化请求发起人的用户名快照、稳定用户 ID 和认证来源；Runner 在 completed 或 failed 落态后写本节点 `migration.result`，详情只包含 `taskId`、结果和是否回滚，不含来源、凭据、令牌或请求上下文。该审计不参与复制；格式 import 的仓库、制品和格式元数据仍走正常写路径产生复制变更。
- **集群与生命周期**：格式 import 产生的单逻辑对象或受控小批写入使用对应格式正常发布路径与 `AssetMutationCoordinator`；迁移任务可持续处理超过 500 项总量，但单次协调器计划不得超过 500 项实际资产变更。其产生的复制变更与审计遵循各格式写入定义，断点续传不得绕过 blob 完整性和 operation 可见性约束。

## 5. 验收标准

### 自动化

- 三来源夹具/`httptest` Nexus 覆盖每种目标支持的 format/type 组合发现；Go modules 仅 proxy，hosted/group 必须被明确拒绝或跳过。计划格式、类型、可执行模式和 warning 与源配置一致，凭据值、来源 URL、主机名和 IP 不会出现在 plan、任务、报告或日志。
- hosted 迁移逐格式验证：目标协议能读取迁入对象，字节/哈希与源一致，派生 metadata（OCI manifest、Cargo index、PyPI simple、NuGet registration）可被原生客户端使用；Go hosted/group 被明确跳过。
- proxy 迁移只创建配置、不复制缓存；group 在成员全部可用后按源顺序创建，缺成员、异格式成员、循环或私有上游凭据缺失时不产生半个 group。
- 对每种 `assets` 模式验证 skip/fail、cancel/resume、启动恢复 running→failed 和 finalize 只补新增逻辑对象；不可变 Release 的既有逻辑对象拒绝 overwrite；大文件全过程为流式。
- online_rest 在进程重启后仅凭同一 opaque `sourceRef` 和运行时解析器可从 checkpoint 恢复；计划、任务、checkpoint、报告、日志与失败样本均不包含来源 URL、主机名、IP、口令、Token 或认证头。失效 `sourceRef` 必须安全失败且不破坏已完成逻辑对象。
- 自动化验证 Nexus 返回跨 origin、相对或无效 `downloadUrl` 时，执行器在请求前拒绝且目标站点未收到认证头或下载请求；远程仓库索引接口与迁移向导只接受 `sourceRef`，传入原始 URL 时不发生出站请求。
- 验证导入经 format importer 而不是直接 SQL 写入，并产生正确的 asset/blob、审计与复制记录；格式化、静态检查、构建和既有迁移回归全绿。

### 真机验收（须用户确认）

- 使用实际支持相应格式的 Nexus 实例，对每种可迁移格式至少迁移一个 hosted 仓、一个 proxy 配置和一个 group；执行前后报告计数、抽样 SHA-256 与客户端读取结果对账。
- 分别用 Docker/OCI 客户端、Cargo、pip、Go、NuGet 原生客户端经 JianArtifact 验证迁入仓；Go 验收仅验证 proxy 配置和拉取。
- 在真实迁移窗口向源新增制品后执行 finalize，确认目标只补新增逻辑对象，报告增量准确；两节点环境同步后对端资产及格式派生 metadata 一致。

## 6. 风险 / 待定

- Nexus 对不同版本、发行版和格式的 REST/config 字段存在差异。实现前必须以受支持的 Nexus 版本/edition 录制样例冻结兼容矩阵；未知字段宁可 warning，不得猜测为可执行配置。
- 在线任务恢复依赖部署侧持续提供同一 `sourceRef` 的运行时来源配置；引用被撤销或解析失败时必须停在可重试失败态，不能把来源地址写回任务以换取自动恢复。
- proxy 缓存不是权威发布数据，默认不迁移是为了避免缓存污染与上游授权泄露；若以后要求迁 cache，须独立定义来源完整性、TTL 和权限语义。
- 格式派生 metadata 的完整性只能由各格式原生客户端证明；“文件数相同”不等价于迁移成功。
