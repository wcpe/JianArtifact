# 功能规格：节点备份包与搬迁（Backup & Relocation）

> 状态：开发中（P1 已落地）　·　关联 PRD：FR-132～FR-138　·　关联 ADR：ADR-0027

## 1. 背景与目标

把一套实例从一台机器搬到另一台机器，原先用实时复制通道表达：静态 primary → standby 单向拉取、级联树拓扑、逐跳凭据、水位与代次、人工提升。对"一次性搬家"这个真实需求来说，这套模型维护成本高、失败模式多，且搬迁完成后旧机通常直接退役，长期维持一条复制边并不划算。

本规格改为**以一致性备份包为传输单位**：生成包 → 传包 → 导入包 → 校验。没有角色、水位、代次或拓扑。

**范围内**

- 离线包的生成（热备份 / 冻结窗口两种模式）、登记、列表、下载导出与删除。
- 导入三通道：CLI 直接导入、Web 填写 URL 由服务端拉取、Web 分片上传。
- 增量差包与分钟级切换窗口。
- 与现有"Nexus 迁移"页合并为一个入口（内部 Tab 化）。

**范围外**

- 持续双向同步、自动选主、自动换父（随复制通道一并退役）。
- 备份包的加密与口令管理（见 ADR-0027 备选方案 3）。
- 定时自动备份与保留策略（本期仅手动生成）。
- 集群数据表的 DROP。

## 2. 需求

### 2.1 离线包内容边界（FR-132）

- 包内**仅含** SQLite 一致性快照与内容寻址 blob。
- **必须排除**：`replication-credential.key`、JWT 密钥、迁移凭据密钥、环境文件、`*.db-wal`、`*.db-shm`、`blobs/tmp/`、`blobs/quarantine/`。
- `manifest.kind` 固定为 `jianartifact-node-backup`，导入端据此拒绝误喂的 Nexus 迁移 bundle。

### 2.2 生成（FR-132 / FR-133）

- 热备份：不停服，用 `VACUUM INTO` 产出快照，且**必须走独立连接**（主池 `SetMaxOpenConns(1)`，在主池执行会独占连接阻塞全部业务查询）。
- 冻结窗口：先停写再取快照，语义更严格；CLI 的 frozen 模式假定服务已停，Web 的冻结窗口由服务端执行冻结/解冻（FR-135）。
- blob 集合**以快照库 `asset` 表为准**，不扫 `blobs/` 目录。
- 同一时刻只允许一个生成任务。
- 生成失败必须清理半成品文件，且不得留下可被误用的残包。

### 2.3 备份列表与下载导出（FR-136）

- 列表按最近优先分页，展示包标识 / 方式 / 状态 / 大小 / 包含规模 / 创建时间。
- 状态可观测：`queued → snapshotting → packing → done / failed`，前端在生成中轮询。
- **下载导出提供带时效的签名链接**：普通 `<a href>` 带不上 `Authorization` 头，而搬迁要求新机器能直接粘贴地址拉取。令牌只绑定单个包与截止时间。
- 支持 Range 断点续传（`http.ServeFile` 语义）。
- 删除：仍被增量差包引用的基线不可删除。

### 2.4 导入（FR-137）

- 三通道：CLI `backup import <file>`、Web 填 URL 服务端拉取、Web 分片上传（支持续传与取消）。
- 校验：`schemaVersion` 可识别、`dbSchemaVersion` 不高于本程序、db sha256、blob 抽样 sha256。
- 运行中不可安全替换 SQLite → **暂存 + 重启替换**：解包到 `restore-staging/`，写 `restore.pending`，下次启动先做 `pre-restore-<ts>/` 备份再原子替换。
- blob 内容寻址可加，可运行中直接合并。
- 服务启动时清理进程重启遗留的"生成中"包（标记 failed）。

### 2.5 短停机切换（FR-134）

- 增量差包：同一基线包的 blob 集合求差，只携带新增 blob + 新 `jianartifact.db`。
- **侧车索引**：每个包生成时额外写 `${JIAN_DATA_DIR}/backups/<packageId>.index`（与包内 `blobs.index` 同格式）。全量包的侧车 = 该包完整 blob 集合；**差包的侧车 = 应用后的完整并集**（所以差包可再派生差包）。
- **`Expected` 摘要**：差包 manifest 新增可选字段 `expected`（`{count,totalBytes,indexSha256}`），全量包不写（`omitempty`，向后兼容），差包写"应用后应有的完整集合摘要"，供导入端判断基线是否就位。
- 生成：`jianartifact backup create --base <packageId>`；基线须存在、状态 `done`、侧车索引存在，否则明确报错。导入算本地集合 ∪ 包内差集并与 `Expected` 比对——一致才继续，不一致报"缺少基线包，请先导入基线包 `<id>`"且不留任何文件/标记；`basePackageId` 非空但 `expected` 为空（畸形手工包）仍报"增量包导入尚未支持"。
- 停机窗口只需覆盖：冻结 → 生成差包 → 传输 → 导入 → 起服 → 切 DNS；把停机窗口从"传整个包"缩到"只传新增 blob + 新 db"，可压到分钟级。
- 删除保护：被差包引用的基线不可删（已有"基线有派生包则拒绝删除"机制）。

### 2.6 集群退役（FR-138）

- 复制通道不再作为搬迁路径，功能面整体退役。
- **必须逐项确认共享代码归属**，不得一刀切删除（详见 §3.4）。

## 3. 设计

### 3.1 包格式

```
manifest.json            包元数据、计数、db 与索引摘要
jianartifact.db          VACUUM INTO 一致性快照
blobs.index              每行 "<sha256> <size>"，确定性排序，用于核对与求差
blobs/<xx>/<yy>/<hash>   仅快照库 asset 表引用的 blob
```

`manifest` 字段：`schemaVersion / kind / packageId / mode / basePackageId / createdAt / nodeId / appVersion / dbSchemaVersion / counts / db{file,sizeBytes,sha256} / blobs{file,count,totalBytes,indexSha256}`。

### 3.2 分层落点

| 层                     | 职责                                                                                        |
| ---------------------- | ------------------------------------------------------------------------------------------- |
| `internal/archive`     | 纯格式层：manifest 与 blob 索引的编解码、tar.gz 读写、摘要校验、集合求差。无项目内依赖。    |
| `internal/persistence` | `SnapshotFile`（独立连接的 `VACUUM INTO`）、`AssetBlobs`（快照库 blob 集合）、`RowCounts`。 |
| `internal/domain`      | `BackupService`（生成编排、登记、校验、签名链接）、`BackupLinkSigner`。                     |
| `internal/api`         | 契约端点；下载的签名/会话双鉴权。                                                           |
| `cmd/jianartifact`     | `backup create/list/verify/link/delete`。                                                   |
| `apps/web`             | 「迁移与搬迁」页 Tab2：备份列表、生成向导、链接与校验。                                     |

### 3.3 签名下载链接

令牌 = `base64url(HMAC-SHA256(派生密钥, packageId + "\n" + expUnix))`，签名密钥由启动密钥派生（`jianartifact/backup-link/v1`），不复用原值。校验时用请求给出的 `exp` 重算签名，因此改动包名或有效期都会失效。包本身不加密。

### 3.4 集群退役的共享代码归属

| 牵连处                                                 | 处理                                                   |
| ------------------------------------------------------ | ------------------------------------------------------ |
| 原子 operation envelope（`asset_mutation*`）           | **保留**：独立服务于审计与制品操作，仅摘除复制专用分支 |
| `format_metadata_service` / `cargo` / `negative_cache` | **保留**：格式语义与上游健康探测仍在用                 |
| `business_write_gate`                                  | **保留并复用**为冻结窗口闸门                           |
| `setting_service` 的集群配置项                         | 移除配置项与设置页入口                                 |
| `config.go` 的 `JIAN_REPLICATION_*`                    | 移除；**保留 `JIAN_DATA_DIR`**                         |
| 集群数据表                                             | **默认保留不 DROP**：不可逆且收益为零                  |

## 5. 验收标准

**自动化（已覆盖）**

- `VACUUM INTO` 在并发写入下产出的事务不变量一致（`a+b=100` 快照永不破），且并发写入不被快照阻塞。
- 包往返：写 → 读 → 浅校验 → 深度校验 → 解包内容一致。
- 篡改 db 摘要 / 篡改 blob 内容（等长）/ 改变 blob 长度，三种损坏分别被对应强度的校验拦下。
- 归档内非法条目名（路径穿越）被拒绝。
- blob 集合只含被 `asset` 引用的内容，孤立 blob 不进包。
- 生成失败：登记置 failed、包体与快照临时文件均不残留。
- 并发生成被拒绝；重启遗留的生成中包被标记 failed。
- 签名令牌：换包名 / 改有效期 / 过期 / 伪造 / 空值 / 换密钥，全部拒绝。
- 端到端：创建 → 列表 → 取签名链接 → **不带任何会话头下载成功且内容是 gzip** → 篡改令牌 401 → 无令牌且无会话 401 → 深度校验通过 → 删除 204 → 再查 404。
- 校验失败按两类区分：包不可用（不存在 / 未完成 / 文件缺失）走通用错误映射（404 / 409）；包在但内容校验未通过返回 **422 + `BackupVerification`**（业务结论，而非泛化的 500）。
- CLI：参数与退出码、create→list→verify→link→delete 全链路、缺对外基址时拒绝签相对链接。
- 前端：视口滚动锁、Table 列结构、StatusPill 状态、生成向导三步全流程。
- 冻结窗口策略边界：给 `until` 早于当前或晚于 `now+24h` 一律 400；省略时 `ttlSeconds` 缺省 7200 且钳到 [60, 86400]；`GET` 未冻结时省略 `until`/`frozenAt`；`DELETE` 幂等（未冻结也返 200 与当前状态）；不提供无限期冻结。
- 冻结放行清单与写门：冻结期间业务/管理写被 503 + `write_frozen` 拦下，但读方法、`POST /api/v1/auth/login`、维护命名空间 `/api/v1/maintenance/` 与备份导入/上传前缀（`/api/v1/backups/import{s}`、`/api/v1/backups/uploads`）放行——它们只写 `restore-staging/` 与 `restore.pending`、重启才生效。
- 导入状态机与错误码映射：`queued → fetching → staging → pending_restart → done`，失败转 `failed`；`target_not_empty` 与 `restore_pending` 映射 409，`fetch_failed`/`package_oversize`/`sha256_mismatch`/`manifest_invalid`/`incompatible`/`internal` 按语义落记录终态；增量差包导入当前返回"不支持"。
- 无会话签名下载（P1 已覆盖，本轮回归确认）：不带任何会话头、仅持签名令牌即可拉包成功且内容为 gzip；篡改/过期/伪造令牌 401。
- 导入规模护栏（防解压炸弹，写盘前校验）：快照声明 8 GiB、blob 总量 50 GiB、blob 条目 500 万，超限即中止并记 `package_oversize`/`manifest_invalid`。
- SSRF 防护：URL 拉取拒绝回环/私网/链路本地/云元数据地址，每次拨号重新解析（防 DNS 重绑定），重定向重新校验；非 2xx、传输错误与私网拦截统一归 `fetch_failed`。
- 目标非空判据排除内置 `anonymous` 主体（迁移 0007 无条件植入），故全新实例不会被误判非空而强迫 `--overwrite`；非空且未 overwrite 时记录终态 `target_not_empty`（409）。
- 分片上传续传按磁盘推导：`uploadedChunks` 由磁盘上真实存在的分片得出（以磁盘为准，不单信库记录），缺哪片补哪片、重复片幂等覆盖；会话过期由 `ReconcileExpired` 清理磁盘与记录。
- 分片上传客户端输入错误统一 400：片号越界（`[0, ceil(total/chunkSize))`）、单片超额（> 服务端 `chunkSize`）、缺失片、空体；单包上限 50 GiB 同样以 400 拒绝。
- 分片上传 `complete`：缺片时返回缺失序号、边拼装边算 sha256、与声明不符删除半成品、再交导入状态机（仍需重启生效）；`abort` 仅删磁盘目录、库记录保留为 `aborted`（故 `GET` 返回 200 + `aborted` 而非 404）；`overwrite`/`deep` 已支持。
- 增量差包侧车与 `Expected` 向后兼容：全量包不写 `expected`（仍可被旧读取逻辑忽略），差包 `Expected` = 应用后完整并集且等于基线侧车 ∪ 差集；差包可再派生差包。
- 增量差包导入基线判定：本地集合 ∪ 包内差集与 `Expected` 一致才继续（Extract 只合并差集 blob），不一致报"基线包未就位，请先导入基线包 `<id>`"且绝不落文件/标记；`basePackageId` 非空但 `expected` 为空（畸形手工包）仍报"增量包导入尚未支持"。
- 删除保护：被差包引用的基线包拒绝删除（与增量基线派生机制一致）。

**需用户确认（实机）**

- AC-B1：真实大仓库（GB 级 blob）生成热备份期间，服务对外读写不受影响，快照与包校验通过。
- AC-B2：在新机器用签名链接拉包并导入，重启后数据、制品下载、账号登录与旧机一致。
- AC-B3：增量差包的切换窗口（冻结 → 差包 → 导入 → 起服）在分钟级内完成。

## 6. 风险 / 待定

- **包明文**：包内是全部业务数据（用户、令牌、仓库、制品）。必须强制 HTTPS + 短有效期令牌，并在 OPERATIONS 中写明风险。
- **`VACUUM INTO` 目标已存在即失败**：生成前必须确保目标名不存在（包标识含随机后缀，天然规避）。
- **深度校验耗时与包同阶**：前端已放宽该请求的超时；CLI 建议按需使用。
- **增量基线被删除**：本期以"基线有派生包则拒绝删除"兜底；基线丢失后的派生包不可用。
- **集群退役风险**：约 1.8 万行、牵连资产操作 / 审计 / 设置 / 仪表盘。必须在 P1–P3 验收后按 `sdd-refactor-code` 门禁逐步执行，每步保持测试全绿。
- **命名区分**：现有 OPERATIONS §3.2 的"离线包"是 Nexus `bundle/`（外部导入）；本功能是"节点备份包"。UI 与文档必须显式区分。
