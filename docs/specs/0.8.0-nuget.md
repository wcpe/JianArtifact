# 功能规格：NuGet V3 仓库

> 状态：开发完成，验收通过，待发版　·　关联 PRD：FR-29　·　分支：main　·　依赖：FR-32（格式启停）、FR-104（制品生命周期）、FR-105（集群复制）、FR-109（发布账号防护）；决策：ADR-0015

## 1. 背景与目标

.NET/NuGet 客户端以 V3 service index 发现发布、flat container 与 registration 资源。仅把 `.nupkg` 当成普通文件无法完成 `dotnet restore`，因为客户端还需要包 ID/版本列表、依赖元数据与可重写的资源 URL。

本 FR 为 NuGet 提供 hosted、proxy、group 的 V3 最小完整链路：原生 `dotnet nuget push` 可发布 hosted 包，`dotnet restore` 可从三种仓库类型恢复依赖，且客户端始终只访问 JianArtifact。

## 2. 需求

- 新增仓库 format `nuget`，支持 hosted/proxy/group；权限、可见性和 group 成员格式校验复用现有仓库模型。
- 每个 NuGet 仓库提供固定 V3 基址 `<public-base>/nuget/<repository>/v3/index.json`，service index 至少声明：PackageBaseAddress、RegistrationsBaseUrl、PackagePublish（仅 hosted）和 SearchQueryService（仅可精确包 ID 查询）。所有 resource URL 均指向当前节点 public URL，绝不透传上游主机。
  - **hosted 发布**：支持 `PUT /nuget/:repo/api/v2/package` 接收 `.nupkg`；认证支持 ADR-0015 协议 Basic 用户名口令、Bearer `jat_` API Token 与 NuGet 标准 `X-NuGet-ApiKey` 中的 JianArtifact API Token，Web JWT Bearer 在 NuGet 协议端点统一为 401，并统一受 FR-109 发布策略、不可变 Release 和审计约束。不可变 Release 的原生 push 一律不覆盖既有逻辑对象，即使主体为管理员；仅未来统一管理 API 携带 `overrideReason` 时才可执行格式感知覆盖。服务端流式落 blob、校验 ZIP/NuSpec 的 package ID 与版本，规范化为小写索引键，并以包 ID + 规范版本保证不可覆盖。成功返回 NuGet 兼容成功状态；proxy/group 发布返回 409。
- **恢复读取**：支持 V3 flat container 的包版本索引与 `.nupkg` 下载，及 V3 registration 的 package/版本元数据读取。hosted 根据已发布的包记录生成索引和 registration；读取 `.nupkg` 必须流式回写，不能整体读入内存。
- **proxy**：service index、flat-container 版本索引、registration 与 nupkg 均可从兼容 NuGet V3 上游按需回源并缓存；所有返回 JSON 内 URL 重写为当前 JianArtifact 路由。上游包一经缓存须建立本地 NuGet 包记录，以供后续 hosted/proxy/group 的索引与 registration 查询使用。
- **group**：服务 index 属于 group 本身；版本列表和 registration 按成员顺序合并，同 ID+版本由首个成员胜出；nupkg 按成员有序解析。成员不可达或未命中时继续下一成员，全部未命中返回 404。
- NuGet 包删除/取消列出、符号包、完整语义搜索、所有者管理、镜像签名验证和漏洞审查不在本 FR。管理端通用删除暂不向 NuGet 暴露，避免把物理删除误当 NuGet unlist。
- 未启用 `nuget` 格式时，FR-32 保证没有 `/nuget` 路由、无 NuGet 派生索引任务且不能创建该 format 仓库。

范围内：NuGet V3 hosted/proxy/group 的 publish、restore、缓存与基础精确查询。
不做：NuGet V2 feed、unlist/delete、symbols、外部搜索引擎、包签名/漏洞策略。

## 3. 设计

- **路由与分层**：`protocol/nuget.go` 注册 `/nuget/:repo/...`，负责 V3 HTTP 协议、API key 提取、URL 重写和错误码；包验证、索引生成与资产编排位于 domain/repository，协议层不访问 SQLite 或 blob 文件。私有上游仅通过 `RepositoryConfig.CredentialRef` 的 ADR-0022 受限运行时 resolver 从 `JIAN_UPSTREAM_CREDENTIAL_<credentialRef>` 取得凭据，所有上游 service index、resource URL、包下载和重定向均经 ADR-0015 的出站地址、DNS 重解析与重定向校验，拒绝环回、链路本地、私网和云元数据地址。
- **数据模型**：在 asset 之外新增受迁移管理的 NuGet package metadata：仓库、规范化 package ID、规范版本、nupkg asset 路径、NuSpec 中恢复所需的依赖与框架元数据、发布时间和来源。唯一约束为 `(repository_id, id_normalized, version_normalized)`；原始 ID/版本保留供 registration 响应展示。不得把完整 nupkg 解压内容、API key 或用户凭据落库。
- **上传与一致性**：上传先以流式方式进入内容寻址 blob，再从本地 blob 的受限随机访问视图读取 ZIP 中 `.nuspec` 建立 metadata；解析限制压缩包最多 128 MiB、最多 10,000 条目、声明的总解压大小最多 512 MiB，`.nuspec` 最多 1 MiB。普通二进制条目不适用 `.nuspec` 的 1 MiB 限制，但仍受总预算约束；任何超限均在创建 asset/metadata 前拒绝。格式、ID、版本与包路径不一致、缺 `.nuspec`、重复版本或解析失败均拒绝。metadata、asset、审计和复制记录使用 FR-104/105 的原子写路径；失败不留下可恢复到客户端的包或索引半状态。
- **资源生成**：flat-container 索引由 metadata 按 NuGet 版本排序生成；registration 只生成 restore 必需的 catalog leaf/page 字段与依赖信息。SearchQueryService 仅接受精确 ID，返回同一 metadata 投影，不做全文搜索或上游任意 query 透传。
- **代理与 group**：上游 JSON 由格式解析器验证并重写 resource/package URL 后缓存；nupkg 下载仍复用内容寻址和 single-flight。代理首次得到 nupkg 时提取 NuSpec 建索引；若上游 registration 的版本指向本地尚未缓存的包，服务端可按请求回源该具体版本，不能凭未经验证的 URL 生成本地记录。group 合并只读取成员已验证的 metadata。
- **可见性与复制**：所有 generated JSON 依请求仓库鉴权，不能借 group 泄露私有成员包名。NuGet metadata 作为 asset 派生真相参与 FR-105 的操作批次与历史回填；blob 仍只在缺失时流式拉取。

## 5. 验收标准

### 自动化

- 覆盖 package ID/版本规范化、ZIP/NuSpec 校验、重复版本拒绝、恶意 ZIP 路径与损坏包拒绝；超多条目、过大中央目录、过大 `.nuspec`、单条目与总解压上限均在无 asset/metadata 副作用下拒绝；大 nupkg 上传/下载的代码与测试证明不整体载入内存。
- `httptest` 验证 hosted service index 的全部 URL 指向本仓、发布后 flat-container/registration 一致、`.nupkg` 字节不变；Basic/Bearer/X-NuGet-ApiKey 成功，Web JWT Bearer 为 401，未授权/越权/非 hosted 发布被拒绝。
- proxy 测试验证 resource URL 不泄露上游、首读缓存、热读不回源、上游 404/502/超时映射、credentialRef 运行时解析、环回/私网/DNS 重绑定/危险重定向拒绝，以及响应、持久化、日志、审计和报告不含凭据值；group 测试验证版本合并、首成员优先和成员故障回退。
- 复制测试验证发布后的 asset 与 NuGet metadata 在第二节点同时可见，缺失 blob 仅拉取一次；失败注入不出现只有 metadata 或只有 nupkg 的半状态。
- 以临时 .NET 项目和本地测试包执行 `dotnet nuget push`、`dotnet restore`、`dotnet build`，分别覆盖 hosted、proxy、group，不依赖公共 NuGet 服务。
- 受影响 Go/前端契约、格式化、静态检查、构建测试全绿。

### 真机验收（须用户确认）

- 使用真实 .NET SDK 从 hosted 发布一个新包，并在干净项目中经 hosted、proxy、group 执行 restore/build；抓包或服务日志证明客户端不直连上游。
- 两节点环境发布和读取 NuGet 包，确认对端在同一复制操作完成后才能通过 service index/registration 发现该版本，包下载哈希一致。
- 私有仓在未认证、无 ACL 与 API key 吊销后均拒绝；公开仓匿名 restore 正常。

## 6. 风险 / 待定

- NuGet 的 registration 数据是恢复正确性的核心；必须以真实 `dotnet restore` 为验收，不以 service index 200 代替。
- `.nupkg` ZIP 元数据解析需要随机访问，但不得因此把包整体读入内存；实现须复用 blob 文件的受限随机读能力或临时文件。
- 本 FR 不提供 NuGet unlist；若以后支持，须先定义与 FR-104 blob 回收、NuGet listed 状态和集群原子复制的一致语义。
