# 功能规格：PyPI Simple API

> 状态：已交付@v0.8.0（客户端维度豁免）　·　关联 PRD：FR-27　·　分支：当前工作区　·　依赖：FR-32、FR-104、FR-105、FR-109；决策：ADR-0010、ADR-0015、ADR-0018

## 1. 背景与目标

Python 工具链以 Simple Repository API 发现候选分发包，客户端根据标准化项目名、文件链接、哈希片段与可选 `Requires-Python` 选择 wheel 或 source distribution。把 wheel 当 Raw 文件保存无法使 `pip install` 发现版本，更不能安全代理上游链接。

本功能提供 hosted、proxy、group 三类 PyPI Simple API：普通 `pip install` 使用本仓 URL，Twine 可向 hosted 发布，proxy 首拉时把上游候选文件映射到本仓下载端点，group 以确定顺序合并候选文件。系统继续用 SQLite 作为元数据真源、内容寻址 blob 保存文件、ACL 做授权。

## 2. 需求（要什么）

- **Simple API**：
  - `GET|HEAD /pypi/<repo>/simple/` 返回项目名索引；`GET|HEAD /pypi/<repo>/simple/<normalized-project>/` 返回 PEP 503 HTML，并在客户端 `Accept: application/vnd.pypi.simple.v1+json` 时返回 PEP 691 JSON。
  - 非规范化项目名或缺少尾部 `/` 必须 301 到规范化、带尾斜杠 URL；项目规范化采用 PEP 503（小写，连续 `[-_.]` 转单个 `-`）。
  - 每个文件链接指向本仓 `GET|HEAD /pypi/<repo>/packages/<normalized-project>/<filename>`，附 `#sha256=<hash>`；HTML 属性正确转义，可选 `data-requires-python` 与 yanked 信息；JSON 具有 `meta.api-version`、files、hashes、requires-python、yanked。
- **hosted 发布**：实现 `POST /pypi/<repo>/legacy/` 的 Twine/legacy multipart `:action=file_upload`。读取表单的项目名、版本、文件名、`requires_python` 等标准字段，流式存储文件并计算 sha256；同仓同项目同文件名不可覆盖。发布成功后文件和 simple 索引在同一事务可见，返回 Twine 可接受的成功响应。
- **hosted 删除限制**：本 FR 不提供 legacy 删除或任意文件 DELETE。PyPI 的管理员删除将在单独的格式感知生命周期 FR 中明确版本/项目元数据规则；现有 Raw 删除端点不得误把 PyPI 保留 asset 路径当普通文件处理。
- **proxy 与 group**：
  - proxy 的 `remoteUrl` 是上游 Simple API 根地址。首次项目索引请求以 PEP 691 JSON 优先、HTML 回退解析；解析每个上游链接的绝对 URL、sha256、requires-python、yanked 状态并持久化映射，对外只返回本仓链接。客户端请求本仓 packages 路由时才流式回源该文件，若声明 sha256 必须校验后缓存。
  - group 按成员顺序合并项目与候选文件；同一规范化项目/文件名冲突首成员胜出。下载按候选记录的来源成员解析；group 不可发布。
- **权限、发布防护、审计与复制**：读写复用 ACL 与 ADR-0015 协议认证；Basic 只接受账号口令或 API Token，Bearer 仅接受 `jat_` API Token，Web JWT Bearer 在 PyPI 协议端点统一为 401。Twine 的 Basic/API token 或 FR-109 允许的账号密码发布认证进入统一 principal。不可变 Release 的原生 legacy 上传一律不得覆盖既有逻辑对象，即使主体为管理员；仅未来统一管理 API 携带 `overrideReason` 时才可执行格式感知覆盖。发布账号可选多个项目名前缀，未配置时覆盖授权仓库全部项目；额度以新分发文件计量。发布、拒绝、代理缓存与复制应用均写完整审计身份，但绝不记录 multipart 表单中的密码、令牌或文件正文。
- **范围外**：Warehouse JSON API、上传前预校验、项目所有者/协作者、搜索、Stats、TUF、签名验证、Pipenv/Poetry 私有扩展、release yanking、原生删除、管理端 PyPI 文件移动/改名不在本 FR。不得从用户提供 URL 代为下载。

## 3. 设计（怎么做）

### 3.1 路由、格式与输出

- 新增 `protocol/pypi.go`，由 FR-32 按 `pypi` 格式开关注册 `/pypi/:repo/simple/*rest`、`/pypi/:repo/packages/*rest` 与 `/pypi/:repo/legacy/`；协议端点不进 OpenAPI，但 repository format 枚举、创建校验、前端/devmock、usage 和 Nexus 发现须同步支持 `pypi`。
- `PyPIHandler` 只完成 HTTP、content negotiation、canonical redirect 和 multipart 边界校验；`domain.PyPIService` 负责名称规范化、文件/上游元数据、候选合并、发布策略、事务和复制。禁止 handler 直接访问 SQLite、blobstore 或上游 HTTP。
- 以节点本地 FR-87 `public_url` 生成 simple 文件绝对链接；没有配置时回退已验证的反代 scheme/Host。不得把 `remoteUrl`、上游 file URL 或 source IP 输出给客户端。

### 3.2 数据与发布

- 新增 `pypi_file`：仓库 ID、规范化项目名、展示项目名、版本、文件名、asset 路径、sha256、大小、requires-python、yanked、来源类型（hosted/proxy）、上游文件 URL（仅服务端使用）、来源成员、创建/更新时间；同仓/项目/文件名唯一。文件 asset 固定为 `pypi/packages/<normalized-project>/<filename>`，继续由 blobstore 内容寻址。
- `PyPIService.Publish` 使用流式 `MultipartReader`，对请求头、字段名/值、边界与非文件字段设置明确上限，禁止 `ParseMultipartForm` 或把完整表单/文件载入内存；随后校验项目名/文件名边界和仓库 hosted/write 权限，流式写入同盘暂存、计算 sha256，最后单事务创建 asset 与 `pypi_file`。文件名冲突、发布策略拒绝或任一失败均不得覆盖旧文件或留下新 metadata/blob 可见状态。
- Simple HTML/JSON 由 `pypi_file` 动态生成，不能保存为用户可覆盖的 asset；项目根索引按规范化项目名排序，文件候选按文件名稳定排序。FR-104 回收和仓库删除必须把该格式 asset 与 `pypi_file` 关系纳入同一可恢复操作。

### 3.3 上游、group、复制

- `PyPIUpstreamClient` 只从仓库配置且经统一出站安全策略验证的 Simple 根地址请求项目索引；私有上游仅通过 `RepositoryConfig.CredentialRef` 的 ADR-0022 受限运行时 resolver 从 `JIAN_UPSTREAM_CREDENTIAL_<credentialRef>` 取得凭据。优先请求 PEP 691 JSON，收到不支持才用现有 `golang.org/x/net/html` 解析 PEP 503 anchor（该模块已在锁定依赖图中，不增加版本或新第三方依赖）。解析 URL 时以已验证上游索引 URL 为基准，拒绝非 http/https、用户信息、环回、链路本地、私网、云元数据地址、危险重定向、缺 filename 或未能关联项目的链接，并在连接时重新校验 DNS；credentialRef 的值、任意环境变量名和解析结果不得进入数据库、响应、日志、审计或报告。
- proxy 刷新项目索引采用 `(repo,project)` single-flight。真正下载时以 `(repo,project,filename)` single-flight 收敛；上游 404→404、超时→504、解析失败/sha256 不符→502，失败不写 `pypi_file` 或 asset。缓存缺少上游 sha256 的文件时仍计算本地 sha256 并只向客户端公布本地值。
- group 合并由 `PyPIService` 根据候选记录完成，不能把代理上游 HTML 直接拼接给客户端。`pypi_file` 的 hosted/proxy 写入及其 asset 作为复制实体；同一发布或缓存记录用 operationId 的完成边界，接收节点先复制 blob 后再在一个事务中使 simple 索引可见。

## 5. 验收标准

### 自动化

- PEP 503/691 夹具验证项目名 canonical redirect、尾部 `/`、HTML 转义、JSON content type、哈希链接、requires-python、yanked 和空/缺失项目响应；输出不能包含 upstream host 或 credentials。
- hosted 集成测试用 multipart 发布 wheel 与 sdist：同文件名覆盖拒绝、hash 正确、simple HTML/JSON 都能发现、packages 字节/HEAD/ETag 一致；中途失败、事务失败和 blob 暂存失败不产生可见候选。
- proxy httptest 覆盖 JSON 优先、HTML 回退、相对/绝对链接、404/超时/5xx、hash 不符、缓存命中与 single-flight。仅可从已解析记录中的上游 URL 下载，伪造 packages 路径不得造成 SSRF。
- group 覆盖项目并集、同名文件首成员优先与正确来源下载；proxy/group legacy 上传均拒绝。发布账号的前缀、额度、Web 禁止、不可变、JWT Bearer 401 以及拒绝审计均有测试。
- 私有上游 `credentialRef`、环回/私网/DNS 重绑定/危险重定向拒绝均有测试；响应、持久化、日志、审计和报告不含凭据值。
- 双节点集成测试确保 node A 发布/代理缓存的文件在 node B blob 到齐前不出现在 simple 索引；断网恢复后 pip 可下载且审计、复制水位、blob 引用一致。

### 真机验收（须用户确认）

- 使用全新 Python 虚拟环境和真实 pip，分别以 `--index-url <base>/pypi/<repo>/simple/` 安装 hosted wheel、sdist 和依赖；启用 `--require-hashes` 验证文件链接 sha256。使用真实 Twine 按 Basic/API token 和受限账号密码发布，确认不可变、前缀与额度拒绝不会污染索引。
- 以公开 PyPI compatible 上游及一个带凭据引用的私有上游完成 proxy 首拉、缓存后断上游安装、group 安装；检查客户端看到的所有链接均为本仓域名。
- 双节点真实部署从 A 发布一个测试包后在 B 的空缓存虚拟环境中安装；断网时 B 的 simple 索引不得出现未下载文件，恢复后无需手工刷新或清理。

## 6. 风险 / 待定

- PyPI 的链接与 HTML 容错面很大，简单正则会误解析/注入；必须以标准 HTML 解析器、严格 URL 白名单和 HTML 转义实现，不能把上游正文原样透传。
- wheel/sdist 文件名并不能无歧义表达所有 Python 元数据；首版以 Twine 提供的 project/version 和唯一 filename 为权威，复杂 core metadata/PEP 658 留后续 FR。
- `pypi_file` 是 asset 外协议索引。FR-104/105 必须先扩展其引用与复制边界，避免回收仍被 simple 索引引用的 blob，或把 metadata 同步到对端却漏传文件。
