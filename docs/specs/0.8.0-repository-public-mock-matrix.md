# 功能规格：仓库与公开浏览 Mock 验收矩阵

> 状态：已交付@v0.8.0　·　关联 PRD：FR-122（原 FR-123 并入）、FR-105（原 FR-108 并入）、FR-114　·　依赖：FR-122　·　目标版本：v0.8.0

## 1. 背景与目标

仓库管理与公开浏览是控制台最常用的路径，但现有开发预览集中于少量正常数据和个别操作，搜索与清理等请求还缺少 Mock handler。管理员和匿名用户无法在不依赖后端的情况下完整核对列表、详情、ACL 和公开浏览的状态反馈。

## 2. 需求

- 覆盖 `/repositories`、`/repositories/:name`、`/repositories/:name/acl`、`/search`、`/p/:name` 与 `/licenses`。
- 仓库列表覆盖正常、空态、加载、失败、匿名公开视图和受限管理操作；新建、可见性/配置编辑、在线重测、清理空制品和删除均覆盖成功与失败反馈。
- 仓库详情覆盖正常树、空树、仓库不存在、树/用量加载失败、Maven 上传链路、Raw 资产删除/移动/重命名以及其成功/失败反馈。详情的「浏览/配置/ACL」语义 Tab 固定在应用页眉下方，长树滚动时仍可切换；移动端单行横向滚动，不增加第二层侧栏。
- ACL 覆盖正常、空态、加载、失败、无权限和保存成功/失败；失败不得丢失本地编辑。
- 搜索覆盖正常结果、无结果、加载、失败、表达式查询、筛选、排序、分页和跳转到制品；不新增后端搜索语义。
- 公开别名只验证保留查询参数后重定向到同一仓库详情状态，不复制第二套页面；开源协议页是只读页，仅覆盖正常、空态、加载、失败和无权限。
- 不做：修改仓库/ACL/搜索的生产 API、扩大匿名权限、改变资产操作事务或新增公开页面能力。

## 3. 设计

- 复用 FR-122 的页面场景基座和 `packages/devmock` 内存态。搜索、清理及现有未覆盖的管理端点补齐为与 OpenAPI/既有 endpoint 一致的 handler。
- 页面读取仍经现有 typed API client；按钮、确认框、通知和页面状态通过实际交互触发，禁止测试直接调用组件内部回调来冒充验收。
- `RepositoryDetailPage` 的固定 Tab 使用标准 tablist/tab/tabpanel 语义和 CSS sticky；不以左侧二级导航取代。

## 4. 任务拆分

- [x] 补齐仓库、详情、ACL、搜索和许可证的 Mock 夹具与 handler，包括搜索、清理、统一资产操作与 Raw 协议上传/删除。
- [x] 为各页面接入读取状态及可写操作的成功/失败场景。
- [x] 固定仓库详情语义 Tab，并补齐窄屏和键盘访问测试。
- [x] 补齐公开、匿名、未授权、404 和操作失败的页面交互测试。
- [x] 文档同步：PRD 状态、CHANGELOG。

## 5. 验收标准

- 六条路由均可在开发态复现其适用的正常、空态、加载和失败状态；公开别名与目标详情路由表现一致。
- 仓库的创建、配置/可见性保存、在线重测、清理和删除；详情的上传、删除、移动和重命名；ACL 的授权保存和删除，均有确认、请求、成功刷新、失败反馈与输入/选择保留的浏览器级组件测试。上述适用操作同时验证 `503 standby_read_only` 不改变 Mock 业务状态。
- 详情页在桌面、窄桌面和移动宽度下可长距离滚动并随时切换固定 Tab；键盘与读屏保留标准 Tab 语义。
- 匿名用户看不到管理操作；无权限、404、网络/服务错误有明确且不泄露凭据的页面反馈。
- 搜索和清理请求均由 devmock 正确接住，不出现 HTML/JSON 解析错误。
- 相关 web/devmock 测试、类型检查、lint、格式检查和构建通过；开发浏览器人工复核仓库、搜索、ACL 和公开别名。

## 6. 风险 / 待定

- 开源协议清单来自构建产物；空态仅用于页面状态呈现验证，不声明正式发行物可以没有许可证。
