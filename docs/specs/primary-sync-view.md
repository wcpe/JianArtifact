# 功能规格：级联树邻接同步观测增强（FR-119）

> 状态：开发完成，待用户验收　·　关联 PRD：FR-119（原 FR-126 并入；扩展 FR-115、FR-121）　·　目标版本：v0.8.0（尚未发布）　·　依据：ADR-0023、ADR-0026

## 1. 背景与目标

级联树中每个节点只应该回答自己的邻接问题：向上从谁拉、向下为谁提供复制、每条边是否新鲜。FR-119 早期只为 primary 展示一个 standby 的最近上报，无法表达 relay standby 的父边和多个子边，也容易让页面误以为 primary 掌握全树状态。

本功能把观测范围收敛为“当前节点 + 直接邻接边”：父节点通过已经认证的 GET 请求接收直接子节点的有界脱敏报告；relay standby 同时保留自己的父边事实和直接子边报告；任何报告不得跨级汇总或冒充全局健康。

## 2. 需求

- 子节点在向直接父节点发起 capabilities/pull/blob GET 时，可捎带本节点最近的父边同步快照；请求已经通过该子节点专属凭据鉴权，父节点按鉴权 node ID 归属报告。
- 父节点只接受直接子节点的报告：primary 接收直接 relay/leaf standby 报告；relay standby 接收自己的直接子节点报告。relay 不把子节点报告转发给祖父节点。
- relay standby 的集群概览必须同时展示：本节点向上拉取父边的状态，以及本节点向下服务的每条子边状态。多个子边彼此独立，不能用一个汇总状态覆盖不同事实。
- 报告只表示最近窗口和新鲜度，不是跨节点历史代理；报告缺失、过期、解析失败、节点离线或凭据未配对必须显示降级，不得编造最后成功时间。
- 报告和页面不得包含令牌、凭据、环境变量、内部地址、原始错误、命令参数、系统路径或跨节点主机指标。
- 不新增 primary→standby 推送、不新增管理写通道、不允许运行时编辑父子拓扑；观测失败永远不能阻断复制请求。

## 3. 设计

### 3.1 取数通路

```text
child --认证 GET + 自己的父边报告--> parent
parent --本地已完整应用的 records/blob 响应--> child
```

每个节点的本地观测分为两类：

- `parentReport`：本节点作为 child 向直接父节点拉取时产生的本地同步事件、watermark、错误和新鲜度；
- `childReports[]`：本节点作为 parent 接收直接子节点在认证 GET 上捎带的报告。

primary 没有 `parentReport`，只可有 `childReports[]`；leaf standby 只有 `parentReport`；relay standby 两者都有。祖父节点不读取孙节点的报告。

### 3.2 有界报告

沿用现有 GET 捎带机制，报告 JSON 经 base64 编码后放入复制请求头。整体大小上限 8KB，超过后从最旧条目开始裁剪；解析失败、schema 不符或超限直接丢弃，不影响复制。

报告至少包含：schema、reportedAt、父边 watermark、最近同步事件窗口、最近接收审计窗口和脱敏阶段错误；父边 stream generation 由 capabilities/record 传输校验，不信任报告内自报身份。子边报告由父节点按鉴权 header 中的子 node ID 绑定。

relay 向上游发送的报告只描述自己的父边；relay 向下游提供复制时接收的报告只写入本地对应子边，不携带其他子边或祖先信息。

### 3.3 本地存储与新鲜度

直接子节点的最近报告可以采用进程内按 node ID 覆盖保存，重启后在下一次子节点请求时恢复；本地父边同步历史继续由 SQLite 追加记录保存。每条边独立计算服务端新鲜度，使用有效同步间隔和最近成功/上报时间，不由前端自行计算。

报告状态至少支持：`healthy`、`syncing`、`stale`、`failed`、`unpaired`、`paused`、`disabled`、`unknown`。没有报告时不能返回“同步成功”；没有成功时间时不能返回“健康”。

### 3.4 API 与页面契约

继续扩展 `GET /api/v1/observability/cluster`，响应使用当前节点字段、可选 `parent`、`children[]` 和固定 `scope=local_neighbors` 表达邻接范围。现有同步事件列表、详情和变更明细接口继续只读当前节点事实；不新增跨节点历史代理接口。

`ClusterPage` 展示父节点关系卡和直接子节点列表；`ClusterMonitorPage` 以父边/子边为监控单元，显示最近请求、watermark、积压、可转发前缀、计数、错误阶段和恢复提示。primary 只显示子边，relay 显示两侧，leaf 只显示父边。

## 5. 验收标准

- root primary、relay standby、leaf standby 的报告字段和页面区域准确；relay 同时看到自己的父边和至少两个直接子边，primary 看不到孙节点，leaf 不出现子边假数据。
- 一个子节点在认证 GET 上报后，父节点能显示其最近同步事件、watermark、结果和脱敏错误；停止该子节点后只有对应子边过期，其他子边不受影响。
- relay 不会把子节点报告上报给自己的父节点，也不会让祖父节点看到孙节点历史；响应的 `scope` 始终为 `local_neighbors`。
- 报告丢失、过期、非法、超限或伪造 node ID 时，复制仍正常或按既有认证失败处理，报告本身被丢弃且不改变旧事实。
- 页面和 API 不显示凭据、令牌、环境变量、内部地址、原始错误、系统路径或跨节点主机指标。
- 后端 race/集成测试、OpenAPI/devmock 校验、前端角色/多子边/过期降级测试、类型检查、lint/build 通过；真实级联树浏览器复核父边与至少两条子边仍待执行。

## 6. 风险 / 待定

- 上报采用最近窗口和内存态，父节点重启后会短暂显示未上报；这必须作为明确降级而不是成功状态。
- 请求头可能被 CDN/隧道剥离或限长；复制不能依赖报告成功，窗口必须可丢弃。
- 多级链路的端到端延迟和健康不能由单个节点直接证明；页面只承诺直接邻接边事实。
