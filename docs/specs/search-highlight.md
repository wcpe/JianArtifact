# 功能规格：搜索结果直达仓库命中位置（FR-145）

> 状态：待实现 · 2026-09-21 · 轻量契约类（仅一个 URL 参数，无数据模型/无新端点）

## 1. 背景与目标

全局搜索（FR-30）命中某制品后，用户点进仓库详情**还要再搜一遍**才能找到它。本 FR 让搜索结果链接携带命中位置，进入仓库后自动定位并选中该制品，与手动点选后的界面完全一致。

## 2. 契约（核心，唯一对外面）

| 项          | 约定                                                                                                                       |
| ----------- | -------------------------------------------------------------------------------------------------------------------------- |
| 参数        | `highlight`（query，挂在仓库详情路由上：`/repositories/:name?highlight=<artifactPath>`）                                   |
| 取值        | 制品在仓库内的**完整路径**（与树 API 的 `path` 字段同口径），按 URL 编码（`encodeURIComponent`）                           |
| 语义        | 进入仓库详情后：**逐级展开**命中路径的祖先目录 → **选中该文件**（等同手动点选：右侧详情/使用说明照常渲染）→ 滚动到树内可见 |
| 幂等        | 刷新、从历史/分享链接进入，均重新定位（可重复消费）                                                                        |
| 生命周期    | **仅作进入时的初始定位提示**：用户后续在树里的选择不写回 URL（不做双向同步，避免把"当前选中"变成路由状态）                 |
| 多值/多命中 | 不支持（单路径；多命中高亮属搜索域能力，YAGNI）                                                                            |

## 3. 行为细节

- **消费时机**：仓库详情挂载且树数据就绪后执行一次；`highlight` 变化（前端路由内跳转）时重新执行。
- **懒加载展开**：树是逐层懒加载（FR-54）——需按路径分段逐级展开祖先目录，全部就绪后再选中文件；复用既有选中/展开机制（`onSelectFile` 与目录展开回调），不新造选中态。
- **失效降级**：路径不存在（制品被删/改名）或解析失败 → **静默降级**为正常打开仓库，不报错、不打扰；控制台无未捕获错误。
- **不做的**：搜索词回填到仓库内搜索框；URL 与选中态双向同步；定位动画。

## 4. 实现要点

- **搜索页**（`SearchPage`）：结果行指向仓库详情的链接追加 `?highlight=`（保留既有链接其余部分）。
- **仓库详情**（`RepositoryDetailPage` / `RepoBrowser`）：读 `useSearchParams()` 的 `highlight`；路径按 `/` 分段驱动逐级展开，末段命中文件后调用既有选中流程；完成后用 `scrollIntoView` 滚入视口。

## 5. 验收标准

- [ ] **真机过**：全局搜索 → 点击结果 → 仓库详情直接**选中**命中文件（右侧详情与使用说明渲染，与手动点选一致）
- [ ] **真机过**：在该页面刷新 / 复制链接重开 → 仍定位到同一文件
- [ ] **真机过**：`highlight` 指向已删除路径 → 仓库正常打开、无报错（静默降级）
- [ ] 无 `highlight` 时行为与现状零差异；既有树交互与测试全绿

## 6. 风险 / 待定

- 深层路径的逐级展开会产生多次树请求（懒加载固有）；命中路径通常 ≤4 层，开销可接受。
- 若同路径制品在选中瞬间被并发删除：按"失效降级"处理（选中失败不阻塞页面）。
