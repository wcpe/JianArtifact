# 功能规格：私有发布候选与有界静态检测

> 状态：开发完成，待用户验收；私有候选全生命周期、scan_job 持久租约、scan_fact 事实库、裁决预览与单次确认令牌已实现并有回归；扫描 OS 硬隔离按规格为部署前提、属明确阻塞项　·　关联 PRD：FR-169　·　分支：`feat/security-two-factor`

## 1. 背景与目标

计划 E。面向 hosted 发布者、审核管理员和运维：内容先进入私有候选区，经受控静态检查或符合要求的人工复核，才有资格进入公开提交；失败可解释、积压可观测、重启不丢裁决。建议 P1，最终优先级随 PRD 登记。

本文定义内容事实、批准与提升前置条件；协议边界与调用覆盖见 [FR-170](security-protocol-admission.md)，事务取舍见 [ADR-0034](../adr/0034-private-candidates-and-publication-admission.md)。依赖 [可信审计](security-trusted-audit.md)；对接 [凭据生命周期](security-credential-lifecycle.md)、[双因素认证](security-two-factor-authentication.md) 和 [事故处置](security-incident-controls.md)，不另定义代次、强认证或恢复闸。

## 2. 需求（要什么）

- 新 hosted 写入先私有、后准入、再公开；批准不是发布，旧公开版本不因同路径候选待审被替换。
- 检测自动，风险判定、拒绝、例外与证据保全保留独立事实；风险命中不是恶意定论，不自动封账号。
- 每项判断可追溯到清单、版本、摘要、规则和覆盖；不得把检测环境不可用、检测未完成或未知格式等同于通过。
- 范围内：候选、私有字节、队列、隔离 worker、覆盖报告、人工复核、提升前置条件、受控存量复检。
- 范围外：动态执行样本、包内命令、安装依赖、拉取镜像、向第三方上传样本、完整漏洞库或杀毒证明；proxy 缓存不宣称已执行 hosted 准入。

## 3. 设计（怎么做）

### 3.1 私有候选、租约与可见性

**当前实现边界**：受信服务调用 `AdmissionService.Prepare` 登记操作号，在私有目录独立接收 Raw 候选，封存清单与安全事件同事务提交。重启后，原发起人凭交互会话及当前目标发布权可按原操作号查询；查询仅返回状态，可触发服务器核验并持久更新拒绝或到期状态。旧临时文件没有持久登记和归属，不会从文件名或摘要推认候选。无对外候选写入、字节下载、全库管理列表或批准入口；既有原生上传行为不变。

- `AdmissionService` 管理候选、事实和裁决，仓储层管理 SQLite 与私有暂存；协议适配只提交声明及字节流，无权构造批准或跳过受控解析。
- 上传流写服务端分配的同卷私有文件，按实际字节计数、计算 SHA-256；完整落盘后持久化封存输入对象。主服务只处理有界协议封装、字节传输与字段预检，格式探测、归档及嵌入元数据全部交给隔离 worker；逐入口归属见 [F 的解析归属矩阵](security-protocol-admission.md#33-逐入口封装与内容解析归属)。如果坐标或依赖须从内容提取，先登记输入摘要及已知路由约束，按租约接收结构结果并封存完整目标清单后才能批准；任何修订产生新 `manifestVersion`，不复用旧批准。
- `candidate`：服务端 `requestId`（只属于当前入口请求）及独立 `originRequestId`（不可变的发起请求关联，后台只继承此字段，不将它填作新的请求标识）、`operationId`、`repositoryId`、`format`、`actionType`、`actorUserId`、稳定 `credentialId/sessionId`、`authMethod/authStrength`、`state`、`targetVersion`、`manifestVersion`、`manifestDigest`、`policyRevision`、时间戳、`expiresAt`、私有字节数，及可选 `taskId/itemId`。`accountEpoch/securityEpoch` 只作最终提交复核的内部快照；内部文件名、原始凭据永不返回。清单条目用 `canonicalPath/digest`，审计按 A 使用 `eventId,occurredAt,ingestedAt,errorCode`；`committed=not_applicable/not_committed/committed/unknown` 与 `httpStatus/outcome` 分离，`committedAt` 只属于已提交回执。
- 候选持久绑定 [A 的不可变来源快照](security-trusted-audit.md#31-来源边界adr-0031) `{originRequestId,clientIp,proxyTrust,sourceTrustVersion}`；迁移候选继承原任务快照。仅 `direct/trusted`、规范 `clientIp` 且快照信任版本与当前一致才可作为安全输入。终提交按当前 D 发布规则重判原有效 IP；未知、无效或版本不符时暂停，不以原始头、客户端自报、新请求元数据、worker、代理 peer、回环或恢复操作者地址补写或放行。
- 清单按版本化确定性编码，禁止重复规范路径；每项绑定规范目标、对象角色、大小、内容类型及 SHA-256，包含派生元数据、标签和被引用依赖的内容身份/条件。清单摘要不只对上传正文求哈希。需要基于最新索引重算时产生新清单，不沿用旧批准。
- `scan_job`：`candidateId`、`manifestVersion`、目标引擎/规则/解析配置、`leaseGeneration`、`leaseUntil`、尝试数及 `nextRunAt`；索引按到期和可领任务游标查询。事实、批准及状态事件追加，状态投影才允许更新。
- `scan_fact`：`objectDigest`、`engineVersion`、`rulesVersion`、`parserProfileVersion`、`coverageRequired/Completed/Missing`、`integrity`、结果分类、`findings`、执行来源及时间。规则条目含 `ruleId/location/severity/confidence/redactedEvidence`，不返回原样密钥或字节。
- 候选文件不加入公开路径、`asset`、格式索引或 FTS，也不进入活动 blob 的摘要读取解析域。提升时可先把已校验字节安置到活动存储但必须受提升租约保护；没有已提交引用前仍不可读。不能用现有 `StageBlob` 已写活动树的事实替代私有候选设计。
- 读取必须先解析当前已提交的仓库与格式引用、实时 ACL 和事故限制，再打开 blob；主名、别名、group、HEAD、Range、条件请求、目录/搜索/协议索引和摘要路由均如此。不能因共享 SHA-256 找到候选、跨仓挂载或绕过受限引用；不无依据屏蔽其他合法引用。
- 私有状态列表/详情仅返回授权字段，无候选下载 URL、预签名 URL 或公开试读。证据保全和内容访问按 D 的独立授权，不以审核权限授权读取原始样本。

### 3.2 状态机与恢复

| 起始                        | 结果                        | 原子条件与可见语义                                                             |
| --------------------------- | --------------------------- | ------------------------------------------------------------------------------ |
| 接收完成                    | `staged`                    | 持久候选和封存清单；失败无公开结果，按意图回收残留                             |
| `staged` / `pending_review` | `queued`                    | 先预留队列预算，登记目标清单及规则；手工重试与自动重试去重                     |
| `queued`                    | `scanning`                  | 事务认领当前清单；单次租约带递增代次、墙钟和尝试预算                           |
| `scanning`                  | `approved`                  | 完整最小和目标专属覆盖，完整性通过、无需要人工裁决命中；事实和自动批准同时追加 |
| `scanning`                  | `pending_review`            | 风险、覆盖不足、环境阻塞、超限或未完成的检测；无下载引用                       |
| `scanning`                  | `rejected`                  | 当前租约证实硬完整性失败；同事务写事实与拒绝，只拒该候选                       |
| `scanning`                  | `queued`                    | 仅可重试故障/租约过期、未到预算；迟到或代次不匹配的结果不生效                  |
| `pending_review`            | `approved`                  | 服务端验证下节例外条件；审核动作、事实、批准绑定和状态一起提交                 |
| `approved`                  | `queued` / `pending_review` | 清单、策略、规则或批准有效性变化；历史保留，旧批准不得提升                     |
| `approved`                  | `published`                 | SQLite 最终事务消费当前批准并提交公开引用和回执；事务失败无该发布              |
| 未发布、非终态              | `rejected` / `expired`      | 人工拒绝、合规取消、恢复发现字节缺失或期限到达；只影响候选，保全不随状态撤销   |

禁止非终态直接转 `published`、覆盖历史决定或用 `published` 回退表示清理失败。候选 `targetVersion` 每次状态/审核变化递增；`manifestVersion` 仅清单内容变化递增。期限、拒绝或取消与提升竞争按写事务先后裁决。

- 恢复先核对暂存意图、不可变清单、字节和租约；缺失字节报硬完整性失败。无有效租约的扫描重领；无回执的未提交提升仅补偿或重新排队，不凭文件存在补发。
- 发布前预置文件、提交、补偿和启动恢复为不同步骤，不声称文件系统与 SQLite 跨介质原子。不可判定的提交结果先查持久操作回执；不得先删除或再提升。
- 清理按私有引用、提升意图、公开引用、D 保全和 GC 的共同裁决边界执行；保全先赢不得删字节，删除先赢仅登记现存证据。恢复闸未通过不启动后台提升/清理或开放对外读取。
- `published` 回执独立保留；释放暂存引用、清理快照、通知失败单独重试、可告警，不回滚已提交状态或重复业务成功事件。

### 3.3 静态粗检与人工例外

- 通用最小事实：实际字节的类型/特征与声明一致性、SHA-256/大小校验、已识别归档的结构和路径/链接安全、计数/展开边界、适用的敏感材料特征检查；不适用项记录依据，不假报覆盖。
- 归档遍历以实际读取数、条目数和深度计数，不解到主机可写路径；拒绝路径越界、危险/歧义链接、结构损坏、重复规范归档路径、摘要/声明完整性冲突。无法读完结构则不得报告完整性通过。
- 专项优先 npm、Maven/JAR：读取 manifest 与安装脚本声明、对照授权可读的前一已发布版本比较有意义变化；无基线标未知而非「无变化」。脚本声明或可执行文件只作证据，不自动定性。其他格式逐项报告检查覆盖；OCI 不运行镜像。
- 内容事实缓存仅用于同一 `digest+engineVersion+rulesVersion+parserProfileVersion` 可验证完整结果；需要发布上下文或前版本的差异规则按清单重算。缓存不得复用批准、身份/IP风险、ACL、失败或不完整结果为通过。
- 自动批准仅对全部适用对象/依赖的最小完整性和目标必检项完成、未命中待审规则的清单；审批策略版本变化重新判断，必要时重新扫描，不能凭缓存只看 SHA-256 获准。
- **有合格事实、但有风险或专属覆盖不足**：最小检查已完成、硬完整性通过；近期强认证管理员基于版本化脱敏证据给出明确原因和限时例外。对未知格式必须有可证明适用的最小检测，不能把解析器盲区默认归为不适用。
- **完全没有可采信的最小检测事实**：例如隔离不可用、worker 未执行或超限/超时前未完成最小检查。首版只能恢复安全检测条件并重新检测；无外部结果导入接口、字段、开关或占位实现，自由文本、附件或单次按钮都不构成检测事实。未来若拟启用受控外部复核，须先另行明确受信签发者、验证根、版本化必检项、摘要/清单绑定和撤销机制，经审核批准后才可启用；默认不可用。
- **硬完整性失败**：终止并拒绝该候选，不可例外；保留失败事实，修正后另建候选重新检测。摘要仅用于内容绑定、保全和关联，不因候选失败封禁任一已发布引用，也不新增全摘要跨仓自动或人工封禁。已有发布确须隔离时，由 D 人工确认具体目标；同一目标的别名、group、摘要等路由不可旁路，无关合法共享引用不连坐。

### 3.4 进程与硬预算

- 单二进制的专用 `scan-worker` 子命令仅收只读输入描述符、受限规则包和一次性任务标识，输出有界结构化事实；不继承业务配置、环境秘密、业务 SQLite、主服务 socket 或通知权限，不出网、不执行样本。
- Linux 验收须证实独立低权限身份/受限文件和网络视图、对完整进程树的 CPU/内存/进程数硬上限与终止；Windows 须证实受限身份/文件与网络权限，以及 Job Object 等对完整进程树的硬限制、禁止脱离和终止。机制、最低部署权限及可用性待实机批准，不自动更改 OS 授权。
- 父进程启动时探测能力并按任务确认配置已生效；任一必需隔离缺失或附加失败，先禁止不安全解析，候选标 `scan_environment_blocked`。`context`、软内存限制和超时是外层控制，不是硬沙箱。解析不得占业务写事务或全局资产读写锁。

下列为审核起始预算，不是现有配置或发布性能承诺；已有更严协议/仓库配额优先，只有受控配置才能调大并重验。

| 资源       | 拟议默认与超限                                                                                                                                                    |
| ---------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 入场       | 单次候选总上传 2 GiB、清单 256 项、最多 8 个并行接收；流式计数，声明/实测超限拒绝，无半公开数据                                                                   |
| 私有容量   | 每发布主体 4 GiB/16 个活跃候选、每仓 8 GiB/64 个，全局 32 GiB/512 个；预留后入场、每档独立，磁盘保留安全余量，达上限拒绝而非驱逐证据                              |
| 工作槽     | 全局 2 个、每仓 1 个扫描；50 秒墙钟、60 秒租约，进程组 CPU 总预算拟 30 CPU 秒、硬内存 512 MiB、只允许受控子进程树；父进程读写与杀树独立超时                       |
| 解析       | 每候选最多 20,000 项、4 GiB 实际总展开、单项 512 MiB 展开、嵌套 3 层；清单/解析树均限制节点和层数，不按声明预分配；不完整不等于通过                               |
| 输出/重试  | 结果 256 KiB、最多 128 条发现并记录截断；默认最多 3 次（含首次），退避 15 秒/60 秒；达预算留待人工，不循环新建任务                                                |
| 留存、页面 | 私有候选 7 天后到期，保全例外并计量；事实和历史审批/回执不得由暂存 GC 删除，审计留存由 A 的策略统筹；列表默认 50、上限 100，以 `(createdAt,operationId)` 游标分页 |

### 3.5 契约草案、权限与错误

接口最终以 `api/openapi.yaml` 为准，沿用 A 的管理错误形状 `{error:{code,message},requestId?,operationId?}`；只有有权主体可得 `operationId`，`errorCode` 是事件独立字段。原生协议映射见 F，不更换原生错误封套。

| 接口 / 内部调用                                           | 请求与响应主字段                                                                                                                                          | 授权边界                                                                                                           |
| --------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| `GET /api/v1/security/admission/candidates`               | `repositoryId,state,limit,cursor`；`items,nextCursor`                                                                                                     | 已强认证管理员，过滤后分页；不是 A 的事件分页接口                                                                  |
| `GET /api/v1/security/admission/candidates/{operationId}` | `state,errorCode?,targetVersion,manifestVersion,manifestDigest,repositoryId,coverage,expiresAt,receipt?`                                                  | 原发起者且当前有对应目标发布权限，仅看自己脱敏状态；管理员按权限看发现、审核证据与历史                             |
| `POST .../{operationId}/decisions/preview`                | `actionType,targetVersion,manifestDigest,reason`；可行性、阻塞原因及短效 `confirmationToken,expiresAt`                                                    | 近期强认证管理员；预览不改候选                                                                                     |
| `POST .../{operationId}/decisions`                        | `actionType=retry/reject/approve_exception`、`targetVersion,manifestDigest,reason,confirmationToken,Idempotency-Key`；返回 `actionId,state,targetVersion` | 近期强认证管理员；令牌单用，绑定人、动作、版本、摘要、规则、有效期及幂等键；事实只由系统从同候选已采信扫描记录选取 |
| `Prepare/Approve/Promote`（领域）                         | 可信主体及来源快照、目标/动作、封存清单、版本化事实、批准 ID；提升成功返回持久回执                                                                        | `Promote` 仅发布协调器；worker 仅报告其租约结果，系统进程身份不可代替发布授权                                      |

批准记录固定 `approvalId,operationId,repositoryId,actorUserId,manifestVersion,manifestDigest,engineVersion,rulesVersion,parserProfileVersion,policyRevision,coverage,factIds,decisionKind,approverUserId?,approvedAt,expiresAt`；自动批准记录签发器身份及规则。起始有效期自动 1 小时、例外最多 24 小时，均不超过候选期限，失效后重新核验或排队。

| 错误                                                              | 管理接口状态及语义                                                                                                                   |
| ----------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| `unauthenticated` / `admission_forbidden` / `admission_not_found` | 401 / 403 / 404；无权查询私有对象统一不可枚举                                                                                        |
| `recent_mfa_required`                                             | 403，近期强认证不足时阻断预览/确认                                                                                                   |
| `admission_invalid` / `admission_limit` / `admission_busy`        | 400 请求不合法 / 413 请求尺寸或清单超限 / 429 队列或主体预算满（可给 `Retry-After`）                                                 |
| `security_confirmation_stale` / `admission_stale`                 | 409 确认绑定失效 / 候选、规则或清单变化；现有审核不被覆盖                                                                            |
| `security_idempotency_conflict` / `admission_key_conflict`        | 409 通用动作键冲突 / 准入内容键冲突                                                                                                  |
| `admission_not_reviewable` / `admission_integrity_failed`         | 422 无合格事实、非法转移或硬完整性失败；详情脱敏区分原因                                                                             |
| `incident_write_locked` / `incident_restricted`                   | 503 实例事故写锁 / 403 目标或来源规则拒绝，适用性与防枚举遵循 [D](security-incident-controls.md)                                     |
| `recovery_isolated` / `write_frozen`                              | 503 恢复隔离 / 503 搬迁窗口冻结，不与事故锁或检测不可用合并                                                                          |
| `admission_unavailable` / `scan_environment_blocked`              | 503 准入服务或硬隔离不可用；可对有权主体显示 `pending_review` 与原因。审计不可写时按 A 返回 `security_audit_unavailable`，不提交业务 |

同一短事务追加 `candidate_staged/scan_completed/review_decided` 等关键事实；公开成功只在提升事务写一次，与 A 可信事件、回执关联。积压、最老等待、阻塞原因、超限、租约接管、待清理字节可观测；指标用闭集原因，避免按主体/摘要打高基数标签。

## 4. 任务拆分

- [ ] 先定稿清单编码、状态转换、预算、契约与 A/D 接口；主代理分配迁移号并登记 FR。
- [ ] 实施私有暂存、持久队列、租约、委派隔离、受控清理与可观察状态。
- [ ] 实施事实、缓存、规则、人工例外和提升前置条件；与 F 联调最终写闸。
- [ ] 旧资产保持可见并标明存量覆盖；批次复检只产发现供人工 D 处置，不因规则升级全局撤下；不补造历史准入回执。
- [ ] 跨平台验收和文档同步：PRD 状态、ARCHITECTURE、API、CHANGELOG，最终契约由主代理统一生成。

## 5. 验收标准

1. **本地实现验收（部分执行）**：候选生命周期、完整性裁定、租约接管、确认令牌重放、保全竞争与本机隔离回归已通过；归档结构负向、超限与解析探针矩阵未全量执行。验收条目原文：：隔离目录/一次性 SQLite 证明暂存、扫描中、待审、拒绝、过期及事务失败不改变公开面；归档结构、超限、解析异常、worker 终止/崩溃/重领不阻塞主服务。关闭任一硬隔离机制，原生与直接服务路径均不得启动旧制品解析器；无合格事实时，管理员附自由文本/文件或提交伪造结果也不能批准，且没有导入路径。有合格事实的覆盖不足例外另验 MFA 缺失为 `403 recent_mfa_required`；确认重放与通用幂等冲突分别遵循 C/A。硬失败只拒候选；D 对已发布目标另行人工隔离后，别名、group、摘要读取不得绕过，同时其他合法共享引用仍可读。验证接收后新增 IP 限制/信任配置变更阻止原候选提升，worker 或新请求来源不能覆盖快照；验证过期规则、清单变化、迟到租约、并发审核和保全竞争。注入提交后清理失败，发布及原回执不消失。
2. **真实部署环境验收（未执行，需独立授权）**：在 Linux/Windows 逐项证明硬内存/CPU/进程树、禁网、权限隔离和任务终止；关闭硬能力时任何未信任解析都不启动，状态明确阻塞。固定数据与并发对照写延迟、可用磁盘、队列水位和下载热路径，未测不报吞吐。
3. **生产可发布判定（未执行，需用户批准）**：目标环境符合硬隔离、资源和运维前提；完成凭据切换及 D 备份/恢复/保全演练，复核存量复检和回滚开关，落实异常告警与手工处置。用本地模拟结果不能替代二、三级。

## 6. 风险 / 待定

- 硬隔离平台能力、首版内置最小检查和默认容量待正式审核确认；环境不支持则阻塞，不提供静默跳过或导入外部复核的占位能力。
- 大 OCI 层和多对象批次可能触及预算，需实际客户端和容量基线确认；卷不足时禁止入场，不清理保全或自动退回旧公开路径。
- 已实现并通过质量门（服务端回归、-race 定向、lint、构建）；二级部署级验收与三级生产可发布判定待独立授权。
