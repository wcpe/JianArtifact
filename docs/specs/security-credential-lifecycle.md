# 功能规格：凭据生命周期、撤销与机器身份

> 状态：开发中，用户已审核；已接入改密和账号资格收窄、持久会话及机器凭据的账号代次校验；未完成机器作用域或灾备恢复验证　·　关联 PRD：FR-166　·　分支：`feat/security-incident-controls`

## 1. 背景与目标

安全处置第二批（B），依赖 [FR-165](security-trusted-audit.md)。扩展 FR-08、FR-109 与既有用户/ACL 管理；为 [FR-167](security-two-factor-authentication.md)、[FR-168](security-incident-controls.md) 及协议准入提供统一权威复核。

[当前架构](../ARCHITECTURE.md) 与代码仍有管理 JWT、API Token、Basic 并行入口；改密未原子更新全套凭据撤销状态。本规格不把现有会话禁用检查、ACL、发布策略和 TLS 约束当成缺失，也不等同于新增联合注销。

## 2. 需求（要什么）

- 当前账号、会话与凭据可撤销，改密、身份停用/事故封禁、强因子重置不留下可用旧代凭据；重新启用不恢复旧会话与机器 Token。
- 管理面只有交互会话承载操作者；机器 Token 用途、动作、仓库、路径、有效期与实时 ACL、事故限制取交集，不能成为新发凭据或安全处置通道。
- 每次鉴权及关键最终提交采用同一权威状态检查；异步任务保留发起人和授权快照、每次重查，失败安全。
- 保留协议 Basic/Bearer/Cargo 的机器 Token 承载格式及 TLS 规则。旧密码发布只过渡，不保留已启用/强制 MFA 管理员的密码发布旁路。
- 不做外部会话数据库、IdP 联合注销、上游凭据外发或自动替换用户 CI。

## 3. 设计（怎么做）

### 3.1 数据与状态机（[ADR-0032](../adr/0032-credential-epochs-and-strong-authentication.md)）

| 实体         | 关键字段 / 状态                                                                                                                                                                                             |
| ------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 账号         | 内部 `accountEpoch` 单调递增；`active` / `disabled` 及独立事故限制；`webLoginDisabled` 单独按通道执行，不能让机器 Token 进入管理面                                                                          |
| 会话         | `sessionId` 随机非秘密、`userId/accountEpoch/securityEpoch`、来源、建立/过期时间及撤销标记；`active → revoked` 或 `expired`，终态不反转                                                                     |
| 机器凭据     | `credentialId`、不可逆秘密摘要、`userId`、代次、`purpose/scopes/expiresAt/createdAt/revokedAt`；明文仅颁发时返回一次；`active → revoked` 或 `expired`，换发必须新 ID/秘密                                   |
| 工作者上下文 | `actorUserId`、适用的 `credentialId/sessionId`、内部 `accountEpoch/securityEpoch`、权限目标及 [FR-165](security-trusted-audit.md) 的不可变发起来源快照；无可重用秘密或原始 Authorization；worker 执行者另记 |

- `securityEpoch` 来自库外恢复闸，见 FR-168；账号代次/会话/Token 行只在当前 SQLite 权威。每一条路均验证启用、到期、撤销、代次、用途与限制，JWT 的签名/受众/到期只是前置；无会话行的旧 JWT 不补造新会话。
- 保留 HS256 会话封装、原令牌载体 `jat_`、argon2id、机制中已有的摘要存储。绑定 `sessionId` 和代次；保留已有到期上限，首版假设上限不超过 24 小时，若当前更严则沿用。JWT 的 `jti` 或认证材料不能另作外部可用令牌。
- `authMethod` 沿用 `web_jwt`、`bearer_token`、`basic_token`、`cargo_token`、`basic`，并增加用于一级登录/挑战事件的 `password`、`oidc_callback`、`ldap_bind`、`totp`、`recovery_code`、`local_claim`、`unknown`；`authSource` 指用户来源（`local` / `oidc` / `ldap` / `unknown`）。`authStrength` 固定为 `none`、`password`（含经本地认可的外部第一因素）、`mfa`、`machine`、`recovery`；`mfa` 只代表当前代次的已验证本地强因子，`recovery` 不建立完整会话。事件字段见 FR-165。
- 密码重设、账号停用、事故用户封禁、角色或网页登录资格下调、因子安全重置，在变更事务内提升账号代次、使旧会话及同账号旧代机器凭据/挑战失效；未发生有效状态变更的重复动作重放原回执。不循环逐条更新全部行，旧代可延后标记/清理。单会话登出、单 Token 撤销只改自己的行，不波及其他主体。
- 解禁仅清除指定限制，不重置代次，不复活已撤销实体；原密码若只封禁未改密仍与原账号绑定，但不能重新使用旧会话。事故处置可继续保留禁用，或要求凭据重设和重新认领后才允许新登录。
- 禁用优先于匿名；已呈现无效、撤销、过期凭据不能默默变成匿名访问。纯匿名只允许既有公开 ACL，且事故/恢复读裁决已知。

**当前实现边界**：实际改密、停用、管理员降为普通用户或禁止网页登录会推进账号代次，成功变更、回执与安全事件同事务写入。同值不升代，一次组合收窄只升一次。新 JWT 与持久会话、签发代次匹配后才可用；机器凭据还须未被单独撤销且未过期。只在初始代次的过渡账号上兼容未绑定代次的旧凭据，不回填会话。已经因改密升代的账号升级后须重登、换发 Token；资格被恢复时不会回退代次。尚未完成机器身份用途/细粒度作用域、因子重置、库外时代及所有业务最终提交点的复核。

### 3.2 权限矩阵与 scope

| 凭据/场景                     | 读制品                                          | 原生发布                             | 普通管理 API               | 安全/凭据操作                                                       |
| ----------------------------- | ----------------------------------------------- | ------------------------------------ | -------------------------- | ------------------------------------------------------------------- |
| 匿名                          | 仅公开 ACL                                      | 禁止                                 | 仅既有公开端点             | 禁止                                                                |
| Web JWT（管理员为 MFA）       | 既有 Web/管理下载按实时权限；不用作原生协议凭据 | 禁止；管理交互上传为单独授权动作     | 按 ACL/角色                | 自己的凭据维护；敏感动作需近期强认证/动作确认；事故操作仅全局管理员 |
| `artifact_read`               | `read` scope 与实时 ACL                         | 禁止                                 | 禁止（含管理员名下 Token） | 禁止                                                                |
| `artifact_publish`            | 仅显式 `read` scope 与 ACL                      | `publish` scope 与 ACL/策略          | 禁止                       | 禁止；不能删、提权、登记 2FA、颁发 Token、调整规则                  |
| Basic 用户口令过渡            | 限获准本地非 MFA 账号和协议、实时权限           | 限获准账号和迁移窗口；最终提交仍复核 | 禁止                       | 禁止                                                                |
| LDAP/OIDC、登记/恢复/确认挑战 | 外部第一因素与挑战不是普通会话、不能读制品      | 禁止                                 | 仅挑战自己的下一步         | 禁止直接执行业务动作                                                |

- 现有 ACL 动作蕴含关系只在 ACL 自身求值，不能扩大 Token 的显式动作许可。`scopes[]` 每项 `{repositoryId, pathPrefix, actions[]}`；路径是规范段前缀，`foo` 不匹配 `foobar`，别名先解析稳定 ID，group 读不继承未授权成员仓库。禁止通配目标/危险编码，区分仓库根与空输入；规范化失败拒绝。
- `artifact_read` 只支持 `read`；`artifact_publish` 允许显式 `read/publish`，角色管理员不扩展其 Token 权限。现存自动化若需要未纳入首版的管理能力，不隐式增加用途，列为迁移阻塞。
- 颁发时校验授予者当前可管理对应身份、欲发动作属于可授实际权限；权限后续收窄即时生效。机器 Token 每账号最多 32 个有效项，单 Token 最多 16 条 scope、默认 30 天且上限 90 天；颁发与更新互不复用秘密，客户端显式轮换。

### 3.3 权威复核与事务

1. 入口先验证可信上下文、凭据和用途。在服务端同一暂存/入队事务内把 FR-165 来源快照与发起身份、操作和清单版本绑定，候选、任务、重试按稳定 ID 引用；不接收业务调用方提交的 IP 作为证据。缓存只可加速解析，不得用缓存的接受结果替代当前权威状态。
2. 排队有权不代表有公开权。最终事务对同一输入重查账号/会话/Token 状态、代次、目标 ACL、策略与 FR-168 提交闸；资产另查当前有效准入回执和清单。任务以原 `clientIp` 重算**当前**含 `publish` 的 IP/CIDR 规则，命中返回 403 `incident_restricted`；来源缺失、`proxyTrust` 非 `direct`/`trusted`、来源信任版本失效或当前规则无法确认，返回 503 `security_state_unavailable` 并保持私有/暂停。worker 的 loopback/来源地址、HTTP 重试地址或 JWT 声称的角色均不替代。所有普通管理写也必须在最终事务和事故锁同序；见 [FR-168](security-incident-controls.md)。
3. 撤销/限制或权限变更先提交则后续最终复核拒绝；本次业务先提交保留原成功，处置可另做限制。改密/撤销/权限变更自身的状态、回执、事件同一事务；不得先回 2xx 再撤销或记账。
4. 具名系统保全/恢复作业不借 system 重放人发起任务。只在原来源快照仍可信、未命中当前规则时，权限过期任务才可由同类有权主体重新授权，产生新授权引用并重验清单/版本，旧凭据不复用。原来源未知/失效或仍被限制时不得借重新授权换 IP 续推旧候选；确需发起新操作须重新通过入口与准入，保留原任务/证据不得覆写。
5. 读取在响应头或第一字节前复核；列表分页、重试、Range 或条件请求为新裁决，已开流限制见 FR-168。

### 3.4 API 与失败

语义待 [OpenAPI](../../api/openapi.yaml) 登记；沿现存服务能力扩展，不声明新 URL 已存在。秘密仅出现在受控颁发响应和认证载体，不落审计、下载票链接或错误明细。

| 能力            | 字段 / 返回                                                                                  | 授权及失败                                                                                                                                                                                                              |
| --------------- | -------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 会话清单/注销   | `sessionId/createdAt/expiresAt/revokedAt/authSource/current`；撤销入参 `sessionId`           | 本人会话；退出当前会话幂等；管理员跨账户撤销走事故动作，不给任意会话检索                                                                                                                                                |
| 机器 Token      | `purpose/scopes/expiresAt/label`；回 `credentialId` 与只展示一次的 `token`，其余操作不回秘密 | 本人交互会话，或现有权限允许的近期 MFA 管理员；有 MFA 的普通用户用近期 MFA；未开 MFA 普通用户需新鲜第一因素，并受当前 ACL/策略限制                                                                                      |
| 轮换/撤销       | 新颁发 ID 后验证客户端，再撤 `credentialId`；回执为 ID/结果，不从重试获得旧明文              | 原属主或全局管理员限定动作；版本冲突 409 `credential_version_conflict`，非法用途/参数 400 `invalid_credential_scope`                                                                                                    |
| 通道认证/终提交 | 管理错误体按 FR-165；协议以原生错误封套与适用认证挑战表达                                    | 401 `invalid_credentials`（外部不区分不存在、撤销或代次错误）；已认证但 scope/ACL 不匹配 403 `credential_scope_denied`；管理面禁用的凭据通道 403 `credential_channel_denied`；状态不明 503 `security_state_unavailable` |

- 受保护响应（一次性凭据、会话、认证状态）`Cache-Control: no-store`；用户不得查询其他人的凭据是否命中。撤销原因可保留在管理员事件，不加入外部协议体。
- 主键/摘要唯一索引查询，或按 `userId` 的有界清单；热路径不做网络、复杂记录扫描或重复哈希口令。固定参考环境认证增量 p95 ≤5 ms（不计原有密码哈希/网络）；拒绝洪峰不霸占写事务；过期会话/墓碑按索引小批次清理，不删案件/恢复所需记录。

### 3.5 迁移与兼容

- 先盘点密码协议、管理 Basic/Token、原生 npm/Cargo 等能发证/取证的入口、现有客户端与 ACL；不得有原生 login/adduser 用 Basic 暗发等权机器 Token 的替代入口。原生凭据发行仅可引导到有人验证的界面，变更必须真客户端验收。
- 准备阶段用批准窗口交付盘点与受限机器身份，开启新资格前完成真实客户端验证并形成回滚/沟通方案。旧 Token 不能自动映射成全权限新 Token；无法证明范围需重签。现有会话在加固切换时重登；旧 `revoked_token` 不成新模型的真源。
- 兼容只限切换前批准的协议密码窗口，列入到期计划。管理员进入强制 MFA 状态或普通账号启用 MFA 后即禁其 Basic 密码认证，不因 CI 兼容延长；到截止关闭全部密码发布。切换后不得通过降级二进制让旧凭据复活。
- 上游凭据引用、出站约束、协议 TLS、用户组 ACL、FR-109 的额度/前缀与不可变 Release 规则仍生效；IdP 远端停用默认只阻止新登录，无已验证联动时由本地撤销/封禁结束已有会话。

## 5. 验收标准

- 改密/停用/角色收窄/因子重置先提交时，旧 JWT/Basic/API Token 不能通过入口或最终事务；重新启用不复活；单 Token 撤销不影响独立 Token。
- 已开始任务在原授权失效后不得公开，严格验证冻结/撤销与最终提交双顺序；事件插入失败无凭据状态偏移；丢响应查询原回执。
- 确认 alias/group、跨仓库、编码规范化、并发收窄权限、机器 Token 尝试登录/发证/处置均不扩大权限；Basic 携带机器 Token 在受控原生客户端通过，口令旁路关闭。
- 负例：排队后新增命中发起 IP 的规则时，worker 位于未封禁 IP 仍不能提交；缺失来源、无效代理链、信任配置换代均不得用重试 IP 或手工重新授权填补。规则解除后也不跳过其它授权和准入检查。
- 暂存、恢复、重试均不泄露凭据，ID 不可登录；灾备后即使能签发新时代会话，也不能使用未核对的旧口令、启停状态或角色（裁决见 FR-168）。需用户批准后在真实隔离客户端演练切换、回退（隔离或前滚，不复活旧身份）与配额，自动化不等同生产上线。

## 6. 风险 / 待定

- 管理自动化和原生自动发证兼容改动需迁移清单与独立确认；若客户不能提前换发，该环境不得开启强制阶段，也不声称已完成加固。
- 状态检查与任务过期可能增加人工重授权；上限是首版预算，正式 API 拼写、迁移编号和基准由主代理协调。
