# 功能规格：事故处置、证据保全与恢复安全闸

> 状态：用户已审核，待实施　·　关联 PRD：FR-168　·　分支：`feat/security-incident-controls`

## 1. 背景与目标

安全处置第四批（D），依赖 [FR-165](security-trusted-audit.md)、[FR-166](security-credential-lifecycle.md)、[FR-167](security-two-factor-authentication.md)。扩展 FR-104 物理回收、FR-109 发布防护、FR-135 搬迁冻结、FR-40/FR-132–137 备份恢复；事故锁不复用搬迁窗口自动解冻语义。

[当前架构](../ARCHITECTURE.md) 的 `FreezeController` 是进程内有界写栅栏；恢复 CLI 在打开 DB 前处理 `restore.pending`；当前提交成功后快照只做待重试清理。这里提出持久事故处置、证据引用与恢复隔离，不宣称已存在。

## 2. 需求（要什么）

- 支持人确认撤销单个 Token、封禁用户、按稳定仓库 ID / 规范路径前缀 / 具体制品版本隔离，以及全实例业务写锁；IP/CIDR 规则明确登录、发布或读取范围。
- 每个动作有预览、原因、近期 MFA、幂等键、期望版本、逐项结果、独立审计；在业务只读时仍有最小安全出口。不自动封禁、解除、回滚生产或恢复公开。
- 最终可见性事务复核授权与限制；区分新写被阻止、在途和已提交。保全保护字节但不形成下载授权。
- 恢复不复活已撤销凭据或限制；不以旧库自身证明当前可信；无法证明安全必须隔离并显式报告证据缺口。
- 不恢复退役复制、不提供任意维护绕闸、自动删除旧证据或抵抗控制主机管理员的承诺。

## 3. 设计（怎么做）

### 3.1 数据与状态机（[ADR-0033](../adr/0033-incident-restrictions-and-recovery-gate.md)）

| 实体                  | 状态与字段                                                                                                                                                                                                                               |
| --------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `securityAction`      | 预览 `previewed → confirmed` / `expired`；执行 `applied` / `partially_applied` / `rejected`；持久 `actionId/actionType/actorUserId/reason/targetVersion/actionDigest/idempotencyKey/createdAt/finalizedAt/items[]`，动作和事件是不同实体 |
| `incidentRestriction` | `active → lifted`；仅显式有期限的 IP 规则可进入 `expired`，没有自动解除的实例写锁；`restrictionId/target/effects/version/effectiveAt/expiresAt`；解除生成单独动作并保留原记录                                                            |
| `evidenceHold`        | `active → released`；字节状态 `present` / `metadata_only` / `unknown`；`holdId/target/objectId/digest/sizeBytes/createdAt/releasedAt`，保留单独的持久引用                                                                                |
| 恢复闸                | `normal → isolated → reconciling → ready_for_review → normal`；失败回 `isolated` 并保留原因；`restoreId/securityEpoch/checkpointStatus/verifiedWatermark/gapStatus`，不等同备份导入任务成功                                              |
| 切换栅栏              | 源节点库外持久 `cutoverFenceId`，与 `sourceNodeId/securityEpoch/securityStateVersion` 组成比对水位；`preparing → sealed` 或 `invalidated`；封存后源不得恢复该时代业务写，详见 §3.4                                                       |

- `target` tagged union：`credentialId`、`userId`、`repositoryId`、`{repositoryId,canonicalPathPrefix}`、`{repositoryId,canonicalPath,objectId,targetVersion,digest}`、`instance` 或 `{ip/cidr}`。名称/别名/用户提供的展示文本不作主键；计划变更或同路径换摘要须重新预览。
- 限制组合在允许集合上取交集，任一适用拒绝胜出；解一条不抵消其他条。实例写锁禁业务/管理状态写入而非默认禁止下载；仓库/路径/版本默认拦写和读取，IP 显式给 `effects:[login,publish,read]` 子集及可选过期。IP 限制不代替撤销；配置限期不得用 TTL 自动释放账号冻结或保全。
- 动作类型 `revoke_credential`、`suspend_user`、`restrict`、`lift_restriction`、`hold_evidence`、`release_hold`。`lift_restriction` 仅取消指定限制，不能把撤销的凭据、缺省 ACL 或隔离的候选复活。已经不可恢复删除的内容只能保元数据。

### 3.2 权限与提交边界

| 主体 / 模式                | 允许                                                                                         | 禁止                                                          |
| -------------------------- | -------------------------------------------------------------------------------------------- | ------------------------------------------------------------- |
| 无身份、普通用户、机器凭据 | 确定安全裁决下的既有业务权限；仅有权查看自己的任务/状态                                      | 读取处置详情、批准、证据保全或恢复解闸                        |
| 全局管理员交互会话         | 查看/预览范围，不因同 IP 自动关联资产                                                        | 无近期 MFA 或对错版确认时执行                                 |
| 近期 MFA 全局管理员        | 经确认执行逐项处置、释放和授权导出                                                           | 普通业务绕闸、通用 Shell/SQL、机器 Token 代替确认             |
| 业务写锁/搬迁冻结          | 只开放具名的安全动作、只读查询及必要的强认证/确认步骤                                        | 处置/保全出口不能写制品、仓库配置、ACL 或授予额外发布权限     |
| 恢复隔离                   | 仅受控本机操作员做认领、凭据替换、恢复核对与保全补录；最后需已重新认领的强认证管理员确认恢复 | 公网管理/协议/下载及一般 worker；旧库账号本身不能授权本机操作 |

1. 预览返回裁决快照、数量、可能影响、各 `targetVersion` 与摘要，不产生副作用。提交以当前主体、版本、限制、摘要、幂等键、近期强认证为准；重复且同一授权、动作和摘要返回旧回执，不重复消费/操作。
2. 事故锁/限制的更新与**所有业务可见状态写入**在 SQLite 最终写事务中同序，不只制品。资产提升和普通管理写共用权威裁决：以最终写事务所见当前角色、凭据/会话、代次、ACL、权限目标、事故锁和当前隔离为准；搬迁冻结另经共享提交栅栏与最终事务定序。资产还查有效准入批准、清单与目标版本；不使用入口快照或未纳入写秩序的预读。网络、扫描与大 IO 在短事务外。
3. 普通管理写包括 ACL 与组成员、仓库可见性、别名/重命名、group 成员及顺序、发布策略与影响公开性的设置，即使无 `AssetMutationRepo.complete` 也须在同一最终事务内拒绝事故写锁。未锁实例仍不得通过配置赋权、换名或重映射解除既有目标隔离；提交校验变更目标及引用映射，读取始终按当时解析到的稳定目标裁决。这里只防绕闸和越权，不重扫存量，不重新批准已发布合法引用或将不合法引用公开。没有合规终提交钩子的既有入口不得启用有副作用操作。
4. 确认消费、限制/账号代次/证据引用、逐项回执和事件同一事务；任一全局版本、认证或事件写失败不得施作。批量目标只有明确互不依赖才允许部分成功，预览指定顺序和允许跳过项；相同原子事务保存每项结果，失败项与副作用分开，不把局部成功经 HTTP 宣称全成功。
5. 冻结先提交，后续写失败/候选留私有；业务先提交则报告已完成，不伪造撤回。后台导入、重试、队列和直接服务调用保留并重查原授权；异步发布按 [FR-166](security-credential-lifecycle.md) 用不可变的原发起 IP 和信任状态重算当前 `publish` IP/CIDR 规则，命中拒绝，未知暂停，不用 worker 地址补齐。界面分别给 `newWritesBlocked`、`inFlightCount/inFlightAsOf` 和已提交水位，未知不报零。
6. 搬迁生成包、上传或签名不证明可切换；实际源安全状态后变更如何失效，见 §3.4。
7. 每个新读取在发送响应头/字节前裁决；未知返回 503。已开始的流无法追回已下发字节；可协作取消活跃流，但不保证瞬断，显示待结束/已观察结束；后续 Range、条件请求、重试都视为新读。

### 3.3 保全与公开性

- 保全的 `digest` 引用只保字节，不增加资产引用、索引或公开权。本期仅按显式目标人工隔离，不新增全摘要跨仓自动或人工封禁；候选硬失败只拒该候选，独立合法引用不连坐。直接、group、别名、重命名、Range、条件/HEAD、OCI digest 必须先解析合法仓库及实际引用，再裁决同一目标；禁止无引用上下文的摘要回退，也不能借另一成员/仓库的合法引用冒充已受限引用。
- 所有可删路径（业务归零、孤立 GC、直接删除备用路径、候选清理、启动/隔离快照收尾）共享按摘要的**删除预约**。在任何归零/引用计数查询之前取得排他预约并在其下重查业务、候选和保全引用；预约持有到该次物理删除与可恢复材料的不可逆清理均完成，或补偿已核验稳定落盘才释放。进程间由同一实例排他边界保障；跨崩溃持久状态须由启动协调器先接管，未能重建则停止这一摘要的回收和 `present` 裁决。任务续跑不得仅沿用旧的零计数；绕开预约的直接删除备用路径必须关闭。
- 保全在同一按摘要边界内裁决：保全先落稳定可用字节的引用则任何删除不得执行；删除预约先到且未终结，返回 409 `evidence_delete_in_progress`、不创建 `present` 回执，可在预约终结后重试。确认字节不可逆消失才以 `metadata_only` 登记；确认补偿已稳定且字节可读才可登记 `present`。IO/索引/所有权不明则 503，暂停删除，不把还可看见的快照当作证据成功。
- 跨介质暂存/补偿仍由协调器执行，不在 SQLite 写事务内等待文件 IO 或抢另一个摘要预约；多摘要按固定顺序取得或不等待退出。提交后快照清理失败只重试，不能逆转业务；对应预约或持久待接管记录仍须阻止此窗口的 `present` 假成功，直到稳定裁决。临时快照无下载入口，也不等于正式证据持有。
- 保全默认不自动释放；重复 digest 计唯一物理字节、各动作分别留引用。展示占用和容量预警，在预算不足时不静默清理保全；对可能的删除先保持保守裁决，并报告内容证据缺口。导出默认仅脱敏事件、持有记录、清单、摘要、完整性工作记录；二进制另需独立授权，不提供临时公开 URL。

### 3.4 灾备恢复顺序

#### 3.4.1 检查点与可判定的最新性

1. 库外、OS 受限且不会被恢复包覆盖的位置持久化节点身份、单调 `securityEpoch`、栅栏/恢复标志与检查点信任材料。`securityStateVersion` 在当前 SQLite 中按受保护状态变更事务递增：账号启停、口令/角色/因子/外部绑定、凭据撤销、ACL/可见性/路由、事故规则、保全、QQ 映射及待执行安全授权等均纳入；消费 TOTP 步等影响安全的状态也需同序。旧库不是真值，接收方校验以**替库前当前受控源**和库外封存证明为准；版本只有在同一节点和时代内可比较。
2. 源先进入有界搬迁停写，建立唯一 `cutoverFenceId`，在当前写序列内导出检查点及包标识。检查点记录并绑定 `{sourceNodeId,securityEpoch,securityStateVersion,cutoverFenceId,backupDigest}`，含撤销/限制/保全与 §3.4.3 所需状态清单及完整性证明；秘密不在清单、日志或 API 输出。`preparing` 时允许的后续撤销/保全等安全事务若已提交，版本即变，旧检查点签名仍有效也必须判过时；源恢复写、冻结窗口到期、栅栏更换或源时代推进同样令旧检查点不可用于切换，必须重取。
3. 源封存需关闭入口和排空写（见 §3.4.2），在同一排他边界下重新读取当前节点、时代、版本与栅栏，和检查点逐项等值后才可持久标 `sealed`。每个 `cutoverFenceId` 只允许一份转移授权：源在 OS 排他边界内先将 `{transferAuthorizationId,cutoverFenceId,checkpointDigest,sourceNodeId,securityEpoch,securityStateVersion,targetNodeId,targetChallenge,restoreId,state}` 持久记录在替库之外，并对栅栏实行唯一约束，随后才能通过独立于旧包的信任途径签出封存凭证。目标、挑战、恢复标识和检查点绑定不可修改；并发向另一目标签发必须失败，响应丢失或重签只能重发同一授权，不能产生第二份授权。只在库外确认已封存并阻止当前源再次接写后签出。同机恢复在替库前以当前库/库外栅栏作同样比对，再推进目标时代。封存后不能自动重新开放源，也不能在原栅栏内接受下一项安全写后继续宣称检查点最新。若要取消切换并重新开放源，目标必须在其解闸的同一 OS 排他边界内确认授权尚未消费，将该 `transferAuthorizationId` 的完整绑定及 `canceled` 终态持久写入替库之外，再提交可核验的取消回执。`canceled` 与解闸前持久写入的 `consumed` 是不可互转、不可随恢复回滚的互斥终态；未知状态不发取消成功，重启后也拒绝已终结授权。源须逐项比对取消回执中的唯一授权 ID、栅栏、水位、目标、挑战、恢复标识和检查点摘要均与其库外记录一致，随后持久撤销该唯一授权，才可按隔离流程重建栅栏；其他目标或其他授权的回执不能解封源。目标已激活、不可达或状态不明时，源保持封存，不凭事前一次查询重新开放。传输不要求实时复制。
4. 目标校验可信源身份、完整性、封存凭证与检查点/备份的节点/时代/版本/栅栏/摘要、目标身份与未用挑战完全匹配；解除隔离前复核该本次转移授权未失效，并持久消费一次。一个时间戳、旧包内自带验证根、仅有初始签名或仅有停机声明均不足。源后续撤销/保全、失效栅栏、不同目标、回放、无法从受控源证明当前封存或状态不一致，一律走隔离，不采信检查点。

#### 3.4.2 替库前停止当前进程并排空在途写

1. 决定应用恢复时，在源封存和目标替换各自相应阶段取得 OS 实例排他权并关闭**当前运行进程**的公网/业务入口及后台写入口，持久进入切换或隔离态；暂停协议、管理写、回调、普通 GC、后台公开及下载票签发，且不允许新的事务开始。必要本机恢复指令走独立受控入口。
2. 逐项确认所有在途 SQLite 写入、制品协调/暂存提交、备份切换和 GC 已正常提交、回滚或受控中止并记录；再关闭当前服务持有的数据库连接/任务，确认不会有迟到提交。若无法排空或验证，保持隔离，不替换数据库文件。不能用设置 `restore.pending` 或预计下次重启代替排空。
3. 目标写入并持久确认库外 `isolated` 标志与本次新 `securityEpoch` 后方可替换库。启动先读外部闸，再决定是否对外监听、清理或启动发布 worker；任何中断、损坏、权限丢失、代次倒退或库/标志不一致都收敛到隔离，不以旧库初始化正常状态。新机首装须独立确认，不把旧包恢复当首装。保留全量/差包与 pre-restore；回退旧二进制不能绕过该闸。

#### 3.4.3 恢复裁决表与解闸

`securityEpoch` 只阻止旧载体直接复用，不证明旧库中的登录输入、身份角色或授权仍可用。可信当前记录是 §3.4.1 已验证的状态；不匹配或缺失时不得把旧库值拷到新时代。如仅有版本清单而未取得相应可信当前数据，按无可用记录处理。

| 恢复材料                                                             | 有可信当前记录时                                                                                                                                                   | 无记录、不匹配或不可验证时                                                                                                                   |
| -------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------- |
| 账号启停、角色、Web 资格、外部身份绑定                               | 按稳定用户 ID 核对当前启停、角色与来源/绑定版本，按当前值重建；已禁用或删除不得启用，权限只授到已核实范围                                                          | 备份账号默认不可登录、无有效角色/绑定；本机受控复核身份、显式收窄授予，管理员须重新认领。旧管理员角色不授审批权；外部 JIT 不得抢占待核实标识 |
| 口令与当前等价一级凭据                                               | 密码校验材料须与可信当前 `passwordVersion` 及所认证的校验记录一致；外部身份须通过当前可信绑定并重新校验一级                                                        | 停用旧校验，须受控设置新口令或重新验证绑定后才启用；不能凭旧口令生成新会话/登记票                                                            |
| TOTP 因子                                                            | 核对当前因子身份、有效状态、密钥版本及防重放水位；确认可用才接入新时代，管理员仍必须新验证 TOTP                                                                    | 旧种子不得验证，走 FR-167 受控重新认领/重绑新因素；不降格到一级登录                                                                          |
| JWT、机器 Token、下载票、挑战、恢复码、动作确认、待提升批准/任务授权 | 无论有无可信记录，旧载体和未决授权均失效；历史行只读。用新时代身份重新签发会话、凭据或确认；欲提升候选须新预览、新授权及重新证明当前准入，满足 FR-166 原始来源裁决 | 同左；旧批准、旧确认、旧队列/租约不可重新消费，不可复制为新的授权                                                                            |
| QQ 绑定、按钮和未投递处置意图                                        | 备份映射默认不生效；只有按 [FR-172](security-notifications.md) 重新校验平台身份、由新时代近期 MFA 管理员确认新绑定/版本后可用                                      | 不接受旧群/用户映射、回调按钮或队列；即使重绑同一账号，旧意图不得继承新绑定                                                                  |
| 事故限制、ACL/可见性及保全引用                                       | 按已核实当前状态重放或核对，不用旧包含义取代；脱离业务引用的保全字节单独受控转移、核验                                                                             | 保持隔离，重建可证的规则或按目标拒绝，暂停无法核对的读取/发布与 GC；字节缺失标 `metadata_only` 或 `unknown`，记录备份后证据缺口              |

- 无可采信检查点时，须在隔离内经本机 OS 权限重新认领管理员、换发凭据、重建或以明确拒绝/禁清理覆盖未知范围；未核对对象不开放，不以备份校验通过自动解闸。具备当前强认证的恢复管理员在受控本机入口审核状态及缺口后确认，库内确认回执和库外恢复状态对得上且转移授权（若有）已消费才允许恢复公网、GC 与后台发布；不一致仍隔离。不得以解闸自动恢复旧配置或放开未核实对象。

### 3.5 提议接口、错误与预算

操作名待 [OpenAPI](../../api/openapi.yaml) 登记；管理错误体、事件字段与回执时间按 [FR-165](security-trusted-audit.md)，动作确认按 [FR-167](security-two-factor-authentication.md)，统一 `actionType/targetVersion/confirmationToken`。已知合法主体才可取得对象、回执与特定原因；原生协议只映射各自封套并保留权威原因码。

| 能力                | 输入 / 返回                                                                                                                                                             | 错误                                                                                                                                                                             |
| ------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 预览 / 确认 / 执行  | `actionType/targets/reason/idempotencyKey`，返回 `actionId/targetVersion/actionDigest/expiresAt/impact`；执行附 `confirmationToken`，返回 `items[]/outcome/operationId` | 400 `invalid_security_target`，403 `recent_mfa_required`，409 `security_confirmation_stale` 或 `security_idempotency_conflict`，503 `security_audit_unavailable`                 |
| 保全清单 / 导出     | `holdId/objectId/digest` 与 cursor；返回 `evidenceState/uniqueBytes/coverage`；导出返回脱敏清单标识/摘要                                                                | 删除预约仍活跃 409 `evidence_delete_in_progress`；确认删除已完成只创建 `metadata_only` 持有；状态未知 503 `security_state_unavailable`，不得冒充保全成功                         |
| 受限业务 / 恢复状态 | UI 显示原因类别、`newWritesBlocked/inFlightCount`；管理员可看 `restoreId/checkpointStatus/verifiedWatermark/gapStatus`                                                  | 实例写锁 503 `incident_write_locked`；目标策略拒绝 403 `incident_restricted`（无权获知存在性时保持原生 404 语义）；恢复隔离 503 `recovery_isolated`；搬迁维持 503 `write_frozen` |

- 单动作最多 100 个目标，未预览、空对象、目标版本不符、摘要变更或超过上限一律拒绝；原因最大 512 B、最短非空且禁止存储秘密。清单默认 50、最大 200 项，索引按稳定 ID、规范路径和摘要查询，禁止全表扫描作为读热路径。
- 读授权增量 p95 目标 ≤5 ms，动作短事务 p95 ≤50 ms（不计 MFA/预览/导出、大 IO）；导出走分页/流式、默认 10 万明细或 64 MiB 上限，显式报告截断/分页。恢复检验流式、单实例最多一个任务，以可见水位报告，不许因超时跳过安全步骤。保全磁盘水位与暂停清理原因可见；首版默认容量告警在 80%，该告警不是删除门槛。

## 5. 验收标准

- 冻结与业务先后两种顺序：挂起已通过预检的 ACL 赋权、仓库改公开、别名与 group 重映射，让事故锁先提交；各最终写均拒绝且没有权限/可见性/配置/成功回执变化。业务先提交如实记录，不反转；无实例锁时配置仍不得解除目标隔离，调整合法存量映射不触发重扫。冻结期间保全/撤销、重启持久化、事件插入失败和重复确认也应验证。
- 负例：候选入队后增加命中发起 `clientIp` 的发布规则，worker 的允许 IP 不能使其公开；缺 IP、失效代理信任或重启后无法验证来源时暂停，不以新重试 IP 补齐。加载当前规则失败不得按未命中处理。
- 负例：同一受限引用通过直接、别名、重命名、group、Range、条件、HEAD 或摘要不得读出；仓库 A 候选硬失败/已有目标被隔离后，同摘要的仓库 B 独立合法引用仍可读，A 不得借 B 的授权读取受限引用。未知裁决不开新流，已开流诚实标记。
- 负例：在取得删除预约后、引用计数已读而尚未 unlink、已删活动字节但清理快照未完成以及启动接管未决期间，并发保全均不得返回 `present`。验证业务归零、孤立 GC、直接删除备用路径、候选清理与启动/快照收尾；完全删除后仅 `metadata_only`，补偿稳定后才允许 `present`，先成功保全的字节均不能被删。
- 负例：源签发检查点后执行新撤销或保全，仅提交有效旧签名给目标，必须因 `securityStateVersion` 不一致拒采；旧/异节点、时代、栅栏、目标挑战/回放亦拒。让当前目标进程持有在途管理写或 GC，恢复必须先停入口并排空；排空失败不替库，替库中断/代次倒退不解闸。另覆盖正常封存、保全缺字节及搬迁差包。
- 负例：同一栅栏并发为两个目标签发时只能持久生成一份授权；相同绑定重签只返回原授权。目标取消与消费竞争只能得到一个库外终态，取消回执缺项/跨授权/跨目标不能解封源；取消、消费及源解封各崩溃点重启后，旧授权和第二目标签发仍被拒绝。源不可达或任一终态未确认时均保持封存/隔离。
- 负例：恢复含曾被重置的口令、已禁用账号、已降权角色、退役因子、旧 QQ 映射、旧 JWT/Token、确认和批准的库；即使新纪元签发可用也不得按旧状态登录、提权、重新消费或开放旧候选，重绑同账号不能执行旧 QQ 动作。缺当前状态时默认拒绝，只有受控重建和当期强认证可通过相关裁决；导入成功不等于解闸。
- 用户另行批准隔离真实部署演练：以本机 OS 权限重新认领及换发凭据、核对当前限制与保全、经 MFA 明确解闸；演练未做不得宣称生产可发布。

## 6. 风险 / 待定

- 平台的库外原子持久化、节点身份迁移、检查点的最新性证明和保全内容转移机制需独立复核；不能让包自身或单个时间戳决定解闸。
- 初始迁移分配附加编号；旧实例不自动推断过去的安全限制。兼容客户端映射、性能预算与留存容量需实测；现有恢复/证据不做生产操作。
