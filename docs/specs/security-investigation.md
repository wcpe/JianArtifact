# 功能规格：安全风险关联与调查（G）

> 状态：开发完成，待用户验收；security_case 案件、事件关联、按人既读水位、三条规则检测投影（自动建案与通知、不自动封禁）、/security 列表与案件四栏详情页已实现并经浏览器实测；SSE 实时流以持久游标轮询回退替代　·　关联 PRD：FR-171　·　分支：`feat/security-two-factor`

## 1. 背景与目标

帮助全局管理员区分「发生了什么」「影响了什么」「谁可以处置」，将现有当前节点审计扩展为可追溯的调查流程。增强 FR-118 审计及 FR-49/50 安全观测，不改变底层限流/IP 防护策略。
批准计划称现有审计页为 `/audit`；当前实际路由及深链为 `/audit-logs`，已有 IP 前缀、时间和结果等筛选。本规格沿用该路由和组件；不重建工作台，不另开一份 `/audit`。
依赖 [A 可信审计](security-trusted-audit.md)、[D 人工处置与保全](security-incident-controls.md)、[E 内容准入](security-content-admission.md)；[H 通知](security-notifications.md)消费已提交的安全风险事实。决策见 [ADR-0031](../adr/0031-trusted-security-events.md)、[ADR-0033](../adr/0033-incident-restrictions-and-recovery-gate.md)。

## 2. 需求（要什么）

- 在现有审计页接入可信事件与调查链接；新增 `/security` 队列及 `/security/cases/:caseId`，按请求时间线、上传清单、身份来源、处置/证据四栏组织，支持窄屏和键盘。
- 从节点内的安全事件推导风险、候选关联和待调查案件；风险命中说明规则条件、版本、证据窗与采集缺口，不标定「攻击者」或「恶意」为既成事实。
- 支持按 IP/CIDR、用户/Token/会话、UA/客户端、状态码、仓库/包/版本/摘要、时间组合查询且能追到原始事实；历史缺字段标「未采集」，已采集但无法解析或归属标「未知」，不以空值推断无风险。
- 事件、案件、处置、通知各自独立；确认已读、案件认领、结案、冻结、撤销、隔离、放行、解冻不可互相代替。后五项只通过 D/E 的管理员人工入口和近期强认证确认。
- 不做跨节点调阅、外部 IP/UA 查询、通用告警平台、自动惩罚或自动结案；不复用恢复即删除的 `operations_alert` 作为案件实体。

## 3. 设计（怎么做）

以下字段、端点、阈值和预算为契约候选，不是现有实现或实测承诺；以审核后 `api/openapi.yaml` 为唯一 REST 契约真源。

### 3.1 事实、关联、案件分离

- A 的不可变事件为事实源：`eventId`、`occurredAt`/`ingestedAt`、服务端 `requestId`、`operationId`/`taskId`、非秘密稳定 ID `actorUserId`、`credentialId`、`sessionId`、`authMethod`/`authStrength`；TCP peer、有效 `clientIp`、可信代理判定、受限转发链、UA/客户端。`accountEpoch`、`securityEpoch` 仅内部快照，不公开。调查投影复用 A 的字段与脱敏，不擅写历史。
- 对象证据只引用稳定 `repositoryId`、`canonicalPath`、包/版本、带算法的 `digest`、`manifestDigest`、候选/清单版本及 A/E 定义的阶段结果；`committed`（`not_applicable|not_committed|committed|unknown`）与 `httpStatus`/`outcome` 独立。处置引用 D 的 `actionId,actionType,targetVersion,errorCode`；下载/读取证据字节不由 G 授权。
- 规则时间窗使用 A 的 `occurredAt`，消费顺序和通知时延基准用 `ingestedAt` 对应的入库事实；`committedAt` 只来自已提交回执，不以推断补写。
- 关系 `reliable` 限服务端验证的同请求、操作/任务、会话/凭据或对象引用；同主体只说明同身份作用域，同摘要只说明内容相同，不证明同一次写入、同来源或同一操作者。
- 关系 `candidate` 用 IP、UA、客户端、时间或地理等线索；记录 `basis`、`confidence`、关联窗口和证据引用；不能并案、触发归因、独立构成高风险或联动处置。无可信代理时不以外来转发头作为有效 IP。
- 风险发现带 `findingId`、`ruleId`、`ruleVersion`、`severity`、`confidence`、`windowFrom`/`windowTo`、证据引用和 `coverage`，与案件中的人工处置结论独立。规则重算新增版本化结果，不覆盖原始事件或已作判断依据。
- 案件带 `caseId`、`status`、`version`、`severity`、`openedAt`、`updatedAt`、`assigneeUserId`、`resolutionCode`/`closedAt`、关联的事件/发现/处置/保全引用。已读按管理员保存，H 投递确认按 H 语义保存，不改案件状态。
- 案件 `open → investigating → closed`；认领 `open → investigating`，由管理员显式提交结论与理由才能结案，不能由计时、渠道接收、恢复告警或一个处置成功自动结案。管理员可附理由重开。已结案后新的独立命中开新案并保留历史关联；旧发现重放不得重开或重复建案。
- 同一受信稳定锚点和规则分组可归入同一未决案件；只有弱线索时保持独立，不跨主体自动合并。显示「已阻止新写」与「在途已结束」的 D 权威结果，不推测冻结前已提交的动作已被追回。

### 3.2 版本化规则与数据质量

- 账号与机器凭据分开以稳定 ID 建立基线；仅以符合策略的已提交、无可疑标记事件给「常用」提供统计，候选/可疑/缺失证据不训练为可信；覆盖不足时标记冷启动。管理员人工信任独立记录操作者、理由、范围、版本、到期与撤销，不能抵消已撤销凭据再用等明确命中。
- 初始确定性规则及建议窗口：同可靠主体 5 分钟内至少 10 次拒绝；10 分钟内同可靠主体拒绝后从新有效来源成功发布（必须有提交事实）；新有效来源遇预定义敏感操作（权限/凭据/安全策略变更）；已撤销凭据被服务端可靠识别后再次出现；以及按主体 15 分钟已提交量超过版本化基线及最小绝对阈值。上传量单位区分提交次数/字节，不重复计重试；阈值不足先显示线索。
- 无可靠主体的拒绝洪峰可按来源生成聚合线索（不归因）；单新 IP、地区或 UA、相邻网段、共享 NAT 不作高风险定论。只用运维授权的本地 IP 地理/ASN 数据，显示库版本、更新时间与精度；无、过期或不可判定数据标未知且不参与地理判定。
- 顺序消费 A 的入库水位；按发生时间应用规则窗口，有限迟到重算，以版本、稳定锚点和命中事实作幂等键。历史超出重算范围、一过性异常、窗口聚合或拒绝洪峰缺口须标记，不填补成「无异常」。
- 每批短事务落发现、成员、案件变化与递增发现水位，批次成功后才前移 A 消费水位；H 按已提交发现水位幂等补读，G 不等待 H 发网。A 事件提交失败不得凭 HTTP 成功响应造事实；G 投影失败停水位并告警，不改变 D/E 决策。

### 3.3 界面、REST 与权限

- 调查队列默认 `status=unresolved`（`open|investigating`），不隐含 `from=now-24h`；历史时间是显式筛选。案件详情四栏分别分页，显示原始事件或可核实的缺失原因、匹配依据、时间与时区；关联和内容检测结果都不是批准。
- 重用当前审计的筛选、表格和详情，旧 `clientIp` 前缀匹配保持不变；新可信事件筛选按 [A 的查询契约](security-trusted-audit.md#34-接口授权与预算)使用互斥的精确 `ip` 或 `cidr`。旧查询和新可信视图各自标明来源及覆盖差异，不把旧响应合并到新事件模型。
- 列表可显示已知空、加载、积压/过期、未知、无权限；投影部分不可用保留上次成功结果但标过期，换管理员/会话立即清空。原始证据的可复制链接仅用不透明 ID，不把凭据、会话令牌、精确来源或任意请求正文写入深链。

| 提议的 `/api/v1/security` 接口                                                   | 请求与响应                                                                                                                                                                      | 权限                                                       |
| -------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------- |
| `GET /events`、`GET /events/{eventId}`                                           | 复用 A 的安全事件列表及详情：共享筛选、分页、覆盖状态、脱敏与字段缺失均以 A 为准；UI 不再定义并行的事件契约                                                                     | 按 A：活跃的全局管理员交互会话                             |
| `GET /cases`、`GET /cases/{caseId}`                                              | 列表 `status`,`severity`,`assigneeUserId` 及适用证据条件；组合证据条件须由同一成员事实满足，时间按该事件的 `occurredAt`。详情返回案件头、已读状态、`projectionHealth`、分栏入口 | 同上                                                       |
| `GET /cases/{caseId}/{section}`                                                  | `section` 为 `timeline`、`uploads`、`identity`、`actions-evidence` 之一，`cursor`,`limit`；返回摘要、可靠/候选关系、A/D/E 稳定引用，不含原始内容字节                            | 同上                                                       |
| `PUT /cases/{caseId}/read`                                                       | `seenVersion` 为实际读到的案件版本；返回 `readAt` 和已读水位，对同一版本幂等，不为事后新事件提前确认                                                                            | 同上；仅写本人已读                                         |
| `POST /cases/{caseId}/transitions`                                               | `actionType` 为 `claim`、`close` 或 `reopen`；提交 `targetVersion`、幂等键，结案/重开需 `reason`，结案加 `resolutionCode`；返回更新后的案件版本及审计引用                       | 同上；QQ 仅可通过 H 的绑定复核后执行 `claim`，复用同一服务 |
| `GET /source-trust`、`POST /source-trust`、`POST /source-trust/{trustId}/revoke` | 版本化信任项，字段 `scope`,`source`,`reason`,`expiresAt`，撤销须 `targetVersion`；服务端记录创建/撤销人及审计 ID                                                                | 读同上，新增/撤销另按 C 要求近期 MFA；不允许 QQ 修改       |

- 交互会话认证、角色和强度复用 B/C，机器 Token/Basic、普通用户、仓库级管理员不能看全局调查数据；无权先拒绝再查对象。来源信任不能更改网络代理配置、鉴权、限流或许可证规则。处置预览和执行不设 G 的额外写端点，转向 D/E 权威流程。
- 原始事件列表完全沿用 A 的固定入库水位、过滤指纹、15 分钟游标、时间窗和分页上限；列表即使为空也按 A 返回投影水位、健康和 `coverage`，不视为空即无缺口。案件时间线可按 `occurredAt` 展示，不改变原始事件的翻页顺序。
- 案件和分栏单独使用不透明 keyset 游标，返回 `items,nextCursor,hasMore,snapshotWatermark,projectionWatermark,projectionHealth,coverage`；案件保留独立状态和不可变排序键，按快照版本读取，不用变动的更新时间翻页或做全表计数。案件列表默认 50、最多 100；游标绑定节点、恢复时代、当前管理员、查询指纹及快照，15 分钟失效。失效时重取对应列表快照，超预算须缩小范围。
- 管理端错误封套及共享错误码沿用 A，近期 MFA 不足按 C 返回 `403 recent_mfa_required`，幂等冲突返回 `409 security_idempotency_conflict`。G 专用：`400 bad_request`（案件专用筛选或分栏参数非法）、`404 security_case_not_found`、`409 security_version_conflict` 或 `security_transition_invalid`、`503 security_projection_unavailable`；游标过期同 A 返回 `410 security_cursor_expired`。降级仍可服务时标不完整、水位与缺口，不假回空列表。
- 认领、结案、重开与来源信任变更用条件版本更新和同事务审计；竞争输方见实际结果，原键同请求重放原回执，不同请求冲突。历史独立旧批次确认不迁成新案件已读、认领或结案。

### 3.4 资源、留存与迁移

- 初始预算提议：事件/队列/分栏读取合计每管理员 60 请求/分钟（突发 10），案件变更 12/分钟（突发 3）；查询 2 秒截止、实例并发查询上限 8，单响应上限 512 KiB，超尺寸以内页、标 `hasMore` 不静默截断证据。必要的处置资源由 D 独立保护。
- SQLite 索引覆盖规范 IP 地址范围/族、`actorUserId`/`credentialId`/`sessionId` 与时间的组合、稳定仓库/摘要、案件状态、案件成员和水位；不能把筛选笛卡尔组合都做索引。投影作业起步每批 100 事实、单写 worker、有界迟到窗 1 小时，有缺口告警并可按水位重建；不得在写事务做网络请求或全库风险计算。
- 保留预算提议：可重建无案件关联的普通调查索引、规则窗口统计保留 90 天；已结案件调查投影默认 365 天，清理前检查保全与再开启状态；未决案件及必要引用不受 24 小时界限或常规清理；不改变 A 事件或 D 保全的权威留存。活跃积压或占用超过预算时告警、限制低优先工作并上报覆盖缺口，不按年龄淘汰未决案，不隐式释放证据。
- 迁移仅追加表/索引；旧 `audit_log`、旧确认、`/api/v1/observability/audit/*` 均保留既有语义。新增调查能力在 A/D/E 契约接入及索引可用后开启；不用旧日志回填未采集事实，历史读取坚持脱敏白名单。

## 5. 验收标准

- **一级：本地实现。** 一次性 SQLite 和现有前后端框架验证管理员/Token 边界、A 的互斥 IP/CIDR 与历史前缀兼容、固定水位下迟入库不跨页、失效游标重取快照、空页仍标采集缺口、历史缺项、弱关联不能合并/归因、乱序重放及 DB 背压；索引计划及同数据量基线验证不扫全审计和不漏页。
- **一级：状态与界面。** 超过 24 小时未处置仍在默认队列；已读/渠道确认不结案；认领竞态只产生一次变更；案件引用真实处置结果。隔离浏览器验证键盘/窄屏、无权限、未采集、失效及故障态，中文/英文键一致，生产无 Mock。
- **二级：真实环境。** 需独立授权和用户确认；用部署的可信代理设置、经批准的地理/ASN 库、兼容协议环境及 D/E 接入验证真实证据与延迟。无授权或无有效本地数据时据实列未验证，不以模拟库代替。
- **三级：生产可发布。** 完成迁移/回滚和恢复安全闸演练，验证真实审计样本、容量预算、H 通知、凭据切换与应急流程，经用户批准；一级不能替代二/三级。

## 6. 风险 / 待定

- 初始阈值、迟到窗、索引与保留配额待审核并以固定负载实测；阈值前后均不应被解释为攻击归因，未压测不承诺吞吐。超期但需保全的案件不得由自动清理释放，部署需容量告警和人工响应。
- 审核时冻结 A/B/C/D/E/H 的字段词表、身份和版本复用边界；地理数据库来源/许可证/加载依赖需单独确认，不假定部署具备。一级实现验收已执行（域回归、索引分页用例与浏览器实测）；二级/三级未执行。
