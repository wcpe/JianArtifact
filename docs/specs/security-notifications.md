# 功能规格：安全通知与 QQ 人工入口（H）

> 状态：开发完成，待用户验收；站内持久游标通知、投递登记、SMTP（强制 TLS）与 QQ 薄适配已实现并有回归；真实 SMTP/QQ 投递为模拟验收、待平台凭据，QQ 绑定挑战确认流待凭据接入　·　关联 PRD：FR-172　·　分支：`feat/security-two-factor`

## 1. 背景与目标

FR-117 已退役原页眉通知下拉和消息中心，现有 `/api/v1/observability/audit/notifications` 仍是审计批次摘要，不是增量流或站外队列。此需求只在 `AppLayout` 恢复管理员安全提醒，详情进入 `/security`，不恢复通用消息中心、不改变旧审计通知接口语义。
依赖 [A 可信审计](security-trusted-audit.md)、[C 双因素认证](security-two-factor-authentication.md)、[D 事故处置](security-incident-controls.md)、[G 调查](security-investigation.md)，放行遵守 [E 内容准入](security-content-admission.md)；见 [ADR-0031](../adr/0031-trusted-security-events.md)、[ADR-0032](../adr/0032-credential-epochs-and-strong-authentication.md)、[ADR-0033](../adr/0033-incident-restrictions-and-recovery-gate.md)。

## 2. 需求（要什么）

- 已提交风险通过站内、SMTP 邮件及既有 QQ 官方机器人通知；站外投递不依赖浏览器打开。实例正常运行且相应渠道可用时，从触发安全事件入库（A 的 `ingestedAt`）计，站内 5 秒内可见，站外 30 秒内开始首次投递尝试；渠道接受另行记录，不等于已阅读或恰好一次。
- 显式区分通知、投递、接收回执、管理员确认和案件状态。支持按优先级限流、退避重试、人工重投和未确认风险升级；故障可见，不改变事故限制、准入或发布结果。
- QQ 支持已绑定管理员查询、认领；冻结、撤销、隔离、放行、解冻仍由管理员在手机网页预览并完成近期二次验证。不接受群管理身份、昵称、可转发链接、按钮或回调本身为授权。
- 不新增 QQ 登录、不建设 `qqbot-core`、不修改参考 TypeScript 项目、不加任意 Shell/SQL 命令，不引入外部数据库或消息队列。

## 3. 设计（怎么做）

以下接口、预算和错误码为契约候选，不是已有能力或压测结论。正式契约以审核后的 `api/openapi.yaml` 为准。

### 3.1 事件、通知与可靠投递

- 以 A 已提交事件、G 已提交发现、D/E 已提交且纳入策略的结果为输入。只在源事务提交后产生可投递记录；同一安全事实跨来源用确定性策略键去重，不把未提交响应、`operations_alert` 或通知回执当案件。增量写入与对应源水位同一短事务；崩溃从旧水位幂等补读，不等待发送。
- 通知 `noticeId,caseId,eventId,findingId?,severity,kind,occurredAt,ingestedAt,enqueuedAt,summaryCode` 带稳定幂等策略键；事件时间取 A 的触发事件，`enqueuedAt` 另记，不用入队时间重置目标计时。投递独立记录 `deliveryId,noticeId,channel,recipientRef,stage,attemptCount,firstAttemptAt,lastAttemptAt,nextAttemptAt,acceptedAt,lastErrorCode`。`firstAttemptAt` 表示首次调用渠道进行实际网络投递的开始，不是占用租约、入队或预检时间。分别记录 `ackByUserId,ackAt`，只表示管理员显式确认，不代表调查完成；也不把发送成功或打开链接视为确认。
- 每个通知/渠道/固定收件标识/升级阶段一条任务，状态 `pending → leased → accepted | retry_wait | failed | unknown | cancelled`；`retry_wait → leased`，租约失效后重领。`accepted` 只表示 SMTP 服务器或 QQ API 接受；超时或崩溃导致接收结果不可判定时记录 `unknown`，按明确策略决定是否重试并提示可能重复。稳定消息标识供去重/排查，不承诺第三方恰好一次。
- 租约持久化、版本条件更新；网络操作在事务外，旧租约结果不得覆盖新状态。手动重投按原通知关联新一轮任务并审计，不覆盖历史回执。只有明确可重试错误进入退避；关闭渠道、收件人已撤销或配置变化先复核有效目标，不把旧行送给新收件人。
- 初始升级策略提议：严重、仍未确认、案件未决，15 分钟后最多一轮升级；重查 G/H 状态，按固定收件配置，不扩大收件范围。合并的是低优先级投递摘要而非源事件或案件；关键高风险通知容量留有保留区。
- 显示队列深度、最老等待、源/频道水位、首次投递时延、未知/最终失败、限流与配置阻塞；源水位卡住或达到配额时显式降级告警并保留补读依据，不能前移水位假装已入队。恢复时期禁止对外发送，重新启用前校验安全时代、有效管理员/目标和历史去重数据，标出无法判定的回执，不无条件重播旧积压。

### 3.2 站内增量与补查

- 站内读取使用同源、已认证管理 API 的 `fetch` 流（现有交互会话授权携带在请求头或既有安全会话机制），不把访问令牌放 URL。不接受普通用户、仓库级管理员、Basic 或机器 Token；处理凭据撤销/退出/更换账号时终止连接并清缓存。
- 从 SQLite 持久递增序列读提交后的安全条目，不依赖进程内广播作真源。首开 `GET /notifications` 获得最近安全摘要、未确认状态与对应快照水位；从该 `cursor` 加入流再补快照之后的数据，避免读完快照到建连间丢失。游标以管理员、节点、安全时代和序列绑定，是分页位置而非登录凭据。
- 流帧：`notice|ack|checkpoint|health`，携带 `cursor,watermark,serverTime`，事件帧有对应 `noticeId`；按稳定通知标识去重并成功应用后更新客户端持久游标。服务器持久序列可跨重启；客户端游标只按同一节点与管理员恢复，不跨会话回放缓存内容。证据载荷不写浏览器持久存储。
- 断线/反代不支持流时用同游标 `GET /notifications?after=…` 有界补查，在线起步 2 秒、有抖动并按 `Retry-After`/指数退避；每页推进到最后已应用位置，不能直接跳到服务器总水位。失效 `410 notification_cursor_expired` 时取 consistent 快照及水位，再分页补读或回到 G 未决队列；显式提示无法重放的片段，不伪造新旧条目完整。
- 提醒展示 `lastSuccessAt`、源/通道水位及 `ok|stale|unknown|unavailable`；连接可用不等于投影无缺口。心跳不是新风险或渠道接收；离线保留同身份最后成功内容并标过期，未确认总数不可靠时不显示为零。24 小时不是案件的失效条件，站内回放留存不限制 G 队列。

### 3.3 SMTP

- 运维配置固定信封收发件人和受控中继，事件、浏览器或 QQ 参数不能决定收件人、头、模板或外链主机。只支持证书/主机名验证的隐式 TLS 或强制 STARTTLS；缺失/降级、证书校验失败时不发，不回退明文，凭据仅在 TLS 建立后使用。
- 内容按白名单仅含严重度、短类别、发生时间、不透明案件号和受信 HTTPS 详情入口；不发 IP/UA、身份详情、凭据/挑战、原始日志、附件或制品。规范化信封/目标及固定头，拒绝 CR/LF 等头注入；不要把任意外来正文嵌入通知。
- 状态按 SMTP 接收响应区分已接受、临时错误、永久错误和不确定；对外及日志只存脱敏分类 `errorCode` 和有限回执引用，不记录中继回显中的地址、认证内容或原报文。测试收件人配置与真实投递凭据须独立授权。

### 3.4 QQ 适配、回调与手机二次确认

- 直接使用官方 `github.com/tencent-connect/botgo` 所需客户端及 DTO，产品内薄适配。既有核实的固定候选 `v0.2.1`，本阶段不假定已安装、不下载、不确认最新或另建 SDK/服务。SDK 示例不作为验签、业务授权或防重放边界。
- 绑定键为 `appId + sceneType + sceneId + platformSubjectId`（按平台稳定作用域），映射系统 `actorUserId`；只允许活跃全局管理员本人发起和确认。手机网页以活跃管理员会话和近期强认证发起一次性短期绑定挑战；QQ 对应已验签事件提出候选，原网页同会话核对并确认 App/场景/平台主体后原子激活。禁止只凭群聊天中的代码完成绑定，不在群发绑定码；重复绑定冲突、解绑、换人及代次变化均撤销旧映射和待确认意图并审计。
- 回调只允许配置的 HTTPS 接收路由、AppID、场景、事件类型；有限读体并在解析业务字段前用平台验证规则校验原始字节和签名。使用签名覆盖且可核实的时间戳做新鲜度校验（拟 ±5 分钟），来源白名单如部署可用作额外校验、不能替代验签。注册验证/握手不进入业务；无法验证的新鲜度、主体或事件标识不得进入交互处理。
- 用 AppID、场景与签名覆盖的稳定平台事件 ID 做持久唯一键；同一 ID 相同有效载荷只复用原处理回执，不重新解析归属，不返回给已迁移绑定的新管理员；不同载荷拒绝并审计。新命令入有界本地队列时，在同一短事务内完成去重及绑定快照校验，持久记录验签时确认的 `bindingId,bindingVersion,actorUserId,accountEpoch,securityEpoch` 及平台主体作用域。无持久写入不返回已接收；过载按已验证的平台语义重试。只保存必要字段和载荷摘要，不存原始回调正文或签名密钥。
- QQ 命令仅能查询获授权的案件摘要或认领。执行与回送前均按原快照复核绑定存在且未撤销、版本/账号/代次相同、当前管理员资格及案件范围；认领将复核与 G 条件更新、审计及同一幂等键落在同一事务。解绑、换人或代次更新后，旧任务终止并记录拒绝，不按平台主体重新查找新绑定重新归属，不认领、不向新管理员回发旧查询结果。群中只发送脱敏概要（严重度、类别、案件短标识）；若场景不支持安全反馈，提示登录网页查看。
- 敏感按钮中的不透明引用只能找回签发时已存在且未过期的 D/E 处置意图；意图须事先经授权的网页预览流程独立建立。没有意图时只提供通用安全页导航，不签发动作引用。引用不是 bearer 凭证，点击、GET、回调及登录回跳均不创建、续期或替换意图，包括丢失、已撤销、已消费及过期引用。意图绑定 `actorUserId,actionType,caseId,targetVersion,digest,manifestDigest,expiresAt`（摘要按动作适用），内部锁定原 `bindingId,bindingVersion,accountEpoch,securityEpoch`；链接不含代次、认证凭据或 `confirmationToken`。
- 同一绑定管理员登录手机网页后，按 C/D/E 复用近期 MFA、预览、单次 `confirmationToken` 与幂等键；提交事务复核原绑定、账号及代次、当前 ACL/状态、`targetVersion` 与同一摘要，回执复用 D 的 `actionId,targetVersion,errorCode`。旧按钮、转发/错主体、已撤销管理员、同路径换摘要、目标版本过期、意图被消费都不得产生新副作用。只有已授权、同键同请求的回执查询可以返回历史回执；按钮重放不走执行，不新增 QQ 处置旁路。

### 3.5 REST、权限与错误

| 提议的 `/api/v1/security` 接口                                                                          | 请求与响应                                                                                                    | 权限                                                   |
| ------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------ |
| `GET /notifications`                                                                                    | 首开 `limit` 或 `after,limit` 补查；`items,nextCursor,hasMore,watermark,lastSuccessAt,health`；快照与游标同源 | 活跃全局管理员交互会话，仅本人确认状态                 |
| `GET /notifications/stream`                                                                             | `after` 或等价恢复头；SSE 增量；不得以 URL 参数认证                                                           | 同上；连接中重查撤销                                   |
| `PUT /notifications/{noticeId}/ack`                                                                     | 以本人身份记录，返回 `ackAt,ackByUserId`；不改变案件、处置或投递事实                                          | 同上；幂等                                             |
| `GET /notification-deliveries`、`POST /notification-deliveries/{deliveryId}/retry`                      | 脱敏状态分页；重投用 `targetVersion`、幂等键及原因，返回新任务引用                                            | 同上；重投按 C 要求近期 MFA                            |
| `POST /qq/bindings/challenges`、`POST /qq/bindings/challenges/{id}/confirm`、`DELETE /qq/bindings/{id}` | 发起/确认/解绑；返回 `bindingId,appId,sceneType,status,expiresAt` 等最小字段；挑战仅给发起会话                | 管理员本人、近期强认证；同会话确认                     |
| `POST /qq/callback`                                                                                     | 官方协议及最小应答；有限请求体，平台验证身份，无用户 JWT                                                      | 仅配置渠道、签名/新鲜度/去重均通过；不直接授权敏感动作 |

- 管理 API 错误封套及共享错误码沿用 [A](security-trusted-audit.md#34-接口授权与预算)：现有 `Error` 内含 `error.code/message`，拟新增顶层可选 `requestId`，`operationId` 仅向有权主体返回；近期 MFA 不足按 C 返回 `403 recent_mfa_required`，幂等冲突返回 `409 security_idempotency_conflict`。H 专用：`404 notification_not_found`（含不可见）、`409 qq_binding_conflict`、`410 notification_cursor_expired`（仅站内通知回放）、`503 notification_projection_unavailable` 或 `notification_channel_unavailable`。涉及处置意图和最终执行的错误遵 C/D/E，不另造接口或错误码。
- 回调非法体/超限、无效签名或不新鲜、未批准来源、重复冲突、限流和不能持久接收分别用平台约定的通用状态；内部分类 `qq_callback_invalid|qq_callback_unauthenticated|qq_callback_replay_conflict|qq_callback_unavailable`，不回显密钥、存在性或应用详细配置。

### 3.6 起步资源、留存与迁移预算（提议）

- SQLite 持久队列采用 `(channel,state,nextAttemptAt)` 等索引，每次取至多 50，SMTP/QQ 各最多 2 并发，单次端到端超时 8 秒、租约 30 秒；退避起步 15 秒、上限 30 分钟带抖动，最多 8 次或 24 小时截止，未知/失败保留并可人工评估。起步每渠道 30 次/分钟，服从更严平台/中继限额。严重新风险不跟长退避任务共用无界 FIFO。
- 单实例待处理投递上限 10,000（其中为严重风险保留至少 20%），按 80% 提前告警；不丢严重记录冒充成功，源水位与公开健康指示反映延期。SMTP 按单封最小模板限制尺寸，QQ 渠道适配限制 DTO 和受支持消息长度。
- 增量每页默认 50、上限 100，每管理员最多 2 条流、合计 60 次查询/分钟；单实例最多 64 流，最多 64 条待发帧/流，慢客户端断开续传；心跳 15 秒、30 秒无有效响应标过期并补查。回调体上限 128 KiB、实例入口 120/分钟起步，配套 App/主体限流且不能未验签信任来源声明。
- 站内可重放序列 7 天；通知回执/失败元数据默认 90 天；回调去重默认 7 天且至少覆盖已核实的重投时长和时钟窗；绑定/动作挑战最多 5 分钟，不存明文挑战或过期重用。保全/必要审计引用受 A/D 留存约束，清队列不删原事件及未决案件。上述数值需以负载和真实渠道限制校准。
- 仅追加迁移，默认关闭未配置或未经验证的站外渠道，以 `unconfigured`/`unverified` 显示；旧通知 API 不回填为 H 第一次站外投递，启动以明确水位接续。按 [D 恢复安全闸](security-incident-controls.md) 裁决：恢复出的旧 QQ 绑定和待决授权默认失效；待执行命令、意图、确认令牌或按钮引用不得自动复活或改绑。安全闸放行后仍须按现行绑定流程授权，旧命令不得沿用新绑定。

## 4. 任务拆分

- [ ] 主代理确认字段、PRD 和迁移，定版 OpenAPI 与生成物；站内安全提醒衔接 G。
- [ ] 实现持久队列、水位和站内流/补查；SMTP、QQ 适配保持故障隔离；真实渠道前置和依赖预检先确认。
- [ ] 实现 QQ 验签、持久去重、管理员绑定和网页二次确认接线；增加故障和权限验证，独立安全复核。
- [ ] 文档同步：PRD 状态、ARCHITECTURE、API、OPERATIONS、CHANGELOG；用户审核前不进入实现。

## 5. 验收标准

- **一级：本地实现。** 使用一次性 SQLite、隔离浏览器和假 SMTP/QQ，覆盖队列重启/租约接管、断线增量/游标失效、签名/新鲜度/持久去重、跨主体/旧按钮/撤销管理员/同路径换内容；重复回调和重试不重复处置，渠道失败不改变准入。验证头注入、TLS 失败、脱敏和积压不伪零。
- **一级：QQ 竞态与恢复。** 命令验签并入队后先暂停执行，再解绑、将同一平台主体绑定给另一管理员或变更代次；恢复执行与重复回调均不得认领、改归属或向新管理员回送旧结果。恢复旧备份也不得复活绑定、命令或待决授权。按钮签发后分别使意图过期、撤销、消费或丢失，再走点击、登录回跳和重放；不得创建、延长或替换意图，也不得执行处置。仅原管理员在有效意图上走正常预览和近期 MFA 才可提交。
- **一级：时延目标。** 在固定硬件、明确事件量、实例正常且相应渠道可用时，从合资格事件的 `ingestedAt` 到活跃管理员页面实际可见 ≤5 秒，到每个已启用且可用的站外渠道首次实际网络投递尝试（`firstAttemptAt`）≤30 秒。分别记录入队、尝试、渠道接受（`acceptedAt`）与管理员确认；只入队不达标，接受和已读不计入 30 秒。渠道不可用时验证退避、补查和显式降级。
- **二级：真实渠道/部署环境。** 需另行授权并由用户确认。逐项验证现有机器人 AppID 所在场景、主动推送/频控、稳定主体标识、交互模板/按钮与回调签名和重投、与已有回调共存、手机网页入口、SMTP TLS/真实收件、关闭网页可通知、反代流和补查。无授权或权限未知标未验证，不覆盖现有回调。
- **三级：生产可发布。** 迁移、恢复/回滚、管理员 MFA 和凭据切换、真实通知与故障升级运维演练有证据并经用户批准；不把一级成功替代二/三级或自动发布。

## 6. 风险 / 待定

- 未核实现有 QQ 机器人部署权限、可主动发送的场景、交互模板、回调占用及支持的安全语义。不能满足验签/新鲜度/稳定主体/去重任一要求时，保持相应交互禁用，并清楚标出只读/仅站内降级，不猜测平台行为。
- 引入 BotGo、SMTP 若需新库，先列精确版本、传递依赖、许可证、漏洞与 `go.mod`/`go.sum`/许可证生成物差异，另行精确确认，不视为本次已批准；真实 SMTP/QQ 配置、配额、SLO 和保留参数未验。
