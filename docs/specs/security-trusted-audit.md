# 功能规格：可信请求上下文与安全事件

> 状态：开发中，用户已审核；登录与 Raw/共用 Maven PUT 样例已接入，管理查询已通过本地验收；不代表全入口、严格门或生产验收　·　关联 PRD：FR-165　·　分支：`feat/security-incident-controls`

## 1. 背景与目标

安全处置第一批（A）：让调查人员能区分请求、认证、业务提交与响应，且不能由客户端伪造可靠关联。延伸 FR-38、FR-109、FR-118，不重做既有审计筛选和风险确认，不宣称补齐历史证据。

[当前架构](../ARCHITECTURE.md) 保留 `audit_log` 和原子操作 outbox；目前入口已有 `X-Request-ID`，协议已采集部分路径、大小、摘要，审计页有 IP 前缀筛选。管理 `AuditLog` 仍有忽略 Insert 错误的路径。这些不等价于可信请求上下文或事务型安全成功事件。

## 2. 需求（要什么）

- 统一管理、协议、认证回调的上下文；后台任务使用服务端稳定任务标识，并保留真实发起人与执行者的区别。
- 追加安全事件与独立对象明细，首先接入认证成功/失败、协议写拒绝及至少一个真实制品写提交样例；凭据/权限变更、处置、各格式发布阶段由 B/D/F 接入，最终验收核对所有入口。
- 保存可信与未采集的区别。按稳定关联标识、规范 IP/CIDR 和时间查询；一致游标；不把相近 IP、UA、用户名、时间等弱关系等同于同一攻击者。
- 拒绝洪峰时先保护关键提交和撤销，给出可见缺口。关键写不可可靠入账时禁止提交；安全读裁决不明时不得新开下载。
- 不引入外部日志队列，不改写旧证据，不以哈希声称抵抗主机管理员篡改，不提供通用请求取证代理。

## 3. 设计（怎么做）

### 3.1 来源边界（[ADR-0031](../adr/0031-trusted-security-events.md)）

1. 在任何应用鉴权或拒绝之前生成随机、服务端专有的 `requestId`，响应 `X-Request-ID` 同值。客户端同名字段不参与关联、不被回显为服务端 ID；A 批验存量调用方与原先可回显语义的兼容差异。
2. 解析连接 `peerIp`，按显式可信代理 CIDR 判断当前 peer。无配置或 peer 不匹配，忽略转发/IP/scheme 头，只使用直接连接事实。TLS 例外仍按既有部署边界，不因 Host、UA 或客户声明而放宽。
3. 对受信 peer，只启用一种配置约定的头族，不混用同义头；从最靠近服务的一侧逐跳剥除已配置代理，以第一个非受信地址为 `clientIp`，其左侧不可信输入不再采集。边缘代理须覆盖外来 scheme，并保证本配置的追加/清洗规则；scheme 取直接 TLS 或已校验的最近代理单值断言，不从最左客户端值推断。
4. 多值冲突、格式错误、超限、缺少非代理终点时标 `invalid_forwarding`，不使用头值作安全输入。若部署依赖该代理做客户端 ACL/限流，无法判定不得按代理 IP 放行；健康视图警示。直接部署不因任意外来头失效。
5. 去端口、映射 IPv4-in-IPv6 归为 IPv4、拒 zone/不合法多表记；持久化按地址族及定长二进制索引，精确等值和 CIDR 闭区间走索引。现有字符串前缀筛选不是 CIDR，保留在旧视图语义。转发链最多 8 跳、原始输入最多 1 KiB，超限不部分信任。
6. 需要后台提交的请求在受信入口固化不可由请求体改写的来源快照 `{originRequestId,clientIp,proxyTrust,sourceTrustVersion}`。`sourceTrustVersion` 是服务端代理信任配置代次；仅 `direct` / `trusted` 且 IP 已规范化才是有效来源。worker 上下文单独记录执行者，不以其地址填补缺失/失效快照；最终裁决见 [FR-166](security-credential-lifecycle.md) 和 [FR-168](security-incident-controls.md)。

### 3.2 事件、结果和共享词表

| 字段族 | 稳定字段与约束                                                                                                                                                                                                         |
| ------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 事件   | `eventId`（不透明稳定 ID）、`eventVersion`、`eventType`、`occurredAt`（服务端 UTC 发生时间）、`ingestedAt`（入库时间）、可索引的持久入库顺序；不采用外部时钟声明                                                       |
| 回执   | `committedAt` 只属于已确认提交的业务回执，不用作事件入库时间或 HTTP 响应观测时间；无提交、未决或回滚时不填                                                                                                             |
| 关联   | `requestId`、`operationId`、`taskId`、`actionId` 值各有域；后台没有 HTTP 时不伪造请求号，可独立保存 `originRequestId`；重试有新的请求号、同操作号                                                                      |
| 主体   | `actorKind`（`user` / `anonymous` / `unknown` / `system` / `local_operator`）、`actorUserId`、`actorNameSnapshot`、`credentialId`、`sessionId`、`authMethod`、`authStrength`；识别失败标未知，不把输入用户名当成功身份 |
| 来源   | `peerIp`、`clientIp`、`proxyTrust`（`direct` / `trusted` / `invalid_forwarding` / `unknown`）、`forwardedChain`（仅获准段）、`userAgent`（有界，非权威）                                                               |
| 对象   | `repositoryId`、`canonicalPath`、`objectKind`、可选稳定 `objectId`、`digest`、`sizeBytes`、`manifestDigest`、`targetVersion`；多对象另表，仓库名/坐标只作当时显示快照                                                  |
| 执行   | `outcome`（`succeeded` / `denied` / `failed` / `pending` / `unknown`）、`committed`（`not_applicable` / `not_committed` / `committed` / `unknown`）、`httpStatus`（可空）、稳定 `errorCode`                            |

- `credentialId` 和 `sessionId` 为不可登录、非秘密的关联标识，不是凭据明文、摘要、JWT 原文或可提交的挑战。认证方式枚举及强度由 [FR-166](security-credential-lifecycle.md) 定义；`accountEpoch`、`securityEpoch` 为内部授权输入，不做公开关联 ID。
- 初始事件类型：`auth.attempt`、`auth.session_created`、`protocol.write_denied`、`asset.change_committed`、`asset.response_observed`、`security.coverage_gap`。预期后继事件分开表达候选阶段、批准、发布、处置与投递，不复用一个 `published` 状态表示其它事实。
- 业务成功事件不等待 HTTP 响应，`httpStatus` 为空；响应若另记，关联同 `operationId`，传输中断不得凭猜测填客户端接收或反写成功。合法回执重放只新增响应/请求事实，不重复追加业务成功。`outcome=pending` 不是成功。
- UTC 毫秒时间戳；缺失字段省略或用明确的 `unknown` 枚举，不用空 IP/零时间推测。异常文本按安全枚举替代；文案脱敏、换行/控制字符清理并校验 UTF-8。最大 UA 256 B、展示名 128 B、单路径 1024 B（可另保存有界显示快照；权威匹配键不得截断）；禁止记录用户提供的任意 details。
- 禁止写入 Authorization/Cookie 及首尾预览、任意正文/查询串、密文、OTP、恢复码、令牌哈希、上游凭据。旧 `tokenPreview` 和正文历史不得通过调查、通知或新增导出暴露；既有可读 API 的弃用/脱敏由契约整合明确。保留原历史存储与确认语义，不擅改旧备份证据。

### 3.3 写入边界与拒绝洪峰

| 类型                                      | 写入方式                                                                                       | 故障语义                                                               |
| ----------------------------------------- | ---------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| 会话建立、制品关键提交与后继授权/限制变更 | 领域事务内写事件及明细；调用方传合成上下文，仓储接当前 tx；一操作一类成功事实由唯一键/回执防重 | 审计失败回滚业务，若故障使提交结果未定则查原回执，不准按失败重新执行   |
| 登录失败、协议拒绝                        | 仅有界最小事实和窗口汇总（事件不反转拒绝）                                                     | 队列满时累积缺口，不分配新动态键；故障期间仍拒绝，不把未记录标称无风险 |
| 响应观察、消费者投递、提交后清理          | 独立队列/任务，按持久水位重放；提交事务不等网络或清理                                          | 失败只降低可观测性或延后清理，不逆转业务及其事件                       |

- 资产成功沿 `AssetMutationRepo.complete` 同一事务：最终权威校验、资产/格式/FTS、回执/operation outbox、事件及必需明细一起提交。前置文件操作沿现有暂存与补偿；完成事务之后只重试清理。用户/Token/ACL 更新须提供同一事务仓储入口，不再靠 handler 尾部补记。
- 对象明细不允许静默截断。每事务首版最多 256 对象且事件包不超过 256 KiB；超限在接受候选前拒绝或按协议已定义的独立提交单元切分，不拆分协议原子闭包。单事件头目标不超过 4 KiB；全批只保留最小索引事实。
- 拒绝记录首版限额：进程级最多 100 条/秒，来源桶最多 4096、每桶 10 条/分钟，内存缓冲最多 1024 条且 2 MiB；超出用有界原因组按 UTC 分钟累计。提交侧不等待此缓冲；写入工人最多 50 条或 10 ms 一批、低优先让路。按来源限流是审计预算，不替代登录/MFA 限流。
- 缺口字段 `windowStart/windowEnd/observedCount/suppressedCount/gapReason/coverage`，`coverage=unknown` 时不可把计数当完整。DB 不可写先报告进程计数与脱敏健康警告，恢复补写有证计数；进程崩溃由启动/刷新持久心跳水位间断标未知，无法恢复的计数留空。不要为每次拒绝单独打日志。

### 3.4 接口、授权与预算

四条已接入的管理 GET 与现有审计共用 `/api/v1/observability/audit` 命名空间，路径、字段以 [OpenAPI](../../api/openapi.yaml) 为准。列表时间边界必须能无损表示为毫秒：`Z` 和合法数字时差按同一 UTC 时刻比较；额外的零可保留，不能精确表示时返回 400，不截断。下表的主事务要求仅由已接入的样例验证。

| 能力               | 入参 / 返回                                                                                                                                                                                                                                                                       | 权限及失败                                                                                                                                          |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| 安全事件列表       | `from/to`（按 `occurredAt`，跨度最多 30 天）、`limit`（默认 50、最大 100）、`cursor`，可组合 `ip`（精确匹配记录的 `clientIp`）或 `cidr`（两者互斥）、主体/关联/对象键、类型/结果；返回 `items/nextCursor/hasMore/snapshotWatermark/projectionWatermark/projectionHealth/coverage` | 全局管理员交互会话；非法过滤器或游标与过滤指纹不符 400 `invalid_security_filter`，游标过期或原快照因留存/恢复不可继续 410 `security_cursor_expired` |
| 安全事件详情与明细 | `eventId`，明细独立游标，返回标识、状态、合法字段，不展示历史敏感快照                                                                                                                                                                                                             | 同上；对无读取权限者不透露事件存在；合法主体找不到 404 `security_event_not_found`                                                                   |
| 采集健康           | 公共健康只给脱敏组件状态；管理员详细视图给最近成功、持久水位、缺口窗口与失败类别；指标按有界枚举                                                                                                                                                                                  | 未知/降级非 `healthy`；不暴露 IP、账户、路径或错误原文，不在 metrics 抓取时查库/外联                                                                |
| 主事务写服务       | 事件上下文由服务端构造；调用返回 `operationId` 供重查                                                                                                                                                                                                                             | DB 忙/满盘/必需明细失败 HTTP 503 `security_audit_unavailable`；各协议用原生封套映射，不伪造成功                                                     |

- A 是共享事件与管理错误契约的规格真源。保留 [OpenAPI](../../api/openapi.yaml) `Error` 的嵌套外形 `{error:{code,message},requestId?,operationId?}`；`requestId` 是可选顶层字段，`operationId` 只在确认存在且主体有权时返回；`errorCode` 不属于管理 `Error` 封套；事件、获准的候选状态及原生协议映射可以用该字段表达同一权威原因码。未认证 401、权限不足 403；近期 MFA 不足 403 `recent_mfa_required`，同幂等键换动作/参数 409 `security_idempotency_conflict`（准入可保留 `admission_key_conflict`）。原生协议只映射封套、不发管理错误体，保留裁决原因码；匿名下载沿既有 ACL 与确定的读取裁决。
- 首页游标固定入库上界 `snapshotWatermark`、规范过滤指纹、认证主体及 15 分钟期限，后续以持久顺序的锚点翻页；不把迟入库但 `occurredAt` 较早的记录插到此快照。`projectionWatermark` 是相同顺序域内已完整处理的最高连续水位；原始查询无异步投影，以原始可读水位填，不隐藏采集缺口。`projectionHealth` 表示投影可用性，`coverage` 表示采集覆盖度；原始列表也报告范围内覆盖，空页或水位相同均不证明无缺口。以至多多取一项判 `hasMore`，无下一页时不发游标；不做整库计数。
- 索引按入库顺序和过滤键设计，较长时间窗由客户端分段读。初始保留目标：普通/低价值拒绝 30 天、独立安全事件 180 天；绑定案件/未结处置/保全或恢复所需记录不由普通 TTL 清理，管理员留存策略另审，不自动擦除 `audit_log`。既有审计 `clientIp` 前缀筛选保持原义，不与本查询混用。
- SQLite 写事务内不做网络、扫描、密码哈希或文件 IO；审计增量以相同参考数据比较，目标关键提交 p95 增量 ≤10 ms，事件列表 p95 ≤250 ms（至少百万普通事件，固定参考机和过滤条件记录于 I 批）；无法达到先诊断容量与索引，不降低记账保证。

### 3.5 升级与共存

- 附加迁移由主代理分配，不修改已发布迁移；检查事件版本、索引、旧视图和新增权限后启用 A 样例。新旧并列期间显示来源类型及旧缺项；不要把旧审计镜像当成第二条安全成功事实。
- 初始上线需明确每个入口的覆盖标记；总体门槛前不把部分接入宣称全部可靠。不得降级旧程序继续处理新安全状态；恢复条件由 [FR-168](security-incident-controls.md) 定义。

## 5. 验收标准

- 未受信转发头、重复恶意 request ID、IPv4 映射、IPv6 CIDR、代理链截断/错误与可信 scheme 都按边界裁决；真实反代拓扑另行演练。
- 注入审计、明细、DB busy/full 与提交前失败，业务不存在/仍旧；提交成功响应丢失、清理故障、重启回放，成功事实仅一条且可查回执。
- 洪峰和写故障有界且可见，关键写/撤销不被拒绝队列挤占；重启只标未知缺口，不伪造窗口计数。新增读裁决无法核实时不开下载，已开流边界见 FR-168。
- 新事件、调查投影、通知、导出与诊断无凭据预览或任意请求体；历史记录和确认未改写，旧缺项显示未采集。
- 负例：同时给 `ip/cidr`、跨度超过 30 天、`limit` 超过 100 或更换游标过滤条件均拒绝；过期/失效快照返回 410。追加一条迟入库记录不得改变已有翻页；原始空页/投影滞后显示对应水位、健康及缺口，不宣称零风险。
- 负例：管理错误不可扁平化，事件只能用 `errorCode`；未经授权的错误不回 `operationId`，拒绝或未决回执没有 `committedAt`；下游不再读取 `recordedAt`。伪造任务来源或 worker 地址不被采为发起 IP。
- 收集索引查询计划、预算压力证据及 A/B/D/F 覆盖矩阵；自动化通过不替代真实代理部署、完整覆盖或生产验收。

## 6. 风险 / 待定

- 预算为首版设计值，不是实测吞吐；超限适配、留存与磁盘水位验收需独立复核。代理头部署约定须逐实例确认，配置未知不推测。
- 正式路由、迁移号、旧敏感字段对旧客户端的展示兼容与 API 细节由契约协调；本规格不宣布已经迁移、验证或交付。
