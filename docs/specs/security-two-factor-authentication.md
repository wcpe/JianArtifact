# 功能规格：双因素认证、管理员认领与受控恢复

> 状态：开发完成，待用户验收；TOTP 因子、单次恢复码、登录挑战门、受控认领（安装票与管理员票）、近期强认证水位与边缘限流已实现，真实后端端到端实测通过；真实客户端与部署演练未执行　·　关联 PRD：FR-167　·　分支：`feat/security-two-factor`

## 1. 背景与目标

安全处置第三批（C），依赖 [FR-165](security-trusted-audit.md) 和 [FR-166](security-credential-lifecycle.md)。管理员必须使用本地 TOTP，普通用户自愿启用。填补仅有密码/外部第一因素即可签发会话，以及网页 bootstrap / CLI reset 可能直接取得管理权限的历史边界。

[当前架构](../ARCHITECTURE.md) 已有本地、OIDC、LDAP 和一处 `AuthService` 签发职责；仍需将不同登录方法的最终发行汇聚成同一道强度门，不把旧代码或现有外部身份源本身当作已启用 2FA。

## 2. 需求（要什么）

- 管理员首次安装、既有管理员升级认领、晋升管理员、普通用户启用与失效恢复，每条路径都必须明确谁能进入与何时才能签发完整会话。
- 本地、LDAP、OIDC 均不绕过本地强度策略；管理 Basic、普通 API Token 和原生协议不作为管理员交互会话。QQ 不加入登录方式。
- 挑战必须短时、单用途、单效消费、限尝试。恢复后撤销旧因子、旧会话、旧恢复码与相关旧代凭据。
- 敏感操作须近期强认证、明确确认且绑定动作、目标版本、内容摘要与具体操作者，最终事务重新校验且防重放。
- 不提供短信登录、密码账户接管、浏览器长期信任绕过、第三方二维码或目录服务强度声明自动折抵本地因素。

## 3. 设计（怎么做）

### 3.1 当前状态与凭据类型（[ADR-0032](../adr/0032-credential-epochs-and-strong-authentication.md)）

| 类型     | 状态 / 关键字段                                                                                                              | 可做                                                                              |
| -------- | ---------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| 账号因子 | `not_enrolled → enrollment_pending → active`；取代/恢复时旧因子 `retired`，账号可进入 `claim_required`                       | 管理员 `not_enrolled` / `claim_required` 一律无完整会话；普通用户未启用可一级登录 |
| 挑战     | `{challengeId,purpose,actorUserId,expiresAt,attemptsRemaining}`；`issued → consumed` / `expired` / `cancelled` / `exhausted` | 仅当前用途端点；登记者和作用域绑定，终态不可重新签发或复活                        |
| 因子     | `factorId`、加密种子、`keyVersion`、`lastAcceptedStep`、状态                                                                 | 只用于验证；一次登录、确认、绑定或恢复后的任何用途均不重复接受同一时间步          |
| 恢复码   | 非秘密行 ID、独立不可逆校验值、`consumedAt`                                                                                  | 单个事务单用；只签发受限恢复挑战，不直接发管理 JWT                                |
| 动作确认 | 服务端摘要、动作 ID、`actorUserId/sessionId/accountEpoch/securityEpoch/expiresAt`                                            | 只对本次规范化动作，不能转让、换目标或用于认证                                    |

- `challengeId` 可用于事件关联；提交时使用另一个高熵不透明 `challengeToken`，服务端只存校验值。响应或短会话 cookie 只走 TLS、禁止缓存；cookie 要设置 HttpOnly/Secure/SameSite，涉及跨站回调时保留 CSRF/Origin/state 检查。URL/query、日志/事件、Referer、通知不得携带票、OTP、恢复码或通用令牌。
- 所有挑战绑定用户、认证来源、途径所需的发起浏览器/会话、账号代次和库外安全时代。验证先区分用途，再读当前状态；待验证/待绑定/恢复挑战不满足普通鉴权中间件。服务端超时为准；可主动取消，不能从终态复活。
- 策略：管理员必开且普通流程不能关闭最后因子；普通用户可自愿开闭，停用要求当前会话、当前一级凭据与近期 MFA，停用不自动重新允许原生密码。管理员强制状态先于角色权限生效；晋升前须完成可信认领/已有活跃因子与升级确认，旧低强度会话一律失效。

### 3.2 登录、初装、升级与恢复

| 场景                  | 第一阶段                                                                                                                                   | 完成条件 / 授权                                                                                                                                             |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 本地、LDAP、OIDC      | 验证本地口令或已绑定外部身份，仅承认一级因素；保留身份源防自动绑定管理员、群组不授角色等既有规则                                           | 无因子且非强制账号可直接签一级会话；已启用者签 `login_mfa` 挑战，验 TOTP 后才签当前会话                                                                     |
| 空库首个管理员        | 本机 OS 授权操作者通过受控离线 CLI 申请一次性 `claim_install` 票；网页必须同时提供票和有效安装输入                                         | 单一未初始化判据排除内置主体；唯一认领约束；密码、票和因子验证后原子入库生效；票不能直换管理 JWT                                                            |
| 旧管理员/新管理员认领 | 有效的旧密码只能进入引导，不能自行设因子；由本机受控 CLI 或已有近期 MFA 全局管理员签 `claim_admin`（跨账号批准不能就是目标账号的一级会话） | 票绑定目标 ID、代次和用途，结合目标的第一因素、一次成功 TOTP；角色/会话切换在事务内复核，不接受仅持旧密码                                                   |
| 普通用户登记          | 自己的当前会话和新鲜第一因素（外部账号走既有来源重新认证）                                                                                 | `factor_enroll` 挑战，确认 TOTP 后才激活种子并轮换会话；失败/取消不改变旧因子，过期废弃待登记种子                                                           |
| 恢复码                | 当前第一因素与合法恢复码；恢复码消费、旧因子撤销、旧码失效、账号代次提升和新受限挑战同一事务                                               | `factor_recover` 只可绑定新因子；成功后重新登录，不沿用旧挑战/会话。中断后不得恢复旧因子，由受控认领续接                                                    |
| 所有因子丢失或灾备    | 日常丢失：本机受控 CLI 或其他近期 MFA 管理员批准；灾备：仅 FR-168 核实的当前安全状态或隔离内本机受控认领，不采信备份中的管理员角色或种子   | 不提供凭旧密码解锁，不向 CLI 签发通用 JWT；灾备恢复裁决按 [FR-168](security-incident-controls.md)；无可信记录须重设第一因素、重绑新因子后才可获受限解闸身份 |

- 离线 CLI 需目标实例数据目录 OS 授权、服务停写/不可并发竞争的实例锁、显式目标与原因；仅出一次限制票，未初始化也须留可验证安装审计记录。数据库恢复隔离时依 FR-168 的本机权限/门禁，不接受旧库的 Web 管理权作为本机权限。
- 安装/认领票绑定实例、安全时代、账号（首次空库时是安装事务与唯一槽位）、用途、期限；票的验证、一次认领、因子激活、账户事件同一事务。过期/冲突由操作者重新出具，并使同用途旧票不可用；失败不得遗留具管理权限的半成品。
- LDAP/OIDC 完成身份校验与既有安全绑定后复用上述策略；外部 `amr/acr` 不在本期接受为本地 MFA；不能在回调重定向、JSON、页面补开的 Basic/API Token 或 npm 登录中提前返回完整会话。IdP 故障不影响已合法认领的本地管理员依其本地因素登录。

### 3.3 验证、确认与事务

- TOTP 首版为 6 位、30 秒步长、窗口当前步 ±1；时钟明显漂移时报告运维状态，不扩大窗口。比较和失败行为不泄露是否存在账号；事务条件更新 `lastAcceptedStep`，严格大于已用步且版本/时间窗仍有效，多请求最多一个成功。登记验证也消耗该因子步。
- 挑战默认 5 分钟、最多 5 次，安装/认领票 15 分钟、最多 5 次；同账户/用途最多 2 个活跃待验证挑战，替换时旧挑战取消；失败配额原子扣减。另有来源与实例限流；首版每账号 10 次/5 分钟、每来源 30 次/5 分钟、实例 200 次/分钟，使用有界计数与受信 IP，避免仅靠攻击者提供的用户名锁死有权用户；不返回精确存在性。
- 种子由独立用途密钥作带认证加密，绑定账号、因子与密钥版本；密钥在实例本地受限存储，不随备份导入，不复用 JWT 密钥。二维码本地生成、仅当前登记挑战可见；返回种子 URI 只在该流程一次展示，禁止第三方传输或浏览器持久缓存。
- 每次给出 10 个随机高熵恢复码，仅在完成登记与重发时一次展示。独立校验值和常数时校验防止暴露明文；成功必须同时条件消费一枚有效码、撤销其余旧码/因子、提升账号代次、创建受限挑战及事件。新一批签发覆盖旧批，不能从重试取回原明文。
- 敏感交互包括跨账户改密、管理员角色授予、因子重置、处置、准入例外、QQ 绑定确认、关键安全配置与恢复解除；各规格可增加，不能减弱。近期强认证窗口默认 5 分钟，满窗先完成一次 TOTP step-up；不以静态 JWT `mfa` 代替对 `mfaVerifiedAt`、代次和会话的重查。
- 为已预览的动作签单次确认，默认 2 分钟；摘要绑定 `actionType/targetVersion/manifestDigest`（无内容时绑定规范化动作参数摘要）、操作者、会话、上下文版本及 `idempotencyKey`。最终短事务重查强度、近期性、目标版本、摘要与授权，原子消费确认、应用动作、写审计和回执；提交结果丢失只查原结果，不重新以旧确认执行。
- 成功认证和强因子变更必须与安全事件同一事务；业务状态不可写时不发完整会话，不以原先签发的 JWT 抵消失败。不在事务内做外部登录网络、二维码渲染或重密码哈希。

### 3.4 接口、权限和错误

能力及命名为 [OpenAPI](../../api/openapi.yaml) 设计输入，不宣布已有端点。所有挑战去向都不泄露密钥或原 OTP；同一通用错误体按 FR-165。

| 能力             | 设计字段 / 返回                                                                                                                        | 访问与失败                                                                                                                                           |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| 登录结果         | `next=authenticated/mfa_required/claim_required`；后两者只返回 `challengeId/challengeToken/expiresAt` 及下一步                         | 仅在一级有效后返回挑战；管理登录只可由对应下一步完成；无效认证 401 `invalid_credentials`                                                             |
| 验证、登记和恢复 | `challengeToken` + 该用途 `otp` 或 `recoveryCode`，登记启动可回 `enrollmentUri`；完成时 `factorId/enrolledAt` 或一次性 `recoveryCodes` | 身份/代次/用途一致；错误/过期/已消费对外统一 401 `invalid_auth_challenge`；限流 429 `auth_rate_limited`，有界 Retry-After                            |
| 状态和管理变更   | 自身 `mfaRequired/enrolled/recoveryCodesRemaining`，管理员列表最小状态                                                                 | 自身或授权管理员；管理员禁用必需因子 403 `mfa_required`；不能通过这一路列种子、码或挑战秘密                                                          |
| 近期认证及确认   | `mfaVerifiedAt/expiresAt`；动作预览回 `targetVersion/actionDigest`，确认回 `confirmationToken`                                         | 同会话和操作者；缺新鲜 MFA 403 `recent_mfa_required`；目标/内容已变 409 `security_confirmation_stale`；机密状态未知 503 `security_state_unavailable` |

- 已消费确认只有合法主体引用同一幂等键、完全相同摘要才得历史回执，不能通过回执查账号是否存在。确认凭据不交给机器人或协议客户端。
- 首版验证路径只做有界索引读取和至多一次挑战条件更新；额外 DB/因子步骤 p95 ≤10 ms（不计第一因素/网络），过期索引小批清理。校验失败率、时钟、密钥版本可观测，不以账号作为指标标签。

### 3.5 升级策略

- 附加迁移不自动造因子、不改变外部身份绑定优先级；切换前确定至少一个受控本地操作员，盘点管理员与旧协议/管理身份，分清首次建库与现存管理员认领；B 批机器 Token 迁移先满足前置。
- 强制期开启的原子边界要废弃无代次的旧会话，并关闭管理 Basic/旧 API Token 和管理员原生密码；支持目录登录不意味着有紧急无 MFA 后门。外部回调、旧浏览器协议及本机票流程需分别验证。
- 丢失用途密钥不允许旧密文或旧版本程序绕回一级认证；隔离、启用受控重新认领和恢复闸，告知用户可用性影响。

## 5. 验收标准

- 空库、旧管理员、晋升、IdP 回调、管理 Basic/API Token、原生发证均无一级旁路；并发首个管理员认领只兑现一次，直接持旧密码不能认领。
- 多请求同一 TOTP/恢复码/票/确认最多一次成功；失效代次、过期、超额和跨用途不能使用。回执重查不复发种子/恢复码或执行动作。
- 灾备负例：回滚库有旧管理员角色、旧口令与已退役因子，即使切到新 `securityEpoch`，仍不得签发会话、完成 TOTP 或解闸；只允许 FR-168 核实当前因子及其防重放水位，或受控重设并绑新因子。旧确认/挑战/恢复码、旧 QQ 绑定不得用于生成新时代授权。日常因子丢失无完整会话，审计失败状态不变；外部 IdP 不可用仍能按本机受控流程恢复。
- 近期 MFA 失败、同路径对象变更、会话撤销、QQ 旧/跨主体按钮和最终提交竞态均拒绝；响应、截图示例、前端持久状态、日志和指标不泄漏秘密。
- 在用户另行批准的隔离部署演练真实浏览器、时钟与密钥轮换、空库和旧管理员认领，演练不代表生产许可。

## 6. 风险 / 待定

- CLI 票传递、钥匙轮换操作、迁移开关时序需独立安全复核；本阶段不更换真实凭据。登记以 otpauth URI 文本呈现、未引入二维码第三方依赖；真实客户端兼容与部署演练未执行。
- 限流和过期是首版设计，不是已压测结果；无可用本机操作员或失去密钥时保持隔离并报告，不放宽验证。
